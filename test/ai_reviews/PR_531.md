# Retained interlink history integrity review

## Scope

Protect the checkpoint-owned interlink history prefix against silent byte
corruption, retain compatibility with readable version-2 history, remove the
active sidecar during checkpoint cleanup, and clarify history-resume guarantees.

## Changed Files

- `src/interfaces/io/checkpoints/checkpoint_storage.jl`: bounded byte-range hashing
  and owned-sidecar cleanup.
- `src/orchestration/simulation/engine/resume_checkpoint.jl`: incremental digest
  state, additive checkpoint checksum, validation before decoding or mutation,
  and explicit legacy warning.
- `src/models/vehicle/interlinks/data_links.jl`: qualify history equivalence by
  checkpoint schedule and complete model-state restoration.

The corresponding storage and link-schedule tests cover the integrity paths.
Architecture, output, interlink and upgrading documentation describe ownership,
compatibility and the unpublished correction.

## Findings

Independent source review found no blocking implementation issue. The history
header stays unchanged; the digest is additive metadata in the version-2
checkpoint entry. Recording settings are compared before file access. Validation
hashes only the checkpoint-owned prefix, then retains existing token, format,
sample-count and end-time checks. Writers extend a temporary copy of the digest
context with new bytes before publishing the new byte count and context.

Readable legacy entries without a checksum warn and retain history. A malformed
present digest is rejected, rather than treated as legacy metadata. Corrupt bytes
remain untouched until the first replacement checkpoint preserves them under the
existing diagnostic naming rule. No-solve resume leaves files unchanged. Cleanup
removes only the owned active sidecar, preserving archived copies.

Review narrowed an initially overbroad determinism claim: equivalent history
requires the same configuration and checkpoint schedule, with every model's
complete run state restored. Determinism alone is insufficient for stateful
extensions that do not implement checkpoint restoration.

## Residual Risk

A checksum detects byte changes relative to saved metadata; it is not
authentication or scientific validation. Legacy history cannot be verified
retroactively. Validating and decoding use separate reads under the existing
single-writer assumption; concurrent external mutation is unsupported. This does
not add a multi-file transaction or an fsync durability guarantee.

History fallback deliberately reports only the resumed interval. Active matching
restores independently, preserving carried receiver-outflow scoring even when
history is unusable. Scoring policy and published releases are unchanged. Final
patch integration and coordinator release closure remain separate requirements.
