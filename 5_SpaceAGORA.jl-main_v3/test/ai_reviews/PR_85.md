# AI Review — PR #85: EddyCurrentDampingModel — passive magnetic damping for attitude dynamics

## Scope

Adds the missing dissipation half of passive magnetic stabilization. The engine already expresses the conservative half — a permanent magnet as a `Magnet` component summed by `MagneticTorqueRodModel` into the restoring `m × B` torque — but that torque does no net work, so an attitude simulation of a passively magnet-stabilized spacecraft precesses forever: no spin-down, no field alignment. `EddyCurrentDampingModel` supplies the classical eddy-current damping torque `τ = k_e · B × (B × ω)`, closing the capability gap for simulating passively stabilized vehicles end to end.

## Changed Files

- `src/dynamics/coupled/perturbations.jl` — new `EddyCurrentDampingModel` struct (`k_e` [N·m·s/T²] validated finite and > 0 at construction — the finiteness half added for a Codex review finding: `Inf` passed the original `> 0` check and would have produced non-finite torques; `field_model ∈ {:dipole, :igrf}` with `igrf_year` required and range-validated for `:igrf`, mirroring `MagneticTorqueRodModel`'s constructor contract); pure torque-law function `eddy_damping_torque(k_e, B_body, ω_body)`; `calcForceTorque` for the ODE path (guarded on the state exposing both `q` and `ω`, i.e. `orientation_sim=true` — zero wrench otherwise); `wrench` for the StateSample path; `environment_requirements` declaring the planet-frame need. The shared `_magnetic_field_inertial` helper's signature is widened to `Union{MagneticTorqueRodModel, EddyCurrentDampingModel}` so both models resolve B identically.
- `src/dynamics/coupled/force_torque_models.jl` — `using .PerturbationEffectors: EddyCurrentDampingModel, eddy_damping_torque` plus the export line (the explicit import is required; export alone does not bring the name into the parent scope).
- `src/dynamics/coupled/force_torque_models/perturbation_effectors.jl` — export extended.
- `test/probes/eddy_damping_probes.jl` — new standalone probe (see below).
- `test/suites/09_probe_drivers.jl` — probe registered.

## Findings

- Dissipativity is structural, not tuned: `τ·ω = k_e[(B·ω)² − |B|²|ω|²] ≤ 0` by Cauchy–Schwarz for any `k_e > 0`, with equality exactly when ω ∥ B. The field-parallel spin component therefore survives while the perpendicular component decays — the correct phenomenology for eddy-current (as opposed to hysteresis) damping, and the reason the model cannot destabilize an integration regardless of `k_e`.
- Field evaluation is shared with `MagneticTorqueRodModel` via the widened helper rather than duplicated, so `:dipole`/`:igrf` selection, epoch handling, and the planet-frame transform can never diverge between the conservative and dissipative torques acting on the same vehicle.
- The zero-wrench guard when attitude is not simulated makes the model a strict no-op for every translational configuration. Because a `wrench` method exists, the engine routes real simulations through the StateSample path (`_wrench_method_available` short-circuits `calcForceTorque`), so the guard that matters in production is the one in `wrench` (`q_ib === nothing || ω_body === nothing`) — the probe pins it directly on both field sources (exact `(0,0,0)` for every missing-attitude-channel combination) and end-to-end (an `orientation_sim=false` propagation with and without the effector is bit-identical in final position and velocity). The legacy `calcForceTorque` guard is pinned separately.
- `k_e` is a lumped conductivity–geometry coefficient, the standard reduction for this torque; per-material eddy modeling is out of scope and the docstring says so.
- Force contribution is identically zero (torque-only effector), matching the rod model's contract.

## P1 Assessment

No P1s. Additive, opt-in effector; strict no-op unless explicitly added to a scenario's effector tuple with attitude simulated; constructor validation rejects non-physical coefficients and unsupported field epochs before any simulation runs.

## Tests Added/Updated

`test/probes/eddy_damping_probes.jl`, four testsets registered in the probe driver:

- **Torque law and validation** — formula equality plus an independent BAC–CAB formulation (`k_e(B(B·ω) − ω|B|²)`, not a transcription of the implementation) and `τ·ω ≤ 0` over 50 seeded random field/rate draws; exactly zero torque for field-parallel spin and for `ω = 0`; constructor throws for `k_e ≤ 0`, `k_e = Inf`, `k_e = NaN`, `:igrf` without a year, and unknown field models; field-model/epoch round-trip.
- **ODE-path torque** — through `ODEParams` + `build_initial_conditions`: zero force, finite torque with `dot(τ, ω₀) < 0` when attitude is simulated; exact zero wrench when it is not.
- **Wrench path (the live engine route)** — direct `wrench` calls with a hand-built `StateSample`/`PlanetFrameSample` for **both** field sources (`:dipole` and `:igrf` at a fixed epoch, with a LEO-band `|B|` sanity gate proving a real field was evaluated): torque matches the independent BAC–CAB form after the body-frame rotation and is dissipative; every missing-attitude-channel combination returns the exact zero wrench; a missing planet frame throws. Also exercises the ODE-path `:igrf` branch (the `rtolatlong` + field-helper copy) and pins the end-to-end translational no-op: `orientation_sim=false` propagations with and without the effector produce bit-identical final states.
- **End-to-end spin-down** — two full attitude simulations of a magnet-carrying spacecraft in a no-atmosphere orbit: with damping, rotational energy ends below 0.9× its initial value; with the magnet torque alone, |ω|² is conserved to within 5% (pinning that `m × B` does no net work at this tolerance and the decay is attributable to the new effector); the damped run ends below the undamped one.

**Post-review additions**: an adversarial multi-lens review (physics / integration / test-adequacy, each finding independently verified against the code) confirmed no live defects but two test-coverage gaps — the translational no-op was originally pinned only on the legacy `calcForceTorque` path the engine never uses when a `wrench` method exists, and the `:igrf` torque branch had zero test executions. The wrench-path testset above was added in response, along with the BAC–CAB independent formulation and the `ω = 0` pin. One inherited P3 was also fixed in a follow-up commit: for `igrf_year ∈ (2030, 2035)` the IGRF library used to warn on every evaluation (no `maxlog`) — once per RHS call inside the integrator hot loop — behavior shared byte-for-byte with `MagneticTorqueRodModel` via the common field helper. The helper now passes `show_warnings=false` and both model constructors emit the reduced-accuracy warning exactly once at construction; `@test_logs` pins in both probe files assert the single construction warning, a warning-free field evaluation at a post-2030 epoch, and no warning for pre-2031 epochs.

## Residual Risk

`|ω|²` is used as the energy proxy in the end-to-end pin rather than the inertia-weighted `ωᵀJω`; for the probe's fixed diagonal-inertia vehicle the trend conclusion is unaffected, but the proxy would not transfer to a vehicle whose principal axes exchange momentum strongly. Realistic `k_e` values are structure-specific and must come from fits or material analysis; the probe's value is chosen for a visible decay within the short test window, not as a physical recommendation.
