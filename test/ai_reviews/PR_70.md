# AI Review — PR 70: constant feedforward torque on the LVLH cascade controller

## Scope
Follow-up to #69 from closed-loop twin work: a pure PD cascade holds a steady attitude offset of |τ_dist|/(k_rate·k_out) under a quasi-constant disturbance torque (e.g. a CP–CG aero torque). Flight ADCS nulls such biases with integral action; the stateless equivalent — and exactly what a converged integrator applies — is a constant body-frame feedforward torque. `tau_ff` (default zero) adds that capability.

## Changed Files
- `src/dynamics/coupled/perturbations.jl` — `tau_ff::SVector{3,Float64}` field (validated finite, default zeros) added inside the saturation; comment records the steady-state offset formula and why true integral action belongs in a stateful discrete control effector (a continuous wrench cannot hold accumulator state correctly under adaptive stepping — rejected steps would corrupt it).
- `test/probes/coverage_parallel_telemetry_probes.jl` — testset extended to 27 asserts: default bit-identical (torque equality against a no-`tau_ff` model), Inf rejection, and a closed-loop settle test — a constant 2 µN·m disturbance holds a >0.15° PD offset which the matching feedforward reduces by >5×.

## Findings
- No P1 findings. Default `tau_ff = 0` is bit-identical (probe-pinned by exact torque equality).

## P1 Assessment
No P1 findings. Additive, default-off, saturation-preserving (the feedforward is applied inside the existing `tau_max` clamp).
Unresolved P1: No

## Residual Risk
- `tau_ff` trims a *known* quasi-steady disturbance; it does not adapt. True discrete-rate integral action (stateful control effector at a fixed rate) remains the tracked follow-up if adaptive trimming is ever needed.
