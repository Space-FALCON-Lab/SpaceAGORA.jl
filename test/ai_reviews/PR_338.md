## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- Telemetry change by decision (G-7 b): `thruster_level` (and the viewer plumes) and the trace's `burn_start`/`burn_end` times change. The measured delta for the examples is in the PR text.
- Resolved in this PR (PI decision 2026-10-16): the data-saving callback is appended after the control callbacks (`density_callbacks/assembly.jl`), so a level read from the held `burning` flag attributed the end of the step to every sample in it (in the Odyssey run, samples up to 17.7 s before a start read 1). The save field now reads `_thruster_levels_at` at the sample's time. `burn_windows[i]` holds the window from the scheduling call on (`refresh_burn!` after `calcControlEffect!`), and still holds it at the stop edge (the schedule is cleared only at a later scheduler tick), so the samples in the steps that end at the start and at the stop see it.
- Low, remaining case: a burn scheduled when its window has already begun lights at the scheduling time, but samples in the step that ends there, between the window's start and the scheduling time, read 1. The measured examples do not hit this (their burns are scheduled well before their windows).
- Low, trace header: two runs creating the trace file at the same moment may each write the header line; rows are never lost or interleaved.
- Note: in the engine the scheduler runs only through `_schedule_thruster_control!`, which calls `refresh_burn!` right after `calcControlEffect!`, so `burn_windows[i]` holds the last scheduled window at the next call. A caller that runs `calcControlEffect!` repeatedly without `refresh_burn!` gets `schedule_set` each time instead of the deduplicated trace.
- Note: `Base.Filesystem.open` with `JL_O_*` flags is a lower-level API than `open(path, "a")`; it is present in Julia 1.12 (the compat bound).

Reviewer to verify:

- No remaining reference to the removed names in `src/`, `test/`, `examples/`, `scripts/` or `docs/` (`git grep -n "_MANEUVER_TRACE\|_maneuver_burn_active\|_maneuver_trace_key"`).
- The scheduling path is unchanged: the in-window test, the early return during a burn, the clear condition and the planning code produce the same model and plan fields as on `main` (only trace bookkeeping moved).
- `refresh_burn!` emits at most one event per switch and nothing when the state does not change (mounted ticks call it every control period).
- The saved-level test fails on `main` and on `cc0a00493` (the first version, which read the held flag), and the trace assertions fail on `main`. The concurrency test errors on `main` because `main` writes no burn events for that run, and it failed on a version with the lock removed but without the append flag.
- `_thruster_levels_at` dispatches on the effector type only; no `isa` site was added in the engine, and every effector other than the burn scheduler saves what `control_thruster_levels` returns, as before.
- The trajectory and result columns of the measured examples are bitwise identical between `main` and the branch (PR text).

Merge with #333 (author's note): faults act on mounted actuators only. A `:mounted` burn scheduler reports no level of its own, so its saved level always comes from the mounted fractions, where a failed, stuck or degraded engine shows as #333 applies it. An `:ideal` burn's force does not go through the mounted thrusters, so a fault on them changes neither the burn nor its saved level, which stays the window's at the sample's time. The reviewer should confirm that #333's precedence is unchanged for every `:mounted` effector on a faulted spacecraft.
