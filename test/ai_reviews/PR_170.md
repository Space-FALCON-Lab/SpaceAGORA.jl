# PR170: coordinated solver migration and KenCarp4 accuracy repair

## Scope

Resolve LinearSolve 5.18.1 with the compatible OrdinaryDiffEq 7, DiffEqBase 7,
SciMLBase 3 and SatelliteToolbox dependencies. Preserve existing ODE tolerance
arrays, algorithm selections and the dense/default versus sparse/KLU routing.
Integrate main `172150d0c00ef814ed97701c7514885a9d939c8a`, including PR171,
and retain Plots 1.41.7 and the study's independent NetCDF dependency graph.

The follow-up restores the EDL study's repository-relative GRAMSuite path and
sets `NLNewton(always_new=true)` only for split-IMEX KenCarp4. KenCarp4 remains
the default split method. KenCarp47, KenCarp58, multirate and other solver modes
retain their prior policies. The source change alters KenCarp4's numerical
results; it does not change integration tolerances or physical models.

## Changed Files

- `src/simulation/callbacks/event_callbacks.jl`: adapt signed simultaneous vector events and preserve direction filtering; avoid marking derivatives discontinuous when no effect runs.
- `src/simulation/callbacks/state_anchor_callbacks.jl`: use the renamed derivative-discontinuity notification.
- `src/simulation/engine/setup.jl`: import the existing IMEX, DP8 and symplectic algorithms and the Newton policy binding used by KenCarp4.
- `src/simulation/engine/execution.jl`: preserve full specialization on the two explicit sparse ODEFunction wrappers.
- `src/simulation/engine/solver_policy.jl`: retain componentwise ODE tolerances across LinearSolve initialization, preserve backend selection, and refresh Newton Jacobians for split KenCarp4 only.
- `src/dynamics/coupled/perturbations.jl`: use the magnetic library's Val-based warning switch with the existing warning policy.

The coordinated dependency files, development SGP4 API updates, focused
regressions and solver-policy documentation complete the change. The study
manifest path is `../../../data/GRAMSuite.jl`, matching its Project sources.

## Findings

Claude independently reviewed the original migration at `1db7346e`, then
executed the combined tree with main `172150d0c`. That review accepted the
six runtime adaptations but identified the nonportable study path and a
nonlinear atmospheric KenCarp4 regression. The earlier linear probe missed
that regression: agreement between old and new solvers on a linear problem
was insufficient evidence for nonlinear atmospheric accuracy.

The study-path defect is repaired. The KenCarp4 candidate explicitly refreshes
Newton Jacobians. Applying that policy to every KenCarp algorithm was rejected:
a shifted-time manufactured-solution probe with KenCarp47 worsened from
9.422e-8 relative error to 2.140e-7. The final change therefore preserves
KenCarp47 and KenCarp58, and the committed tests protect that choice.

The original callback migration also changes observable behavior. All events
at an exactly simultaneous vector root are now applied; the old stack could
skip all but the first. Ignored-direction crossings are still located by the
new library before the effect is declined, so they may add an internal step
and a saved point. Cross-version internal-step or saved-row identity is not
promised.

Current repair verification is performed by Codex in the implementation task.
Claude's earlier independent review does not constitute independent acceptance
of this new numerical-policy change.

## P1 Assessment

The nonportable manifest path is repaired. The KenCarp4 candidate corrects the
original atmospheric regression: on the integrated source, position error
falls from 18.682088 m with the library-default policy to 0.002673513 m with
fresh Jacobians, against the same DP8 reference and unchanged physical inputs.

Numerical acceptance remains open. An expanded 110 km periapsis case misses
its preselected velocity target: 7.479713e-5 m/s against a limit of 5e-5 m/s.
Its position error is 0.001137037 m, below the 0.01 m limit. The reference
solvers agree within 1.907787e-6 m/s in that case. No threshold was weakened.
The old-policy control covers the original 130 km case only, so this expanded
miss alone does not establish a new cross-version regression. It does require
review before a broader accuracy claim or numerical acceptance.

This PR remains a draft pending numerical review and fresh CI. Passing CI
would not resolve the expanded-case miss, which is in the separately retained
scientific validation matrix rather than the unit CI suite.

## Residual Risk

The corrected policy is verified on bounded fixtures, not full-duration native
GRAM missions. Strongly cancelling split problems retain a documented accuracy
limitation; the original failed criterion is preserved in retained evidence and
is not relabeled as passing. Local tolerances do not imply an equal global
endpoint-error bound. First-use compilation remains an upstream usability risk;
no performance claim or optimization-flag change accompanies this correction.
Fresh Linux CI, including coverage, and review of the repaired head remain
required before merge.
