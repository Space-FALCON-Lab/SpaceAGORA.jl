# Review record: PR 506: merge constellation results from disk

## Scope

Review of the SpaceAGORA `constellation-results-from-disk` branch against main (0f03bbfce). It is stacked on C-4b (`constellation-merged-results`, head 734d80542), which is stacked on C-5a (`results-long-layout`, head ae3ce6998); it contains their commits. This is C-5d of the constellations program's large-outputs step, built to the accepted design decision D-C5-11.

What changes:

- **`read_constellation_results(results_directory)`** merges the member folders a constellation ensemble wrote into the members and constellation tables of `ConstellationEnsembleResult`, without running anything again.
  - It reads one member at a time and writes `constellation_members.feather` member by member, one record batch each, then reads it in place.
  - It writes `constellation_summary.csv` beside it.
  - Its members are the folders found and the members an earlier summary lists, and a `read_status` column says whose rows were read, and why not.
  - It reads a member's bundle only of a known version and layout, of one spacecraft when wide, and with the file sizes its manifest records. A streamed run that did not finish has no rows.
  - It replaces merged files already in the folder only with `overwrite=true`.
  - It returns `(members, constellation, files)`.
- **`run_constellation_ensemble(merge_results=true)`** writes its members feather with the same per-member writer when it writes results, and its `members` table then reads that file in place (D-C5-11). Without results files it is built in memory as before.
- **The viewer's ensemble export** reads one sample's table at a time. In a folder with `constellation_summary.csv`, it labels members by id, plane and slot and colours them by plane.

## Findings

No open P1 or P2 findings.

- **The in-house review (2026-10-23): Not clear.** Here it found P1-2 (from C-4b, still in this branch's merge), P2-1's comment, two P2s and two P3s. This round:
  - **P1-2, fixed** with C-4b's round, merged in. `_constellation_member_rows`, which this branch's merge shares, copies a member's tables first when its returned value holds them. C-4b's test of returned values in the long layout runs here, with the members feather written and read in place.
  - **P2-1, fixed** with C-4b's round. Each sample is replaced as its rows are taken, so `member_rows` holds the only reference until the writer takes it. The comments say so.
  - **P2-4, fixed.** `read_constellation_results` took its members only from the folders it found and rewrote the summary from them, and a member without its results file showed as successful.
    - Its members are now the folders found and the members an earlier summary lists.
    - A `read_status` column says whether each member's rows were read, and why not, and the members not read are named in a warning.
    - `success`, `error` and `elapsed_s` are `missing` without a summary.
    - It replaces merged files already in the folder only with `overwrite=true`.
  - **P2-5, fixed.** It reads a bundle only with a known schema version and layout (`"1"` wide, `"2"` long), and refuses any other, naming the folder. A manifest that still says `streaming = true` is an unfinished member, with no rows. A results file whose size is not the manifest's is not read.
  - **P3-11, fixed:** a wide bundle of more than one spacecraft is refused.
  - **P3-12, fixed:** a folder without the results bundle is marked `no results bundle`, and named in the warning.

- **Changed on purpose.**
  - With `merge_results=true` and results written, `members` reads `constellation_members.feather` in place (read-only columns) instead of holding a copy. It holds the same values.
  - The feather has one record batch per member.
  - The viewer's discovery labels a constellation ensemble's members by id, plane and slot and gives their plane as the scalar, when the folder has `constellation_summary.csv`. Folders without it (Monte Carlo campaigns, ensembles run without the keyword) are labelled as before.
- **Design choices for review.**
  - **One schema for every batch.** An Arrow file has one schema, so the members' columns and types are found first: the union in first-seen order, `Union{Missing, T}` for a column some member lacks, `promote_type` across members. This is what the in-memory merge's `append!(...; cols=:union, promote=true)` gives. Each member's rows are then conformed and written.
  - **From disk, a wide member is renamed by prefix.** The save fields' `per_satellite` flags are not in a member's files. A member runs one spacecraft, so its per-spacecraft columns are exactly its `sc1_` ones. Long members need no renaming.
  - **Identity from disk.** Position and id come from the folder name, or from the summary for a member whose folder is gone. Plane and slot come from a long member's own rows, or for a wide member from `constellation_summary.csv`, `missing` without it.
  - **Status from disk.** `success`, `error` and `elapsed_s` come from an earlier summary. Without one, all three are `missing` rather than guessed, and `read_status` says whether the rows were read. A member the summary records as failed has no rows, as in the in-memory merge (D-C4-6), even when its partial results files are there.
  - **Sizes, not hashes.** A member's files are checked against the sizes its manifest records, not its hashes, so that each file is read only as often as the merge needs it.
  - **The viewer** reads each sample's table twice, once for its outline (columns, last time, cadence) and once for its rows, and holds one table at a time. Colouring by plane uses the page's existing scalar, so the renderer needs no change.

## Residual Risk

- **Memory in the ensemble merge.** The members' rows come back from the members in memory and stay there until the merge writes them, so its peak is the members' rows; the merged table itself is not held. `read_constellation_results` holds one member at a time.
- **One member at a time is by construction, not measured.** The writer takes the members from a lazy iterator and writes each before the next is read. No test counts the members in memory.
- **Sizes, not hashes.** A member file rewritten to the size its manifest records is read.
- **A run-wide save field of a wide member whose column starts with `sc1_`** would be read as a per-spacecraft column from disk. The default fields have no such column.
- **The viewer's labels** change for constellation ensembles that have a summary; scripts that match sample labels by folder name should match `directory` instead.
