# AI Review — PR #78: engage aero across the EI partition for non-vanishing atmospheres; refuse epoch-less NRLMSISE queries

## Scope

Fixes two engine correctness traps surfaced by internal A/B verification of drag configurations.

1. **EI partition zeroed aero above the entry interface.** The split/implicit solver path (`solver_mode=:split_imex`, including the flat-constellation implicit route) treated `EnvironmentModel.EI` as a force gate: aerodynamic forces were hard-zeroed for any spacecraft above EI, for every density model. An orbit that never crossed EI downward therefore flew drag-free on the split path even with a non-vacuum density model — inconsistent with the full (unsplit) RHS, which evaluates the same density model at all altitudes. The gate is now trait-based: only density models guaranteed to vanish above EI (`NoAtmosphereModel`) keep the coast-arc fast path; everything else stays engaged, with the aero wrench's own `rho <= eps` short-circuit handling genuinely negligible densities.
2. **Six-arg NRLMSISE fallback used a fixed reference epoch.** `getDensity(::NRLMSISE00AtmosphereModel, h, lat, lon, el_time, wind)` anchored `el_time` to the J2000 reference epoch, so any caller on that path silently evaluated space indices for dates decades away from the mission epoch. NRLMSISE-00 is calendar-dependent; the 6-arg form now throws a clear `ArgumentError` directing callers to the 7-arg method, whose epoch comes from `p.args.initial_time`.

A third, related trap is surfaced (not errored): configuring a non-vacuum `density_model` with no aerodynamic effector in `dynamic_effectors` — the `make_example_config` default — silently produces zero drag everywhere. `run_simulation` now emits a loud one-shot warning, gated on `SPACEAGORA_WARN_DENSITY_WITHOUT_AERO` (default on, following the `SPACEAGORA_WARN_NORMALIZE` convention); it stays a warning because density-without-drag is a legitimate heating/diagnostics configuration (e.g. the no-GRAM quickstart).

## Findings

- Reproduced with a minimal A/B (NoAtmosphere vs ConstantDensity, single spacecraft, SimpleEphemerides): an orbit entirely above EI on `split_imex` produced trajectories identical to vacuum to the last digit pre-fix, and diverges with dissipating specific orbital energy post-fix. Every other solver mode (default, `auto_stiff`, `rodas5p`, multi-sat flat route) already engaged drag at all altitudes, and below-EI orbits engaged on every path — the defect was specific to the split/implicit partition above EI.
- Bit-exactness for unaffected configs was verified by stash-based A/B at full `%.17g` precision: vacuum configs on the default and split paths, and an `ExponentialAtmosphereModel`-above-EI split config (density underflows below `eps(Float64)`, so the wrench computes exact zeros) are byte-identical before/after the change. The implicit partition's `assign_force_only_translational_rhs!` writes the same zeros the old hard gate produced, so opening the gate for underflowing models is a no-op at the trajectory level.
- GRAM models above EI resolve through the extension's analytic polyfit shortcut in non-keplerian runs (`ext/SpaceAGORAGRAMSuiteExt.jl` already branches on `drag_state`), so opening the gate does not put native-library calls in the coast-arc hot loop for the standard aerobraking configuration.
- In-engine audit of the 6-arg surface: every engine call site of `getDensity` passes `p` (track cache, vacuum-predicted cache, density callback, batch scalar dispatch for NRLMSISE); the model-specific 6-arg delegations (Exponential, Piecewise, Tabulated, TimeTabulated) are typed to their own models and cannot capture NRLMSISE. The only NRLMSISE 6-arg consumers were two contract-suite assertions, updated here.

## P1 Assessment

No P1s. Behavior changes are confined to (a) split/implicit-path runs whose density model does not vanish above EI — which previously produced physically wrong (zero) drag — and (b) the 6-arg NRLMSISE query path, which previously produced wrong-epoch densities and now refuses loudly. No engine caller used (b). Default-path trajectories are untouched (verified bit-exact).

## Residual Risk

- `split_imex` + GRAM + `keplerian=true` now evaluates native GRAM density above EI per RHS call (the polyfit shortcut is gated on `keplerian=false`); slower but correct, and an unusual combination.
- The trait is deliberately conservative: analytic models whose density above EI underflows still pay one cheap density evaluation + wrench short-circuit per implicit RHS call instead of the old free skip.
- External code that relied on the 6-arg NRLMSISE form now errors instead of silently getting fixed-epoch densities — an intentional breaking change of a silent-wrong API surface.
- The no-aero-effector diagnostic is a warning, not an error, so a fully automated pipeline that discards logs could still miss it; promoting it to an opt-in error is a cheap follow-up if desired.
