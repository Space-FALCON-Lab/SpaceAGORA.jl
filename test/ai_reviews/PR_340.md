# PR review: check model hooks against the run's own argument types

## Scope

Review of PR 340 (branch `model-hook-preflight-exact-types`, head `6201bb4e9`) against
main (`56fd7df0d`, the merge of #332). The PR fixes the two P2
review findings on #332's pre-run hook check: a method typed more narrowly than
the engine's arguments (for example `u::Vector{Float64}`) passed the check and
failed at its first call, and under `gravity_backbone_split` a backbone
declaration passed without the acceleration hook that mode calls. No hook
signature, dispatch target or numerical path changes.

Authorship disclosure: this record was drafted by the author of the PR. It
does not replace an independent review.

## Changed Files

- `src/orchestration/simulation/engine/setup.jl`: `_hook_call_types(u0, p)`
  (the run's concrete state, spacecraft-view and parameter types);
  `_missing_model_hooks(args, call, solver_mode)` looks each hook up with
  `hasmethod` on those types, and under `gravity_backbone_split` requires the
  acceleration hook each backbone declaration names; `_has_methods_for` adds
  "none accepts the arguments this run passes" to a line when the model has
  methods of the hook; `_validate_model_hooks!(args, u0, p, solver_mode)`.
  `_hook_method_may_apply` is removed.
- `src/orchestration/simulation/engine/execution.jl`: the check moves from
  beside the thermal-model check to just after the run's `ODEParams` are
  built, before any setup that evaluates a model.

## Findings

No P1 or P2 findings.

What a reviewer should confirm: the types the check uses are the ones the
calls receive. The GNC ticks (`navigation_guidance_callbacks.jl`,
`control_callbacks.jl`) pass `integrator.u` and `integrator.p`, whose types
are those of the initial state from `build_initial_conditions` and of the
`ODEParams` built from the same arguments. The dynamics (`dynamics_rhs.jl`)
pass `u.sc[i]` and `p`. A probe that recorded the types each hook received in
real runs matched them exactly in every case: `:tsit5`, `:dp8`,
`:auto_stiff`, `:rodas5p`, `:split_imex` and `:multirate`; one and two
spacecraft; attitude on. A run's spacecraft share one state layout
(`build_initial_conditions` refuses mixed layouts); the check keeps each
distinct view type regardless. Force/torque models still reuse the engine's
`_wrench_method_available`, so the check agrees with
`_evaluate_dynamic_effector`.

Points a reviewer should check:
- Low, by design: a checkpoint resume replaces the initial state with the
  saved one after the check. Its layout matches the configuration (the resume
  path checks the interlink fields), so its type is the same in practice; a
  method typed for one exact layout would not notice a difference.
- Low, by design: the backbone acceleration hooks are looked up on
  `StateSample` and `EnvironmentSample` as a whole, as the engine's `wrench`
  rule does, so a method typed for one parameterisation of those samples is
  refused.
- Low, unchanged from #332: a model that opts into `link_wrench` without
  `wrench`, and the components of a wrapping density model, are not checked
  further; each still fails during the run, as before.

## P1 Assessment

No P1 findings. The check still only reads method tables and returns or
throws before integration; it now runs after `build_initial_conditions` and
`ODEParams`, which evaluate no model hook.

Unresolved P1: No

## Tests Added/Updated

- `test/unit/gnc/model_hook_preflight_tests.jl`, now 130 checks in five
  testsets. Added:
  - the check's inputs equal the run's state, spacecraft-view and parameter
    types;
  - built-in models checked on those concrete types, including every
    built-in backbone declaration's acceleration hook;
  - a `Vector{Float64}`-typed guidance method refused with the "none accepts"
    note, while a `ComponentVector`-typed one passes;
  - backbone declarations with and without their hooks, inside and outside
    `gravity_backbone_split`;
  - runs refused before any dynamics evaluation, for a `Vector`-typed
    guidance method and for a backbone core without its acceleration hook.
