# AI Review — PR #74: Merge `origin/main` into `parllelization_paper`, revert `test/` to main's layout

## Scope

This review covers (1) the test/CI/docs remediation done while merging
`origin/main` into `parllelization_paper`, and (2) a full read of every
`src/*.jl` file this PR changes relative to `origin/main` (30 files, 1256
insertions / 185 deletions — the actual parallelization-work delta this
branch introduces; a much larger apparent diff against a stale local `main`
ref was a red herring, see commit history for the reconciliation).

After merging `origin/main`, the branch's own in-progress test-suite
restructure (`test/unit/` + `test/contracts/` as gate implementations +
`test/golden/` fixture harness, tracked in the now-removed
`test/TEST_RESTRUCTURE_PLAN.md`) was reverted wholesale back to main's
`test/gates/` + `test/suites/` layout, per explicit direction, to keep the
branch mergeable. That revert (`git rm -r test/; git checkout origin/main
-- test/`) is a blunt instrument: it silently overwrote every branch-local
fix, restored test, and doc note the prior restructure had layered on top
of main's copies. Most of this session — three independent `/code-review`
passes (two "high" effort, one "max" effort) plus manual diagnosis — found
and repaired what that blind revert broke. The `src/` review below is
separate: five parallel finder passes plus independent verification of every
candidate finding against current file content (not paraphrased summaries).

## Findings

### `src/` findings (new to this pass — five parallel finder agents, every
finding below independently re-verified by direct file reads before
inclusion)

**P2 — real, confirmed, not currently demonstrated to break a passing
test:**

1. **Shared planet singleton gets mutated in place by a real test call
   site, contradicting the cache's own documented invariant.**
   `src/environment/ephemerides/planets.jl` (`_EARTH_CACHE` etc., ~line
   350) caches one `Earth`/`Mars`/`Venus`/`Titan`/`Moon` instance per
   `(topo_harmonics_file, spice_path)` key, with a comment asserting "no
   caller in this codebase invokes [`TopographyHarmonicsWorkspace!`]" and
   warning that the cache "needs revisiting" if that ever changes. It
   already has: `test/suites/02_callbacks_parallel_and_smoke_tests.jl:1330`
   calls `TopographyHarmonicsWorkspace!(topo_file, earth)` on an `earth`
   obtained via `Earth("", SPICE_PATH)` — the same cache key as the shared
   `EARTH` test constant used throughout the rest of the suite. This
   mutates the singleton's `topography_workspace` field in place with
   test-only synthetic coefficients, polluting shared state for the rest
   of the process. No currently-passing test appears to read
   `topography_workspace` afterward in a way that fails, but the mechanism
   is real and unguarded (also a data race under any concurrent access).
2. **Process-pool worker bootstrap has no error handling; a failure mid-batch
   leaks OS processes and desyncs the pool's bookkeeping.**
   `src/parallel/process/worker_pool.jl`: `_bootstrap_process_worker!`'s
   first statement (`Distributed.remotecall_eval(Main, [worker],
   :(using SpaceAGORA))`) is the only step in the whole bootstrap sequence
   with no `try`/`catch` (every step after it — GRAMSuite import, SPICE
   furnishing, GRAM warmup — is best-effort/caught). If it throws for any
   worker in a batch, the exception propagates out of
   `ensure_process_workers!` before `append!(pool.workers, new_workers)`
   runs: already-spawned OS processes for the whole batch are never added
   to the pool and never `rmprocs`'d, and the next call recomputes
   `shortfall` against the stale (smaller) count, compounding the leak.
3. **The shared process pool has no worker-liveness check; one crashed
   worker permanently poisons it for every future campaign in the
   session.** `src/simulation/campaigns/monte_carlo.jl`'s
   `_run_monte_carlo_process` calls `remotecall_fetch(run_sample, pool,
   index, seed)` inside a `Base.@async`/`Base.@sync` block with no
   `try`/`catch`; a dead worker (native GRAM is documented elsewhere in
   this repo's own project history as segfault-prone under process pools)
   throws `ProcessExitedException`, aborting the whole `@sync` block —
   not a per-sample failure. Nothing evicts the dead PID from
   `campaign_process_pool()`'s module-level singleton
   (`src/parallel/process/worker_pool.jl` has no liveness check anywhere
   outside the manual, test-only `shutdown_process_pool!`), so every
   subsequent campaign that reuses the pool inherits the same dead worker
   and fails the same way.
4. **No worker reservation/leasing: concurrent campaigns can silently
   contend the same process-pool workers.**
   `src/simulation/campaigns/adaptive_routing.jl`'s
   `_run_campaign_with_route_env` always slices `worker_ids[1:worker_count]`
   from the front of the shared pool with no locking or marking-in-use.
   Two concurrent `:process`-routed campaigns in the same process would
   silently share and serialize on the same PIDs — not a crash or wrong
   answer, but a throughput collapse that also poisons the adaptive-routing
   feedback statistics with artificially slow `:process`-route timings for
   unrelated reasons.
5. **`GRAMAtmosphereModelSurrogate` is unconditionally classified
   lock-free for auto-thread-budget purposes, even when its point-fallback
   path uses a real GRAM lock.**
   `src/simulation/callbacks/density_callbacks/config.jl` (~line 287):
   `source = model isa EnvironmentModels.GRAMAtmosphereModel ?
   :density_callback : :density_callback_lockfree` routes every surrogate
   through the low (4-thread) auto-mode floor. But
   `EM.getDensity(::GRAMAtmosphereModelSurrogate, ...)` falls back to a
   locked native-GRAM point sample below `point_fallback_below_m`, which
   defaults to `260_000.0` m for Titan (`data/GRAMSuite.jl/src/GRAMSuite.jl:124`)
   and is a documented, settable constructor kwarg for any planet. A
   Titan (or explicitly-configured) surrogate campaign in `auto` density-
   thread mode gets threaded below that altitude — exactly the
   entry/aerobraking regime this package targets — defeating the 16-thread
   floor that exists specifically to prevent GRAM-lock oversubscription.
6. **Not all callers of `simulation_engine_config_from_env` were updated
   for the new lenient default.**
   `src/simulation/engine/adapters/from_env.jl` changed the function's
   default to `solver_strict=false` (malformed `SPACEAGORA_SOLVER_*` env
   values silently fall back instead of throwing). `solver_policy.jl`'s
   `_active_solver_config()` was correctly updated to pass
   `solver_strict=true` explicitly — but
   `src/simulation/engine/adapters/from_simulation_configuration.jl:2`
   (`SimulationEngineConfig(args::SimulationConfiguration; env=ENV)`,
   used to build the config for an actual simulation run, not just
   introspection) was not, and silently inherits the lenient default with
   no logging on the caught-and-defaulted path.

**P3 — real but low-impact (performance/scheduling-only, dormant, or purely
informational):**

7. `_count_flat_queue_only_effectors` (`src/simulation/engine/dynamics_rhs.jl`,
   ~line 713) unconditionally excludes batchable/harmonics effectors from
   its count regardless of `partition`, but the actual pre-pass skip it's
   meant to mirror (~line 434) is gated by `partition === nothing`. For a
   partitioned (IMEX `:explicit`) call with a heterogeneous effector set,
   this undercounts and can silently skip the cost-based work-item sort
   that heterogeneous queues need — a load-balance/throughput regression,
   not a wrong-answer bug (verified: summation order changes only, no
   value-affecting logic).
8. The new single-inverse-square/J2 flat-routing path
   (`src/simulation/engine/setup.jl`, `_rhs_single_invsq_flat_supported`)
   has only a satellite-count threshold (default 8), unlike every sibling
   perf-routing knob in the same file (harmonics batch, plan-step cache),
   which are explicit opt-in. Any existing ≥8-satellite single-gravity
   constellation study silently changes its default RHS routing on
   upgrade, with no toggle to restore the old default.
9. `ReactionWheelAssembly.J_rw_pinv` (`src/vehicle/spacecraft/components.jl`)
   is computed once at construction from `J_rw`; both fields are directly
   mutable with no invariant enforcement. Dormant today (no current
   in-place mutation site for `.J_rw` found), but a future
   wheel-reconfiguration feature could silently desync them.
10. A stale comment in `src/parallel/process/worker_pool.jl`
    (`_warm_gram_wrapper!`'s rationale) misattributes
    `_gram_apply_user_ephemeris_state!`'s location (says
    `ext/SpaceAGORAGRAMSuiteExt.jl`; it's actually in the vendored
    `data/GRAMSuite.jl/src/GRAMSuite.jl:1061`) and claims it lacks its own
    `invokelatest` (it already has one). The warmup call itself is
    harmless.
11. `adaptive_routing.jl`'s `:process` branch has an unreachable
    `spec.fail_fast && _throw_first_monte_carlo_failure(samples)` after
    `_run_monte_carlo_process`, which already performs the identical check
    internally before returning — dead code, harmless.

None of the above were fixed in this pass (see Residual Risk); this
artifact documents them for follow-up.

  pass.** They were found reviewing this PR's actual `src/` delta for the
  first time in this session (prior passes only covered test/CI/docs).
  Recommend a follow-up pass to fix at minimum findings 1, 2, 3, and 6

  coupled multi-satellite propagation and GRAM-backed Mars propagation).
  This was an explicit, direct instruction from the user earlier in this
  session ("delete it too" when asked whether `test/golden/` should
  survive the revert) — not an oversight, but flagged here since the
  max-effort review independently surfaced it as a real coverage gap.
  Revisit if desired; `scripts/regenerate_golden.jl` (the only way to
  regenerate a fixture) was also removed as dead code, so reconstructing
  these would need that tooling rebuilt first.
- **Pre-existing, not introduced here**: `test/suites/01_contract_and_api_tests.jl`
  has an `isapprox(...; atol=0.0, rtol=0.0)` bit-exact equality check on a
  value that passed through an adaptive-step ODE solve (mass-conservation
  invariant). Any future solver-path change that introduces even one ULP
  of rounding flips this pass→fail with no diagnostic slack. Present
  identically in the deleted `test/unit/simulation_engine/run_metadata_and_rhs_tests.jl`
  before this revert; simply reactivated into the default `test/runtests.jl`
  path by it. Loosening the tolerance is a domain judgment call, not
  attempted here.
- **Structural fragility, not fixed**: the `kclear()` →
  `_reset_furnished_kernels!()` contract is now hand-duplicated at 5 call
  sites across 3 differently-bootstrapped test files with no shared helper
  enforcing it — this exact pairing was already silently dropped once by
  the revert and had to be independently rediscovered 3 times. A
  `safe_kclear()` test helper would close this, but was judged too risky
  to introduce quickly across 3 different bootstrap conventions in this
  pass.
