# AI Review — PR 51: CYGNSS drag verification tooling (frontal ref-area convention + decay-calibration drivers)

## Scope
Review of the opt-in `bus_ram_face` reference-area convention added to the telemetry-verification spacecraft builder (kwarg, config field, manifest key, builder logic) and of the productized CYGNSS 48-hour drag/decay study drivers. Focus areas: backward compatibility of every previously calibrated scenario (odyssey, vex, earth_gmat must be bit-for-bit unchanged), consistency of the new convention with the Hart free-molecular coefficient normalization, and keeping mission-derived geometry/results out of the public tree.

## Findings
- P2 (fixed during development): the initial driver approach hard-coded a bus-dims workaround (lx = ly) to make the legacy `ref_area = dims[1]*dims[3]` numerically equal the flow-normal face; the `bus_ram_face=:frontal` option replaces that with an explicit, validated convention and an ArgumentError on unknown symbols.
- P3 (accepted): the `:frontal` convention is correct for the translational fixed attitude (flow along body +x). With `orientation_sim=true` the ram face changes with attitude and neither static convention is exact; documented in the builder comment, and out of scope for the fixed-attitude verification harness.
- P3 (accepted): `run_drag_decay_calibration.jl` overrides `EnvironmentModels.getDensity` for `GRAMAtmosphereModelSurrogate` at script scope to serve the along-track density table. This is deliberate include-world experiment wiring (same pattern the campaign validated); it never executes in package/CI contexts because the drivers require private data and are not wired into any test suite.
- P3 (accepted): `harness_48hr_common.jl` duplicates helpers that `run_position_accuracy_48hr.jl` also carries (both copied verbatim from `test/gmat_scenario_matrix.jl`); consolidating the older script onto the shared include is deferred to keep this PR's diff reviewable.
- No P1 findings.

## P1 Assessment
No P1 findings were identified. The default path is unchanged (`:legacy` preserves `dims[1]*dims[3]` exactly and is the default in the struct, the kwarg, and the manifest parser), so previously calibrated scenarios cannot shift.
Unresolved P1: No

## Tests Added/Updated
- `test/probes/coverage_parallel_telemetry_probes.jl` — new "Spacecraft builder ram-face convention" testset (6 assertions): `:legacy` produces the historical bus `ref_area`, `:frontal` produces the flow-normal face, panels are unchanged in both modes, unknown symbols throw, and the `SpacecraftConfig` default remains `:legacy`. Full probe file run locally: all testsets pass including this one.
- Rationale: the probe file is the existing home of the telemetry physics contracts (airspeed sign, per-link dynamic pressure), and the convention pin is exactly that class of contract.

## Residual Risk
- The study drivers cannot run in CI (private telemetry, WamIPEDensity dependency, network access to the NOAA bucket); they are exercised manually. Syntax is parse-checked; their logic mirrors scripts executed end-to-end during the campaign.
- The decay post-processor's estimator-bias cancellation assumes the drag-free zero reference shares the telemetry's sampling-gap structure (it does, by construction of the comparison grid); a synthetic-injection validation of the recovered decay slope is a noted follow-up.
- `bus_ram_face` is intentionally not surfaced in published example specs; only the private CYGNSS geometry TOML uses `"frontal"` today.
