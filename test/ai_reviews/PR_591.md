# AI Review Artifact — PR #591

## Scope
Final defaults for the adaptive parallel policy, plus the measurement and scripting support used to evaluate them. Under the adaptive policy (`SPACEAGORA_PARALLEL_POLICY_ADAPTIVE=1`) the RHS-calibration confirmation and the sweep-time floor now default on, the per-region width tuner (`SPACEAGORA_RHS_REGION_WIDTH`) now defaults to off (opt-in via `auto`/`on`), and the predictive planner no longer proposes mixed multi-sample plans. New opt-in knobs cover pin margin, sweep seeding, skip-by-prediction and a regret guard (default off). The harmonics batch workspace pool is right-sized per shape and restored after a calibration sweep, and the inner-speedup curve is clamped. Benchmark-harness knobs and Expanse job scripts are included. Not included: the spin-barrier/workspace hang fix.

## Findings
- **P2: the regret guard throws from a post-solve hook.** `regret_guard_margin()` (src/orchestration/parallel/policy/regret_guard.jl:41) raises `ArgumentError` when the guard is on and no margin is set. It is reached from `_rhs_calib_record_solve_time!` (src/orchestration/simulation/engine/rhs_calibration.jl:1998-2000) after the solve has finished, so a misconfigured opt-in run fails at the end of the first solve rather than at startup. The failure is loud and the guard is off by default, so this is a usability issue only.
- **P2: guard baseline is a prediction, not a measurement.** The rule compares the minimum chosen-plan sample to `baseline_ns * (1 + margin)` (regret_guard.jl:30-33); `baseline_ns` comes from `_rhs_calib_regret_baseline_ns`, built from sweep timings. A stale or contaminated baseline can fire or suppress the freeze. The minimum-sample rule and the `min_solves` default of 3 (documented in the source as assumed, not measured) limit false fires from cold samples.
- **P3: confirmation compares whole-solve wall times taken in sequence** (rhs_calibration.jl:773-800): K solves of the pin, then K of the heuristic, on possibly different workloads of the same signature. State is in memory only, by design (comment at rhs_calibration.jl:~706), and `_rhs_confirm_sample!` is called under `_rhs_calib_lock` from `_rhs_calib_record_solve_time!`; `_rhs_confirm_begin!` takes the same lock. A demotion rewrites the cache row to the heuristic verdict and keeps the candidate list.
- **P3: new defaults are policy-conditional.** Confirmation and the sweep-time floor read `adaptive_policy_enabled()` when their variable is unset (rhs_calibration.jl:673, 698), and `allow_mixed` does the same (predictive_planner.jl:197-199). Outside the adaptive policy behavior is unchanged; an explicit value always wins. The region-width tuner is the one default that changes regardless of policy (dynamics_rhs.jl:1283), from on-under-adaptive to off everywhere unless set.
- **P3: pool restore after a sweep drops pools created concurrently.** `harmonics_batch_pool_restore!` republishes the pre-sweep map (models_and_workspaces.jl, restore helper), so a pool another thread built during the sweep is unpublished. Holders keep their reference and the pool is scratch, so results are unaffected; the cost is a rebuild on the next request. The row-ratio (2) and shape-count (4) limits are labeled assumed in the source.
- **P3: the inner-curve clamp changes planner inputs.** `curve[b]` is now `min(t(1)/fastest, b)` and a sweep with any width beating `t(1)/w` by more than `SPACEAGORA_INNER_CURVE_SUPERLINEAR_SLACK` (default 2.0, assumed) returns `nothing`, so the planner assumes no inner gain for that stem (rhs_calibration.jl:~560-640).
- No numerical-path change: workspace row count only sets a leading dimension, and the pool, sweep and confirmation changes select among plans that were already bit-identical.

## Residual Risk
Moderate, and mostly about performance policy rather than correctness. The new defaults were chosen from benchmark evidence that is not reproduced in this artifact, and the unmeasured constants (pool row ratio 2, pool shapes 4, regret `min_solves` 3, curve slack 2.0) are assumptions named as such in the source. The integration suites did not run on sf3, so interaction with the legacy suites rests on the unit tests and the contract suite. The region-width default change affects users who relied on it being on under the adaptive policy. The spin-barrier/workspace hang fix is not part of this PR, so that failure mode is unaddressed here.
