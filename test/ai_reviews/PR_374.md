## Findings

Author's notes for the reviewer (no blocking finding known to the author):

- **Note, equivalence:** in SciMLBase 3.57.0 `u_modified!(i::DEIntegrator, bool)` is
  `Base.depwarn(...)` followed by `return derivative_discontinuity!(i, bool)`, and
  neither OrdinaryDiffEqCore 4.18.0, DiffEqBase 7.21.2 nor DiffEqCallbacks 4.19.4
  defines a `u_modified!` method. OrdinaryDiffEqCore's
  `derivative_discontinuity!(::ODEIntegrator, ::Bool)` assigns the integrator's flag.
- **Low, test cost:** the new test starts one child process (about 1.5 minutes
  locally, mostly the child's compilation of its run paths).
- **Note, docs:** the old advice could not be followed with the page's own imports,
  because `OrdinaryDiffEq` exports `derivative_discontinuity!` but not `u_modified!`.

Reviewer to verify:

- **No call is left:** `git grep -n 'u_modified!' -- src docs examples templates ext`
  is empty.
- **The binding in each module:** `SimulationCallbacks` already uses
  `DiffEqBase.derivative_discontinuity!` (`interlink_scheduler.jl`, the control and
  event callbacks); `MissionWorkflow` imports `SciMLBase`.
- **The test discriminates:** with any one of the three `src/` calls restored, the
  child process stops with SciMLBase's deprecation error at that call.

## P1 Assessment

No P1 findings known to the author. The change replaces a deprecated alias with the
