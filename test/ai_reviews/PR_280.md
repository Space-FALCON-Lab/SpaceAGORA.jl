# Compliant multibody naming review

## Scope

Independent review of the naming migration from baseline `d44f06e353d4549f1e02ac28cf8ed2fa205ad835`. The subsystem moves to `src/dynamics/compliant_multibody/` and gains preferred robot-arm and compliant-multibody names. Historical defining modules, types and generic functions remain the same objects so existing calls, downstream methods and serialized owners retain their identities.

The change does not add contact coupling, change scientific settings or alter the separate Basilisk comparison harness.

## Findings

No blocking source finding was identified. An independent parsed-code comparison checked all 15 implementation files, including all four moved files and the robotics owner, against the baseline. Executable syntax is unchanged apart from the 25 intended constant aliases and alias exports, reviewed include paths and diagnostic wording. Root import/export additions were reviewed separately. The versioned HYPR facade, retiming fields, planner identifiers and checkpoint implementation are unchanged.

The public module aliases remain qualified-only. The mode alias remains nested because it is merely `Symbol`, not a new validated type. Documentation explains these boundaries and describes end-effector clearance without implying whole-arm contact validation.

## P1 Assessment

No P1 issue was found within this naming-only scope. Preserving type/function identity and defining owners avoids changing dispatch or state representation. This review is not new scientific validation of the compliant model or MuJoCo contacts.

## Residual Risk

Local tests use Julia 1.12.3 on macOS with existing dependencies. Hosted Linux/native, coverage and optional installation checks remain required on the final published head. No native GRAM data, downloaded MuJoCo engine, long scientific campaign or new dependency installation was used locally.

Two temporary local test-driver defects were corrected without changing repository tests: an isolated module initially lacked an include function, and the later anonymous module was not bound in Main for serialization of test-local closures. Earlier partial logs are retained as failed driver attempts, not counted as completed regression suites. The initial strict docs failure for module aliases was fixed in the public API renderer without weakening documentation checks. The enlarged combined API page exceeded the existing size limit, so its robotics and compliant sections were moved to focused pages through the existing reference-page generator.
