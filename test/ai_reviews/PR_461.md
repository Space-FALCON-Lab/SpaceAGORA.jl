## Findings

No P1 or P2 findings.

Points a reviewer should check:

- **Exact membership.** The old test was `c isa AerobrakingEnergyDepletionControlModel`, a concrete type with no subtypes. The new predicate is `true` by dispatch on that same type and `false` for anything else. For every current model the two agree, including models that share the supertype (`SolarPanelAngleOfAttackControlModel`).
- **The filtered container.** `filter(_is_edg_control, tuple)` returns the same tuple of selected objects as `filter(c -> c isa ..., tuple)`.
- **Load order.** The predicate is declared in GuidanceHooks, which loads first. ControlHooks adds the method when it loads its EDG lifecycle file, once per module world, in the package and in the standalone composition alike. `_edg_preflight` runs at preflight, after both have loaded.
- **The ownership check's reach.** The new check finds every lookup through the parent module:
  - `getfield` or `getproperty` on `_PARENT`, on another name bound to `parentmodule(...)` (such as typed EDG's `_CORE`), or on a `parentmodule(...)` call;
  - dot access through those (`_PARENT.Name`).

  It allows exactly `{typed_edg/guidance_models.jl => [:EDGAlgorithms]}` by name. `_CORE` is only used for `Base.get_extension(_CORE, :SpaceAGORAEDGExt)`, an extension query rather than a module lookup, so it is not counted.
