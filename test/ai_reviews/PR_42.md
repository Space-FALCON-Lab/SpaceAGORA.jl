## Findings

- The diagnostic mode injects flight truth into the replay by construction; it is opt-in, rejected unless `replay_scale_mode = "flight_apoapsis_ratio"` is set explicitly, errors if altitude data are supplied without the mode (prevents silent activation), and is labeled per-row in the summary CSV so downstream consumers can filter it. The benchmark manifest does not enable it.
- Scale factor is clamped to [0.1, 10] and falls back to 1.0 (verbatim replay) on any non-finite or non-positive input, so a malformed manifest degrades to the benchmark behavior rather than amplifying burns unboundedly.
- The altitude→radius conversion uses the equatorial radius on both sides of the ratio; the convention error cancels to first order and is bounded well below the physical effect being measured.
- Registration correction (`epoch_orbit_offset`, `orbit_number_offset`) only relabels the comparison axis and shifts the burn-firing apoapsis index by one; burn Δv values, drop-filter semantics (same five pre-epoch walk-in burns), and dynamics are unchanged.

## P1 Assessment

No P1s. The only behavior change to the default benchmark path is the one-index maneuver-firing correction and the comparison-axis relabel, both validated against the NAV kernel and the PDS accelerometer archive time tags. The diagnostic mode is inert unless explicitly enabled.

## Residual Risk

- The diagnostic scale is evaluated at guidance-command time; the effective value is the last command before the control layer locks the burn plan (first post-exit, pre-apoapsis tick), where the osculating apoapsis differs from the true apo-passage radius only by short-period gravity terms — negligible relative to the flight/sim ratio being corrected, but not identically zero.
- Flight apoapsis altitudes for the diagnostic are scenario data interpolated from the telemetry product; if the telemetry files are regenerated, the manifest values must be refreshed (they live outside the repo's benchmark manifest by design).
- The registration constants encode the mission P-numbering convention; if a future telemetry product renumbers orbits, both offsets must be re-derived together (procedure documented in the lab notes).
