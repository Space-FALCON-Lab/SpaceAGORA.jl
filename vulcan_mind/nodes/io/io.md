# IOConfig — internals

## Purpose
Stands for the `IOConfig` / `IOOutputs` / `IOSerialization` trio on workflow sheets: the code that decides where a run writes results and checkpoints, assembles saved trajectory segments into a results DataFrame and CSV, and writes or restores JLD2 checkpoints atomically so an interrupted campaign can resume.

## Design & Implementation
Members span the path helpers (`_checkpoint_directory`, `_results_csv_path`, `results_bundle_prefix`), the output builders (`_append_saved_segment!`, `_build_results_dataframe`, `_write_results_csv!`, `write_results_bundle!`) and the checkpoint layer (`_atomic_write_file`, `_sha256_hex`, `_load_checkpoint`, `write_checkpoint!`, `_clear_checkpoint!`). On a workflow sheet the block replaces them with one node; calls from the simulation engine arrive on `members_in` and calls out leave on `members_out`.

## Limitations
A readability projection only. Lifted-edge counts on each connection say how many real member calls are summarised; open the `io` module chart to see which member the engine calls. File-system failures inside the block surface as exceptions in the caller, not as a state the block reports.
