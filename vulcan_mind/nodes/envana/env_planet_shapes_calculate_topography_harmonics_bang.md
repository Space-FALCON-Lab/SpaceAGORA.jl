# calculate_topography_harmonics!

## Purpose
`calculate_topography_harmonics!` evaluates a spherical-harmonic topography expansion at one geodetic point and returns the elevation. It is the shared kernel behind the planet-specific wrappers `Mars_elevation!`, `Venus_elevation!`, and `Earth_elevation!` in the same file, each of which supplies coefficients in its own source format before delegating here.

## Theory & Math
The elevation is the truncated sum `h(phi, lambda) = sum_{n=0}^{N} sum_{m=0}^{M} Pbar_{nm}(sin phi) * (C_{nm} cos(m lambda) + S_{nm} sin(m lambda))`, where `phi` is latitude in radians, `lambda` is longitude in radians, `Pbar_{nm}` are fully normalised associated Legendre functions, and `C_{nm}`, `S_{nm}` are the normalised cosine and sine topography coefficients in metres. The sine and cosine of multiples of longitude are generated by the Chebyshev recursion `sin(m lambda) = 2 cos(lambda) sin((m-1) lambda) - sin((m-2) lambda)` and the matching cosine form, which costs two multiply-adds per order instead of a trigonometric call.

## Model & Assumptions
Degree and order are supplied as `topo_degree` and `topo_order`, and the loop bounds become `l = topo_degree + 1` and `m = topo_order + 1` because Julia arrays are one-based. The Legendre values are filled in place by `fnALF_IDR!(Plm, sin(latitude), l, m)`, so the caller must pass a workspace matrix at least `l` by `m`. Coefficient normalisation must match the recursion used by `fnALF_IDR!`; mixing conventions silently scales the result.

## Design & Implementation
Two `MVector` buffers of length `m+1` hold the longitude sines and cosines and are seeded with `cos(0)=1`, then `sin(lambda)` and `cos(lambda)`. The accumulation double loop is annotated `@turbo`, which vectorises the inner product over the coefficient matrices. The function mutates only the caller-supplied `Plm` workspace and returns the scalar `harmonic`.

## Limitations
The stack-allocated `MVector` buffers scale with the requested order, so very high orders raise stack pressure. The Chebyshev recursion for `sin(m lambda)` loses relative accuracy at high `m`. No range check is performed on the coefficient array dimensions against `topo_degree` and `topo_order`, so an undersized array trips a bounds error only when `@turbo` is disabled.
