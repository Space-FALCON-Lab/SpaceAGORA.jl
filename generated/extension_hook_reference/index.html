Extension Hook Reference

Every extension hook SpaceAGORA exports, by family: the function a model, effector, actuator, sensor or algorithm implements for its own type, when the engine calls it, and what happens for a type with no method of its own. Each hook links to its docstring in the API reference, and the last column to the page that explains it. Extensibility shows how the hooks fit together.

This page is generated from docs/extension_hooks.jl, which test/gates/ci_extension_hook_reference_gate.jl checks against the package: every exported hook has a row, each signature is the first line of the hook's docstring, and each fallback agrees with the hook's methods.

The shape is the kind of hook; the Called column says when each one runs.

ShapeKind
T, tickupdates a GNC effector's held state, periodically, for one spacecraft
R, right-hand sidea term of the equations of motion, for one spacecraft
Q, queryanswers an environment query
D, declarationdeclares a property of a model
A, accessorreads a held value for one spacecraft
H, hardwareone actuator's or sensor's physics
P, planner or algorithmproposes, checks or installs a planning product
L, configurationprepares a model or an algorithm for a run

The fallback is what a type with no method of its own gets: none means every type that uses the hook needs its own method; otherwise the fallback returns the value given or throws. The status is current, or deprecated with its replacement and the release that removes it.
