# AI Review — PR #45: earth_gmat epoch correction, speed-channel tolerance tables, surrogate fail-loud

## Scope

Single-commit follow-up to PR #42. Corrects the `earth_gmat` scenario epoch from a VEX-inherited timestamp to the epoch the GMAT truth file itself records in its `DefaultSC.A1ModJulian` column (2014-05-27T05:00:00 UTC), recalibrates the scenario's tolerances at the corrected epoch, adds explicit tolerance tables for the derived speed channels, and makes the Earth offline-surrogate paths honor `gram_offline_surrogate = "off"` end to end — including the library-missing fallback. Quantitative before/after results are recorded in the lab notes (lab members only).

## Changed Files

- `src/analysis/verification/telemetry_verification/manifest_parsing.jl` — `_parse_tolerances` previously read only the scenario's `events` list, so an explicit `peri_speed`/`apo_speed` tolerance table in a manifest was silently ignored and the derived speed rows always inherited the base event's limits (the existing fallback in `_evaluate_thresholds`). Explicit `<event>_speed` tables are now parsed when present, via a small extracted helper (`_parse_event_tolerance`); limits for speed rows are in km/s. Absent tables preserve the inheritance behavior exactly; a malformed explicit table still errors loudly through the same `_require_*` validators.
- `src/analysis/verification/telemetry_verification/scenario_builders.jl` — `_try_libraryless_gram_surrogate` now takes the scenario's `AtmosphereTruthConfig` and returns `nothing` when `gram_offline_surrogate = "off"`, so the library-missing catch in `_make_required_gram_density_model` re-throws instead of silently substituting the frozen-epoch surrogate (previously that fallback was gated only by the `SPACEAGORA_TELEMETRY_ALLOW_GRAM_OFFLINE_NO_LIB` env default; flagged by external review on this PR).
- `test/telemetry_benchmark_manifest.toml` — `earth_gmat` epoch corrected to the truth file's recorded start (provenance comment inline); periapsis full-run tolerances tightened to match the corrected-epoch tracking; apoapsis nmae tightened within the existing envelope; explicit `peri_speed`/`apo_speed` tables added (km/s); `gram_offline_surrogate` `"auto"` → `"off"` (the shipped Earth surrogate is a frozen-epoch grid capped at 300 km that returns zero density above it — a missing native library must fail, not silently degrade); `assumption_id` bumped to `earth_gmat_gram_deterministic_v2`. VEX audited in the same pass: no change needed (epoch matches the ESA flight-dynamics elements source; epoch is the only physically meaningful atmosphere knob Venus-GRAM exposes).
- `test/coverage_parallel_telemetry_probes.jl` — regression testsets for the speed-table parsing (explicit table honored, absent table falls back, malformed table throws) and for the surrogate opt-out (`"off"` blocks the libraryless fallback regardless of the env gate; non-`"off"` proceeds to the file checks).

## Findings

- The epoch value is auditable against the committed truth file (first `A1ModJulian` row, 26804.708739 → 2014-05-27T05:00:00 UTC); the previous value matches the VEX example timestamp, consistent with an inheritance mistake at scenario creation. Grading is elapsed-time-aligned, so the old epoch skewed only Sun/Moon geometry and the epoch-fixed atmosphere date, not the comparison axis.
- The parser change is additive and backward-compatible: manifests without `*_speed` tables parse to an identical tolerance map, and `_evaluate_thresholds`' fallback path is unchanged. The only scenario using the new tables is `earth_gmat`.
- External review (Codex) correctly noted that flipping the manifest key alone did not make the benchmark fail loudly, because the library-missing fallback ignored the key; the scenario_builders.jl change closes that path. With `"off"`, a missing native library now surfaces as the existing `ErrorException` from `_make_required_gram_density_model`.
- Threshold direction is strictly tightening or neutral for every gate (periapsis, apoapsis nmae, speed channels vs their previously-inherited limits at the old epoch); no limit was loosened.

## P1 Assessment

No P1s. The scenario_builders.jl change only removes a silent-degradation path for scenarios that explicitly opt out (`"off"`); `"auto"`/`"on"` scenarios and the env-gate behavior are unchanged. The manifest changes affect only the `earth_gmat` scenario's configuration and gates. The parser change cannot alter any existing manifest's parsed tolerances unless it already contained (previously ignored) `*_speed` tables — the shipped manifest gains them intentionally.

## Tests Added/Updated

- `test/coverage_parallel_telemetry_probes.jl`: new "Speed-event tolerance tables" testset — explicit `apo_speed` table parsed alongside base events, absent `peri_speed` table stays absent (fallback preserved), base-event values and `max_rmse_km = Inf` default intact, malformed explicit speed table throws `ArgumentError`; new "Libraryless surrogate honors off" testset — `_try_libraryless_gram_surrogate` returns `nothing` for `gram_offline_surrogate = "off"` with the env gate forced on, and proceeds past the opt-out for `"auto"`. Full probes file green; full-profile telemetry study passes `--enforce=true` end to end for all three scenarios at the new thresholds.

## Residual Risk

- The corrected-epoch thresholds are calibrated on one platform (local arm64); CI (x86_64) numbers may differ in the tails, as measured for the Odyssey sentinel. Headroom of roughly 3–4× over observed errors was left on every tightened gate; if CI's telemetry runs land outside them, the envelope gets the same platform-robust treatment the Odyssey gates received.
- The GMAT reference's own space-weather assumptions remain unrecorded upstream, and EarthGRAM's F10.7/ap inputs are not currently settable through GRAMSuite (dead wrapper hook), so the apoapsis channel keeps a structural truth-side bias; documented in the lab notes with the plumbing follow-up.
- Quick-profile tolerances were left untouched pending a CI quick-mode measurement at the new epoch.
