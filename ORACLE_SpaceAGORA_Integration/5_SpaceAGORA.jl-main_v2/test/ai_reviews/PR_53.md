# AI Review — PR 53: Restore the published CYGNSS IC recipe in the 48-hr reference builder (+pin)

## Scope
Replication-gap fix found by running the shipped CYGNSS entry point on fresh main with the private data: `_build_cygnss_48hr_reference` fed the raw first-sample GPS state as the initial condition, omitting the published N=5 vis-viva SMA-averaged velocity-scale step (which lived only in the study script on the `parllelization_paper` branch). The single-sample state carries ~63 m of SMA noise (~3.5 cm/s velocity noise), which drifts ~18 km along-track over 48 h — the entry point silently produced 6.21 km instead of the published 1.578 km while every assertion stayed green.

## Changed Files
- `test/gmat_scenario_matrix.jl`

## Findings
- P2 (fixed): the merged reference builder dropped the published IC recipe during the study extraction; restored (5-sample vis-viva SMA average, first-sample velocity direction rescaled to that energy) with a comment explaining the noise arithmetic.
- P2 (fixed): the entry-point testset asserted only `pos_rmse < 1e4`, so a 4× regression of the published number was invisible. The published baseline is now pinned: `abs(pos_rmse - 1.5777551) < 0.005`.
- P3 (accepted): the 96-hr builders are unchanged — the cyg04 builder already sources its IC from the 48-hr product for the documented energy-accuracy reason, and no published pin exists for the 96-hr numbers.
- P3 (pre-existing, out of scope): the "GMAT Early vs Full Error" / "STK Strict Acceptance" testsets assert the presence of Mars/Moon harmonics files (`GGM2B.csv`, `LP165P.csv`) that are not distributed with the repo, so the file cannot run clean on a fresh clone; tracked separately.

## Residual Risk
- The pin tolerance (5 m) is far above cross-machine floating-point spread (mm-level observed) and far below the failure mode it guards against (km-level IC regressions).
- The recipe intentionally matches the published paper lineage; a future arc-fit IC would supersede it and must update the pin deliberately.
