# Review record: PR 406: rename RobotArmReactionEffector.spacecraft_idx to spacecraft_index

## Scope

Review of the `robot-arm-reaction-index-name` branch (commit `bf4f2857c`) against
main `f31cb6bbb`: `git diff origin/main...robot-arm-reaction-index-name`, one
commit. Main has since taken #403 (the 0.3.0 release: version fields, a few
documentation lines and one record), which touches none of these files;
`git merge-tree` merges the branch with main `14174a682` without conflict.

#390 renamed the GNC models' index fields to `spacecraft_index`, `chaser_index`
and `target_index`, and left `RobotArmReactionEffector.spacecraft_idx` as an open
question. Giusy decided on 2026-10-18 that it follows. This PR:
- renames the field and keyword to `spacecraft_index`, with the pattern of #390:
  a written-out keyword constructor that also accepts `spacecraft_idx`, and
  `@inline` `getproperty`/`setproperty!` forwarding of the old name, both through
  `_renamed_keyword`/`_renamed_field_warning` (`:depwarn` group, once per type and
  name, an error under `--depwarn=error`), removed in 0.5.0;
- keeps `hasproperty(effector, :spacecraft_idx)` false, so the engine's
  duck-typed index reads never warn, and keeps those reads accepting
  `spacecraft_idx` on contributor models;
- updates the docstring, the comments on the engine's and the viewer's fallback
  reads of the old name, the migration page and the conventions page. The change
  lands after the 0.3.0 release, so the docs say its warning starts in 0.4.0.

Authorship disclosure: the author of the PR drafted this record. It lists what the
author checked and what the independent reviewer must verify; it does not replace
that review.

Independent review: the coordinator reviewed the change under Giusy's delegation on
2026-10-18. It follows #390's pattern. Every keyword default equals the former
`@kwdef` default, `hasproperty(m, :spacecraft_idx)` stays false, and no built-in code
reads the old name on this type (a `git grep` over `src/` and `examples/` finds only
the forwarding and the engine's reads for contributor models). The engine finds the
effector through `_effector_spacecraft_index`, which reads the new field first.

## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- **Low, structure:** the type loses `Base.@kwdef` for a written-out keyword
  constructor, as the four types of #390 did. The defaults now live in the
  constructor; a test compares each with its former value, including a fresh
  `joint_actuators` vector per call.
- **Low, timing:** the old name starts warning in 0.4.0 and is removed in 0.5.0
  with the others, so it gets one tagged release of warnings, the minimum the
  migration page's schedule asks for.
- **Note:** the effector's `wrench` still returns zero force and torque (a
  placeholder, unchanged); the field matters for the arm coupling, which finds
  the effector through `_effector_spacecraft_index`.

Reviewer to verify:

- Every default in the keyword constructor equals the former `@kwdef` default.
- No built-in code path reads `spacecraft_idx` on this type, so no warning can
  come from the right-hand side or the setup checks.
- `getproperty` with a literal field name folds to `getfield` (the forwarding
  branch is `@inline` and constant), as for the types of #390.
- The parity evidence: runs with the effector are bitwise identical to main.

## P1 Assessment

No P1 findings known to the author. The parity probe builds the same
configurations on main `f31cb6bbb` and on the branch, choosing the index keyword by
the field each tree has, and hashes the raw bits of `sol.t` and `sol.u` (each
Float64 as a plain UInt64 word, streamed into SHA-256). The hashes are identical
for:
- one spacecraft carrying the effector;
- two spacecraft with different arms (different stiffnesses), the effector for
  spacecraft 2 listed first, so a lost or ignored index would couple the wrong arm.

Controls: the arms swapped between the spacecraft give a different hash, the same
one on both trees; each case run twice per tree gives the same hash; on both trees
`_robot_arm_coupling` gives each spacecraft its own arm's stiffness; the branch run
under `--depwarn=error` gives the same hashes, and no run logged a rename warning.
