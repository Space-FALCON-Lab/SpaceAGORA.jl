# Optional KS propagation route: review record

## Scope

An experimental, optional solver mode `:ks` for one rigid spacecraft, provided by an extension that loads only when the separate KSPropagator package is present. SpaceAGORA keeps the configured Cartesian force, heating and mass-flow right-hand side, physical time, events, controls, checkpoints and outputs; the package owns the coordinate transformation and the stepping. Stacked on the checkpoint table cadence repair. No change to the other solver modes, to any force model or to any release.

## Findings

Core supplies the configured total Cartesian right-hand side; exactly one applicable inverse-square (or J2) central model is removed once and represented in KS coordinates. Mass and heating share the nonlinear stage and the component-wise error decision. Trial evaluations refresh the state-dependent atmosphere stamps, and a model joins the route only by declaring `trial_rhs_safe`, which is an interface contract, not validation. Endpoint clocks are physical, Cartesian resets are canonical, a typed nonlinear failure forces a step rejection, and dense output keeps the pre-event interval payload. The admission check runs after effector scopes and spacecraft-declared control models are resolved, so scoped and mounted configurations are seen as the run will see them; the runtime checks also require that no per-run density model instances exist, which the admitted analytic atmospheres never create. The cache-type check in the solver policy cannot change any existing mode, because every route hands a fixed algorithm type to a given cache.

## P1 Assessment

No P1. The other solver modes take the same code paths as before; the new mode refuses every configuration outside its contract before setup and refuses to run without the package. Against the Cartesian reference, only the finest tolerance settings met the accuracy target in the tested one-day cases, and the coarser settings did not; this is recorded as the route's qualified scope, not hidden by retuning. The extension's use of the solver library's integrator interface was checked against the pinned library source. CI never compiles the extension, so that check is repeated by hand on every solver-library update.

## Tests Added/Updated

test/unit/simulation/ks_solver_admission_tests.jl exercises the core-side admission boundary (one refusal per rule), the optional-package refusal, the runtime checks and the trial right-hand side without the extension, so the engine file is covered in ordinary CI where the package is absent. The solver-configuration validation tests cover the mode name. The extension's own checks (force parity, dense history, lifecycle replays, resume prefixes and the baseline accuracy matrix) run outside CI with the package installed; their scripts and records are kept with the lab notes.

## Residual Risk

Accuracy is sampled and case-specific; there is no uniform continuous validity claim. The route's run time was much longer than the ordinary solvers' in the two-body comparison, and its timing with J2 and drag was not resolved; it stays experimental while that cost is investigated. Attitude, articulation, mounted systems, interlinks, external propagation, history-dependent atmospheres, multiple spacecraft and the TrajectoryRecorder cadence are outside admission. The extension is not compiled in CI.
