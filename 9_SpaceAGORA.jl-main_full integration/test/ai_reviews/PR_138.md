## Findings

The prior wrapper delegated deepcopy and serialization to its native core. The installed wrapper reconstructs that core from paths, planet and date, omitting custom perturbation/Mars options. A real construction probe reproduced the lost customization markers on both paths. Keyword construction now owns a recipe independent of caller inputs and passes a separate copy to the native constructor. Reconstruction preserves that recipe and uses fresh handles and locks. A copied container preserves repeated references to the same wrapper. The exposed `constructor_kwargs` dictionary is live reconstruction metadata, not an immutable snapshot: callers should treat it as read-only. Mutating it changes future copies/transfers without reconfiguring the current native instance; use `deepcopy(model.constructor_kwargs)` before deriving a new constructor recipe.

An unknown raw-core recipe is represented by `nothing`, distinct from known default keyword construction. Raw-core signatures and fallback behavior remain unchanged; missing options cannot be recovered from that core. Surrogate wrapping retains its configured filename and fallback threshold. This does not establish evaluation of an arbitrary surrogate file with unsupported settings.

The tagged serializer sends known construction options rather than the native core. It also accepts the previous core-only payload when that payload is decoded, without promising cross-version Julia Serialization compatibility. Explicit library paths are resolved; omitted library paths still use environment-influenced discovery, including `GRAM_LIB`.
