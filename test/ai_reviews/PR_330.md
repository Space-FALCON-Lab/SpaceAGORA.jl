# PR review: remove spacecraft structure helpers that fail on the current SpacecraftModel

## Scope

Review of PR 330 (SpaceAGORA branch `remove-broken-structure-helpers`, head
`f66bb1950`) against main (`980b35eda`). The PR deletes 13 helper methods
of `SimulationModel.Structure` that cannot run on the current
`SpacecraftModel`, deletes the file that held
`traverse_bodies`, and updates the two gates and the topology contract that
named them.

Authorship disclosure: this record was drafted by the author of the PR. It
does not replace an independent review.

The defect: since d9fe31081 (2026-02-10) `SpacecraftModel` has one
`root::Link` and one `inertia_tensor`. The removed methods read the old
`roots` or `inertia_tensors` fields, call `traverse_bodies` (which reads
`roots`), index `prop_mass` per root, or call `hat`, which the `Structure`
module has never imported (it was created in 21a308695 without that import).

## Changed Files

- `src/models/vehicle/structure/assembly_graph.jl`: deleted
  (`traverse_bodies`).
- `src/models/vehicle/structure/mass_properties.jl`: removes
  `update_inertia_tensor!`, `update_inertia_tensor`,
  `get_inertia_tensor(model, root_index)`, `set_inertia_tensor!` and the three
  `get_spacecraft_mass` methods. `get_COM` and `get_inertia_tensor(model)`
  stay.
- `src/models/vehicle/structure/geometry_properties.jl`: removes the
  `(model)` and `(model, body)` methods of `get_spacecraft_reference_area`,
  `get_spacecraft_length`, and the `(model, body)` methods of `get_SA_area`
  and `get_SC_area`. The `Vector{Link}` methods, `get_normal_vector` and
  `get_tangent_vector` stay.
- `src/models/vehicle/structure/structure_models.jl`: drops the include of
  `assembly_graph.jl` and six names from the export list.
- `test/gates/ci_vehicle_structure_boundary_gate.jl`,
  `test/gates/ci_architecture_contract_gate.jl` and
  `docs/architecture/canonical_topology_contract.md`: no longer require the
  deleted file or the removed names.

## Findings

No P1 or P2 findings.

Points a reviewer should check:
- Reachability. No caller in `ext/`, `examples/`, `docs/`, `benchmarks/` or
  the tests; none in the companion packages at their pinned revisions
  (SpaceAGORAEDG `d050ee88`, HYPR `80a4f53a`, SpaceAGORAMuJoCo `3f2845b0`,
  SpaceAGORAVisualizer `6c008074`). The names were exported from
  `SpaceAGORA.SimulationModel` only; `docs/public_api_symbols.jl` does not
  list them.
- Low, by design: retained legacy code still names removed helpers and is
  not changed. That code is the legacy aerobraking bridge
  (`heat_rate_models.jl:3-5`, `closed_form_solution.jl:156`,
  `tracking_executor.jl:36` and `:247-254`, `control_commands.jl:85`, `:95`,
  `:315-316`) and `scripts/plotting/plot_data.jl:100` and `:341`. Each line
  already failed on main at the same call or earlier:
  - `.roots` is read first at `tracking_executor.jl:247`,
    `closed_form_solution.jl:156`, `heat_rate_models.jl:3` and both
    `plot_data.jl` lines.
  - `asim_ctrl` raises `MethodError` at `control_commands.jl:50`
    (alpha-first `aerodynamic_coefficient_fM`) before lines 85-316 of the
    same function can run.
  - The bridge needs a mission object with `body`, `planet` and
    `aerodynamics`. The only type with `body::SpacecraftModel` is the unused
    legacy `Model` (`runtime_types.jl`), which has no `planet` and is never
    constructed. Tests reach the bridge only with `mission=nothing` or
    fixtures.

  The error type changes (`UndefVarError` or `MethodError` instead of
  `FieldError`); reachability does not.
- Low: `get_spacecraft_mass(model, bodies, 1)` returned a value on main,
  because indexing the scalar `prop_mass` at 1 returns it; index 2 threw
  `BoundsError`. Its `root_index` argument only ever came from
  `traverse_bodies`, and its only `src` caller follows a `traverse_bodies`
  call.
- Low, unchanged: the docstrings of the kept `get_COM(model)` and
  `get_inertia_tensor(model)` still show a `body::Link` argument the methods
  never took.

## P1 Assessment

No P1 findings. The PR only deletes methods that throw on every valid input,
apart from the one method above that returns a value only when called by
hand with root index 1. No simulation path, saved result, mass or inertia
value changes. The inertia the engine integrates (`inertia_tensor` in the
rigid path, link inertias in the articulated path) and the joint handling
are untouched. Proposals on those are in the PR text for a separate
decision.

## Tests Added/Updated

No runtime tests added: the removed code had no tests and no reachable
caller.

Evidence on the branch:
- `test/contracts/pr_runtests.jl`: all 31 gates pass, including the updated
  vehicle-structure boundary and architecture contract gates and the P1
  findings gate. `test/unit/gates/local_gate_controls_tests.jl`: 49 of 49
  pass.
- Suites 01 and 05, plus the unit files

  `dynamics/mesh_aero_tests.jl`, `gnc/rpo_configurable_station_tests.jl`,
  `visualization/viewer_bundle_tests.jl` and
  `visualization/articulation_tests.jl`, pass with the EDG companion loaded.
  Suite 05 includes Aqua's undefined-exports check on `SimulationModel`.

  `SpacecraftModel` and called every removed method on a valid two-link
  spacecraft. Each one throws, except
  `get_spacecraft_mass(model, bodies, 1)` as noted above.
- The kept helpers return the expected values on `make_three_body_spacecraft`.

## Residual Risk

- Code outside this repository and its companions that called a removed
  helper gets `UndefVarError` or `MethodError` instead of `FieldError`. It
  could not have run before either.
- The legacy aerobraking bridge and `plot_data.jl` still name removed
  helpers. The bridge is to be deleted in a separate removal PR, now that the
  EDG companion is the single EDG implementation; `plot_data.jl` stays
  retained pending its own capability review.
- The docs site was not built locally; CI builds it. No documentation page
  referenced the removed helpers.
