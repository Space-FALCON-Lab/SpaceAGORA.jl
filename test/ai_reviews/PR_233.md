# AI Review Artifact — PR #233

## Scope
Articulated spacecraft. `Joint` gains `:hinge`, `:slide` and `:ball` types with joint-space stiffness, damping, rest and initial coordinates. A spacecraft with any non-fixed joint is integrated as a tree in joint coordinates on a free-floating base; spacecraft whose joints are all `:fixed` are unchanged.

## Changed Files
- src/vehicle/spacecraft/model.jl — `Joint` type fields, validation and keywords on every constructor (existing constructors produce `:fixed`).
- src/dynamics/coupled/articulated_body.jl — new `ArticulatedBody` module:
  - tree build, merging fixed joints and validating tree shape and joint-point coincidence
  - composite-rigid-body mass matrix, bias terms and an in-place Cholesky
  - forward kinematics and link poses
  - ball-joint quaternion rates
  - runtime workspace
- src/core/simulation_model.jl, src/core/types/runtime_types.jl — module wiring; per-satellite `articulated_runtimes` plus a run-constant `articulated_present` flag in the shared buffers.
- src/simulation/engine/dynamics_rhs.jl:
  - articulated RHS path at the serial and batch sites
  - gravity-only effector sum evaluated per body
  - non-gravity effector tuple filtered at compile time
  - state shape and initialization of `joint_q`/`joint_qd`
- src/simulation/engine/setup.jl — setup validation and guards, plus runtime initialization.
- src/simulation/engine/execution.jl — calls to the validator and initializer.
- src/simulation/engine/solver_policy.jl, src/simulation/callbacks/density_callbacks/assembly.jl — tolerances for the joint state (reuse the attitude tolerances).
- src/simulation/callbacks/event_callbacks.jl — ball-joint quaternions are projected in the existing per-step projection callback.
- src/simulation/callbacks/save_fields.jl, src/simulation/callbacks/registry.jl — default save fields `joint_q`, `joint_qd`, `articulated_link_pose` and `system_com` for articulated spacecraft.

## Findings
- P3 (reviewed): the rigid path adds one cached boolean load per RHS call. Bit identity was checked base-vs-candidate on 25 examples with byte-identical result CSVs; all 30 exit 0 on both.
- P3 (reviewed): the articulated path filters the gravity effectors out of the tuple passed to `_accumulate_dynamic_effectors!`. `effector_decision` holds only threading flags and an allotment, nothing indexed per effector, so filtering is safe. The only side effect is the effector cost model seeing the shorter effector count in articulated runs.
- P3 (reviewed): each satellite's workspace is touched only while that satellite is evaluated, because the serial and `@batch` loops partition by satellite.
- P3 (documented limits):
  - mixed rigid and articulated runs are refused
  - third-body gravity acts at the root with total mass
  - a gravity-gradient torque effector uses `inertia_tensor`
  - the harmonics gravity hook allocates per call
  - the viewer still draws configured rigid poses
- P3 (process): the first remote verification failed for environment reasons. The push script's copy excludes tracked `data/` files and is not a git repository. Re-verified from an exact `git archive` of the commit.
