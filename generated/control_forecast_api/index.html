Control Forecast API

This page documents the supported public interface available from SpaceAGORA.

Control Forecasts

SpaceAGORA.SimulationEngine.ControlForecastSnapshot — Type
ControlForecastSnapshot

A copy-owned restart of one spacecraft immediately before its sole periodic controller applies a command. Created by capture_control_forecast. The snapshot contains configuration and plain checkpoint state, not an integrator, a borrowed parameter bundle, a worker, or previous output rows.

source
SpaceAGORA.SimulationEngine.capture_control_forecast — Function
capture_control_forecast(u, p, t, controller) -> ControlForecastSnapshot

Capture a forecast at the beginning of the sole controller's update_control!, before it changes its command, plan, phase, panel geometry or histories. This initial interface supports one spacecraft and one periodic controller, with no linked producers, navigation, guidance, mounted devices, or attitude dynamics. Unsupported models fail before copying state. The controller must expose its previous command time through held_command_time and implement checkpoint hooks.

The current control tick is still pending in the forecast, although core has already advanced its clock index before entering update_control!. This is a pre-command forecast boundary, not a general way to write a checkpoint midway through arbitrary callback code. The caller must not have partially updated its controller. Both the absolute simulation time and original ephemeris epoch are preserved. Evaluate the snapshot only in a separate process.

SPICE forecasts require directly loaded, unchanged kernel files. Meta-kernels and programmatic kernel-pool assignments are unsupported. Scoped engine overrides are rejected; resolved solver settings and SPACEAGORA environment values are frozen. Controller state must contain ordinary data, without closures, remote references or other live runtime handles.

source
SpaceAGORA.SimulationEngine.run_control_forecast — Function
run_control_forecast(snapshot, candidate; duration_s, sample_period_s)

Evaluate a copied candidate controller from a pre-command snapshot in a dedicated forecast process, preferably created by with_control_forecast_worker. Do not run unrelated simulations in that process. Forecast calls are serialized there because SPICE owns process-wide state. Nested forecasts are rejected. The candidate replaces the snapshot's sole controller and must preserve its own state through checkpoint hooks. It must keep the intended plan fixed rather than recursively invoking this service. Its spacecraft scope and control period must match the snapshot. Candidate constraints and failure policies remain the caller's responsibility.

Returns copied saved rows, the final state/time and solver return code. It returns no integrator or live runtime handles and writes no results or checkpoint files. The saved time coordinate remains the original run's absolute elapsed time.

source
SpaceAGORA.SimulationEngine.with_control_forecast_worker — Function
with_control_forecast_worker(f, snapshot; packages=())

Run f(evaluate) with a dedicated local Julia worker, where evaluate(candidate; duration_s, sample_period_s) calls run_control_forecast. The worker uses the current Julia/project and is removed on success or failure. packages contains the Base.PkgIds of companion packages defining candidate controllers; core is loaded automatically. No existing worker is adopted.
