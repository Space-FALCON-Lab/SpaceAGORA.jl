# Review record: PR 387: build the planet-frame reuse key from the whole ephemerides cache key

## Scope

Review of the `ephemerides-reuse-key` branch (head `aff169676`, one commit)
against main `9ea941a1c` (the merge of #373): `git diff main...ephemerides-reuse-key`.

The planet-frame cache built at the start of a run is kept for later runs in a
shared reuse store. Its key holds the planet, a string for the ephemerides model,
the planet's transform constants and the run's span. The model's string came from
`_ephemerides_model_reuse_key`, which read `ephemerides_cache_key(model)`: `"spice"`
for `(:spice,)`, and otherwise `"simple:<2nd>:<3rd>"`. The cache and its reuse are
on by default, so every run builds this string at setup. Two consequences for an
ephemerides model of your own:
- a key with one or two elements, such as `(:mine,)` or `(:mine, 1)`, stopped the
  run at setup with a `BoundsError`;
- two models whose keys differ only in the first element (the tag) shared one
  cache, so the second model's run read the first model's planet frames. This
  includes a model of your own whose key is `(:other, e, p)` with the default
  `SimpleEphemeridesModel`'s `e` and `p`: it got the string
  `"simple:0:-9223372036854775808"` and read the simple model's cache.

The PR keeps the built-in strings and writes any other key whole. The contract it
establishes: `ephemerides_cache_key(model)` may be any tuple, of any length, with
its first element naming the model or backend; the whole tuple is the reuse key,
so a cache is reused only between models whose keys are equal, and models with
equal keys must give the same frames and times.

Authorship disclosure: the author of the PR drafted this record. It lists what the
author checked and what the independent reviewer must verify; it does not replace
that review. This record was reviewed under Giusy's delegation on 2026-10-17.

## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- **Low, by design: what "equal keys" means for a key of your own.** Two keys of
  your own share a cache when they print the same. For symbols, strings, integers,
  floats and tuples of them, printing the same means being equal. Keys that are
  equal but print differently, such as `1` and `1.0`, get separate caches: a
  rebuild, never a wrong frame. A type whose `show` prints two different values
  alike would share. On main `ephemerides_cache_key` has no docstring; #385
  documents it as a tuple. Keys made of symbols, numbers and strings, like the
  built-in ones, cannot run into this.
- **Low, by design: a key of your own equal to a built-in key** (`(:spice,)`, or
  `(:simple, e, p)` with `Int64` elements) shares the built-in model's cache. This
  is the contract: models with equal keys must give the same frames and times.
- **Low, scope: only the planet-frame cache depends on the ephemerides model.**
  The SRP Sun cache and the N-body ephemeris cache are always built from SPICE.
  Their keys (primary body, body names, span) rightly leave out the model, and
  they are unchanged.
- **Note, not changed: the harmonics planet-frame memo.** `_harmonics_lpi_cache_key`
  in
  `src/models/dynamics/effectors/perturbations/gravity/models_and_workspaces.jl`
  already holds the whole key tuple in a `Ref{Any}`, so keys of any length work
  there. It compares with `==`, so a key that holds `missing` would raise there,
  and a key that holds `NaN` would never match, which costs one frame lookup per
  evaluation. Neither happens with the built-in keys. Candidate follow-up: compare
  with `isequal`.
- **Note, overlap with #385 (ephemerides hooks model first).** `git merge-tree` is
  clean. The new test's model implements `planet_frame_lpi`,
  `ephemerides_sun_direction_ii` and `ephemerides_time_seconds` under main's
  names. On the merged tree (with #385's head `1249ec0e1`) the test passes, 47 of
  47, with deprecation warnings for the old names. The deprecated-hook gate scans `src/`, `templates/` and
  `examples/`, not `test/`. Whichever of this PR and #385 merges second renames
  the three methods and one call in the new file. With that rename the file
  passes on the merged tree, 47 of 47, under `--depwarn=error`.

## Tests Added/Updated

- `test/unit/simulation/ephemerides_reuse_key_tests.jl` (new, 47 checks in five
  testsets). Its model answers from the analytic model under a key of its own and
  can turn the planet frame about the pole, so two models can share a key's tail
  and still give different frames.
  - Built-in keys keep their strings: `"spice"`,
    `"simple:0:-9223372036854775808"` for the default `SimpleEphemeridesModel`,
    `"simple:1500000:250000000000"` for an explicit epoch and prime meridian. A
    key of your own equal to a built-in one gives the built-in string.
  - Keys of your own: one, two and five elements, the empty tuple and
    `(missing,)` each give their printed form. Keys that differ only in the tag
    give different strings, and `(:other, e, p)` with the default simple model's
    `e` and `p` does not give the simple model's string. Twelve distinct keys

    `("simple", e, p)`, a four-element `:simple` key, short keys and keys with
    `":"` inside) give twelve distinct strings. Two `:simple`-tagged
    three-element keys with string elements do not run together. No such key
