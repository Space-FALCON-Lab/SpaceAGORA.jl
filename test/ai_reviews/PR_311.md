## Findings

The five source edits touch only the module header docstring of each file; a line-level diff of every `src/**/*.jl` file against main shows no changed line outside those docstrings, and the only other change under `src/` is a retargeted link in `src/models/gnc/README.md`. Each replacement matches exactly once and keeps the description words in place. The exported RPO and asset docstrings remain in the generated API pages, and the strict build reports that all generated public API symbols have docstrings. The earlier alternative, adding these modules to the ignored-module list, was rejected by execution because it hid root-reexported public RPO docstrings; the delivered change does not use it.

The published tree retains the supported API policy, the adapter contract, the EDG adapter boundary, the external propagation services, the HYPR services page and a user-facing RPO planner contract. The contributor material that left the published tree is present under `docs/contributing/` with rebased links; no contract body was dropped.

The outputs page previously said smoke runs ignore the selected output directory while the quickstart said they honor it. The implementation honors it: an independent command-line walkthrough ran two smoke cases into chosen directories and found every result in the selected directory, with the first run preserved. The corrected page matches that behavior.

The two removed files have no tracked build, apply or include consumer in the tree. The study scripts next to them and the installed native libraries are unchanged. The files remain in history.

No P1 or P2 finding. One low observation: the configuration prose still does not name the nested field path to the inclination of a returned configuration, and the public DynamicsModel docstring keeps an older "Roots" sentence; both predate this change and are left for the owner.

## Follow-up: published content corrections

A fresh-context content read of the two rewritten pages against the pre-split
pages and the code found one regression and several thinner spots, all
corrected on the same branch without touching `src/`:

- `docs/src/reference/rpo_planner_contract.md`: a new "Built-in planners"
  section restores the published behavior of `DirectRPOPlanner` (duration rule,
  analytic maxima, clearance query) and `HYPRRPOPlanner` (explicit mapping,
  headroom caps, the requirement that a requested acceleration limit be paired
  with the acceleration-limited retimer, `rrt_on_replan`) and the outcome
  symbols both planners report. These sentences had moved to the unpublished
  contributor record while the pilot guide's default example still needed them:
  `RPOPSOConfig` defaults `retime_accel_limit_enable` to `false` and the default
  `make_rpo_configuration` constraints include an acceleration limit, which the
  adapter test pins as `:acceleration_limited_retimer_required`. The extension
  paragraph now marks `initialize_planner` optional, matching the code default.
- `docs/src/user/rpo_planner_pilot.md`: one sentence beside the default
  `HYPRRPOPlanner(RPOPSOConfig())` example pointing at that requirement.
- `docs/src/user/architecture.md`: "HYPR owns motion-planning implementations"
  reworded, since the contract, the direct baseline and the shared path geometry
  live in SpaceAGORA; one closing paragraph points users who outgrow the guide
  at `CONTRIBUTING.md`.
- `docs/src/user/concepts.md`: stale reference to maintainer-only documents
  reworded.
- `docs/contributing/rpo_planner_development.md`,
  `docs/contributing/architecture.md`: dead `@docs` blocks for the five modules
  whose header docstrings became comments replaced by those one-line
  descriptions.
