# AI Review — PR #581: Precompile an Earth/J2/NoAtmosphere workload

## Scope

The precompile workload ran only the Mars default (exponential atmosphere, inverse-square gravity), so the first `run_simulation` of an Earth case, including the `AGORA_Basic_Quickstart` configuration, compiled for about 10 s in every fresh process. The workload now also runs Earth with J2 and no atmosphere, once with `results=false` and once with `results=true`. The Mars default is unchanged. No runtime code path changes; only what is compiled at precompile time.

## Changed Files

- `src/precompile_workload.jl` — `_spaceagora_precompile_args` takes `planet`, `dynamic_effectors`, `density_model`, `results` and `results_directory` as keywords (defaults reproduce the old Mars configuration). `_run_spaceagora_precompile_workload` runs three configurations in order (Mars default, Earth/J2/NoAtmosphere without results, the same with results written to the workload's tempdir).

## Findings

- P3 — Earth results are not bit-identical to the previous main, because Earth-typed methods now run from the pkgimage instead of JIT-compiled code. Measured on one process per arm and duration, Earth/J2/NoAtmosphere: final-state position differs by 3.9e-4 m at 30 d, 1.5e-3 m at 90 d, 4.3e-4 m at 180 d and 4.7e-3 m at 365 d (relative 6.5e-11 to 8.6e-10, roughly linear growth). Running with `--pkgimages=no` reproduces the previous results exactly. Mars is bit-identical. Specific energy and angular momentum drift identically in both arms.
- P3 — Cold precompile of SpaceAGORA is about 6 s longer (58.9 s to 64.5 s, one run each). `using SpaceAGORA` time is unchanged (4.203 s and 4.199 s median of 3).
- P3 — Warm Earth runs were about 9% slower in all three process pairs (median 0.957 s to 1.044 s for a 30-day mission), which is consistent with pkgimage code being slower than JIT code here. Warm run times are bimodal in both arms, so this rests on the lower mode.
- No P1 or P2 issues found. `Earth()` (the keyword constructor) furnishes no SPICE kernel and fills no planet cache, so `_reset_furnished_kernels!` and `_reset_process_local_state!` have nothing extra to undo.

## P1 Assessment

No P1. The change adds compile-time coverage only, does not alter any simulation algorithm, and does not touch the modules the contract gates guard. The one observable difference is the last-digit change in Earth results described above, bounded by the measurements listed in Findings.

## Tests Added/Updated

No new tests. The workload itself is exercised by every precompile. The Precompilation Contract in the integration suite passed 25/25 on the earlier base `9fc7e8791`; the A/B measurements above were taken on `3ef2ed2e2` (median of 3 fresh processes: first Earth `run_simulation` 9.71 s to 0.14 s, quickstart wall time 25.74 s to 16.86 s, first Mars call unchanged at 0.052 s).

## Residual Risk

- Users who compare Earth results against numbers produced before this change will see last-digit differences of the size listed above.
- The 9% warm slowdown is not isolated further; the cause (pkgimage versus JIT code generation for Earth-typed methods) is the likely explanation but is not tested beyond the `--pkgimages=no` reproduction.
- The +6 s cold precompile applies once per source change and is paid by CI and fresh worktrees.
