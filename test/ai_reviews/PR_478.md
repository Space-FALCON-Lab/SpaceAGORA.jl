# Review record: PR 478: interlink scheduling policies as types

## Scope

Review of the SpaceAGORA `typed-scheduling-policies` branch against main
(2088b4408: v0.5.1, with #465, #468, #469 and #470). The branch was cut from
main 51ef1bce5, merged main once v0.5.1 was released, and merged main
04c14ae3f (#477 and #484), then 60c117c9d (#485, #481 and #476), then
d38ed88d9 (#491, #479 and #482), and then 81431249c (#475 and #493) after the
in-house review.
- Plan: "Constellations and interlinks: implementation plan" (2026-10-19), I-5.

- Decisions D-I5-1 to D-I5-9, accepted by Giusy on 2026-10-21. D-I5-6 removes
  the symbol forms without a deprecation period, so this PR is breaking for
  scripts that use them and is for 0.6.0.

What it does:
- Scheduling policies as types: `AbstractSchedulingPolicy`, the hook
  `candidate_score(policy, candidate::LinkCandidate, ctx::SchedulingContext, t::Float64)`,
  and a setup check that the run's policy has a method.
- The five symbol forms as four typed built-ins: `SemimajorAxisRatePolicy`
  (`:gve_sma`, `:gve_sma_first_index`), `EccentricityRatePolicy`,
  `PowerDeliveryPolicy` and `DataThroughputPolicy`.
- `SchedulingPolicyModel(policy)`, the scheduler, holding the policy
  (`objective`) and the matching workspace; `scheduling_policy_model=` also
  takes a policy alone.
- The symbol constructor refused with an `ArgumentError` naming the typed
  replacement; the `policy`, `target_index`, `target_indices`, `target_idx` and
  `target_idxs` properties removed.
- The checkpoint entry of a policy: the built-ins as 0.5 wrote their symbol
  forms, other policies by kind and every field, and recorded symbols rebuilt
  as typed policies when a checkpoint is read.

Rule: runs moved to the typed policies are bitwise identical to the same runs
with the symbol forms on main.

- **The refusal.** `SchedulingPolicyModel(::Symbol; kwargs...)` only throws. Its
  `ArgumentError` repeats the call as given and names the typed call that
  replaces it, targets included when the call gave any. An unknown symbol is
  refused with the list of policy types. Other keywords are named as having no
  replacement. The removed properties end in a plain `FieldError`, as the record
  says, not in a message naming `objective`. (Corrected after the in-house
  review: Julia 1.12's `FieldError` does list `objective` among the type's
  fields. Since cf30d1f8f a removed property throws an `ArgumentError` that
  names `.objective` or `.objective.targets`.)
- **Setup checks.** `_validate_interlinks!` checks that the policy's concrete type
  has a `candidate_score` method before anything is scored. A checkpointed run
  also builds its policy's checkpoint entry there, so a closure capturing a
  reassigned variable (`Core.Box`) or a self-containing payload is refused before
  the run starts, not at its first checkpoint.
- **The checkpoint entry.** The four built-ins write the keys 0.5 wrote
  (`policy`, `target_idx`, `target_idxs`), through `_symbol_policy_fields`, so an
  unchanged run writes an unchanged entry. Any other policy is written by its
  kind and every field, recursively, with no target keys. On resume, a snapshot
  with a symbol, of either snapshot version, is rebuilt as the typed policy it
  stands for before the comparison. A symbol that stands for no policy is left
  as written, and the comparison refuses it.
- **Identity limit.** A named function is identified by its type alone, so
  changing its code between writing and resuming a checkpoint is not detected.
  The code comment and the docs say so.
- **The defaults.** The keyword default and the old positional constructor both
  build `SchedulingPolicyModel(SemimajorAxisRatePolicy())`, today's `:gve_sma`. A
  new positional method takes a policy alone.
- **Scoring.** Each score passes through `Float64`, and a nonfinite one is refused
  with the policy's type and the candidate's key. Unavailable candidates are not
  passed to the hook.
- **History.** Main 2088b4408 is merged in, not rebased, and no commit carries a
  trailer. The branch does not contain main's later #472 (CI and docs only), and
  it merges cleanly with that main and with the open #473 to #477. It opens as a
  draft for 0.6.0.

## Findings

No P1 or P2 findings in the author's own review. Points a reviewer should check:

- **The breaking change (D-I5-6, decided).** `SchedulingPolicyModel(:gve_sma)`
  and the other symbol forms throw an `ArgumentError` naming the exact typed
  call, also under `--depwarn=error`, and the removed properties throw an
  `ArgumentError` naming `.objective` or `.objective.targets` (a plain
  `FieldError` before cf30d1f8f). The 0.5.0 notes and the conventions page had promised
  `target_idx` and `target_idxs` until 1.0; the conventions and migration pages
  now say they went in 0.6.0, and the 0.6.0 notes need to say so too.
- **Bitwise identity.** For every edge the typed built-ins compute the same
  Float64 as the symbol policies: the same arithmetic on the same values in the
  same order, 0 for unavailable edges without a call, the same checks before the
  loop and the same nonfinite refusal. `select_interlinks!` is untouched. The
  score fixture (Tests) checks the bits. The claim holds for runs, and for every
  form on run-state views (ComponentArray), with and without a caller's
  `candidate_force`. One form is not bit for bit on other states: the in-house
  review's fixture found that `SemimajorAxisRatePolicy(targets=:lower_index)`
  with a caller's `candidate_force` on states held as `SVector`s differs from
  0.5's inline `:gve_sma_first_index` arithmetic by a few ulps in some cases,
  with no selection changed. StaticArrays' dot product rounds by its compile
  context, and on main the `:gve_sma` and `:gve_sma_first_index` paths already
  disagree there; the typed policy is self-consistent.
- **The orbital built-ins read the run state's views (D-I5-9).** A candidate
  carries `StateSample` copies of its endpoints. On main's environment,
  `dot(v, v)` on a run-state view goes through BLAS and differed in the last bit
  from the same product on the copy for 44,505 of 200,000 random velocities
  (`norm` and `dot(view, force)` never did). The built-ins therefore read the
  views, as the symbol policies did; a policy of your own gets the samples. A
  mutant that scores from the samples is caught by the score fixture.
- **The eccentricity refusal.** It runs after scoring, over the same candidate
  set. Since cf30d1f8f the scheduler records the near-circular candidates while
  it scores, so the rates are computed once per accepted step; its message
  names `EccentricityRatePolicy`.
- **Checkpoints (D-I5-7).** The keys and the version are unchanged, and the
  five forms write what 0.5 wrote when no target index was set. A run that had
  set a target index beside a target set, or one its policy ignores, writes the
  canonical value instead (for example `target_idx=1`); its old checkpoints
  resume, because recorded symbols are rebuilt as typed policies before the
  comparison. Snapshots that differ only in such ignored targets now resume;
  main refused them although the runs are identical.
- **Low: terminal lookups.** Each candidate carries its terminal hardware. Since
  cf30d1f8f the scheduler looks every spacecraft's terminals up once per
  scoring call rather than once per candidate. The scores do not change.
- **2026-10-21, independent design review, P2 (fixed in 1f475953e): a
  function field's identity.** The design recorded a function-valued policy
  field by its type alone. Two closures made by one factory expression with
  different captured gains have the same type, so their policies had the same
  identity while their scores and selected links differed, and a resume would
  have admitted a changed experiment. A function field is now recorded by its
  type and, for a closure, every value it captures, recursively (floats with
  their bits, vectors element by element). A closure that captures a variable
  reassigned after it was made (a `Core.Box`, whose contents can change) and a
  payload that contains itself are refused, at setup when the run checkpoints.
  Tests: same factory with another gain or vector contents refused, the same
  captures resumed, a named function resumed and another refused, the box and
  the cycle refused, a shared non-cyclic vector accepted, and a checkpointed run
  with a boxed closure refused before it writes anything.
- **Low, by design: a named function is its type.** A named function's code is
  not part of the identity, so a change to a function's body under the same name
  is not detected. The interlinks page says so.
- **Low, by design: a policy's identity is its fields.** A policy of your own
  that keeps run state in a mutable field (against `AbstractSchedulingPolicy`'s
  docstring) changes its identity as it runs, so its checkpoint would not
  resume.
- **2026-10-21, in-house review of 6049677c6: four P3 points, addressed in
  cf30d1f8f.**
  - P3-1, the bitwise claim: narrowed above, under Bitwise identity. No code
    change.
  - P3-2, the identity around the closure fix. (a) A top-level closure that
    reads a script global captures nothing, so a changed global was admitted.
    This is documented now: a closure reads its globals when it is called, so
    build it in a function or a `let` block. (b) A `Core.Box` inside a named
    tuple or struct field passed the setup check, and every resume was then
    refused with a misleading message. (c) A callable struct that is not a
    `Function`, a closure that captures a `Ref`, and a struct field holding
    arrays never resumed, even with the same values. The fix does both of the
    review's options: the identity now records any struct, mutable or not,
    named tuple or reference by its type and fields, under the existing cycle
    guard, and arrays with their size, so equal values resume; and it refuses
    at setup what it cannot record by value (a dictionary, a set, a stream, a
    task, a lock, an unassigned field or element, a value that is not a
    struct), instead of failing every resume. Tests: each of these with the
    same value resumes and with another is refused, also after a serialization
    round trip, a box in a named tuple and each unrecordable kind is refused,
    a cycle through a mutable struct is refused, and a checkpointed run
    holding a dictionary is refused before it writes anything.
  - P3-3, the removed properties. The record's sentence was wrong: Julia 1.12's
    `FieldError` lists `objective`. Reading or setting `policy`,
    `target_index`, `target_indices`, `target_idx` or `target_idxs` now throws
    an `ArgumentError` naming `.objective` or `.objective.targets`, and every
    other name is a field. With a constant name the check folds away at compile
    time, so a property read costs what a field read does.
  - P3-4, the scoring cost. The context's fields are typed; the terminals are
    looked up once per call; an edge none of whose ends a built-in policy
    scores is scored 0 without building its candidate; a link's forces are
    evaluated once per candidate; and the eccentricity check reuses the rates
    of the scoring pass. The rate functions stay compiled on their own and a
    caller's `candidate_force` stays a dynamic call, so every score keeps its
    bits (the review's fixture, below). A scored candidate still allocates its
    state samples and the link hook's result.
- **2026-10-21, in-house recheck of 4030044b3: Clear, two P3 points,
  addressed in ec5e9e3f0.**
  - P3-B, a pointer. A policy that holds a pointer, such as a `Regex` (its
    compiled pattern) or a wrapper of a C handle, was recorded with the
    address, which differs from one process to the next, so an equal policy
    never resumed, against the docs. A pointer, a bits value holding one, and
    a struct with a pointer field are now refused at setup, with a message that
    says why and names the type. The docs list it among the values a
    checkpoint cannot record.
  - P3-C, the refusal's wording. An unassigned element or field was reported
    as its container ("holds a Array", "holds a RefValue"), which arrays and
    references are not. The refusal now names the value's type and says which
    element or field is unassigned. Every refusal gives the type as `repr`
    prints it.
  - Tests: a pointer, a bits struct holding one, a `Regex` and a closure
    capturing a pointer are refused; the unassigned element and the unassigned
    `Ref` field are named; a dictionary, a set and a stream are refused with
    their type.
- **Callers outside core.** A bounded search of the companions and the private
  research repositories found no use of the scheduling API or its symbols (see
  Residual Risk for its limits). Two callers build a `SimulationConfiguration`
  without a policy; the default keeps them working.

## Residual Risk

- **Scripts that use the symbol forms stop.** This is the decided break: an
  `ArgumentError` names the typed call. A bounded search of the companions and
  the private research repositories at fixed revisions found no explicit use of
  the scheduling API or its symbols, so no known external user breaks. The
  search did not inspect SpaceAGORA_integrators.jl, did not load binary
  checkpoints or retained datasets, searched two repositories at selected entry
  points only, and cannot see names built at run time or code it was not
  given.
- **The 0.5.0 promise.** The target names `target_idx` and `target_idxs` were
  promised until 1.0 and go in 0.6.0. The 0.6.0 notes must say so under the
  breaking changes.
- **Release.** This PR is for 0.6.0. It should merge after the v0.5.1 tag,
  with main merged in.
- **User copies of a built-in.** A policy of your own that reimplements the
  semimajor-axis rate from the state samples can differ from
  `SemimajorAxisRatePolicy` in the last bit, and so break an exact tie
  differently.
- **Named functions.** A policy field holding a named function is recorded by
  the function's type, so a resume after its code changed is admitted.
- **A `BigFloat`'s precision** is not part of a policy's identity: a resume
  with the same value at another precision is admitted.
- **Old checkpoints and GNC models.** "Old interlink checkpoints resume" holds
  for runs without GNC models: since main's #476, a run with GNC models refuses
  any checkpoint written before 0.6.
- **Globals in a closure.** A closure that reads a global records nothing of
  it, so a resume after the global changed is admitted. The interlinks page
  says to build the closure in a function or a `let` block.
- **What a policy holds.** A policy that holds a large object (a spacecraft
  model, say) records all of it at every checkpoint, and is refused at setup
  if anything inside it cannot be recorded by value.
- **The lower-index form on SVector states.** With a caller's
  `candidate_force` and states held as `SVector`s,
  `SemimajorAxisRatePolicy(targets=:lower_index)` can differ from 0.5's inline
  arithmetic by a few ulps; runs are unaffected.
- **Not yet.** Energy balancing, weighted mixes and a state-of-charge accessor
  for policies are I-5b.
