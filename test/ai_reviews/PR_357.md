# PR review: sample declared third bodies for any force or torque model

## Scope

Review of PR 357, the SpaceAGORA `third-body-sampler` branch (head `35ad91064`, one
commit) against main `e5d68b7ba` (the merge of #346).

A force or torque model asks for third-body positions with the public
declaration `environment_requirements(model) =
EffectorEnvironmentRequirements(third_body_names=...)` and reads them from
`env.third_bodies` in `wrench`. The engine's only third-body sampler was a
method of `sample_third_body_ephemerides` for `NBodyGravityModel` that read
that model's own `body_names`, and both environment samplers called it for
every model that declared third bodies. Any other model following the
declaration stopped with a `MethodError` at its first sample. The setup checks
(the `SimpleEphemeridesModel` refusal and the run-start N-body ephemeris
cache) did not see the declaration either, and the per-link environment of
articulated spacecraft dropped the field.

The PR drives the sampler from the declared names for any model, makes the
setup checks read the declaration, and passes the sample to every link.
`NBodyGravityModel` keeps its sample byte for byte. The PR also audits the
other declared requirements for the same gap.

Authorship disclosure: this record was drafted by the author of the PR. It
does not replace an independent review.

## Changed Files

- `src/orchestration/simulation/engine/effector_sampling.jl`:
  `sample_third_body_ephemerides(body_names, primary_name, x, p, sat_idx, t)`
  is the former `NBodyGravityModel` method body with `model.body_names` and
  `model.primary_body_name` replaced by its arguments; the same cache, SPICE
  memo and runtime-counter path. `sample_third_body_ephemerides(model, x, p,
  sat_idx, t)` now accepts any model and forwards
  `environment_requirements(model).third_body_names`.
  `_third_body_primary_name(model, p)` is `model.primary_body_name` for
  `NBodyGravityModel` and the run's planet name otherwise.
  `sample_environment` and `sample_environment_with_reusable_buffers` pass
  `req.third_body_names`.
- `src/orchestration/simulation/engine/setup.jl`:
  `_has_active_nbody_effector` is also true for a model whose declaration
  names third bodies; `_collect_nbody_query_names` adds the declared names
  after an N-body-like model's own `body_names`, once each. Through these, the
  `SimpleEphemeridesModel` refusal in `_validate_ephemerides_support!`, the
  run-start cache (`_initialize_nbody_ephemeris_cache!`) and
  `prewarm_nbody_ephemeris_cache` cover declaring models. The refusal and
  prewarm messages name the declaration.
- `src/orchestration/simulation/engine/dynamics_rhs.jl`: one line in
  `_add_live_link_loads!`: each link's `EnvironmentSample` also carries the
  root sample's `third_bodies` (positions measured from the planet do not
  depend on the link's position).
- `src/foundation/core/types/effector_sampling.jl`: the
  `ThirdBodyEphemerisSample` docstring only.
- `docs/src/user/custom_effector.md`: the `EnvironmentSample` row of the
  reference table says what `third_bodies` holds and that such runs need
  `SpiceEphemeridesModel()`.
- `test/unit/simulation/third_body_ephemeris_requirements_tests.jl` (new),
  one testset in `test/unit/live_pose_loads_tests.jl`, one include in
  `test/unit/runtests.jl`.

## Findings

No P1 or P2 findings.

What a reviewer should confirm:
- `NBodyGravityModel` is unchanged. Its declaration is
  `third_body_names=model.body_names`, so the sampler receives the same tuple
  and the same primary name as before. A recording of direct samples,
  right-hand sides at six (state, time) pairs, whole solves and SPICE runtime
  counters on main and on the branch is identical bit for bit in seven
  configurations (one spacecraft with and without SRP; the SPICE memo with
  the cache off; direct SPICE with memo and cache off; 32 spacecraft on the
  flat route, with the cache and with the memo; `gravity_backbone_split`).
- A declaring model's positions are measured from the run's planet, which is
  also the primary the run-start cache and the solar sample use, so the cache
  serves it. `NBodyGravityModel` measures from its own `primary_body_name` as
  before.

Points a reviewer should check:
- Low, behaviour change: `SimpleEphemeridesModel` with a model that declares
  third bodies is now refused before integration with an `ArgumentError`, as
  it already was for `NBodyGravityModel`. Such a run used to fail at its first
  sample. No built-in model other than `NBodyGravityModel` declares third
  bodies.
- Low, by design: a declaring model cannot choose another primary body; the
  run's planet is documented on the sample and on the custom effector page.
- Low, unchanged: duck-typed "N-body-like" models (fields `body_names` and
  `primary_body_name`) keep their setup treatment; their sample now comes from
  their declaration, where before they had no sampler at all.

Audit of the other declared requirements, in `sample_environment` and
`sample_environment_with_reusable_buffers`:
- planet frame: `sample_planet_frame` and the flat-route prefill are generic.
  No gap.
- atmosphere: `_sample_atmosphere_from_planet_frame`, the prefill, the
  missing-aero warning and the initial force output callback read the
  declaration. `_requires_density_callback` names only the built-in aero types,
  but it is also true for every non-vacuum density model, and under
  `NoAtmosphereModel` a declaring model samples zero density on demand. No
  value difference; not changed.
- solar: `sample_solar_ephemeris`, the SRP Sun cache, the prefill and the
  `SimpleEphemeridesModel` refusal already read the declaration. No gap.
- magnetic field: `EffectorEnvironmentRequirements` has no such field. The
  built-in magnetic effectors declare the planet frame and evaluate their own
  field model inside `wrench`; a custom model has to bring its own field model
  the same way (the engine's dipole and IGRF helpers are not exported).
  Mounted actuators declare `ActuatorRequirements(magnetic_field=true)` and
  get the field with the settings of the first `MagneticTorqueRodModel`
  effector, or the default dipole. A design question (no field declaration for `wrench` models), not a
  sampler gap; not changed.
- Third bodies, listed and not changed: the flat route's memo warm-up
  (`_prefill_shared_body_samples!`) still warms only `NBodyGravityModel`'s
  bodies, which affects lock time only, not values; cost ranks, thread-safety
  flags, flat batch kernels and the `:auto_stiff` smooth-gravity list name
  built-in types and treat a declaring model as a generic effector.

## P1 Assessment

No P1 findings. `NBodyGravityModel` results are identical bit for bit, the
only new refusal covers configurations that already failed during the run,
and the per-link change adds a field that is `nothing` for every built-in
link model.

Unresolved P1: No

  external links (HTTP 429, unreachable hosts) this PR does not touch; CI
  builds the docs.

- The SPICE part of the new test is skipped where the kernels are absent.
