# Review record: PR 497: measure only the machine constants something reads

## Scope

Review of the SpaceAGORA `calibration-trim` branch against main `0487e8226` (the
v0.6.0 release). Its commits: `c9c5f0f15`, the change, built on PR 487's head,
which removed the unwired RHS-plan predictor; `207e970fc`, a merge of main
`228c1f309` after PR 487 merged; `3d6995bfb`, this record; `93e1c0c07`, a merge
of main `0487e8226`; `b9ab1c1fc`, the in-house review's fixes; and the update of
this record for that review. Against main it shows only this change. It is
planned for the 0.6.1 patch. It follows the calibration trim plan (2026-10-21)
and Giusy's decisions of 2026-10-22, all as recommended:
- D-T1: the staleness canary goes: `constants_are_current`, `reference_fma_ns`,
  `reference_mem_ns` and the two reference kernels;
- D-T2: files at schema 5 are measured again, with a loader that reads one
  version (schema 6);
- D-T3: `usl_beta_arith` is not saved.

After PR 487, live code reads three of `MachineConstants`' twenty fields: the
predictive campaign planner reads `usl_alpha_base` and `usl_beta_alloc`
(`src/orchestration/simulation/campaigns/predictive_planner.jl`), and
`ensure_machine_constants!` reads `measured_threads`. `calibrate_machine` still
measured the rest for the removed predictor: the coefficient-touch and SIMD-lane
curves, the scalar-item, queue-node, dispatch and atomic costs, the parallel
speedup curve, the bandwidth ladder (and the last-level cache size it used) and
the two reference kernels. The first `parallel=true` run on a machine paid for
all of them.

Change:
- `calibrate_machine` runs the two USL ladders, arithmetic and allocation,
  unchanged. `MachineConstants` keeps `usl_alpha_base`, `usl_beta_alloc`,
  `fingerprint`, `schema_version` and `measured_threads`.
- The constants file holds those five keys and, as before, any `[campaign]`
  table. `load_machine_constants` reads schema 6 only and returns `nothing` for a
  file without one of the two USL terms or without `measured_threads`, so such a
  file is measured again rather than read with a made-up value. A recorded count
  of 0 is not current at any thread count either.
- `CALIBRATION_SCHEMA_VERSION` goes from 5 to 6. A file at 4 or 5 loads as
  `nothing`, so `ensure_machine_constants!` measures again and keeps the file's
  campaign table, the same path PR 485 used for schema 4. The constant and its
  history move next to `MachineConstants`, whose `schema_version` now defaults to
  it, so a value built with the defaults saves a file the loader reads.
- Removed, as their last caller went: `RateCurve` and `rate_at`;
  `constants_are_current`, `reference_kernel_ns`, `reference_memory_kernel_ns`
  and their kernels; `calib_touch_kernel!`, `calib_scalar_kernel!` with
  `CALIB_SCALAR_FLOPS`, and `calib_stream_kernel!`; the ladders
  `_calibrate_coeff_touch`, `_calibrate_simd_lane`, `_calibrate_scalar_item`,
  `_calibrate_dispatch`, `_calibrate_polyester_dispatch` and
  `_calibrate_parallel_speedup`, with `_llc_bytes`, `_least_squares_line` and
  the knot tables; the bandwidth step of `_calibrate_usl`; and
  `ParallelCost`'s Polyester import, which `_calibrate_polyester_dispatch` used.
- Kept from PR 485: `calib_batch_kernel!`'s column wrap and bounds checks,
  unchanged, and its bounds test (see Tests).
- `scripts/calibration/calibrate_machine.jl --repeats=N` prints the two kept
  terms for every pass and their range.
- `docs/src/user/upgrading.md` has a 0.6.1 entry: the constants are measured
  again once, and a machine that uses the predictive planner without
  `parallel=true`, or that was calibrated with the script at a job's thread
  count, reruns the script.
- Prose that PR 487's review left for this change, rewritten for what remains:
  the `MachineConstants` docstring (it described the predictor's rates and the
  canary), the headers of `machine_calibration.jl`, `calibration_kernels.jl` and
  `robust_timing.jl`, the USL comment in `machine_calibration.jl`, and
  `timed_min`'s docstring, where a sentence that named the cost model is
  reworded and one about the removed probe path goes. The reference-kernel note
  and the dispatch-ladder comment go with their code.
  `ensure_machine_constants!`'s docstring drops a measured-duration paragraph
  that described the longer calibration. The R7 page
  (`docs/architecture/predictive_routing_r7.md`) says which ladder each USL term
  is fitted to.

## Findings

No P1 or P2 findings in the change. Points a reviewer should check:

- Results are unchanged; routes may not be. `SolverConfig(parallel=true)` runs
  the calibration before its first run in a working directory without a current
  constants file (`ensure_machine_constants!`, called from
  `src/orchestration/simulation/engine/adapters/from_env.jl:465`). The flag's
  profile, R7, uses the predictive campaign planner, which prices routes from the
  two USL terms. The ladders that measure them are the same code as before, but
  a new measurement gives new values, so after the re-measurement below a
  campaign can take another route than under 0.6.0. The route decides where the
  samples run, not what they compute.
- Deliberate behaviour change: on a machine that saved constants before this
  change, the first `parallel=true` run in a working directory measures them
  again, as after PR 485. The calibration it runs is shorter: of its former
  measurements, only the two USL ladders remain.
- Low: the removed names lived in the internal module
  `SimulationModel.ParallelCost`, which `SpaceAGORA` does not import, and no page
  documents them. Code that reached into the module for them, or for the removed
  `MachineConstants` fields, now gets an `UndefVarError` or a keyword error.
  Locally no companion or maintained repository names them; a retained audit
  probe from 2026-09-15 in a private repository calls `_llc_bytes` and would
  throw if rerun.
- Low: `timing_noise_floor` loses its only caller in `src`, the removed dispatch
  ladder. It stays exported as part of robust timing, which `timed_min`'s
  docstring points to, and its tests stay.
- The branch merged main `0487e8226` without conflicts. Of the open PRs, only
  PR 489, a draft, shares a file with it: `docs/src/user/upgrading.md`, where
  this branch adds the 0.6.1 section above the 0.6.0 one. PR 489 already
  conflicts with main in that file and others, so its next main merge resolves
  this section with the rest.
- **In-house review: Clear, no P1 or P2.** Its eight P3s, F1 to F8, are
  addressed in `93e1c0c07`, `b9ab1c1fc` and this record's update:
  - **F1, over-claims in this record.** Corrected: the calibration does run
    from `parallel=true`
    (`src/orchestration/simulation/engine/adapters/from_env.jl:465`), and routes
    can differ after the re-measurement while results do not (first point
    above); Residual Risk points to the 0.6.1 upgrading entry, not to release
    notes that do not exist yet; the Polyester import is named as
    `_calibrate_polyester_dispatch`'s.
  - **F2, no upgrading entry.** `docs/src/user/upgrading.md` has the 0.6.1
    entry described under Scope; a line saying the same is drafted for the
    0.6.1 release notes.
  - **F3, the calibration test bounded `usl_alpha_base` above by 1.** With two
    threads the fit has one rung above serial, and a noisy reading can put
    alpha past 1, so the test now checks only that it is finite and
    non-negative. `_fit_usl` is unchanged.
  - **F4, a file without `measured_threads` counted as current for any thread
    count.** It now loads as `nothing` and is measured again, like a file
    without a USL term, and a recorded 0 is not current either. No reason to
    keep reading such a file was found: every schema-6 file this change saves
    carries the key, so only a damaged or hand-written one lacks it.
  - **F5, `schema_version` defaulted to 1.** It defaults to
    `CALIBRATION_SCHEMA_VERSION`, so a value built with the defaults saves a
    file that loads back equal instead of being refused. The constant moves to
    `src/orchestration/parallel/cost/cost_terms.jl` so the default can name it.
  - **F6, the `--repeats` report printed "n/a" or large percentages.** A
    relative spread says little for two terms near zero. The script now prints
    both terms for every pass and their range, and its header says why.
  - **F7, the branch was behind v0.6.0.** Main `0487e8226` is merged with a
    merge commit (`93e1c0c07`), without conflicts, and the local evidence below
    was run again on the merged tree.
  - **F8, two residual risks missing.** Added under Residual Risk: the campaign
    corrections' heap-scale evidence, and a scripted calibration replaced by a
    first `parallel=true` session.

## Residual Risk

- Every machine that saved constants before this change measures them once more,
  on its first `parallel=true` run in each working directory that holds an old
  file, and its campaigns can then take other routes. A predictive-planner run
  that does not go through `SolverConfig(parallel=true)` (profile R7, or
  `SPACEAGORA_CAMPAIGN_PLANNER=predictive`, set by hand) plans without constants
  until `scripts/calibration/calibrate_machine.jl` is rerun. The 0.6.1 entry in
  `docs/src/user/upgrading.md` says so; the 0.6.1 release notes are not written
  yet.
- The campaign corrections file beside the constants keeps its heap-scale
  evidence across the re-measurement. Where the heap model charges the USL fit,
  that evidence was fitted to the slowdowns the old USL values predicted, so
  until new campaigns update it the planner scales the new terms' prediction by
  a factor fitted to the old ones.
- On a machine whose constants the script measured at a job's thread count, the
  first `parallel=true` session in that working directory after updating
  measures again at its own thread count and replaces the file. A job with more
  threads then measures again at its start under `parallel=true`, or plans from
  the smaller session's terms under R7 set by hand, until the script is rerun at
  the job's count. The 0.6.1 upgrading entry says to rerun it.
- Checkouts on either side of a schema bump that share a working directory
  overwrite each other's file once per process.
- Out-of-tree code that read the removed fields or names breaks loudly. The
  names were internal; the local search covered the companions and the lab's
  checkouts, not every clone.
