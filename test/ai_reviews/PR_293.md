## Findings

The following review findings were corrected before acceptance:

- P2: Preserve the exported `AssetCheckItem` six-argument positional constructor, alongside legacy keyword construction; validate explicitly supplied states and their agreement with `available`.
- P2: Make recovery hints runnable outside the repository and correct for nested checkouts/submodules and symlinked pointer targets. Hints now select the actual owning checkout with `git -C`, use owner-relative include paths, and quote shell arguments. Paths without a Git owner receive a documented-route instruction.
- P2: Exclude hidden-directory contents so cached payloads and pointers cannot determine an asset root's state.
- P3: Describe a missing required entry as blocking a successful asset check; required verification data do not by themselves block a baseline no-GRAM simulation. Document byte-level readiness and inspection errors explicitly.
- Validation gap: Add actual process-entrypoint failure and success cases. A helper-only status assertion did not exercise propagation through either changed command boundary.
- Integration requirement: Preserve current main's generic `AssetCatalog` service as the single owner of readiness behavior. Plain catalog records and typed CLI reports now agree on state, reason, availability, and all existing fields; the CLI does not regain a duplicate classifier.

No unresolved actionable source finding remains in this scope. The README quickstart smoke does not invoke `assets check`, but CI does invoke the unqualified command through the suite 05 coverage probe and checks real-manifest status in suite 08; CI independence is not claimed.
