## Findings

- [P2, fixed in 5d55e8bc5] `ConformanceFixture.call` was typed
  `NamedTuple{(:state, :spacecraft, :params)}`; after `_hook_call_types` dropped
  the spacecraft-view types, every conformance check failed with a MethodError.
  Found by the conformance negative controls.
- [P3, fixed in 5d55e8bc5] `Meta.parseall` does not throw on a syntax error, so
  the gate's (and the old gate's) "does not parse" branch was unreachable and an
  unparsable file would pass. The new gate looks for `:error` and `:incomplete`
  nodes; its control checks it.
- [P3, fixed in 69495a77f] Building the state sample before a `:mounted`
  effector's actuator path turned that path's `ArgumentError` for a state without
  attitude into a `BoundsError` (`actuator_contract_tests.jl`). The sample is now
  built after it. A mounted effector still gets a sample, which the bridges
  skipped unless its type had a wheel-torque method; it only reads the state view,
  and the bitwise check below covers a mounted run.
- [P3, pre-existing, follow-up] `probe_effector_costs!` takes a wrench effector's
  state sample from the flat route's per-satellite buffers, which only the flat
  route fills, so on any other route every wrench effector is left unmeasured
  (`ns_per_sat = NaN`). Reproduced on `main` and on the branch with a wrench-only
  user effector. The suite 02 test used old-hook effectors, which need no sample.
  Fixed separately by #428 (merged); until the merge of `main` the suite 02 test
  filled the flat buffers first, and 695f8677b drops that.
- [P2, fixed in the texts of abd4f919d] The PR text, this record and the migration
  page say 0.4.0 carried the warnings, which holds only once v0.4.0 is tagged
  (today, from a `main` that still warns). The draft's lead now says it does not
  merge before v0.4.0 is tagged and the 0.5.0 date is chosen; the statements stay.
- [P2, outside review of 2026-10-20, fixed in the revision that follows it] The
  gate counted a comma-form keyword (a `:kw` node) in a call as a positional
  argument, so `wrench(m, x, env, t, option=true)` was refused and
  `wrench(m, x, env, t, i, option=true)` passed. Calls and method signatures are
  now counted apart: a call's keywords are skipped after a comma or a semicolon,
  and a signature counts each arity its defaulted and trailing `args...`
  parameters allow. No such call was in the scanned tree.
- [P3, fixed in abd4f919d] The gate skipped `ext/` (shipped package code) and
  five-argument `wrench` calls; it now scans `ext/` and refuses such calls. A name
  built from a string (`Symbol("calcForceTorque")`, `Meta.parse`,
  `include_string`) stays out of its reach, which its comment says.
- [P3, fixed in the texts of abd4f919d] "Warned before each run" was inexact: the
  pre-run check warned once per process for each model type and old name
  (`_preflight_warning`, `maxlog=1`), and the five-argument plume form warned
  only on a direct call. The PR text and the migration page say so.
- [P3, fixed in abd4f919d] The pre-run check accepted any `link_wrench_capable`
  model without `wrench`, but only a run with live-pose loads on articulated
  spacecraft evaluates it through `link_wrench`; any other run reached
  `_force_torque_without_wrench` at the first right-hand-side evaluation (an
  `ArgumentError` now, a `MethodError` before the removal). The check now refuses
  it outside such runs and names the setting; `link_wrench` has no other caller
  and a run with one articulated spacecraft has only articulated spacecraft, so
  no run it accepted before and could complete is refused.
- [P3, fixed in abd4f919d] The claim that the untyped defaults do not change which
  conformance checks a model skips had no test; the negative controls now check
  `positive_consumption` and `output_hook_pure` for a model with only
  `control_wrench` and for a `:mounted` model without output hooks.
- [P3, accepted] The untyped `control_propellant_rate` default returns `+0.0`
  where the old fallback chain returned `-0.0`. The accumulation is
  `mass_rate -= c`, which starts at `+0.0` and never holds `-0.0` (design 4.3), so
  `m - 0.0` and `m - (-0.0)` are the same bits; the thruster scenario below has an
  effector without its own rate method.

## Residual Risk

- User code that defined a method of a removed name without qualifying it
  defines an unrelated function. If the replacement is a required hook (a tick,
  `control_wrench` outside `:mounted` actuation, or `wrench`), the pre-run check
  refuses the model and names it. If it is an optional output with a default
  (`control_propellant_rate` 0.0, `control_wheel_torque` nothing), the run uses the
  default instead, with no refusal; the migration page lists both cases (corrected
  after Codex's review of 2026-10-20).
- The conformance kit's check lists lose `no_deprecated_hooks`; a contributor
  test that names that id must drop it. Giusy decided both kit changes on
