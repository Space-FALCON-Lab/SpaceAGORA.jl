## Findings

No unresolved source correctness findings. The output guards preserve populated
directories and actual input files, including symlink/hardlink aliases. Saved
scene loading resolves the result bundle at its existing location. Requests for
HTML reject a missing renderer before run/campaign output is created. Core-only
results, scene and portable JSON export remain independent of the renderer.

Mission builders retain all scientific settings; only result output choices are
overridden. Factories receive the isolated configuration that actually runs,
allocate event state once per run, and are checked before output creation. The
empty default preserves the existing callback path and ordering. Phase windows
are explicitly descriptive metadata; they do not change models or solver stops.
Checkpoint workflows remain on the existing direct engine API.

Core retains all numerical conversion. A source-preservation proof checks the
AST of 21 conversion and 15 ensemble functions against the parent and confirms
the retained saved-data loading block. The renderer and its third-party notices
move to the companion. Its separately documented JSON-reference and quaternion
interpolation fixes affect standalone presentation and retain historical
extraction hashes, with a separate reviewed repair record.

CLI review verified explicit prepared-project selection, preloading before
example activation, preserved PROGRAM_FILE and ARGS (including spaces), both
load orders, and refusal without creating output when the companion is absent.
The mandatory optional-viewer job is included in tests and coverage aggregates;
existing native, MuJoCo and HYPR gates and thresholds are retained.

## Workflow context repair

On head `6d3b90bb1b7d83bc16d57dc0ab1885d0bd245298`, other workflows began
running while Julia CI had no jobs. A source audit identified `runner.temp` in
job-level `env`, where the runner context is unavailable under GitHub's
[context rules](https://docs.github.com/en/actions/reference/workflows-and-actions/contexts#context-availability).
The preparation step now appends the absolute prepared-project path to
`GITHUB_ENV` after setup succeeds. Quoting preserves spaces in runner paths;
a failed setup retains its exit status and does not export an unusable path.

Both new regression cases failed on the previous workflow. All 13 workflow
self-tests now pass: the context check rejects job-level runner expressions
while accepting their permitted use in steps, and a stubbed execution of the
actual preparation body verifies successful export, existing environment-file
preservation and failure propagation. This bounded check supplements YAML
parsing; it is not a full GitHub Actions validator. Whitespace checks pass.
Scientific source, companion pins, mandatory jobs, aggregates and coverage
thresholds are unchanged. Fresh hosted checks are still required on the repaired
head; no native or numerical suite was rerun for this workflow-only correction.
