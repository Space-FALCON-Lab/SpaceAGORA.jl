# AI Review Artifact — PR #121

## Scope
Post-hoc interactive 3D visualization of runs. A run flagged with `simulation_settings.save_visualization_scene` (or `run_simulation(args; visualization=true)`, `SPACEAGORA_VISUALIZATION=1`, `spaceagora run --visualize`) writes a scene sidecar beside its results and three new save fields (link poses, arm poses, density); `export_visualization` then bundles the sidecar, the decimated trajectory, a planet texture, optional 3D models (STL/OBJ/glTF), planned-path overlays and reference "ghost" trajectories into one self-contained HTML page driven by a vendored three.js viewer under top-level `viewer/`. Monte Carlo ensembles get their own manifest and page. The last commits add NASA models for Magellan, Cassini-Huygens and the Apollo lunar module, the ghost feature, and mission-recreation drivers (Magellan aerobraking at Venus, Cassini's TA and T5 Titan flybys with the reconstructed SPICE trajectory drawn as a ghost, Apollo 11 in lunar orbit). The final commits add mesh aerodynamics: a free-molecular panel method over a CAD mesh with depth-buffer self-shadowing, an analytic surrogate (real spherical harmonics in the airspeed direction times a polynomial in the inverse speed ratio, with the wall temperature kept as a runtime parameter through the exact sqrt(Tw/T) split), and an `AerodynamicCoefficientMeshSurrogate` effector; the mesh readers move from the visualization scene into the structure layer so both consumers share them. The last round adds a standalone viewer page that builds its payload in the browser from a CSV or JSON table (no simulation, no Julia), a nominal sample and a 3-sigma dispersion tube for ensembles, and fixes a pre-existing defect found while debugging the Magellan case: a GRAM density model carries the epoch it was built with and nothing propagated the run's `initial_time` into it, so local solar time and season were evaluated at 2000-01-01 for every example that built the model without an explicit epoch. Two further additions: model articulations (`articulate_triangles`/`articulation_payload` in the structure layer, `model_articulations` in the bundler, the same rotation applied to the drawn model in `lod.js`), used to turn the Magellan model's cruise-canted wings broadside for both the aerodynamic mesh and the picture; and an MP4 export in the viewer (`video.js`: deterministic frame-by-frame rendering through `viewer.renderAt`, WebCodecs H.264, the vendored MIT `mp4-muxer`, WebM fallback). Finally, a heating overlay on the close-up (every heatable face of the links and the 3D model shaded by ½ρV³ cos θ from the saved density and the airspeed, inferno on a log scale, toggle and legend), and a spelling sweep to American English across the viewer, its docs, the demo scripts and the new source and test files, with the rule recorded in CLAUDE.md. Last, a Mars Odyssey aerobraking case (`scripts/dev/viewer_demos/odyssey_aerobraking.jl`) with NASA's Odyssey model posed array-broadside, the initial state and a ghost from the Odyssey navigation kernel already in the asset tier, Mars-GRAM by default and the telemetry study's accelerometer-derived density as a variant. Then two interaction features in the viewer: every number in the selection panel (and the ensemble panel's 3σ readouts) is a clickable quantity that opens a time-history plot panel (`plots.js`: canvas plot over the kept frames, playback cursor, click-to-seek, automatic log axis), and the spacecraft body is pickable in the close-up: a click on a link box or a model mesh raycasts the face and opens a face panel with the incidence angle to the airspeed, the local ½ρV³cosθ and ρV²cos²θ, the airspeed and flow direction in body axes, the face normal (following the link's recorded pose), the inertial position and velocity, the attitude quaternion and the link pose, each also plottable. The last commit adds a lunar landing: a terrain layer (`src/environment/terrain/terrain_models.jl`: `DEMTerrainModel` over one or more DEM grids, `NoTerrainModel`, the fetch-script file format), an Apollo-style powered descent guidance effector (`src/gnc/guidance/landing/apollo_descent_guidance.jl`: Klumpp's quadratic law with the time-to-go cubic, P63/P64/P66 phases, DPS throttle envelope, attitude command) paired with a 6-DOF descent control effector (`src/gnc/control/landing/apollo_descent_control.jl`: throttle slew, RCS-bounded attitude loop, thrust along the actual engine axis, `touchdown_spec`), a touchdown event on the terrain that replaces the impact event when a control effector reports a landing (`event_callbacks.jl`, `assembly.jl`), the Apollo 11 scenario driver, the Moon Trek/PDS fetch script, and the viewer's terrain module (nested DEM patches with imagery, a hole in the globe, height above terrain). Reviewed: every changed `src/**/*.jl` against the default no-visualization path, the viewer modules, the bundler's data contract, the CDN page builder used for artifact pages, and the new unit tests. Rendering was verified in headless Chromium (Playwright, SwiftShader) on this machine for the ISS, Magellan, Cassini and Apollo pages, both the local `data:`-URL variant and the CDN variant.

## Findings
- **P2 (found and fixed during review): the selected-spacecraft panel reported a wrong latitude, longitude and altitude (altitude equal to minus the polar radius) on every page.** `globe.rotationAt(t, out)` wrote the quaternion with `out.set(x, y, z, w)`, which is correct for a `THREE.Quaternion` but a no-op for the `Float32Array` that `selectionInfo` passes, so the body-frame position was rotated by a zero quaternion. Planet-fixed playback was unaffected because it passes a `THREE.Quaternion`. Fixed in `viewer/src/globe.js` by branching on `isQuaternion`; verified in headless Chromium that the readout now carries the geodetic values.
- **P2: the "ISS is back to a box" report could not be reproduced.** The ISS orbit page and its CDN variant both load the glTF (`glb (36 meshes, ×2.4)` in the model-status row) and draw the station in follow mode under headless Chromium. Boxes stay visible only when the parse fails or never returns; the status row now names the failure, and the ghost feature reuses the same loader so a failure shows in both places. Left open pending a report of the status row's text from the affected browser.
- **P2 (design, recorded): the depth-buffer shadowing zeroes every facet behind another along the mean flow, including the back facets of a convex body near the limb, which in free-molecular theory still receive the thermal part of the flux.** On a sphere this costs 1.5% of the drag at speed ratio 3 and 0.3% at 8; at aerobraking speed ratios (5 to 10) it is below the accommodation uncertainty. The box case is unaffected because the Hart closed forms drop the back faces too, which is why a box mesh reproduces them to round-off. The unit test pins both numbers.
- **P3: the surrogate clamps the speed ratio to the fitted range silently.** Outside (3, 20) by default the coefficients are those at the boundary; the fit range is stored and documented, but a run at very low speed ratio will not warn.
- **P3: a link without a surrogate carries no aerodynamic load.** Intended for the whole-vehicle case (vestigial wing links), documented, but a per-link fit that forgets a link silently loses its drag.
- **P3: `calcForceTorque` on the legacy (non-sampled) path reads the propagated attitude through `hasproperty(x, :q)` and otherwise falls back to the stored root quaternion**, the same limitation the fM legacy path has; the engine uses the sampled `wrench` path for this effector, so the fallback is not reached in `run_simulation`.
- **P1 (pre-existing, found and fixed during review): GRAM runs sampled the atmosphere at the wrong date.** `GRAMAtmosphereModel(planet_name=...)` defaults its epoch to 2000-01-01, GRAM's ephemeris hook and native date both read that epoch plus the elapsed time, and nothing in the engine or the examples set it to the run's `initial_time` (none of the examples pass one). On Venus at 149 km that put Magellan's periapsis on the night side (5.6e-11 kg/m³, 132 K) where SPICE puts it at 13:24 local solar time (GRAM at the right epoch: 1e-9 kg/m³, 246 K, the value the flown energy loss implies), an order of magnitude in drag; on Mars and Earth the same defect moves local time and season. Fixed by `with_density_model_epoch` in `run_simulation`; a new unit test covers the identity path and, when GRAM is present, the rebuild. Every previously published GRAM-backed number (the telemetry validation studies included) was produced with the model's own epoch unless the manifest set one, and should be checked.
- **P2 (found by the author on the Odyssey page, fixed): linear interpolation between decimated frames made the follow camera wobble.** Positions were interpolated along the chord between saved frames; at the 25 s page cadence and 4.7 km/s near periapsis the chord sags 0.49 km mid-segment, and since the follow camera rides the spacecraft, the ghost (sampled every 5 s) appeared to jitter by a few hundred meters at 25 s period. Both tables now interpolate with a cubic Hermite through the saved velocities (`hermitePosition` in `data.js`), which cuts the mid-segment error to about a centimeter at that cadence; the chord remains the fallback when a run saved no velocities or the tangents are too long for the chord to resolve them. Verified on the Odyssey page: the reported separation no longer sawtooths between frame times.
- **P3 (observation, not a defect): Mars-GRAM under-predicts Odyssey's November 2001 density by about two.** The Odyssey case at the run epoch (2001-11-06, orbits P19 to P21, 70°N periapsis) loses 49% of the energy the navigation kernel loses over two passes with the TES mapping-year-2 climatology (peak 1.5e-8 vs 3.6e-8 kg/m³ measured), which matches the stored accelerometer-to-GRAM density ratio of 2 to 2.7 on the inbound legs of those passes; the accelerometer-density variant recovers 102% of the kernel's energy loss and ends 52 km from it. The climatology gap is the atmosphere, not the viewer or the aerodynamics, and is documented in the driver and the demo README.
- **P2 (design, recorded): the landing effectors keep their state in the effector objects, so a run must be started with `isolate_state=false` to read the touchdown record afterwards.** `run_simulation` deep-copies the configuration by default; the scenario and the unit test pass `isolate_state=false`, and the scenario also saves thrust, throttle, time-to-go, radar altitude, phase and attitude error as result columns so the outcome is on disk regardless. Documented in the user page.
- **P3: the braking targets front-load the demand.** With the Apollo-11-like targets the quadratic law asks for up to 1.7 times full thrust at PDI; the throttle logic clamps to full thrust for the first 6 minutes and the profile is re-solved each cycle, as the flown guidance did, so the run still reaches the high gate at 494 s (Apollo 11: 507 s) and touches down at 740 s (755 s) with 7,555 kg of DPS propellant used (Apollo 11 about 7,900 kg of 8,200 kg). Apollo's padloaded targets sat below the surface for the same reason; a future pass can tune `apollo11_descent_targets` toward a demand of one at PDI.
- **P3: the DEM-relative altitude is measured to the state point, which the viewer draws as the model's center.** `touchdown_height_m=3.7` in the scenario puts the footpads on the ground for NASA's model at scale 1.45; the LM's true center of mass sits lower. Vehicle inertia and RCS torque authority are order-of-magnitude values from the LM data, not the flight values.
- **P3: the touchdown event evaluates the terrain every step.** `get_touchdown_callback` transforms the state to the body frame and interpolates the DEM in the root condition; at the landing's step sizes this is negligible, but a constellation run with a landing effector would pay it per satellite.
- **P3: face quantities share the overlay's assumptions.** The face panel's local heating and ram pressure use the spacecraft-level density and airspeed with full accommodation and no shadowing, like the overlay; a face in the wake of another part reads as if exposed. The face normal comes from the raycast triangle in the picked mesh's frame, so on a model with flipped winding the normal points inward and the incidence reads as lee; the Odyssey and Magellan models pick correctly (array face 9.9° windward at the Odyssey periapsis). Histories are evaluated on the page's kept frames (every 5th row on the Odyssey page), not the full results table.
- **P3: the heating overlay is an incidence map, not the thermal model.** It shades faces by ½ρV³ cos θ with full accommodation and no shadowing, from the spacecraft-level density and airspeed; the thermal model's heat rate stays a spacecraft-level number in the panel. Documented as such. Verified on the Magellan standalone page at the first periapsis (0.033 W/cm² peak on the leading dish and wings, lee faces dark).
- **P3: articulations select vertices, not triangles.** A triangle with vertices on both sides of a region boundary is stretched. Fine for separate parts such as wings on booms, wrong for a region cutting through a single mesh; documented, not guarded.
- **P3: the MP4 export downloads through a page-started link**, which the claude.ai artifact host blocks; the dialog says so. Verified headlessly on the standalone page: 121 frames at 1280x720, Baseline H.264, a valid fast-start MP4 (`ftyp`, `moov`, `mdat`).
- **P3: `render_viewer_html` escapes `<`, `>` before `&`**, so a title containing `<` becomes `&amp;lt;`. Cosmetic (titles are set by the caller); should be reordered in a follow-up.
- **P3: `_gltf_accessor` reads buffer slices under `@inbounds`**, so a truncated or malformed GLB with a bad `byteOffset` or `count` can read out of bounds instead of raising. Only reachable through a caller-supplied model file; the STL reader validates lengths first.
- **P3: `_density_sample` swallows every exception** (bare `catch`) and returns `nothing`, so a broken density model yields an empty profile with no diagnostic. Only reached with the flag on.
- **P3: `_save_density` reads `shared_buffers.densities`**, written by the density callbacks and the flat-RHS prefill; a route that samples with `write_buffers=false` would leave a stale column. The three mission drivers (serial, GRAM) show the expected profiles; a non-flat multi-satellite run with the flag on is untested.
- **P3: the thruster plumes are drawn along the glyph's `direction`, which the repo uses with two meanings.** `SixAxisThrusterModel` and `add_thruster!` treat `Thruster.direction` as the thrust direction; the Apollo 11 scenario uses it as the exhaust axis (DPS `direction=(0,0,1)` while the effector thrusts along body −z). The plume follows the exhaust convention, so a scene built with the thrust convention draws its plumes backwards. One sign in `plumes.js` fixes either way; the convention should be settled and documented in `Thruster`.
- **P3: the Apollo 11 demo's thruster locations sit inside the NASA model**, so each plume's bright throat is occluded and the RCS puffs, already tiny in P66 (levels of 0.001 against 734 N·m per jet), are barely legible except at the phase handovers. Moving the demo's thruster locations onto the rendered skin is the fix; left as is so the recorded case stays comparable.
- **P3 (pre-existing): `add_thruster!` in `src/vehicle/spacecraft/assembly.jl` assigns a 3-vector to the `Matrix{Float64}` field `J_thruster`**, so adding the first thruster to a link throws a `MethodError`. Every caller builds thrusters through `Link(thrusters=...)`, which is why it has gone unnoticed. Predates this PR.
- **P3: the sun shadow box is 100 m across at 2048²**, tuned with bias −5e-4 / normal bias 2e-4 for the 10.6° Apollo 11 sun; a vehicle hovering above about 15 m casts its shadow outside the box, and a wider box needs the bias re-tuned. The auto-exposure is measured once from the ground texture and the Sun's incidence at the end of the run; an orbital run with `sun_dir` falls back to a reference cosine of 0.5, which is a guess.
- **P3: the path tracer patches two r165 properties onto `THREE.Scene.prototype`** (`backgroundRotation`, `environmentRotation`) because three-gpu-pathtracer 0.0.23 reads them unguarded on three r160; the versions are pinned for that reason and a library bump may need more. Thruster plumes and dust are not part of the traced scene (they are emissive interface geometry, not lights), so a path-traced still shows the shadow but no plume.
- **P3 (design, recorded): the plume-surface model has two calibrated parameters** (`threshold_shear_pa=0.15` sets the erosion onset at 31 m for the Apollo 11 approach thrust; `erosion_efficiency=10` stands in for the saltation cascade), and the ground-effect augmentation (3 % of thrust at contact, zero above two exit diameters) is a modeling choice sized to the few-percent effect reported for lander-class plumes, not a flight measurement. The Apollo 11 run erodes 429 kg, the same order as the tonne-scale literature estimates and low by about two. The cumulative integral advances under a monotone time guard rather than an accepted-step hook, so a rejected step neither double counts nor runs it backwards; a very long rejected step could still be integrated over a state the solver later discarded.
- **P3: the control effector that reports thruster levels is `PlumeSurfaceInteractionModel`'s type parameter**, duck-typed on `actuators.thrust_n`, because `force_torque_models.jl` is included before `control_hooks.jl` in the aggregator. Constructor-validated; a concrete field type would need the aggregator reordered.
- **P3: the auto exposure meters a 64-pixel render of the linear buffer through an asynchronous readback**, excluding additive overlays and taking the interquartile log-luminance mean; it is clamped to EV +6 to +17 and adapts with a 0.5 s time constant. Under SwiftShader the fence lags by seconds, so headless verification needs about 20 s per view to converge. `lighting.setEv()` now also switches the camera to fixed, a behavior change on the first-round interface (nothing else calls it).
- **P3: the path-traced image has no ground-bounce term** (the raster hemisphere light is not a tracer light), so a traced still is darker than the raster frame at the same EV; the dust and plumes are not traced either.
- **P3 (design, recorded): below the 4 m NAC DTM cell the terrain relief is procedural** (a tiled 3 cm/texel detail normal map at 0.12 RMS slope with small craters), sized to continue the site's measured slope-versus-baseline trend, not measured relief; `options.microRelief=false` disables it. The albedo normalization is a large-kernel flat-field of the brightness-matched mosaics: crater-scale shading survives, slow genuine albedo trends are flattened.
- **P3: the finest height grid travels quantized** (Int16 with a 1 cm step, `quantize_heights=true`), which keeps the landing page at 10.9 MB; Float32 is still readable by the page.
- **P3: the earthshine and foil environment probe depend on `frames.earth_dir` and `frames.sun_dir`**; on a page without the Sun the probe is skipped and the foils rely on direct specular plus the fallback fill. The Earth from Tranquility Base sits at 59.3 degrees elevation at the landing epoch (libration), slightly below the 60 to 65 the task text assumed; the test asserts 58 to 70.
- Design notes recorded rather than flagged: `with_visualization_scene` and `with_results_directory` rebuild `SimulationSettings`/`SimulationConfiguration` field by field (a future field is silently dropped on the visualization path, the same pattern `_ensemble_member_settings` already used); `export_visualization` runs inside `run_simulation` when `visualization=true`, so a missing `viewer/` tree fails the run after the results are on disk; the CDN page builder concatenates the viewer modules into one scope, so top-level names must stay unique across modules (checked with `node --check` on the concatenation).

## Residual Risk
Moderate, concentrated in the viewer rather than the runtime. The Julia side is additive and gated, and the unit tests cover the data contract end to end, so the default simulation path carries no new risk. The browser side is verified only in headless Chromium here and in the user's Firefox earlier; a rendering difference in another browser (the box report) has no automated catch beyond the status row. The mission drivers depend on external assets (NAIF kernels downloaded on first run, Venus/Titan GRAM) and are dev tooling, not CI. The reference ghosts assume the run's inertial frame is J2000 centerd on the primary, which holds for the SPICE ephemerides path used by the drivers; a run on the simple ephemerides would need its own sampling. The standalone page reproduces the bundler's payload in JavaScript (IAU rotation instead of SPICE; leap seconds ignored), verified headlessly with the Apollo CSV and a five-file ensemble but not covered by the Julia tests. The mesh aerodynamics path is validated against closed forms and the existing box model, not against flight data; its accuracy on a real vehicle rests on the accommodation coefficients, the wall temperature and the mesh's winding, and the depth-buffer shadowing is an approximation of the directional flux (see the P2 note). The Magellan and Cassini drivers can run either model against the SPICE ghost (`SPACEAGORA_DEMO_MESH_AERO=1`), which is the intended check; both cases now fly with the long axis along the flow, and for Magellan that puts the NASA model's wings edge-on (the cruise geometry) while the box model keeps them broadside, so the two aerodynamic models differ by design there until an articulated wing mesh exists. With the GRAM epoch fixed, two aerobraking orbits of Magellan end 2.4 km from the navigation kernel with the box model (energy loss 13% above the kernel's) and 0.7 km with the mesh surrogate flown bus-and-antenna forward (9% below; 1.0 km antenna aft), the two aerodynamic models bracketing the flown trajectory; Cassini stays within 5 km over five hours with drag negligible. These separations are reported on the pages rather than hidden.
