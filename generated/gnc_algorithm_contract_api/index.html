GNC Algorithm Contract API

This page documents the supported public interface available from SpaceAGORA.

GNC algorithm contract

SpaceAGORA.GNCAlgorithms.AbstractGNCAlgorithm — Type
AbstractGNCAlgorithm

An algorithm whose output is consumed later or can be rejected: a planner, a scheduler or a decision service. It runs in the planning profile of the GNC contract: its family builds an owned request, the algorithm proposes a product, trusted code validates the proposal, and only a validated copy is installed. Feedback control laws that act at once use the feedback profile instead (a tick that computes and holds a command).

An algorithm declares algorithm_family and implements propose!; the other algorithm-side functions have defaults. AbstractRPOPlanner is a subtype.

source
SpaceAGORA.GNCAlgorithms.AbstractAlgorithmFamily — Type
AbstractAlgorithmFamily

The trusted definition of one problem: its request and product types, how a proposal is validated (validate_proposal), where an accepted product is installed (install!), when an installed product stops being usable (is_current) and what happens on rejection (on_rejection). Algorithms declare a family; they never validate or install their own products. RPOReferenceFamily is a subtype.

source
SpaceAGORA.GNCAlgorithms.AbstractAlgorithmRequest — Type
AbstractAlgorithmRequest

An owned snapshot handed to an algorithm, in SI units, carrying a positive request_id. The lifecycle keeps its own copy for validation and passes the algorithm a separate deep copy. RPOPlanningRequest is a subtype.

source
SpaceAGORA.GNCAlgorithms.AbstractAlgorithmResult — Type
AbstractAlgorithmResult

An algorithm's outcome for one request: request_id, status (:candidate, :infeasible, :unsupported or :failed), termination, the proposed product (present exactly for :candidate) and diagnostics. A candidate still needs trusted validation. AlgorithmResult and RPOPlanningResult are subtypes.

source
SpaceAGORA.GNCAlgorithms.AbstractValidationResult — Type
AbstractValidationResult

The outcome of trusted validation, with fields accepted::Bool, reason::Symbol and metrics. ValidationResult and RPOValidationResult are subtypes.

source
SpaceAGORA.GNCAlgorithms.GNCAlgorithmError — Type
GNCAlgorithmError <: Exception

Supertype of the errors an algorithm lifecycle raises when a request fails under the :fail policy. Subtypes carry a copied run report, the reason, and the original cause and backtrace. RPOPlanningError is a subtype.

source
SpaceAGORA.GNCAlgorithms.AlgorithmResult — Type
AlgorithmResult(; request_id, status, termination, product=nothing, diagnostics=NamedTuple())

A generic algorithm outcome for families that need no result type of their own. status is one of :candidate, :infeasible, :unsupported or :failed; only a :candidate carries a product, and it must carry one. Construction deep-copies the product and the diagnostics, so later edits through an algorithm-held handle cannot change them. Diagnostics are never read by validation or installation.

source
SpaceAGORA.GNCAlgorithms.ValidationResult — Type
ValidationResult(accepted, reason, metrics=NamedTuple())

A generic validation outcome: whether the proposal is accepted, a machine-readable reason and the measured values behind it.

source
SpaceAGORA.RPOPlannerInterfaces.RPOReferenceFamily — Type
RPOReferenceFamily(; on_rejection=:fail)

The RPO reference-planning family of the general GNC algorithm contract. Its request is an RPOPlanningRequest, its product an RPOReference, its trusted validation validate_rpo_result and its currency rule rpo_reference_is_current. Every AbstractRPOPlanner belongs to it, and the general functions forward to the RPO names: propose! to plan_rpo!, propose_revision! to retime_rpo!, algorithm_capabilities to planner_capabilities, initialize_algorithm to initialize_planner and require_algorithm_support to require_planner_support.

on_rejection is the rejection policy: :fail (the default) stops the run with an RPOPlanningError; :install_fallback installs a hold at the chaser's position (fallback_product). A planner declares the default family; a binding configures the policy (bound_family).

source
SpaceAGORA.GNCAlgorithms.algorithm_family — Function
algorithm_family(algorithm) -> AbstractAlgorithmFamily

Required. The family whose request, validation, installation and failure rules govern algorithm. The fallback throws an ArgumentError that names the type.

source
SpaceAGORA.GNCAlgorithms.default_capabilities — Function
default_capabilities(family)

The capabilities an algorithm of family has when it declares none: support for nothing. The fallback is an empty NamedTuple; a family with a capability type returns its empty instance.

source
SpaceAGORA.GNCAlgorithms.algorithm_capabilities — Function
algorithm_capabilities(algorithm)

What algorithm supports, in its family's capability type. Defaults to default_capabilities(algorithm_family(algorithm)), which supports nothing. Declaring capabilities never loads algorithm configuration.

source
SpaceAGORA.GNCAlgorithms.require_algorithm_support — Function
require_algorithm_support(algorithm) -> nothing

Throw before a run starts if something algorithm needs is missing, such as an optional package. The default checks nothing.

source
SpaceAGORA.GNCAlgorithms.initialize_algorithm — Function
initialize_algorithm(algorithm, run_context) -> state

Create fresh run-owned state for algorithm; stateless algorithms return nothing (the default). run_context is a copied NamedTuple (for example seed, stream_words, epoch and spacecraft IDs).

source
SpaceAGORA.GNCAlgorithms.propose! — Function
propose!(state, algorithm, request, rng) -> AbstractAlgorithmResult

Required. Propose a product for request using run-owned state. rng is the only random stream the algorithm may draw from; there is no default global stream. The algorithm receives its own copy of request and must not install anything. The fallback returns an :unsupported result and draws nothing.

source
SpaceAGORA.GNCAlgorithms.propose_revision! — Function
propose_revision!(state, algorithm, request, active_product, rng) -> AbstractAlgorithmResult

Optional. Revise the installed active_product instead of proposing from scratch (RPO calls this retiming). The fallback returns an :unsupported result and draws nothing; an unsupported revision never falls back to a full proposal.

source
SpaceAGORA.GNCAlgorithms.consumes_rng — Function
consumes_rng(algorithm) -> Bool

Whether algorithm draws from the stream passed to propose!. The default is true. A deterministic algorithm declares false; its contract tests then check that a proposal leaves the stream unchanged.

source
SpaceAGORA.GNCAlgorithms.validate_capabilities — Function
validate_capabilities(family, algorithm, request; checkpoint=false) -> AbstractValidationResult

Check algorithm's declared capabilities against request before asking for a proposal; checkpoint=true also requires restart support. The default accepts, for families that have no capability rules.

source
SpaceAGORA.GNCAlgorithms.validate_proposal — Function
validate_proposal(family, request, result, trusted) -> AbstractValidationResult

Required for each family. Validate result against the lifecycle's own copy of request. trusted holds queries the lifecycle supplies independently of the algorithm (for RPO, clearance_at). Validation never installs a product, never advances a random stream and never reads diagnostics as geometry.

source
SpaceAGORA.GNCAlgorithms.install! — Function
install!(link, family, product, request, t; validation, diagnostics) -> nothing

Required for each family. Install a validated copy of product into link, the object the family shares with the product's consumer, at time t. Installation is atomic: no yield or user callback runs between validation and installation. The lifecycle passes the accepted validation result and the algorithm's copied diagnostics as keywords, so a family may keep them with the product.

source
SpaceAGORA.GNCAlgorithms.is_current — Function
is_current(family, request, product, t) -> Bool

Required for each family. Whether an installed product (accepted for request) may still be used at time t, including any preview the consumer needs.

source
SpaceAGORA.GNCAlgorithms.on_rejection — Function
on_rejection(family) -> Symbol

What the lifecycle does when capability checks or validation reject a proposal: :fail raises a GNCAlgorithmError (the default), :keep_previous keeps the installed product, and :install_fallback installs fallback_product.

source
SpaceAGORA.GNCAlgorithms.fallback_product — Function
fallback_product(family, request)

The product installed on rejection by a family whose on_rejection is :install_fallback, such as a hold. Families with another policy need no method.

source
SpaceAGORA.GNCAlgorithms.family_contract_version — Function
family_contract_version(family) -> Union{Nothing, VersionNumber}

The version of family's request, product and validation contract, so that a companion package can require the one it was built for. The default nothing means unversioned.

source
SpaceAGORA.GNCAlgorithms.family_request — Function
family_request(family, settings, u, p, t, spacecraft_index, reason, request_id) -> AbstractAlgorithmRequest

Required for a family that AlgorithmGuidance runs: the owned request snapshot for the spacecraft at spacecraft_index (its position in the run, from 1) at elapsed time t in seconds. Trusted family code builds it from the simulation state u, the run's parameters p and the binding's settings, which the family defines (nothing when it needs none). reason is the request's reason and request_id its positive number. The fallback throws an ArgumentError that names the family.

source
SpaceAGORA.GNCAlgorithms.family_link — Function
family_link(family, link, settings, p, spacecraft_index)

The object AlgorithmGuidance installs accepted products into for the spacecraft at spacecraft_index, resolved once per run before the first request. link is the binding's configured link and p the run's parameters, so a family whose install target belongs to the run (the burn-plan family: the spacecraft's slot in the burn scheduler's plan buffer) finds it there. The fallback returns link, and throws an ArgumentError when it is nothing.

source
SpaceAGORA.GNCAlgorithms.preflight_family — Function
preflight_family(family, algorithm, settings, args, spacecraft_index; isolate_state) -> nothing

Check, before a run starts, that the configuration args can run algorithm of family for the spacecraft at spacecraft_index with the binding's settings, and throw an ArgumentError naming the problem otherwise (for example a missing consumer of the family's products). isolate_state is the run's isolate_state setting. The default checks nothing.

source
SpaceAGORA.AlgorithmLifecycle.AlgorithmGuidance — Type
AlgorithmGuidance(; algorithm, spacecraft_index, settings=nothing, link=nothing,
                  seed=0, events=AlgorithmEvent[], replan_interval_s=Inf)

The guidance model that runs algorithm, of any family, for the spacecraft at spacecraft_index (its position in the run, from 1). Each request goes through the shared request driver, run_algorithm_request!: the family builds the owned request (family_request), the algorithm proposes (propose!), the family validates the proposal (validate_proposal) and installs an accepted product into the binding's install target (family_link, install!), and a refusal follows the family's on_rejection.

  • settings: the family's request settings, or nothing when it needs none.
  • link: the install target, shared with the product's consumer, for a family that does not find its own in the run. The binding declares it as a GNC link it produces (gnc_links), so the engine checks and initializes it with its consumers (joint-reference family: the arm controller's plan buffer).
  • seed: the seed of the binding's random stream, MersenneTwister(gnc_stream_words("AlgorithmGuidance/v1", seed, F, id)), with F the family's type name and id the spacecraft's ID; fresh in every run.
  • events: requests at given times (AlgorithmEvent). An event due when the run starts is requested before the first tick.
  • replan_interval_s: when finite, a request with reason :interval at the run's start and then whenever this many seconds have passed since the last request. The default Inf makes none.

Requests happen at the binding's guidance ticks, at the rate its GuidanceModel gives it, and before the same tick's control, so the consumer sees a product at the tick it is installed. The engine also runs every guidance model outside those ticks when the burn scheduler plans (as a spacecraft leaves the atmosphere); a request that is due by then is made there. The binding keeps a record of every request, installation, rejection and failure (algorithm_run_report). A configuration may hold one binding per install target: one per family and spacecraft for a family that finds its own target, one per configured link otherwise. Checkpoint writing and resume are refused, because the binding's run state is not checkpointed. On a spacecraft, bind_spacecraft gives a copy for that spacecraft that shares the configuration and has fresh run state.

source
SpaceAGORA.AlgorithmLifecycle.AlgorithmEvent — Type
AlgorithmEvent(time_s; reason=:forced, token=1)

A request that an AlgorithmGuidance makes at its first tick at or after time_s (elapsed seconds, finite and nonnegative), with reason handed to the family's request. A positive token identifies the event, which is delivered once; events with distinct tokens due at one tick are separate requests, in the order they are listed.

source
SpaceAGORA.AlgorithmLifecycle.AlgorithmGuidanceError — Type
AlgorithmGuidanceError <: GNCAlgorithmError

A request of an AlgorithmGuidance failed: its family's rejection policy is :fail, or algorithm or family code threw. Fields: spacecraft_index, request_id, reason, report (a copy of the binding's run report, as in algorithm_run_report), and the original cause and backtrace.

source
SpaceAGORA.AlgorithmLifecycle.algorithm_run_report — Function
algorithm_run_report(solution) -> NamedTuple

Copied run records of every AlgorithmGuidance in an isolated run_simulation result (return_solution=true), as bindings, one entry per binding: its spacecraft_index, algorithm type, settings, seed, random-stream identity (generator, stream_mapping, stream_words), request_id (the number of requests made), the installed_request and product, and records: one per request (:request, with a copy of the request), installation (:installed), rejection (:rejected, with the family's validation result and reason) and failure (:failure), in order.

source
SpaceAGORA.GNCAlgorithms.gnc_stream_words — Function
gnc_stream_words(namespace, seed, ids...) -> Vector{UInt32}

The seed words of a binding's random stream, for MersenneTwister(words): SHA-256 over the ASCII text "SpaceAGORA/<namespace>/<seed>/<id>/...", decoded little-endian into eight 32-bit words (held as unsigned integers; the RPO mapping has always produced them this way). The namespace carries a version, so a changed mapping is a new namespace. RPO uses "RPO/v1" with the chaser and target IDs. A stream depends only on these values, never on run order or threads.

source
SpaceAGORA.GNCAlgorithms.AlgorithmRuntime — Type
AlgorithmRuntime(stream_words; state=nothing)

Run-owned record of one binding, created fresh when the run starts and never shared between bindings:

  • the algorithm's state and its random stream rng (seeded from stream_words);
  • the request counter request_id;
  • the installed_request and product, which stay nothing until a product is installed;
  • the delivered event tokens (processed_tokens);
  • the last guidance and request times;
  • the run records.
source
SpaceAGORA.GNCAlgorithms.run_algorithm_request! — Function
run_algorithm_request!(binding, u, p, t, reason; exception_reason=:algorithm_exception) -> Bool

Run one request of binding at time t through the contract's steps:

  1. advance the request counter, resolve the algorithm and its family (bound_algorithm, bound_family, checked against algorithm_family) and build the request (build_algorithm_request);
  2. record a copy of it;
  3. check capabilities (validate_capabilities);
  4. ask for a proposal, passing a separate copy of the request (propose!, or propose_revision! with a copy of the installed product when is_revision_request);
  5. check the proposal's type and copy it, then resolve the link (bound_link) and copy the product (proposed_product);
  6. validate the copy against the retained request (validate_proposal with the binding's trusted_queries);
  7. install the product (install!) and update the runtime. Nothing else runs between validation and installation: no yield, no hook and no user callback;
  8. record the install (installed_record, called after installation on copies).

A refusal follows the family's on_rejection policy. Any error thrown once the counter has advanced, by algorithm or family code (resolving the family included) and including a GNCAlgorithmError, becomes a failure of this binding with reason exception_reason; only the binding's own failure passes through unwrapped. Every failure counts as a request: the counter stays advanced. Returns whether a product was installed.

source
SpaceAGORA.GNCAlgorithms.algorithm_runtime — Function
algorithm_runtime(binding) -> AlgorithmRuntime

Required for each binding: its run-owned AlgorithmRuntime.

source
SpaceAGORA.GNCAlgorithms.bound_algorithm — Function
bound_algorithm(binding)

Required for each binding: the algorithm it runs.

source
SpaceAGORA.GNCAlgorithms.bound_family — Function
bound_family(binding) -> AbstractAlgorithmFamily

The family instance a binding runs its algorithm under. Defaults to algorithm_family(bound_algorithm(binding)). A binding returns its own instance to configure the family's policy, such as the RPO rejection policy. The instance must have the same type as the family the algorithm declares; otherwise the request fails with reason :family_mismatch.

source
SpaceAGORA.GNCAlgorithms.bound_link — Function
bound_link(binding)

Required for each binding: the object accepted products are installed into, shared with their consumer (for RPO, the plan buffer).

source
SpaceAGORA.GNCAlgorithms.build_algorithm_request — Function
build_algorithm_request(binding, u, p, t, reason, request_id)

Required for each binding: the owned request snapshot for this tick, built by trusted code from the simulation state u and parameters p.

source
SpaceAGORA.GNCAlgorithms.trusted_queries — Function
trusted_queries(binding) -> NamedTuple

The queries the lifecycle hands to validate_proposal, supplied independently of the algorithm (for RPO, clearance_at). Defaults to none.

source
SpaceAGORA.GNCAlgorithms.fail_algorithm_request! — Function
fail_algorithm_request!(binding, reason; cause=nothing, backtrace=nothing, details=NamedTuple())

Required for each binding: record the failure and throw a GNCAlgorithmError carrying the binding's copied run report. The request driver calls it when a request fails under the :fail policy, and with the driver's exception_reason when algorithm code throws.

source
SpaceAGORA.GNCAlgorithms.algorithm_result_type — Function
algorithm_result_type(family) -> Type

The type every proposal of family must have. A proposal of any other type fails the request with reason :invalid_result_type. Defaults to AbstractAlgorithmResult.

source
SpaceAGORA.GNCAlgorithms.is_revision_request — Function
is_revision_request(family, request) -> Bool

Whether request asks for a revision of the installed product, which the driver sends to propose_revision! instead of propose! (RPO: reason === :retime). Defaults to false.

source
SpaceAGORA.GNCAlgorithms.proposed_product — Function
proposed_product(result)

The product a candidate result proposes: result.product for an AlgorithmResult (RPO: the reference). The request driver calls it on every proposal of the family's result type before validation, so it must also return, not throw, for a result that validation will refuse.

source
SpaceAGORA.GNCAlgorithms.installed_record — Function
installed_record(family, request, result, validation, product, reason, t) -> NamedTuple

The run record kept when product is installed. The driver calls it after installation, with copies of its arguments, and stores a deep copy of the result. The default names the product product.

source
SpaceAGORA.GNCAlgorithms.rejected_record — Function
rejected_record(family, request, result, validation, reason, t) -> NamedTuple

The run record kept when a request is rejected under the :keep_previous or :install_fallback policy. result is nothing when the capability check refused the request before any proposal.
