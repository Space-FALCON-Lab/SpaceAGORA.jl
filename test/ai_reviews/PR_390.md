## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- **Low, structure:** the four types lose `Base.@kwdef` for written-out keyword
  constructors. `@kwdef` cannot alias a keyword, and replacing its method is
  refused during precompilation. The defaults now live in the constructors; a
  test compares each with its previous value.
- **Low, scope:** `RobotArmReactionEffector.spacecraft_idx` (a force/torque model
  outside the design's table) is not renamed. The engine reads either name.
- **Low, behaviour:** the engine's field-name checks now also recognise a
  contributor model whose fields already use the new names.
- **Note:** the warning fires where the old name is used, not in a separate
  pre-run pass, and uses the `:depwarn` group, as the renamed hooks do.

Reviewer to verify:

- Every default in the four keyword constructors equals the old `@kwdef` default.
- No built-in code path reads an old name, so no warning can come from a callback
  or the right-hand side.
- `getproperty` with a literal field name folds to `getfield` (the forwarding
  branch is `@inline` and constant).
- The five engine checks keep their results for the built-in types.
- No run changes: the parity evidence.

## Update after review (576640580)

- **Resolved (P2, automated review): an explicit `nothing` index took the
  default.** `_renamed_keyword`
  (`src/foundation/core/interfaces/hook_deprecation.jl`) treated `nothing` as "not
  passed". So an explicit `nothing` for `spacecraft_index`, `chaser_index`,
  `target_index` or an old name gave the default index, where the typed `@kwdef`
  fields used to refuse it. An old name with a `nothing` new name also escaped the
  both-names refusal.
- **Fix:**
  - a private sentinel, `_NOT_PASSED`, in `HookDeprecation` now means "not passed";
  - the keyword constructors default to it:
    - `src/models/gnc/control/momentum_manager.jl`;
    - `src/models/gnc/control/robot_arm_control.jl`;
    - `src/models/gnc/control/rpo_mpc/rpo_control_types.jl`;
    - `src/models/gnc/planning/rpo/planner_lifecycle.jl`, which uses it for the
      required-keyword check too;
  - `src/models/gnc/control/control_hooks.jl` imports it;
  - an explicit `nothing` now reaches the field conversion and fails as before,
    and both names are always refused.
- **Test:** "an explicit nothing is refused, as before the rename", and three cases
  in "the planner binding", both in `test/unit/gnc/index_field_rename_tests.jl`.
  - Each renamed field refuses `nothing` under the new and the old name. Under
    `--depwarn=error` the old name's warning refuses first.
  - Both names are refused when either is `nothing`.
  - With `5055ad5dd`'s source, every new assertion fails and the earlier ones
    pass.
- **Evidence on `576640580`:**
  - the rename, runtime, scope, per-spacecraft GNC and RPO planner lifecycle tests
    pass;
  - the 33 pull-request gates pass;
  - this record passes the review-record gate.
- The Findings note on the written-out constructors still holds; their index
  defaults are now the sentinel instead of `nothing`.
