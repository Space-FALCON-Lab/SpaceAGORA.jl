# SpaceAGORACLI — internals

## Purpose
Stands for the whole `SpaceAGORACLI` module on workflow sheets: the command-line front door that parses `spaceagora <subcommand>` arguments, resolves example scenario paths, runs benchmarks and telemetry verification in a subprocess, and checks that large binary assets (STL meshes, ephemeris kernels) are present before a scenario that needs them starts.

## Design & Implementation
The block gathers `run_cli`, the `SpaceAGORACLI` entry struct, the `_run_example` / `_run_benchmark` / `_run_telemetry` dispatchers and the asset-manifest helpers (`load_asset_manifest`, `render_asset_report`, `check_assets`). On a workflow sheet the block replaces these symbols with one node; calls into it arrive on `members_in` and calls it makes to guidance or simulation code leave on `members_out`. The module chart `cli` draws the members individually.

## Limitations
The block is a projection, not a boundary: it exists so a workflow sheet stays under the readability limit, and the count of lifted edges on each connection says how many real calls it summarises. Open the `cli` module chart to see which member each call actually reaches.
