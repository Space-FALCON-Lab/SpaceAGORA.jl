# PR 80: Roots 3 migration review

## Scope

Allow Roots 2 and 3 and resolve Roots 3.0.8, while migrating four deprecated legacy guidance calls and preserving successful solver tracing at two existing targeting calls. Prepared against main `62199228732bbd28e559493dff959048c6f9a03a`. Source and tests have been evaluated as candidate files while the shared checkout is occupied by another review; integrated branch gates and PR-head CI remain pending.

## Findings

No blocking findings in the bounded migration. The four `fzero` calls become qualified `Roots.find_zero` calls with the same Brent method, brackets, residual closures, catches and post-processing. The two logging calls use explicit Tracks/NullTracks; residual tolerances remain unchanged.

The two second-switch fallbacks are intentionally different: the integrated caller retains its saved value, while the sampled caller still applies its ten-percent adjustment after a caught failure. Tests reach actual interior roots so Roots 3 deprecation errors cannot silently pass through these catches.

Pre-existing limitation: legacy closed-form targeting references undefined `aoa_cf` after the root. The caller probe confirms the solve and post-root path before the existing error; this PR does not repair or claim physical success of that entire legacy function.

## Residual Risk

- Roots 3 can throw `ConvergenceFailed` when an exhausted Roots 2 Brent solve returned a finite inaccurate value. A deliberately capped diagnostic reproduces this upstream change; it does not demonstrate exhaustion at the normal production cap. No tolerance relaxation, new iteration limit, copied old finalizer or expanded catch is introduced.
- Explicit trace display runs after successful return. A failed solve may no longer display the Roots trace before throwing. Application residual logging and exception handling are unchanged.
- Comparisons establish the tested cases on Roots 2.2.13 and 3.0.8, not all allowed minor versions or global bit identity. No speedup is claimed.
