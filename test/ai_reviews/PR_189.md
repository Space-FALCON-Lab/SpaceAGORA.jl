# Full-arc GMAT/STK parity matrix review

## Scope

Independent review of `pr/xval-fullarc` (head `f284daff`) against `origin/main`.
The review covered the single executable source change (an opt-in PCK override
in the planet constructors), the new and derived gravity-field files, the
reference-target split in `test/gmat_scenario_matrix.jl`, the full-arc driver
script and its export helper, and the probe test. The permanent-tide numbers in
both derived field files were recomputed independently from their stated inputs.
The full 24-case matrix and the probe suite were not rerun; the PR's matrix
results are author verification.

## Changed Files

- `src/environment/ephemerides/planets.jl`: adds `_furnsh_pck_overrides`, called
  after the planetary kernel in the Earth, Mars, Venus, Titan and Moon
  constructors; reads `SPACEAGORA_SPICE_PCK_OVERRIDES` and returns immediately
  when it is unset or blank.
- `test/gmat_scenario_matrix.jl`: the old `:gmat` target is renamed `:basilisk`
  with values unchanged; a new `:gmat` target for the real GMAT R2025a runs
  (zonal J2, file GM at every degree, EGM96 for Earth); the fitted STK Moon
  C(2,0) is removed; STK `j0_tbtrue` cases take the file GM.
- `test/probes/scenario_matrix_debug_probes.jl`: drops the removed cache name
  and adds a subprocess check of the script's usage path plus three override
  assertions.
- `scripts/xval_fullarc.jl`: full-arc driver, environment-variable sensitivity
  overrides, and a diagnostic redefinition of `_spice_planet_frame_lpi`.
- `scripts/xval_fullarc_export.py`: collects run outputs into paper CSVs.
- `data/Gravity_harmonics_data/EGM96_GMAT_L50.csv`: GMAT's EGM96.cof to degree 50.
- `data/Gravity_harmonics_data/EGM96_GMAT_L50_zerotide.csv`: same, zero-tide C(2,0).
- `data/Gravity_harmonics_data/LP165P_permtide.csv`: LP165P plus the Earth-raised
  permanent tide in C(2,0) and C(2,2).
- `data/Gravity_harmonics_data/README.md`: documents `EGM96_GMAT_L50.csv` only.
- `data/spice_overrides/mars_iau2009_pole.tpc`: IAU 2009 Mars orientation.

## Findings

No P1 finding. Default simulator behavior is unchanged: with the variable
unset, `_furnsh_pck_overrides` returns before touching the kernel pool, and
every other change is in tests, scripts or data. The `:basilisk` GM and J2-order
entries are byte-for-byte the old `:gmat` entries, and the default
`reference_target` moved from `:gmat` to `:basilisk`, so the Basilisk matrix
configuration is preserved.

Verified independently:
- `EGM96_GMAT_L50.csv` coefficients equal `egm96.csv` for all 1,326 (n, m ≤ 50)
  terms (maximum difference 0).
- Zero-tide file: only C(2,0) differs. The difference is −4.200675e-9, which
  equals A0·H0·k20 = 4.4228e-8 × (−0.31460) × 0.30190, the IERS Conventions 2010 §6.2.2
  form, with the sign that makes the zero-tide field more oblate.
- LP165P permanent tide: only C(2,0) and C(2,2) differ, by −4.059375e-8 and
  +7.031044e-8. Both are reproduced to every printed digit by
  (k2/5)(GM_E/GM_M)(R/a)³(1−e²)^(−3/2)·P̄2m(0), with the sub-Earth point at
  latitude 0 and longitude 0, P̄20(0) = −√5/2 and P̄22(0) = 3√(5/12). The
  resulting C(2,0), −9.093077e-5, falls within 2.3e-9 of the removed fitted
  value (−9.093310e-5). That agreement independently supports the reading that
  the fit was absorbing the permanent tide.
- `:gmat` GMs equal the header GMs of Mars50c, MGNP180U and LP165P, and Earth
  uses EGM96.cof's 398600.4415 km³/s². Because of that, the STK `j0_tbtrue` remap
  to the `:gmat` entries does select the file GM.
- The IAU 2009 Mars values match pck00010. Text-kernel `=` replaces the whole
  pck00011 array, so the zeroed NUT_PREC terms do remove the periodic terms.
- Every path in `planets.jl` goes through `_furnsh_once`, so a later constructor
  cannot reload pck00011 over the override.
- The script's `_spice_planet_frame_lpi` copy matches the current
  `simple_ephemerides.jl` body when no frame table is installed.

P2-1, description and code disagree on the STK Earth and Moon fields. The PR
summary says that STK Earth uses `EGM96_GMAT_L50_zerotide.csv`, that STK Moon
uses `LP165P_permtide.csv`, and that "every STK case now agrees to within
11 m". Neither file is referenced anywhere in the code. The committed `:stk`
target still uses `EarthGGM05C.csv` for Earth and unmodified `LP165P.csv` for
the Moon. Both files are reachable only through `XVAL_EARTH_FIELD_FILE` and
`XVAL_MOON_FIELD_FILE`. The committed STK results are therefore not the ones
the PR reports. The fix is to wire the files into `_matrix_scenario_overrides`
for `:stk`, or to restate the PR and the paper record as sensitivity results.

P2-2, STK Moon J2 strict acceptance regresses. Removing the fitted C(2,0)
without substituting the permanent-tide field brings back the drift that the
removed comment measured: 202 m at t = 600,000 s. In the quick profile, 10,000
samples at 60 s cover exactly 600,000 s. The 5 mm limit in
`_strict_position_rmse_limit_km("moon_j2_*")` will therefore fail whenever the
STK and Basilisk references are both present. That set is skipped in CI, and
failures are caught and printed rather than rethrown, so CI stays green. This
is inferred from the PR's own numbers and from the data spacing; it was not
rerun. P2-1's fix would also resolve this; otherwise the expectation needs to
be updated.

P3-1, stale `:gmat` references. `scripts/tb_matrix_debug.jl` (line 17) and
`docs/quality/scenario_matrix_debug.md` (line 39) still say that the Basilisk
references use `reference_target=:gmat`. After this PR `:gmat` means real GMAT,
so external callers passing `:gmat` explicitly now get a different force model
silently.

P3-2, copied provenance headers. The derived field files reuse their source
headers verbatim. `EGM96_GMAT_L50_zerotide.csv` still claims it reproduces
`Sim_Earth_J2_TBFalse.csv` byte for byte and that its coefficients equal
`egm96.csv`. `LP165P_permtide.csv` still claims byte-for-byte agreement with
LP165P.cof. The appended lines clarify both, but the false clauses should be
removed. The README lists neither derived file.

P3-3, Earth tide convention constant. The zero-tide shift uses IERS k20 =
0.30190 (−4.2007e-9). EGM96's own tide-system conversion (Lemoine et al. 1998,
k2 = 0.3) gives −4.1736e-9, a C(2,0) difference of 2.7e-11 (0.6% of the shift).
Whichever convention STK's EGM96 file follows, the effect on the 8.9 m Earth J2
residual is probably small, but the review did not quantify it.

P3-4, PCK override hygiene:
- No unit test covers default-off behavior, path resolution or the
  missing-file `ArgumentError`.
- Relative paths resolve against the SPICE directory, not the repository, so
  the committed `data/spice_overrides/` file needs an absolute path. No doc
  states this.
- Once loaded, the override stays in the process-global kernel pool after the
  variable is unset, and the planet caches do not key on it. This matches the
  existing `SPACEAGORA_SPICE_PLANETARY_KERNEL_RELPATH` pattern.
- The PM zero array has 25 entries against pck00011's 26. This is harmless
  because the array is replaced wholesale and every entry is zero.

P3-5, script-only `:gmat` target. `_gmat_reference_available()` is defined but
unused. No testset grades the new `:gmat` target, so the real-GMAT parity has
no regression guard in the suite. The script's `Base.eval` replacement of
`_spice_planet_frame_lpi` is a verbatim copy and will go stale silently if the
source function changes. The frame correction interpolates rotation matrices
linearly, which is acceptable for small, densely tabulated corrections but not
orthonormal.

## P1 Assessment

Unresolved P1: No. The only `src` change is opt-in and inert when unset, and
none of the default simulator force, frame or kernel paths change. The two P2
findings concern how the test harness and the PR text represent the STK
comparison, not the simulator's behavior. They should be resolved before the
PR's STK figures (within 11 m, Moon J2 at 10.5 m) are cited as committed
results.

## Tests Added/Updated

The probe `Full-arc entrypoint uses the maintained definition boundary` runs
the script in a separate process with no arguments. It asserts that the usage
error fires before any campaign or output write, that the matrix caches are
untouched, and that the fitted-C20 cache is gone. It also asserts that the STK
Moon J2 case uses `LP165P.csv` unmodified and that Mars J2 order is 0 for
`:gmat` and 2 for `:basilisk`.

Not covered:
- the `:gmat` Earth field file and GMs;
- the STK `j0_tbtrue` GM remap;
- `_furnsh_pck_overrides`;
- any numerical check of the derived field files.

The probe and the matrix were not rerun in this review. The PR reports a
two-case smoke run (Venus L=0 and Earth J2 against GMAT) that reproduces the
paper values, which is author verification.

## Residual Risk

The STK convention claims (zero-tide EGM96, an Earth-raised lunar permanent
tide, the per-run GM with third bodies on) are inferred from residual
reductions, not from STK documentation or file contents. Each reduction comes
from a physically motivated adjustment with no free parameter, which is
stronger evidence than the removed fit, but the convention is still selected
from the graded comparison. LP165P's own tide convention, whether its C20 and
C22 exclude the static tide, is assumed and was not verified against Konopliv
et al. (2001). Real-GMAT parity rests on reference CSVs outside version control
(`data/telemetry/GMAT_Examples`) and on a script that is not exercised in CI.
The SpaceAGORA–GMAT residuals attributed to frame models are demonstrated only
through the diagnostic frame substitution, which the default simulator does not
use.

## Correction follow-up (2026-10-03)

The preceding sections are historical reviews and author reports of earlier
revisions. A subsequent independent review requested corrections before merge.
This section records the implementation response; it is not independent
acceptance of the corrected revision.

- F1: the full-arc runner now records source identity and dirty state, environment
  controls, effective models and solver settings, input/kernel hashes and retained
  output hashes. The exporter reads this record and refuses incomplete runs,
  scientific overrides, renamed variants, dirty or mixed source revisions,
  mismatched output hashes, and incomplete or duplicate primary matrices before
  writing outputs. Primary CSVs retain model and provenance columns.
- F2: the Moon STK probe expects the permanent-tide file, with a separate GMAT
  assertion for the unmodified field. The probe is now in the PR probe driver.
- F3: PCK overrides are furnished after every standard kernel and reapplied when
  mixed-body construction loads more kernels. Cached construction validates the
  fixed ordered override policy. Changing that policy requires a fresh process
  or an explicit kernel-pool and planet-cache reset. Binary PCK precedence over
  text PCK remains CSPICE behavior.
- A1: normal runs retain the package rotation method. The script replacement is
  installed only for an explicitly selected diagnostic frame-table mode.

The focused checks cover actual CSPICE binary and text precedence, both
Earth/Moon construction orders, repeated/cached construction, other body loads,
policy-change refusal, normal and diagnostic frame modes, run-record lifecycle,
export rejection and a synthetic 48-row/144-sample export. No native collection
or full numerical campaign is part of these corrections. Gravity coefficient
files, comparison configuration values and numerical thresholds are unchanged.
Fresh independent acceptance and CI on the published correction are still due.

The reference-generation provenance gap remains open. An available older GMAT
generator specifies JGM2 for Earth and no Luna central-body case; the retained
comparison uses EGM96 and LP165P. The cited historical rerun record remains
unavailable. STK tide conventions were inferred from comparison residuals.
Accordingly, documentation and exported records describe conditional comparisons
with unverified generation settings. Diagnostic rotation agreement does not
prove default simulator accuracy or that every residual is a frame-model error.
