# Review record: PR 498: forward multi-docstring names to Documenter without nested Markdown

## Scope

Review of the SpaceAGORA `docs-interpolation-warnings` branch against main (0487e8226, the v0.6.0 release). It removes the "Unexpected Julia interpolation in the Markdown" warnings from the docs build, for 0.6.1. The build passed with them; this is a cleanup.

Cause: `src/SpaceAGORA.jl` forwards docstrings onto its own bindings with `@doc (@doc Inner.X) X`. For a name with one docstring, that stores an MD whose only content is another MD, which Documenter's `DocSystem.parsedoc` unwraps. For a name with several docstrings (a type and its constructor, several methods, some documented in other modules) it stores an MD with one nested MD per docstring, which Documenter cannot unwrap. It renders each nested MD as plain text, so the page showed raw Markdown (backticks, code fences, unresolved `@ref` links), and warned once per nested MD.

Six names are affected, 22 warnings in all:

- `RPOStationGeometry` and `RPOCubeSatGeometry` (type and constructor), on `public_api.md`: 4 warnings;
- `cmg_momentum`, `actuator_wrench`, `actuator_consumption` and `actuator_levels` (several methods, some documented in other modules), on `actuators_api.md`: 18 warnings.

What changes:

- **`_flat_doc`** in `src/SpaceAGORA.jl` splices the nested MDs into one MD, keeping the docstrings in order with a horizontal rule between them (the rule the REPL shows). The result carries none of the lookup's metadata (`:results`, `:binding`, `:typesig`). Documenter and the docs scripts do not read these from a stored docstring, and a non-empty `:results` would make the REPL draw a rule between every block.
- **The six re-exports** go through it: `@doc _flat_doc(@doc SimulationModel.X) X`.
- **Unchanged.** Every other forwarded name, the docstrings themselves, the exports and the public API listing.

## Changed Files

- `src/SpaceAGORA.jl`: adds `_flat_doc` and forwards the six names through it.

## Findings

- **No P1 or P2.**
- **P3, accepted: `_flat_doc` relies on the shape of the Markdown standard library's `MD`.** It builds the result with `typeof(md)(blocks)` and takes the rule from `parentmodule(typeof(md)).HorizontalRule()`, so SpaceAGORA needs no `Markdown` dependency. The repository pins Julia to 1.12; a change in that shape fails loudly when the package loads, and the new test covers the result.
- **P3, addressed in `44aa3f660`: `_flat_doc` assumed that `@doc X` returns a `Markdown.MD`** (`src/SpaceAGORA.jl`, the helper and its six call sites).
  - That holds only while the REPL's doc lookup is loaded when SpaceAGORA precompiles. Today it always is, through DataFrames and PrettyTables 3, which depends on REPL; the current compat bounds allow no other PrettyTables series.
  - Without it, `@doc X` returns the first `DocStr` of `X` (or `nothing`). `_flat_doc` then throws a `FieldError` and the package fails to precompile, where the plain forward would keep only the first docstring. A minimal package reproduces both behaviours.
  - Fix: the helper returns an argument that is not a Markdown `MD` (one with no `content` and `meta` fields) unchanged, which forwards what the plain form forwarded. The testset pins it for a `DocStr` and for `nothing`.
- **P3, not changed (existing): the REPL shows a forwarded name's docs twice.** `?X` gathers the docstrings of every module that has them, the inner module's and SpaceAGORA's copy. This holds for every forwarded name and is outside this change.
- **Other build warnings, not of this class and not changed:**
  - the size warning for `generated/public_api.html` (about 176 KiB, against the 150 KiB warning and 200 KiB error limits; the change adds about a quarter of a KiB);
  - the size warning for the search index;
  - the local-only "could not auto-detect the building environment" notice.
- **In-house review (2026-10-22, at `68ab9e736`).** Clear: no P1 or P2. It adds the P3 on the `@doc` assumption above, and one optional test polish: the scan could assert that it visited the six bindings, so that it cannot pass on an empty scan. Both are addressed in `44aa3f660`.
  - The set is complete. Re-derived from the doc metadata, the forwarded docstrings whose binding has more than one source docstring are exactly these six. After Documenter's unwrap, no docstring in any loaded module keeps a nested MD at any depth.
  - With the six forwards put back to their v0.6.0 objects, the docs build (link check off) gives the 22 warnings; on this head it gives none, and so does the hosted docs job. On the built site only the six entries change, and the rest of both pages is identical. The REPL text of the six names is unchanged.
  - The testset fails with the v0.6.0 objects (7 of 13), with the docstrings reversed, without the rule, and with a seventh nested forward in a SpaceAGORA submodule. It passes 13 of 13 in the test environment and in the hosted suite-01 shard.
  - The 33 PR gates pass.
  - This record's metadata and count wording were corrected.

## P1 Assessment

No P1 finding is open. The change touches docstring metadata only. No exported name or method changes, and no simulation path; the helper runs once for each of the six names while the package loads. The documentation text of the six names is the same, and the page renders it as formatted text where it was raw Markdown.

## Tests Added/Updated

- `test/suites/01_contract_and_api_tests.jl`, testset "Forwarded Docstrings Render Without Nested Markdown":
  - no docstring stored in a SpaceAGORA module keeps a nested MD after Documenter's unwrap, so a later multi-docstring forward that skips `_flat_doc` fails here and not only in the docs log;
  - the scan saw the six forwarded bindings, so an empty scan cannot pass;
  - `_flat_doc` returns a `DocStr` and `nothing` unchanged, the two results `@doc X` gives when the REPL docsystem is not loaded;
  - for the six names, the forwarded docstring equals the docstrings of the inner modules, gathered as `Base.Docs.doc` gathers them, in the same order, joined by one rule.
- With the six forwards put back to the plain form, the testset fails 7 of its 16 assertions: the scan lists the six names and each of the six comparisons fails. With the guard removed, the two unchanged-return assertions error. On this branch it passes 16 of 16.
- Checked by hand, outside the suite:
  - the docs build with link checking off reports no "Unexpected Julia interpolation" warning (22 before);
  - the REPL text of each of the 447 bindings documented in SpaceAGORA's own doc metadata, and the terminal text of every docstring stored there, is identical before and after; only the plain-Markdown text of the six differs, by the added rules;
  - of the built site's HTML, once source-link line numbers and the build date are set aside, the only docstring entries that differ are the six, and their text differs only in Markdown syntax (backticks, fences and `@ref` link text, which were shown raw).

## Residual Risk

- The six entries on the API pages change in appearance: signatures become code blocks, links such as `actuator_saturate` resolve, and a rule separates the docstrings. The text is the same.
- The scan covers the docstrings stored in modules of this package. A forward made through another mechanism than `@doc` on a copied MD is not covered.
- The change leaves the REPL's repeated display and the two size warnings as they are; neither is a defect of this change.

Unresolved P1: No
