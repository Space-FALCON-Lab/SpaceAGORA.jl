# PR310 review: regroup data/ by purpose

## Scope

Review of SpaceAGORA PR310 (branch `data-layout`) against `main`. The PR moves the
inputs under `data/` into `planets/` and `scene/`, folds the RPO station mesh into
`scene/models/`, keeps the three manifests at the `data/` root, and leaves
`data/telemetry/` and the GRAMSuite submodule in place. Every path reference in
tests, studies, scripts, examples, workflows and documentation follows the moves,
in both string and `joinpath` segment spellings.

Authorship disclosure: this record was drafted by the author of the PR and
committed by the principal investigator on 2026-10-14, because the independent
reviewer was unavailable. It is a second, separate pass over the complete diff
rather than a stamp: it found and repaired three defects that the first pass and
the hosted checks had not surfaced (Findings 1 to 3). Readers should weigh the
record accordingly.

## Changed Files

- `src/orchestration/simulation/config/run_settings.jl`: the `gravity_harmonics`
  and `topography_harmonics` default directories become `data/planets/gravity` and
  `data/planets/topography`; a stale "move to planet?" note is dropped. Explicit
  user values are unaffected.
- `src/interfaces/analysis/visualization/scene/viewer_payload.jl`: the
  `TEXTURES_DIR` constant and its docstring point at `data/scene/textures`.
- `src/foundation/assets/rpo_station_assets.jl`: the station geometry root becomes
  `data/scene/models`; the CAD path names `gateway_core.stl`; the demo point-cloud
  default becomes `station_pointcloud_demo.csv` beside it. The functions, their
  argument checks and error messages are unchanged.

Outside `src/`, the same change set repoints the asset manifest, the LFS attribute
for the surrogate grids, the ignore-rule exceptions, 86 files of path references,
and the extension helper `ext/SpaceAGORAGRAMSuiteExt/gram_grid_atmosphere.jl`
(Finding 3).

## Findings

1. Historical download URL rewritten. The Odyssey scenario catalog
   (`data/odyssey_surrogate_assets.toml`) pins the Mars gravity coefficients to a
   raw GitHub URL at commit `62d56d8b`, where the file lives at the former path.
   The reference sweep had rewritten the path inside that URL, which would make
   the download fail and the recorded checksum unverifiable. Restored to the
   historical path; the local asset check reports 17 of 17 entries usable.
2. Python path form missed by the sweep. `scripts/dev/terrain/fetch_moon_site.py`
   builds its default `--match-texture` with `pathlib` segments
   (`"data" / "textures"`), a spelling the sweep did not cover. Repointed to
   `data/scene/textures`.
3. Surrogate grid discovery silently lost. The pinned GRAMSuite wrapper resolves
   `<planet>_surrogate.jls` by probing, after any caller roots, its own
   package-local `data/GRAM_surrogate`, then the adjacent SpaceAGORA
   `data/GRAM_surrogate`, then the bundled GRAM Suite grids. The move removed the
   adjacent candidate, so native-free grid construction without an explicit file
   no longer found SpaceAGORA's grids. The extension helper now supplies
   `data/planets/gram_surrogate` as a search root, but only when the wrapper's
   package-local grid for that planet is absent, so the selection order is
   unchanged: package-local, SpaceAGORA, bundled. Explicit `surrogate_file` values
   and caller-supplied `search_roots` are never altered. The wrapper itself is not
   modified.

Also covered by the hosted run on the previous head: the RPO navigation probe
asserted the former demo point-cloud suffix; it was repointed in 89057bce.

No behaviour changes beyond default paths were found in the three source files.
The surrogate preset catalog resolves grids through `Artifacts.toml` and is
unaffected. The three manifests at the `data/` root, the telemetry layout and the
GRAMSuite submodule pointer are unchanged. All 44 moved payloads keep their
blobs; `git lfs ls-files` lists the seven grids at the new path.

## P1 Assessment

Unresolved P1: No

The three findings above are repaired in this PR. No tolerance, threshold,
scientific setting, package pin or workflow requirement is relaxed. The remote
launcher syncs the SPICE stanza from its new repository path exactly as before;
remote-side tooling that expects the former path would need the new one, which
the PR body states.

## Residual Risk

The GRAMSuite wrapper still names the former adjacent directory in its own
candidate list; until the wrapper is updated to the new location, SpaceAGORA's
extension carries the compatibility logic. Users who call
`GRAMSuite.resolve_gram_grid_file` directly, rather than through SpaceAGORA's
grid model, must pass the relocated directory themselves. The Gateway station
mesh has no recorded provenance in the repository; the models README says so.
The terrain pipeline Python test needs the optional terrain tooling environment
and was not run on the author's machine; it runs in the hosted workflow.
