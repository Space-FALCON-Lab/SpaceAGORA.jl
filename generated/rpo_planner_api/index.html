RPO Planner API

This page documents the supported public interface available from SpaceAGORA.

RPO planner pilot

SpaceAGORA.SimulationModel.HYPRSupport.hypr_available — Function

Whether the optional HYPR implementation has been loaded in this process.

source
SpaceAGORA.SimulationModel.HYPRSupport.HYPRUnavailableError — Type

HYPR was selected before loading its optional companion package.

source
SpaceAGORA.RPOPlannerInterfaces.AbstractRPOPlanner — Type

An algorithm producing a timed target-relative RPO reference; a GNCAlgorithms.AbstractGNCAlgorithm of the RPOReferenceFamily.

source
SpaceAGORA.RPOPlannerInterfaces.RPOPlanningConstraints — Type

Explicit SI clearance and optional discrete reference speed/acceleration limits.

source
SpaceAGORA.RPOPlannerInterfaces.RPOValidationSettings — Type

Prospective software validation settings. Clearance is sampled on the reference polyline at spacing at most clearance_sample_ds_m, including endpoints. This is not continuous collision certification. The work cap rejects, never skips, checks that would exceed max_clearance_samples. Speed/acceleration comparisons allow at most 128eps(Float64) relative roundoff, with no absolute floor. Set limit_roundoff_rtol=0 for exact comparisons. Physical planning margin belongs in the adapter, not in this bounded software allowance.

source
SpaceAGORA.RPOPlannerInterfaces.RPOPlanningRequest — Type

Owned planning snapshot in SI units. x_rtn is rotating-frame relative position and velocity. Geometry must be static within a request and target-RTN aligned; a geometry provider supplies a new snapshot and revision for later requests. The caller retains a separate snapshot for validation; pass a deep copy to untrusted planner code. No integrator or live model belongs here.

source
SpaceAGORA.RPOPlannerInterfaces.RPOReference — Type

Owned candidate reference. Construction copies arrays; validation, rather than construction, diagnoses malformed algorithm output. Times are relative to origin_time_s. The only initial terminal policy repeats the last position AND velocity sample; it is not a stationary-hold guarantee.

source
SpaceAGORA.RPOPlannerInterfaces.RPOPlanningResult — Type

Algorithm outcome; :candidate still requires independent validation.

source
SpaceAGORA.RPOPlannerInterfaces.RPOPlannerCapabilities — Type

Capability declaration; an unimplemented planner supports nothing by default.

source
SpaceAGORA.RPOPlannerInterfaces.RPOValidationResult — Type

Pure validation outcome with a machine-readable reason and measured values.

source
SpaceAGORA.RPOPlannerInterfaces.RPOPlanningHeadroom — Type

Prospective adapter planning reserve. fraction reduces enabled physical limits before planning; it never changes the shared validator. At most one quarter of this reserve may be consumed by the scale-based Float64 resolution estimate. The default one-percent reserve is a policy, not a total-acceleration theorem. Every delivered reference must still pass independent validation.

source
SpaceAGORA.RPOPlannerInterfaces.planner_capabilities — Function

Declare planner capabilities without loading algorithm configuration.

source
SpaceAGORA.RPOPlannerInterfaces.initialize_planner — Function

Create fresh run-owned planner state. Stateless planners use nothing.

source
SpaceAGORA.RPOPlannerInterfaces.plan_rpo! — Function

Plan with the comparison mode's kernels under the request's clearance, reference step, lifetime and limits, never the comparison's fixed 0.5 m safety distance. Request limits with headroom cap the configured retiming limits as for HYPRRPOPlanner, and the returned path is timed with the configuration the kernel returned. The planner works without a wall-clock limit. A search that finds no path is :failed/:path_not_found; it never returns the direct-segment diagnostic as a candidate. The unchanged validator runs before a candidate is returned, which still requires lifecycle-owned validation.

source

Generate a candidate with an explicitly supplied random stream.

source
SpaceAGORA.RPOPlannerInterfaces.retime_rpo! — Function

Optional retiming hook. Unsupported retiming does not silently replan.

source
SpaceAGORA.RPOPlannerInterfaces.validate_rpo_result — Function
validate_rpo_result(request, result; clearance_at=nothing, time_s=request.time_s)

Validate a candidate without mutating either input or installing a plan. clearance_at(point_rtn_m, geometry) is a trusted geometry query supplied by the caller, NOT the planner. It returns finite signed clearance after the declared station/chaser approximation. Missing queries fail closed. Unexpected query exceptions propagate, rather than being mislabeled as infeasibility.

Clearance is sampled on the reference polyline, independently of any diagnostic control polygon. Speed checks cover declared velocity norms AND displacement between position samples per controller interval, reported separately. Acceleration is the norm of a velocity-vector finite difference, including changes in direction. These are reference checks, not physical tracking or derivative-consistency proof.

source
SpaceAGORA.RPOPlannerInterfaces.validate_rpo_capabilities — Function

Check declared capabilities. This contract does not implement run startup.

source
SpaceAGORA.RPOPlannerInterfaces.rpo_reference_is_current — Function

Check current and forecast times against the candidate's declared lifetime.

source
SpaceAGORA.DirectRPOPlanning.DirectRPOPlanner — Type

Direct segment with a cubic rest-to-rest time law. The assembly supplies a trusted analytic segment_clearance_at(start, goal, geometry) query for its declared geometry. Missing queries reject; this baseline does not find obstacle detours. max_reference_samples bounds allocation before building the timed reference.

source
SpaceAGORA.HYPRRPOPlanning.HYPRRPOPlanner — Type

Wrap a copied HYPR configuration. The physical request owns clearance and the reference interval. Enabled request limits cap the configured retiming limits using prospective headroom. Other settings and optimizer-returned adaptations are retained. rrt_on_replan explicitly enables the existing warm start for :replan requests. The adapter retimes an active reference (retime_rpo!); restart is not advertised.

source
SpaceAGORA.HYPRRPOPlanning.RetainedPathRPOPlanner — Type
RetainedPathRPOPlanner(path_rtn, config::RPOPSOConfig; endpoint_tolerance_m=1e-6,
    headroom=RPOPlanningHeadroom(), max_reference_samples=100_000)

Replay a saved geometric path, such as a published HYPR plan, instead of searching. path_rtn holds the path's 3 by N points in target RTN metres (N ≥ 2): the control polygon for a Bézier config.curve_type, the vertices for :polyline. config is the HYPR configuration the path was planned with. Both are copied.

For a request whose chaser position is within endpoint_tolerance_m of the path's first point, and whose goal is within it of the last, plan_rpo! sets those two points to the request's and times the path with the HYPR retimer. The request's clearance, reference step and limits are mapped onto config with headroom, as HYPRRPOPlanner maps them for a new plan. Otherwise it refuses (:infeasible, :start_not_on_path or :goal_not_on_path), and it refuses or fails for the same budget, lifetime and validator reasons as HYPRRPOPlanner. In a run, the timed reference still passes the lifecycle's validation before it is installed.

It draws no random numbers, declares no retiming or restart, and needs the HYPR companion.

source
SpaceAGORA.SimulationModel.GuidanceHooks.RPOPSOConfig — Type
RPOPSOConfig(; kwargs...)

Existing HYPR configuration, exported for explicit HYPRRPOPlanner assembly. It controls swarm counts, geometric cost/search, adaptation and reference retiming. The adapter copies it, maps the request's clearance/interval, applies the declared planning reserve, and retains optimizer-returned settings. The public pilot example shows a deterministic bounded configuration; its numerical limits are not defaults for arbitrary missions. Existing internal constructors retain their behavior.

source
SpaceAGORA.SimulationModel.GuidanceHooks.rpo_pso_config — Function
rpo_pso_config(config; overrides...)

Copy the existing HYPR configuration with explicit field overrides. This root alias preserves the existing configuration owner and calculations; pass the result to HYPRRPOPlanner. Request-owned limits and interval still apply at planning time.

source
SpaceAGORA.RPOPlannerLifecycle.RPOPlanningEvent — Type
RPOPlanningEvent(time_s; reason=:forced, token=1)

Deliver a request at the first accepted guidance tick at or after time_s. Reasons are :forced, :replan, or :retime. Positive tokens identify events; repeated delivery of one token is idempotent. Distinct tokens at one tick are separate requests. Retiming must be supported explicitly by the planner.

source
SpaceAGORA.RPOPlannerLifecycle.RPOPlanningError — Type

Planning failure with copied run diagnostics, original cause and backtrace; a GNCAlgorithms.GNCAlgorithmError.

source
SpaceAGORA.RPOPlannerLifecycle.make_rpo_configuration — Function
make_rpo_configuration(; planner, seed=741, start_rtn_m=(3,0,0),
    goal_rtn_m=(5,0,0), station_points_m=zeros(3,1), control_dt_s=0.1,
    mission_time_s=2.0, plan_validity_s=120.0, extra_effectors=(), ...)

Build a bounded Earth RPO pilot using public planner contracts: circular 420 km orbit, truth observations, zero initial rotating-RTN relative velocity, static RTN point-cloud geometry, inverse-square gravity, no atmosphere and LQ-MPC. The run returns the usual simulation solution; inspect it with rpo_run_report.

chasers may be a tuple of (id, start_rtn_m, goal_rtn_m) named tuples sharing one passive target (target_id=201). Each gets a copied planner and private RNG. This geometry checks the station only, not collisions between chasers. planning_events is a sequence of RPOPlanningEvent; optional positive replan_interval_s and tracking_error_limit_m enable background replanning. A failed request stops the run unless on_rejection=:install_fallback. HYPRRPOPlanner implements retiming; DirectRPOPlanner does not.

Three opt-in extensions, all off by default:

  • geometry_provider, an AbstractRPOGeometryProvider such as RPOReplanningSpheres, supplies each request's geometry and revision from the station geometry. When the revision changes, the chaser's remaining reference path is checked against the new geometry with the trusted clearance query, and replanned (:replan) only if it no longer clears it.
  • on_rejection=:install_fallback installs a hold at the chaser's position instead of stopping the run when a request is rejected. A hold is retried once the chaser settles on it (within hold_position_tolerance_m and hold_speed_tolerance_mps), renewed by a new request before it expires and replanned when the geometry revision changes; interval and tracking-error replans are suspended while it holds.
  • retime_tracking_error_m requests :retime when the tracking error exceeds it (and stays within tracking_error_limit_m). It needs a planner that declares retiming.

Run records mark these requests with event=:trigger.

Defaults: station keepout 0.25 m plus largest chaser half-extent 0.15 m; clearance 0.2 m; speed 0.5 m/s; reference acceleration 0.5*0.05/5.2 m/s². The controller uses a 12-step preview. extra_effectors extends the existing force interface. isolate_state=false is refused at startup; a checkpoint holds the planners' and controllers' run state, and a resumed run continues from it. simulation_settings/solver_config may use their existing public types. Only the default :tsit5 route is validated for this lifecycle; other solver modes are outside the pilot. The first control update needs 13 steps of validity, although the constructor accepts 12; periodic replanning also needs to cover the interval to the next guidance tick plus the 12-step preview. Events with no eligible tick before the mission end remain undelivered; inspect the run report. This is a reference/tracking demonstration, not a certified rendezvous model.

source
SpaceAGORA.RPOPlannerLifecycle.rpo_run_report — Function
rpo_run_report(solution)

Return copied planner requests, validation, references, stream identities, controller commands and sampled states from an isolated run_simulation result. This pilot reports reference acceptance; it does not certify physical tracking.

source
SpaceAGORA.RPOPlannerInterfaces.AbstractRPOGeometryProvider — Type
AbstractRPOGeometryProvider

Supplies RPO request geometry that changes during a run, such as obstacles that appear and disappear. A provider implements rpo_geometry_revision and rpo_geometry_snapshot. The binding takes one owned snapshot per request, so the geometry stays static within a request and validation uses the request's copy. Equal revisions must mean equal snapshots.

source
SpaceAGORA.RPOPlannerInterfaces.rpo_geometry_revision — Function
rpo_geometry_revision(provider, revision, time_s) -> String

Required for each provider: the nonempty revision of the geometry at simulation time time_s (s), given the configured base revision. The binding calls it at every guidance tick, so it must be cheap and deterministic, draw no random numbers and change whenever the snapshot changes.

source
SpaceAGORA.RPOPlannerInterfaces.rpo_geometry_snapshot — Function
rpo_geometry_snapshot(provider, geometry, time_s) -> geometry

Required for each provider: the geometry at simulation time time_s (s), given the configured base geometry, which it must not modify. The binding calls it to build a request and, when the revision changes, to check the installed reference's remaining path against the new geometry.

source
SpaceAGORA.RPOPlannerLifecycle.RPOReplanningSpheres — Type
RPOReplanningSpheres(spheres; sphere_surface_samples=96, observation_window_s=0.0)
RPOReplanningSpheres(config::GuidanceHooks.RPOReplanningConfig)

A geometry provider (AbstractRPOGeometryProvider) for spherical obstacles that appear and disappear during a run, built with rpo_active_replanning_spheres and rpo_geometry_with_replanning_spheres. Each sphere is a GuidanceHooks.RPOReplanningSphere or a named tuple with center_rtn (m) and radius_m, and optionally appear_time_s, disappear_time_s (s), velocity_rtn_mps and label. A sphere is active from its appearance until observation_window_s after its disappearance. The snapshot adds sphere_surface_samples surface points of each active sphere to the station point cloud. The revision is the base revision, then +spheres: and the active spheres' positions in spheres; while an active sphere moves, the snapshot time follows @, so each time has its own revision. With no active sphere it is the base revision and geometry. The second form uses the spheres, surface samples and observation window of an existing RPOReplanningConfig.

source
SpaceAGORA.SimulationModel.GuidanceHooks.HYPRComparisonPlanner — Type
HYPRComparisonPlanner(config=<comparison HYPR configuration>; headroom, max_reference_samples)

The :hypr mode of the RPO planner comparison: HYPR's swarm optimizer with every feature config enables. It holds a copy of config, an RPOPSOConfig, which also sets the cost and the retiming of the planned path. The default is the comparison's tuned configuration with its 0.5 m safety distance.

As an AbstractRPOPlanner, plan_rpo! plans under the request's clearance, reference step and limits; headroom and max_reference_samples have the meaning they have for HYPRRPOPlanner. This is a comparison mode, not a replacement for HYPRRPOPlanner: it does not retime and has no replan warm-start option. All seven comparison planners need the optional HYPR companion and draw from the planner's random stream.

source
SpaceAGORA.SimulationModel.GuidanceHooks.UnrefinedPSOPlanner — Type
UnrefinedPSOPlanner(config=<comparison HYPR configuration>; headroom, max_reference_samples)

The :pso_unrefined comparison mode: the HYPR swarm kernel of HYPRComparisonPlanner with refinement, adaptation, scheduling, stagnation learning, the RRT warm start, culling and re-exploration switched off when it plans. The other settings come from its copy of config.

source
SpaceAGORA.SimulationModel.GuidanceHooks.RRTConnectPlanner — Type
RRTConnectPlanner(settings=RPORRTConnectSettings(); config, optimizer, headroom, max_reference_samples)

The :rrt_connect comparison mode: bidirectional RRT-Connect with the search settings, scored, refined and retimed with config (an RPOPSOConfig, default the comparison's HYPR configuration). optimizer, an RPOTrajectoryOptimizerSettings, supplies the comparison's iteration policy: match_hypr_iters takes the iteration count from config, and runtime_max_iters replaces it when the comparison sets a finite runtime limit.

source
SpaceAGORA.SimulationModel.GuidanceHooks.RRTConnectBezierPlanner — Type
RRTConnectBezierPlanner(settings=RPORRTConnectSettings(); config, optimizer, headroom, max_reference_samples)

The :rrt_connect_bezier comparison mode: the RRT-Connect search of RRTConnectPlanner, with its path refitted as a Bezier curve under config. The keywords are those of RRTConnectPlanner.

source
SpaceAGORA.SimulationModel.GuidanceHooks.RRTStarPlanner — Type
RRTStarPlanner(settings=RPORRTStarSettings(); config, optimizer, headroom, max_reference_samples)

The :rrt_star comparison mode: RRT* with the search settings, scored, refined and retimed with config. The keywords are those of RRTConnectPlanner.

source
SpaceAGORA.SimulationModel.GuidanceHooks.CHOMPPlanner — Type
CHOMPPlanner(settings=RPOCHOMPSettings(n_iters=config.n_iters); config, optimizer, seed, headroom, max_reference_samples)

The :chomp comparison mode: a CHOMP-like covariant gradient optimizer with settings, under the cost of config and the obstacle, stopping and iteration settings of optimizer. The optimizer is deterministic, but its initial path is an RRT-Connect search with the seed settings (an RPORRTConnectSettings) drawn from the planner's random stream, unless the comparison supplies a warm start.

source
SpaceAGORA.SimulationModel.GuidanceHooks.STOMPPlanner — Type
STOMPPlanner(settings=RPOSTOMPSettings(n_iters=config.n_iters); config, optimizer, seed, headroom, max_reference_samples)

The :stomp comparison mode: a STOMP-like stochastic optimizer with settings, started from an RRT-Connect path as for CHOMPPlanner. The seed search draws from the planner's random stream before the rollouts do. The keywords are those of CHOMPPlanner.
