# AI Review Artifact — PR #117

## Scope
The CLI launched every child process with `--project=<repository>/.AGORA`, an untracked, machine-local directory that no setup step creates any more, so the `telemetry` and `benchmark` subcommands and any example that loads the package directly failed on every checkout without that directory. Children now run under the repository project. Scope: the launcher, one regression testset, one paragraph of the CLI page.

## Changed Files
- src/cli/spaceagora_cli.jl — `DOT_AGORA_PROJECT` replaced by `CHILD_PROJECT = REPO_ROOT`; `_run_subprocess` launches every child with `--project=$CHILD_PROJECT` and prints that project on the `--print-only` `project=` line. A comment records why the old directory was wrong and why examples that include `examples/common.jl` hid the defect.
- test/suites/08_cli_and_assets_tests.jl — new testset "CLI children run under the repository project": a probe script that does `using SpaceAGORA` without activating anything is launched through `run --example=<path>` with the child's `JULIA_LOAD_PATH` reduced to `@`, and must report the repository's `Project.toml` and `src/SpaceAGORA.jl`; the `--print-only` output of `run`, `telemetry` and both `benchmark` modes must name the repository project on the `project=` line and inside the `cmd=` line (normalised paths) and must not mention `.AGORA`.
- docs/src/cli.md — one paragraph stating that children run under the repository project and what `--print-only` prints.

## Findings
- P1 (the defect this PR fixes): a child launched with a missing project directory gets an empty project and cannot load SpaceAGORA. Reproduced on a fresh clone of `main` at `80240c2b`: the probe child exits 1 with "Package SpaceAGORA not found in current path" and `--print-only` shows `project=<clone>/.AGORA`. On this branch the same probe exits 0 and reports `<checkout>/Project.toml` and `<checkout>/src/SpaceAGORA.jl`, from inside and from outside the repository. Resolved.
- P2: the regression must not be satisfiable by anything but the project the CLI hands the child. Two ways the original defect could be hidden are closed: the probe loads the package directly instead of including `examples/common.jl` (which re-activates the repository project), and the child's load path is reduced to `@` so a globally installed or dev'd SpaceAGORA cannot resolve the import. Checked: the same probe fails on unmodified `main`.
- P2: the printed launcher must agree with what launches. The testset parses the `project=` line and the `--project=` token of the `cmd=` line and compares both to the repository root after normalisation (the root can carry a trailing slash).
- P3: other `.AGORA` references remain outside the launcher: the telemetry plotting subprocess prefers `.AGORA` only when it exists and otherwise uses the repository root (unaffected); several benchmark studies keep `.AGORA` in candidate lists or as a hard-coded project, and the calibration sub-package defaults to it. Benchmark and calibration settings are outside this PR; they are listed in the PR body for their owners.
- P3: the fix changes which project the children get, not what they need. On a fresh clone without the GRAM submodule the `telemetry` and `benchmark` children still stop on their GRAMSuite prerequisite; that is reported separately in the PR body and is unchanged by this PR.

## P1 Assessment
One P1, the launcher defect, resolved by this PR and covered by the regression. Unresolved P1: No

## Tests Added/Updated
- test/suites/08_cli_and_assets_tests.jl: testset "CLI children run under the repository project" (child launch with a reduced load path; printed-versus-launched project for four subcommands).
- Manual: the standalone form of the regression against a fresh clone of `main` (fails) and against this branch (passes); the probe launched from a working directory outside the repository; suite 08 in full locally (59 assertions pass); docs build and the docs contract gate.

## Residual Risk
Low. The change is one constant and its two uses. The remaining risk is environmental: a checkout whose repository project is not instantiated fails in the child exactly as `julia --project=.` would, which is the intended behaviour.
