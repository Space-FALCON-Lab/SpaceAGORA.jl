# AI Review: PR 259

Review date: 2026-10-10. A read-only correctness review of `466c26d35` against main `74aa38045`. The accepted findings are fixed in the commit that adds this record, which the record covers.

## Scope

The PR fuses the harmonics-only flat RHS into one parallel region and adds an opt-in spin-barrier pool for it (`SPACEAGORA_HARMONICS_BATCH_SPIN_BARRIER=1`), whose workers yield every 1024 polls. It also adds a per-region thread-width search, on under the adaptive policy (`SPACEAGORA_RHS_REGION_WIDTH`).

The review read every changed src hunk and traced callers, pool keying and teardown (`with_policy_context`). It checked the `_publish_initial_force_outputs!` call sites from b1ce5032e and the mutable `ODEParams` from #254. It compared closure boxing between main and this branch with `Meta.lower`. It ran 1- and 2-thread probes of SIGTERM and exit behaviour, bit identity, and per-call allocation.

## Findings

- **Fixed (P2, adaptive policy only).** With the width search on, the harmonics, aero and flat-queue regions recorded their cost-model and policy observations under `plan.allotment`, even when the search had run the call narrower. The policy could learn width-1 timings as allotment-N timings.
  - `_rhs_region` now records each call's width in `RhsRegionTuner.last_width`.
  - Observations are recorded only for calls that ran at the full allotment (`_rhs_region_ran_full`). The 1024-call reprobe keeps full-width observations flowing.
  - Results are unaffected; this concerns only how the adaptive policy learns.
- **Fixed (P3).** In the flat queue, `packet_count`, assigned twice and captured by the region closure, was boxed: one heap allocation per call and an `Any` argument. A single-assignment copy (`n_packets`) is now captured instead.
- **Fixed (P3).** `SPACEAGORA_RHS_REGION_WIDTH` silently treated unknown values as `auto`. It now throws an `ArgumentError`, as other boolean settings in the package do.
- **Fixed (P3).** Stale comments:
  - the fused-route comment named a function that does not exist;
  - the finisher comment said `ODEParams` is immutable (no longer true after #254);
  - the `RhsRegionTuner` block was inserted between `SharedBuffers`' doc comment and the struct it documents, so the block was moved above the comment.
- **Recorded (P2, opt-in only).** Spin pools are torn down only by `run_simulation` (`with_policy_context`). A flat RHS called directly outside that scope with the spin barrier on leaves nthreads−1 spinning tasks for the life of the process.
  - The review found that this does not block SIGTERM or a normal exit: termination took 1 s and exit 0.6 s at 2 threads, while JIT-compiling, sleeping and exiting.
  - The spin barrier stays off by default.
- **Recorded (P3).**
  - The harmonics pre-pass closure still captures the harmonics model by value, at about 7.5 kB of the roughly 19.5 kB allocated per fused call at 37 spacecraft.
  - The width search reads the raw adaptive flag rather than the run's snapshot. Under `SPACEAGORA_ADAPTATION_GATE=1` or `SPACEAGORA_RHS_IDENTIFY` it stays on.
  - The harmonics workspace pool grows and never shrinks; it is bounded, and the code comments on it.
  - `_try_assign_flat_translational_rhs_direct_layout!` has no src caller left.

## P1 Assessment

No change to physics or results was found. Derivatives stayed bit-identical in every probe, including 3000 calls with the search changing widths between 1 and 2, with inactive gaps. The spin barrier is off by default, and the SIGTERM hang suspected earlier did not reproduce on the opt-in path.

Unresolved P1: No

## Residual Risk

- **Bit identity across widths** depends on every routed region writing per-spacecraft slots in a fixed order. Effector or atmosphere code with per-instance state, such as GRAM perturbation history or pooled GRAM handles, would make results depend on which worker ran which spacecraft. The GRAM isolated pool is excluded from the search for that reason, but those internals were not audited further.
- **Test coverage:**
  - the aero, atmosphere-prefill and packet-queue regions are not tested under the search;
  - widths above 2 are not tested locally;
  - concurrent solves with the spin barrier on are not tested; each creates its own spinners and would oversubscribe threads.
- **Performance at 16–32 threads** was measured on the 64-core benchmark machine (Threadripper PRO 9985WX), not in this review.
