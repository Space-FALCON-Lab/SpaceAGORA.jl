## Findings

No P1 or P2 findings.

Found by an outside review and fixed (2a9981eb4):

- P3: "one entry per checkpoint segment" meant one per segment solved. The docstring now says so, and that `retcode` and `solution` are the last solved segment's; a run stopped by a termination event in its second of three segments returns two entries and `"Terminated"`.
- P3: "at the mission end" also holds past it. A run resumed from a checkpoint at or past the mission end solves nothing, and the docstring now names all three results: `retcode` and `solution` are `nothing` and `solver_trace` is empty.

Points a reviewer should check:

- **What the docstring states:**
  - one `solver_trace` entry per segment solved;
  - the last solved segment's `retcode`, and its `solution` with `return_solution=true`;
  - for a run resumed from a checkpoint at or past the mission end, `retcode` and `solution` are `nothing` and `solver_trace` is empty.

  This matches the metadata return in `run_simulation`:
  - `_solve_run_interval!` pushes one trace entry per solve, and a solver fallback is recorded inside that entry;
  - the checkpoint loop solves once per segment. A run that an event stops early ends in the segment where it stopped, so it has one entry per segment it reached;
  - `last_sol` is the last solved segment's solution, and stays `nothing` when no segment is solved.

  The in-code comment at the return says to test the mission rather than the field, now "at or past mission end".
- **The moved sentence:** `return_results=true` with `return_solver_metadata=true` still throws the same `ArgumentError`, and the existing test of it is unchanged. The user guide (`docs/src/user/outputs.md`) already states the restriction this way.
- **Other text:** no other docstring or page said checkpointing and solver metadata cannot be combined.

## Tests Added/Updated

Added to `test/unit/simulation_results_tests.jl`, "Solver metadata of a checkpointed run" (7 tests):

- A checkpointed run (1200 s segments over 3600 s) returns `retcode == "Success"`, `solution === nothing` and three trace entries.
- Stopped by a termination event in its second segment, it returns `"Terminated"` and two trace entries.
- With `return_solution=true`, the solution spans the final segment (2400 s to 3600 s).
- Resumed from its final checkpoint, into the same 3600 s mission and into a 2400 s one, the run returns `retcode === nothing`, `solution === nothing` (with `return_solution=true`) and an empty trace.
- Resumed with the mission extended to 4800 s, the run returns `"Success"` and one trace entry.
