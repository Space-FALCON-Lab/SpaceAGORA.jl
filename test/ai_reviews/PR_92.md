# AI Review — PR #92: Remove orphan source files and the dependencies only they used

## Scope

Second Phase A item of the September 2026 structure audit. The PR deletes six `src/` files that the package never loads (an include-graph walk from `src/SpaceAGORA.jl` never reaches them, and a repo-wide grep finds no consumer of any symbol they define), removes the one dead include that pulled one of them into a live module, drops the seven `Project.toml` dependencies that had no remaining symbol use, and updates the gate entry, allowlist entry, contract sentences, sysimage package lists and Copilot workflow that pinned the removed pieces. Reviewed: every deleted file's definitions against the tracked tree, the four modified `src/` files line by line, the Manifest diff, and the gate/contract edits.

## Changed Files

- `src/dynamics/coupled/perturbations.jl` — drops `using AssociatedLegendrePolynomials` (no exported name of that package is used; the harmonics code carries its own fully-normalized Legendre filler) and the `include` of `environment/ephemerides/planet_data.jl` (the included `planet_data(ip)` had no caller and required a `Planet` type that no longer exists). No executable line changes.
- `src/core/interfaces/reference_system.jl` — drops `using SatelliteToolboxTransformations`; the file's only references to that package are commented-out code and a docstring, and the live `ned_to_ecef` calls elsewhere resolve through `using SatelliteToolbox`, which re-exports the transformations.
- `src/gnc/guidance/aerobraking/t_edg/eom_predictor.jl` — drops `using PreallocationTools` and the commented-out `get_tmp` line; the package was never called.
- `src/gnc/guidance/aerobraking/t_edg/trajectory_predictor.jl` — drops `using PreallocationTools`; never called.

Deleted (not counted by the gate's Added/Modified/Renamed filter): `src/mission/operations/attitude_control_plans.jl`, `src/gnc/control/attitude_control_models.jl`, `src/io/outputs/save_csv.jl`, `src/core/utils/misc.jl`, `src/environment/ephemerides/planet_data.jl`, `src/mission/initial_conditions.jl`, plus `CondaPkg.toml`.

## Findings

- P3 — `src/mission/initial_conditions.jl` was required to exist by `test/gates/ci_architecture_contract_gate.jl` as the "mission configuration owner" while owning nothing (two functions with zero callers). The gate entry is removed and the two contract sentences (`docs/architecture/canonical_topology_contract.md`, `docs/architecture/src_completeness_contract.md`) now name where initial-state definitions actually live (`src/vehicle/spacecraft/model.jl`).
- P3 — `src/environment/ephemerides/planet_data.jl` was on the raw-include allowlist of `test/gates/ci_no_legacy_include_chains_gate.jl`; the entry is removed with the file.
- P3 — `scripts/plotting/plot_data.jl` included `src/core/utils/misc.jl` by relative path; the include line is removed. The script was already unrunnable as written (its `using .SimulationModel` cannot resolve) and is left otherwise untouched.
- Verified no behaviour change: the four modified `src/` files lose only `using` lines, one dead include and one comment. The Manifest diff is exactly the eight pruned entries (the seven packages plus Hungarian, LinearMaps, MatrixPencils, Polynomials, which only they required) and the project hash; stdlib pins were restored to the values on `main` after `Pkg.resolve` had rewritten them for the local Julia patch version.
- Out of scope, noted for follow-up: `Quaternions` is also unused in `src/` but its bare `using` lines live in the test harness files that PR #91 rewrites; `LoopVectorization` is still imported by `src/simulation/engine/setup.jl` without use (that file is under active change in PR #90).
