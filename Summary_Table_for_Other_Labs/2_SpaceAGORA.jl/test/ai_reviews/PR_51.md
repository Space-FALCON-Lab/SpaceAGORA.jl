# AI Review — PR 51: CYGNSS replication fixes (ram-face convention, NRLMSISE-00 source, tolerance env vars, EI guard, altitude convention)

## Scope
Review of the simulator/harness changes required so the CYGNSS 48-hour verification campaign can be replicated from the public tree alone (study drivers and mission data stay in the private telemetry archive). Five changes: (1) the opt-in `bus_ram_face` reference-area convention in the spacecraft builder; (2) `atmosphere_truth.atmosphere_model = "nrlmsise00"` as a first-class scenario density source; (3) honoring the `SPACEAGORA_TELEMETRY_{RELTOL,ABSTOL}_{ORBIT,ATM}` env vars (tighten-only); (4) a warning when a drag-enabled scenario starts above `EI_km`; (5) the oblate/geodetic altitude convention in the CYGNSS reference builders. Focus areas: backward compatibility of every previously calibrated scenario (odyssey, vex, earth_gmat must be unchanged) and that no change can silently loosen the CI accuracy gate.

## Findings
- P2 (fixed during the campaign): the tolerance env vars were set by existing callers (`test/gmat_scenario_matrix.jl`, the 96-hr sweep worker) but silently ignored by `_with_study_settings`, so "tightened" runs ran at the study defaults. They are now honored with tighten-only semantics: `min(env, study base)`, so an env var can never loosen the gate past the strict caps.
- P2 (fixed): a drag-enabled scenario whose orbit sits above `EI_km` has its aero force silently zeroed by the entry-interface gate on the split/implicit solver paths (the failure mode that would zero drag for any LEO scenario copied from an entry example). `_make_time_aligned_args` now warns once with the two altitudes.
- P2 (fixed): the CYGNSS reference builders computed the `altitude_km` channel as vacuum `r − Rp_e` while the scenarios score the oblate/geodetic channel — a latitude-dependent inconsistency of up to ~21 km in the altitude error rows. All three builders now use the shared `_telemetry_altitude_km(..., :oblate)` helper.
- P3 (accepted): `"nrlmsise00"` constructs `NRLMSISE00AtmosphereModel(use_space_indices=true)`; the CelesTrak dataset initializes lazily on first evaluation and needs network access then. Construction and manifest parsing are offline-safe; no bundled manifest uses the source, so CI is unaffected.
- P3 (accepted): the `:frontal` ram-face convention is correct for the translational fixed attitude (flow along body +x). With `orientation_sim=true` the ram face changes with attitude and neither static convention is exact; documented in the builder comment, out of scope for the fixed-attitude harness.
- P3 (accepted): the EI warning only covers Cartesian-IC time-aligned scenarios; Keplerian orbit-events scenarios (aerobraking) legitimately cross EI and are excluded by design.
- No P1 findings.

## P1 Assessment
No P1 findings were identified. Every default path is unchanged: `:legacy` preserves the historical bus `ref_area` and is the default in the struct, kwarg, and manifest parser; the density source defaults to `"GRAM"`; with the env vars unset the tolerances are bit-identical to before; the env vars can only tighten; the altitude-convention change touches only the CYGNSS reference builders, which are private-data-gated and not part of the default CI matrix.
Unresolved P1: No

## Tests Added/Updated
- `test/probes/coverage_parallel_telemetry_probes.jl` — "Spacecraft builder ram-face convention" testset (6 assertions): `:legacy` produces the historical bus `ref_area`, `:frontal` the flow-normal face, panels unchanged in both modes, unknown symbols throw, `SpacecraftConfig` default stays `:legacy`.
- `test/probes/coverage_parallel_telemetry_probes.jl` — "Replication guards: density source and tolerance env vars" testset: manifest whitelist accepts `"nrlmsise00"` and rejects unknowns; the scenario builder returns `NRLMSISE00AtmosphereModel` for Earth and throws for other planets; the tolerance env vars tighten (`1e-9` honored) but never loosen (`1e-3` clamped back to the `1e-7` study base).
- `test/probes/coverage_parallel_telemetry_probes.jl` — "Scenario builder branch probes (coverage backstop)" testset: pins the planet/N-body name mappings and the tabulated-flight density builder (synthetic two-pass table with an archive gap, both legs, nonpositive-density skip, missing-file and missing-column throws) from the in-process probe file. Rationale: the CI coverage gate's active-window filter can drop scenario-suite worker coverage, which made `scenario_builders.jl` file coverage nondeterministic; these probes keep it above the 80% floor from the gate's own process.
- Full probe file run locally: all testsets pass.

## Residual Risk
- The lazily initialized CelesTrak space-indices download is exercised only when a user actually runs an `"nrlmsise00"` scenario; a first-run failure surfaces as the SatelliteToolbox init error, not a harness error.
- `bus_ram_face` is intentionally not surfaced in published example specs; only the private CYGNSS geometry TOML uses `"frontal"` today.
- The campaign's study drivers live in the private telemetry archive (`campaign_drivers/productized/`) and are exercised manually there; the public tree carries only the simulator/harness capabilities they need.
