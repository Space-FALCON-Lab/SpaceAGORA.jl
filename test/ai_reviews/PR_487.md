# Review record: PR 487: remove the unwired RHS-plan predictor

## Scope

Review of the SpaceAGORA `remove-unwired-cost-predictor` branch against main
`25355f3a9`, for 0.6.0. It is C-4c of the constellations track (the C-4
campaign-results design, 2026-10-21: §4.1 and decisions D-C4-9 and D-C4-10).
The branch was built on PR 485 (`calibration-table-bounds`), which edits the
same folder, and merged main after PR 485 merged; against main it shows only
this change. It also carries two P3 follow-ups from PR 485's review.

On main, `SimulationModel.ParallelCost` held an analytic predictor of one RHS
pass's cost under a candidate execution plan:
- `cost_predictor.jl`: `PlanCandidate`, `PlanPrediction`, `predict_plan_ns`,
  `plan_candidates`, `select_plan` and `LOCK_CONVOY_ABSTAIN_RATIO`;
- `work_counts.jl`: `constellation_work_counts`, the `effector_cost_terms`
  methods, `model_in_cost_domain`, `flat_queue_node_effector`, the `_cost_*`
  aliases of the `EffectorRouting` predicates and `_alf_recurrence_iterations`;
- `effector_probe.jl`: `EffectorProbe`, `validate_declaration`, `probe_ns_map`;
- in `cost_terms.jl`: `WorkCounts` with its `+` and `zero`,
  `workload_usl_parameters` and the fallback `effector_cost_terms`;
- in `SimulationEngine` (`rhs_cost_probe.jl`): `probe_effector_costs!` and
  `warn_on_declaration_mismatch`.

Its own header said it was "NOT WIRED INTO ANY ROUTING PATH". Nothing in `src`
called it, `SpaceAGORA` imported none of the names, and no page documents them.
A usage inventory of the companions and the lab's private repositories
(2026-10-21) found no maintained user outside core: only frozen copies of core
trees, retained audit probes and data records. So the names are removed in
0.6.0 with a "Removed" release-notes line and no warning release (D-C4-10).

Kept, because live code reads them:
- `probe_contention_inputs!` and `ContentionInputs` with `lock_duty_cycle`:
  the native-lock width cap (`engine/execution.jl`). The probe's file is
  renamed `contention_probe.jl`;
- `MachineConstants`, the calibration, `usl_speedup`, `usl_peak_workers` and
  `_fit_usl`: the predictive campaign planner and the RHS calibration;
- robust timing: the RHS calibration.

Also removed, as it lost its only reader: `ContentionInputs.workspace_bytes_per_sat`
and `probe_contention_inputs!`'s keyword of that name. Only
`workload_usl_parameters` read the field, and the width cap never passed the
keyword.

The two follow-ups from PR 485's review:
- P3-1: the batch kernel's comment said that, thanks to the counter, "no touch
  pays for an integer division"; the workspace index already takes one per SIMD
  pass. It now says the wrap adds no integer division.
- P3-2: `benchmarks/studies/paper_parallelization_benchmarks/targeted_points.sh`
  warned only when no constants file existed. After PR 485 a file written under
  schema 4 still exists, but the predictive planner ignores it, and only a
  `SolverConfig(parallel=true)` run measures it again, which these jobs never
  do. The script now checks by loading the constants the way the planner does,
  so a missing, unreadable or old-schema file warns. It still only warns: the
  script deliberately does not calibrate on a machine about to run timed jobs.

This PR's own review asked for five more (P3-1 to P3-4 and P3-6), in
`a1ffce89a`:
- P3-1: `contention_probe.jl` was covered only by the direct test's success
  path. Suite 02 now also checks a warm-up pass that throws and a measured pass
  that throws after the warm-up succeeded.
- P3-2: the width cap catches any error from its call to the probe and logs it
  only at debug level. That behaviour is unchanged; a cap-on solve in suite 02
  now asserts that no "contention probe failed" record is logged, so a changed
  call fails a test.
- P3-3: the removed probe-route test held the only field-for-field check that
  the flat route's state sample, rebuilt from its buffers, is the one built
  from the state. The check is kept, without the probe, in
  `rhs_direct_assembly_tests.jl`.
- P3-4: two docstrings in `machine_calibration.jl` and the header of
  `scripts/calibration/calibrate_machine.jl` no longer describe the predictor.
- P3-6: `targeted_points.sh` names the constants file it checked
  (`SPACEAGORA_COST_CONSTANTS_PATH` can move it) and reports a failed Julia or
  package start as such, rather than as missing constants.

## Findings

No P1 or P2 findings in the change. Points a reviewer should check:

- Every run is unchanged. No code a run executes called the removed names
  (`git grep` over `src` and `ext` before the change). The width cap calls the
  same `probe_contention_inputs!` and reads the same `lock_duty_cycle`. The
  dropped field was read only by the removed `workload_usl_parameters`. The
  fingerprints in Tests confirm it.
- Low: the names lived in the internal module `SimulationModel.ParallelCost`
  (and two in `SimulationEngine`), which `SpaceAGORA` does not import. Code
  that reached into the module for them now gets an `UndefVarError`, and code
  that passed `workspace_bytes_per_sat` to `ContentionInputs` or
  `probe_contention_inputs!` gets a keyword error. The inventory found no such
  maintained code. Two retained audit probes from 2026-09-15 in the private
  telemetry repository would throw if rerun on 0.6.0; they are historical.
- Low: the `effector_cost_terms` docstring invited users to extend
  `SpaceAGORA.effector_cost_terms`, which never resolved, because `SpaceAGORA`
  does not import the name. The docstring goes with the function.
- Low: `targeted_points.sh`'s check now starts Julia and loads SpaceAGORA once
  per job, where it used to list a directory. On the benchmark box the package
  is precompiled for the job's project, so the check reuses that cache.
- Low, wording: the `load_machine_constants` and `constants_are_current`
  docstrings and the header of `scripts/calibration/calibrate_machine.jl` no
  longer describe the predictor. Left for the calibration trim, which rewrites
  them with the constants they describe: the `MachineConstants` field docs, the
  headers of `machine_calibration.jl`, `calibration_kernels.jl` and
  `robust_timing.jl`, and the comments on the reference kernels in
  `robust_timing.jl` and on the USL and dispatch ladders in
  `machine_calibration.jl`. After this change only `usl_alpha_base` and
  `usl_beta_alloc` (and `measured_threads`) have a reader; the
  `MachineConstants` docstring now says so. Trimming what `calibrate_machine`
  measures is a planned follow-up with its own schema step.
- Coverage moved, not lost:
  - the only behavioural test of the live `EffectorRouting` predicates was the
    second half of `cost_work_counts_tests.jl`, written against the `_cost_*`
    aliases and `flat_queue_node_effector`. It is rewritten against
    `EffectorRouting` and the engine (see Tests);
  - `probe_contention_inputs!` had no direct test. The width cap calls it
    inside a `try` that turns any failure into "no constraint", so a solve with
    the cap on passes even if the probe is gone. Suite 02 now calls it
    directly, on its success and failure paths, and a cap-on solve checks that
    the cap's call does not fail;
  - the removed probe-route test also checked, field for field and with
    attitude off and on, that the flat route's state sample rebuilt from its
    buffers is the one built from the state. That check is kept in
    `rhs_direct_assembly_tests.jl`.
- `git merge-tree` against the open PRs that share a file with this branch
  (#476, #478, #479, #482; they share only `test/unit/runtests.jl` and
  `.github/ci-shards.toml`) is clean. #477 has since merged, with the main
  merge.

## Residual Risk

- Out-of-tree code that reached into `SimulationModel.ParallelCost` for the
  predictor's names breaks loudly on 0.6.0. The inventory covered the
  companions, the lab's repositories and the local folders at their branch
  tips, not every clone. The release notes name the removed functions.
- The calibration still measures constants that nothing reads after this
  change, and the first `parallel=true` run on a machine pays for them until
  the calibration trim lands.
- The width cap still treats any error from its call to the probe as "no
  constraint", logged at debug level. The cap-on test catches a call that fails
  for its run; a probe that failed only on other workloads would still go
  unnoticed. Changing the catch is left out of this PR.
- Outside `targeted_points.sh`, a predictive-planner run that does not go
  through `SolverConfig(parallel=true)` (profile R7 set by hand) still plans
  without constants when the saved file predates PR 485's schema. A release
  note tells users to rerun `scripts/calibration/calibrate_machine.jl` on such
  machines.
