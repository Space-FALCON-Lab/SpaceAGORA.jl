## Findings
- P2: the pre-solve RHS sweep's verdict flips between plans on some shapes at high thread counts (TRX50, 24 threads: `satellite_batch` vs `flat@4` on the same 256-satellite GRAM-surrogate case from two cold stores). Bounded, not removed: a pin is honoured only once two sweeps agree, a flip retains the heuristic, and votes accumulate across pins, so a bucket converges on the heuristic after three indecisive sweeps (record §3.3 J/K, §4.5a). The in-run width trial was measured as an alternative and is 1.5–2× worse on those shapes.
- P2 (fixed on this head): the calibration store is rewritten whole on save, and `_rhs_calib_load!` marked the cache loaded regardless of which path it loaded; a mid-process change of `SPACEAGORA_RHS_CALIBRATION_PATH` therefore truncated the real store to the in-memory entries — three times on 2026-09-08 (twice by a test isolation block during merge testing, once by the coverage run of the default entrypoint at four threads). The cache now records its source path (`_rhs_calib_loaded_path`), a path change empties and reloads it, and `_rhs_calib_save!` refuses to write a cache that mirrors another file; a cache marked loaded by hand adopts the current path so tests that inject entries keep working. Verified by `test/unit/parallel/rhs_store_path_tests.jl` and by a full entrypoint run against a seeded copy of the 79-verdict store, which came through byte-identical.
- P2: the harness's median-of-repeats metric lands on an exploration campaign for any rounds-tie shape (cold, two per arm, then exploit); the record reports the steady figure alongside. Not a behaviour defect.
- P3: the first process-pool campaign in a process still costs ~1.5 s over the static pool path's cold start on both machines after precompiling the dispatchers; the remaining specialisation is on the caller's sample closure.
- P3: the analytic cost model's cold-validation gate is documented as failing at 20 %; the model is not on the routing path and does not affect any decision this PR ships.
- P3: `data/Gravity_harmonics_data/titan5.csv` as tracked on `main` differs from a local headered copy that the branch's `_read_harmonics_source_metadata` would read; as checked in, Titan falls back to the planet's own radius and GM. Data ownership question, not code.

## Residual Risk
Medium, concentrated in two places. (1) The calibration store's whole-file save is now guarded by the loaded-path check; the residual risk is a caller that marks the cache loaded by hand at one path and saves at another, which no shipped code does. (2) The sweep's verdict instability on high-thread-count shapes means the first two or three long solves of a new shape on a new machine may run a re-sweep each (bounded by the two-agreeing-sweeps rule and the vote carry-over); on a persistent store this is a one-time cost per shape per machine. Everything measured on a warm store on both machines is at parity with or ahead of the best static route (record §4.5, §4.5a). The `main` merge itself was verified file by file (six conflicts; the GRAMSuite submodule pointer stays at the branch's because `main`'s is unpushed) and the full gate suite, unit runner and default entrypoint were green on the merged head.
