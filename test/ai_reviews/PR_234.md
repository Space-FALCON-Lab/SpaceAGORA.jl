# AI Review Artifact — PR #234

## Scope
Compliant attachments, stacked on PR #233. A `CompliantMultibodyModel` (for example a cloth panel mesh) is mounted on any spacecraft link through `CompliantAttachment`. It exchanges forces and torques with that link in both directions: through the bus equations of motion on rigid spacecraft, and through per-body wrenches into the articulated backbone on articulated spacecraft. Spacecraft without attachments are unchanged.

- src/dynamics/multibody_cloth/compliant_attachment_dynamics.jl — per-run attachment runtime with a concrete model mirror and preallocated buffers; bus-relative loads, gravity as a difference from the base gravity, mount reactions; `finish_attachments!` subtracts the base acceleration.

## Findings
- P2 (fixed during review): the attachment state was first stored in absolute inertial coordinates (~7e6 m), like the robot arm. That put a roundoff floor of about k × 1e-9 m on every spring force, and a 2e5 N/m attachment hit MaxIters. Switched to bus-relative positions and velocities, with gravity taken as a difference. The 2e5 N/m rigid-limit case now completes, and conservation drifts improved 10–100x.
- P3: the attachment path's stage 2 needs the base acceleration, so attachment derivatives are written last at every RHS site. Checked at both supported sites; every other route is refused at setup.
- P3: a non-concrete matrix-field type on `CompliantJoint` forces dynamic dispatch. It is left as is, because making it concrete moved the arm by 1 ulp. A concrete mirror built per run keeps the hot path allocation-free.
- P3: zero-allocation assertions are skipped under coverage instrumentation, which adds allocations. They still run in the plain shards.
