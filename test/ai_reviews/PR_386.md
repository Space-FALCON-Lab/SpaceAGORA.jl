## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- **Design deviation, low: `held_command_time` is `NaN` for four built-ins.** The
  RPO controller, robot arm, EDG controller and burn scheduler do not record their
  tick times; recording one adds a struct field to each.
- **Interpretation, low: R-H3 under `:mounted`.** `held_command` returns the law's
  own command in both actuation modes; the mounted levels stay in
  `actuator_levels`, derived from it.
- **Interpretation, low: guidance and navigation models keep the default
  `held_command`.** They hand commands through shared state.
- **Low, behaviour of direct calls:** a direct `update_control!` call on the
  descent controller for an inactive spacecraft now computes a command, and the
  descent guidance no longer checks `is_active` in its tick. The engine never
  makes those calls (`skip_inactive`); one unit test that did now takes the
  engine's step.
- **Low, new pre-run warning:** a scope naming a run position outside `1:n` warns
  before the run and is refused under `--depwarn=error`. The planner's indices are
  resolved from IDs at the run's start; the check reads the configured ones, which
  `make_rpo_configuration` sets correctly. K3's one-spacecraft
  `RPOMPCControlModel()` instance (target 2) triggers it once K3 and this PR are
  both on main (PR text, note 8).
- **Note:** refusal text of the `bind_spacecraft` fallback changes.

Reviewer to verify:

- The tick loops' filter sits inside each spacecraft's step, so the control
  callback's threading decision and the stop registration are unchanged.
- Every built-in scope equals the index check at the top of that model's tick, so
  no tick that used to do work is skipped.
- The descent controller's `release_command!` is exactly the removed branch, and
  `_apply_mounted_tick!` still runs after it.
- `held_command` returns no object the model can mutate.
- `check_spacecraft_scopes` runs after every model's own preflight.
- No run changes: the parity evidence.
