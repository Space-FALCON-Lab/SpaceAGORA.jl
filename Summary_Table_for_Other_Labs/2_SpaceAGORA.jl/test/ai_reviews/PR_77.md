# AI Review — PR #77: fix doubled solar-panel areas in Odyssey/VEX example spacecraft

## Scope

Corrects panel reference areas in three example spacecraft that violated the builder's per-wing convention, and documents that convention at the construction site. Found by a student's frontal-area audit; the defective divisors date to the April 2026 tuning commit `d354addc` (the same commit that carried the J2000-element-frame and Bowring-altitude defects fixed in July). The telemetry benchmark scenarios are unaffected — their manifests already carry correctly halved per-wing dims, and the measured-density certification independently pins the drag area.

## Changed Files

- `src/analysis/verification/telemetry_verification/example_support.jl` — comment-only: the per-wing contract is now stated where the two panel links are built (each link carries the full `panel_dims[2]*panel_dims[3]`, so `panel_dims[2]` must be the half-span; passing the full span doubles the array's drag/SRP area). No behavioral change; no line of executable code modified.
- `examples/AGORA_Vex.jl` — `panel_dims` `5.7 / 1.0` → `5.7 / 2.0`: was exactly double the documented 5.7 m² two-wing VEX array (11.4 m²); offset formula already assumed the 5.7 m total span and is unchanged.
- `examples/AGORA_Odyssey.jl` — `panel_dims` `(0.01, 5.5/1.35, 2.6)` → `(0.01, 3.89/2.0, 1.7)` and `panel_offset_y` `2.6/2.0 + 5.5/4.0` → `2.6/2.0 + 3.89/4.0`: the old dims were a hand-tuned divisor that disagreed with the file's own offset geometry; the new values are the flight-certified benchmark wing (identical to the telemetry manifest craft, offset 2.2725 m).
- `examples/AGORA_Mars_RAAN_Scenario.jl` — same fix as `AGORA_Odyssey.jl` (copied snippet).

## Findings

- The builder constructs two symmetric panel links and assigns each the full `dims[2]*dims[3]`; every correctly-configured example (all Earth-class files) passes the half-span (`5.7 / 2.0`). The three fixed files were the only violations in `examples/`; a repo sweep found one further inconsistency in `benchmarks/studies/aerobraking_perturbation_mc/analytical_perturbation_models.jl` (2×(3.0×1.5) = 9.0 m² of panels for an Odyssey-class craft), deliberately left out of this PR because its constants back already-produced study outputs — flagged to the study's owner.
- The regression pins for the affected examples are 120-second truncated arcs near apoapsis: drag is negligible there and the SRP delta from the area change is sub-millimeter over the arc against a 288 m position tolerance, so existing pinned values remain valid without retuning — verified empirically, not just analytically.

## P1 Assessment

No P1s. Executable changes are confined to `examples/`; the single `src` change is a comment. The telemetry benchmark path is untouched (manifest-driven craft with its own dims), so nightly gates and thresholds are unaffected.

## Tests Added/Updated

None added; existing coverage exercises the change. `test/integration/examples/runtests.jl` (examples regression): 8/8 cases, 27/27 assertions, exit 0 with the corrected craft — including the `AGORA_Odyssey.jl` case executing the native-GRAM path. No pinned values required updating (see Findings).

## Residual Risk

- The examples now under-produce drag relative to their pre-fix behavior (they previously flew up to 2–3× the physical panel area); any external notebook or study that copied the old example dims inherits the old error — the perturbation-MC helper is the one known in-repo case and is tracked separately.
- The regression harness pins only truncated arcs; full-length example flights are exercised by the examples suite smoke (completion, not accuracy), so a future area regression of this kind would again be invisible to CI — a cheap guard would be a static check asserting `panel_dims[2] ≤ total_span/2` conventions in examples, not included here.
