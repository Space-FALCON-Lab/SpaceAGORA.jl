# Review record: PR 428: the cost probe measures wrench effectors on every route

## Scope

Review of the `cost-probe-route-samples` branch against main (c7db8b6fb, v0.3.1).
The change is independent of 0.4.0 and can land after it.

Defect. `probe_effector_costs!` runs one right-hand-side evaluation, then times each
dynamic effector on its own. An effector evaluated through `wrench` needs a
`StateSample`, and the probe read it from the flat route's per-satellite buffers
(`shared_buffers.rhs_flat_state_*`). Only the flat route fills those buffers. After a
warm-up on the serial, satellite-batch or per-satellite route they are empty, so the
read threw inside the probe's per-effector `try` and the effector was recorded with
`ns_per_sat = NaN`. This hit:

- every built-in `wrench` effector on those three routes (reproduced on main with
  `InverseSquaredJ2GravityModel`);
- every user-defined effector on every route. A user-defined effector is not on the
  flat route's thread-safe list, so a run that has one never takes the flat route.

After the 0.5.0 hook removal (#420), `wrench` is the only force hook, so this would
cover every user-defined effector. `constellation_work_counts` reads an unmeasured
effector without cost terms as `in_domain = false`, so the cost model declined to
predict these workloads rather than predicting them wrongly.

Change. The probe builds the sample from the state:
`build_state_sample(sc_view, spacecraft[sat_idx], orientation_sim, sat_idx)`. That is
the call `_accumulate_dynamic_effectors!` and `_accumulate_dynamic_effectors_partitioned!`
make on the serial, satellite-batch and per-satellite routes. On the flat route,
`_prefill_rhs_flat_state_samples!` fills its buffers from the same state with the same
extraction helpers, so the sample is identical field for field. The effector is
therefore timed with the same arguments as before. The docstring's warm-up paragraph
no longer names the flat buffers as a reason for the warm-up.

## Findings

No P1 or P2 findings. Points a reviewer should check:

- Low, equivalence on the flat route. `build_state_sample` reads `q` and `ω` only
  when the state has them (`hasproperty`). The flat prefill reads them whenever
  `orientation_sim` is set. With `orientation_sim` the state always carries both, so
  the two samples agree. The new test compares them field for field with `===`, with
  and without attitude.
- Low, timing. The sample is built once per effector before `timed_min`, as before,
  so building it is not part of the measurement on any route.
- Note, no solve changes. On main, `probe_effector_costs!` and
  `warn_on_declaration_mismatch` have no caller in `src/`; suite 02 and the new tests
  call them. The fix changes what the probe returns, not how any run is routed today.
  Built-in effectors with declared cost terms are now probed on every route, so a
  future caller of `warn_on_declaration_mismatch` checks their declarations on every
  route, not only after a flat warm-up.
- Note, the environment sample. `sample_environment_with_reusable_buffers` already
  falls back to fresh sampling when the flat route's planet-frame, atmosphere and
  solar buffers are not marked filled, so the state sample was the only
  route-dependent input.

## P1 Assessment

No P1 findings were raised. The change touches one probe that has no caller in `src/`
on main, and it leaves the flat route's measurements unchanged.

## Tests Added/Updated

- `test/unit/parallel/cost_probe_route_tests.jl` (new):
  - "Effector cost probe measures wrench effectors on every route": three spacecraft,
    built-in J2 gravity plus a user-defined `wrench`-only effector, with the warm-up
    route pinned to serial, satellite-batch and per-satellite in turn (the plan's mode
    is asserted). Satellite 1 is inactive, so the probe runs on satellite 2. It asserts
    that the flat buffers stayed empty, that both effectors are measured (finite, and
    the user effector above the timing noise floor and in `probe_ns_map`), and that the
    sample the user effector received is satellite 2's state, model and index. On main
    this testset fails on all three routes: both effectors are NaN.
  - "Effector cost probe on the flat route times the flat route's sample": runs the
    flat route itself at width 1 (any thread count), then the probe. It asserts that
    the sample the probe passed is `===` the flat route's own sample for that
    satellite, field for field, with and without `orientation_sim`. This pins the
    flat-route behaviour; it passes on main and on the branch.
- Mutants, each swapped into `rhs_cost_probe.jl` and restored byte for byte: the code
  on main (flat buffers), the first spacecraft's model, attitude dropped, the first
  satellite's state, and the index left at its default. The file fails against every
  one of them.
- Runs on the branch: the new file standalone at 4 threads and at 1 thread; suite 02
  (including the existing "Effector Cost Probe" testsets) and the parallel cost unit
  files through the CI shard runner; the 33 PR gates (`test/contracts/pr_runtests.jl`);
  the AI-review artifact gate with `SPACEAGORA_PR_NUMBER=428`.
- Flat-route check, not committed: on a pinned flat route with built-in J2 gravity and
  box aerodynamics, four spacecraft, with and without attitude, main's probe and the
  fixed probe ran alternately in one process. Both measured every effector, the
  samples were identical for every satellite, and the measured costs agreed within
  run-to-run noise.
