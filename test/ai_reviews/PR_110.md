# AI Review Artifact for PR #110

## Scope
Numerical determinism: remove `@fastmath` (seven sites) and one `@simd` from the gravity kernels in `src/dynamics/coupled/perturbations.jl`, and stop inlining `_evaluate_dynamic_effector` in `src/simulation/engine/dynamics_rhs.jl`, so that the serial and threaded evaluations of the same effector run one compilation of each kernel with the same IEEE operations in the same order on every CPU. No formula or interface changes.

## Changed Files
- src/dynamics/coupled/perturbations.jl — `_nbody_body_force_ii` return expression; the four scalar harmonics loops (`for n`, `for j`, `for l`, `for idx in eachindex(active_orders)`); the `@fastmath begin` block and `@simd` loop in `wrench(::GravitationalHarmonicsModel, ...)`.
- src/simulation/engine/dynamics_rhs.jl — `_evaluate_dynamic_effector` is `@noinline`: the serial tuple loop and the `threaded_collect!` closure previously each inlined their own copy of the kernels, and LLVM decides per compilation context whether the `muladd` products inside StaticArrays operations are fused. The router-branch rework reproduced exactly this: identical inputs, one-ULP difference in a `mass * L' * g` product between two copies of the same expression.

## Findings
- P2: removing fast-math changes the last bits of the harmonics and n-body forces relative to previous runs, so tolerance-based references could move. Checked: the telemetry regressions and the suite-04 harmonics parity tests compare against external references with tolerances far above one ULP; no bit-exact golden tables exist yet.
- P2: performance of the harmonics recurrences without FMA contraction. Checked with a single-satellite 60x60 run on this machine; the difference is within run-to-run noise (details kept out of the public PR).
- P3: `_nbody_body_force_ii` is the legacy `calcForceTorque` path; the wrench path (`_nbody_acceleration_ii`) never had `@fastmath`. Checked: both remain arithmetically distinct paths, unchanged in structure here; unification is part of the flat-route rework.
- P3: a non-inlined dispatch adds one call per effector per satellite per stage. Checked: microseconds against kernel work in the tens of microseconds; the route oracle and gates are unchanged.
