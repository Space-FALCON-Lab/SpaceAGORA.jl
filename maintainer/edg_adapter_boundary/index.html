EDG adapter boundary preparation

This is a design proposal for a future external energy-depletion guidance (EDG) adapter under the optional adapter standard. It creates no public facade, package, contract version or new supported execution mode. Scientific qualification and integration of the experimental controller remain prerequisites; this document does not establish manuscript equivalence or authorize extraction.

The inventory below uses core commit f9eb5f13. The experimental comparison uses draft PR251 at 6888f007, whose base is Gen-EDG at 8d86d5edf2cfd459d9467047b0ddd29b90328a02, not this core revision. These are source observations, not an accepted combined tree. Refresh this comparison against the scientifically accepted revision before implementing the interface.

Paths in this table are relative to core. The existing EDGServices module is private: its name does not make it the versioned facade required by the standard.

The present algorithm still consumes ODEParams, u, spacecraft objects and private core modules. Re-exporting that whole module would expose mutable engine storage. The future facade must replace those accesses deliberately, with parity tests, rather than treating the current signatures as a stable external API.

Proposed supported interface

Use one guidance-domain facade with the standard's version check, compatibility error and explicit implemented/consumed inventories. Its final name, symbols and version are to be selected in the implementation review. The operations below describe the proposed contract, not callable methods available today.

OperationInputsResult and permitted effects
PreflightEDG configuration, spacecraft/link mapping, callback periods and execution capabilitiesValidate supported combinations before output creation or stepping; no scientific feasibility claim.
InitializeRun-owned EDG runtime and initial observationReset plan/history according to the reconciled lifecycle; establish any required passage baselines without resetting physical integrals.
Passage transitionSpacecraft index, event time, boundary kind, direction and copied observationUpdate only that spacecraft's plan/history; deliver once to the runtime shared by guidance and control.
Guidance updateImmutable observation, configuration, run-owned EDG runtime and scoped prediction servicesSelect mode and update bracket/target state; return a diagnostic snapshot. No link rotation or trajectory-state write.
Control updateThe same ownership inputs at the configured control tickReturn an apply flag, the core-owned panel-AoA command, switch/cache status and diagnostic snapshot; core applies the command.

The control result should preserve the distinction already present in EDGControlDecision: whether to apply a command, the command itself and what the switch planner did. A successful computation or cache hit is not evidence that a trajectory meets its constraints. Reuse the existing core command identity where appropriate; do not return a mutable view of runtime state.

An observation must identify the 1-based spacecraft and controlled links, elapsed simulation time in seconds, inertial position in metres, inertial velocity in metres/second, mass in kilograms and copied per-panel cumulative heat in J/cm². Environment observations must label geodetic altitude in metres, density in kg/m³, temperature in kelvin, airspeed in metres/second, dimensionless molecular speed ratio and dynamic pressure in pascals. AoA is in radians; heat rate is W/cm²; specific energy is J/kg. Missing values and invalid samples need explicit status, preserving the accepted algorithm's existing handling rather than silently inventing replacements.

Core must distinguish simulation time from ephemeris time. Existing live and trajectory queries use the configured epoch plus elapsed time for frames and the elapsed time for atmosphere queries. Local atmosphere wind is east/north/up; airspeed is spacecraft velocity relative to the rotating planet minus atmosphere velocity. l_pi maps inertial components to planet-fixed components. Preserve these conventions and the rotation transport term. The altitude-only prediction helper currently queries zero latitude/longitude; it is not interchangeable with the full trajectory query.

Prediction services should take explicit state/time values and a run-scoped, opaque environment context. Inventory frame/atmosphere queries, configured gravity evaluation, per-link aerodynamic evaluation and vehicle geometry projections. Retain core implementations of shared physics; do not copy them into the adapter. The facade must specify query side effects, atmosphere caches and RNG ownership: a predictor must not gain direct access to shared_buffers, mutate geometry, or silently reseed a live atmosphere. Separate prediction instances or replayable samples require a reviewed equivalence decision if they change existing query semantics. Call-scoped borrowed service handles must not escape their run.

State ownership and lifecycle

Core retains the public configuration/model/state types and creates the run's configuration. The EDG implementation may mutate only its run-owned algorithm state through the agreed contract. Paired guidance and control must share that same state within a run; separate runs and supported concurrent samples must not share it. Current run_simulation isolation deep-copies configuration while preserving that within-run relationship. Explicit isolate_state=false means caller ownership and fresh initialization, not implicit resume.

Current preflight checks require state-vector lengths to match spacecraft count, at most one EDG guidance and one EDG control model, matching paired configuration and shared state, and a guidance partner for targeting control. Maximum-depletion control can operate alone and then owns initialization/reset. Preserve these guards unless a separately reviewed feature deliberately changes them. Record any additional adapter scratch arrays and RNGs as per-run resources; define cleanup if a later implementation allocates external resources. There is no need for a global provider registry or a dynamics-owner stepping loop.

The engine owns event scheduling and normal guidance/control periods. It supplies the correct spacecraft index and calls the adapter at those times; the adapter does not advance the physical trajectory. Core alone rotates the validated non-root panel links. EDG's current force/torque effector returns zero; the normal aerodynamic dynamics observe the resulting geometry. Preserve callback ordering, held-command activation, event save behavior and output sampling explicitly in the accepted integration. No period, threshold or solver setting changes as a side effect of packaging.

Error behavior

An incompatible contract must fail before adapter methods or optional libraries become available, and be checked again during runtime initialization. Missing providers and unsupported capabilities must produce a clear setup error, not activate a different algorithm. Invalid configuration, ownership or panel mapping must fail before actuation. Preserve current checkpoint refusal.

Prediction failure, an unreachable target, a sampled constraint exceedance and absence of a valid command are distinct outcomes. Preserve the scientifically accepted mode fallback and command law, accompanied by structured diagnostics; do not introduce a new generic low-drag override or classify a sampled failure as proof of global infeasibility. Programmer errors must remain errors. Existing legacy exception fallback behavior must be inventoried before any change in propagation policy. A rejected compatibility load requires a fresh process.
