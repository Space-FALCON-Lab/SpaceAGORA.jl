# PR316 review: make the actuator folder the home of actuator hardware

## Scope

Review of the SpaceAGORA `actuator-layout` branch against its base,
`dynamics-layout` (PR #314). The PR flattens
`src/models/vehicle/actuators/thruster/` into `src/models/vehicle/actuators/`,
moves the `Thruster`, `ReactionWheelAssembly` and `Magnet` records out of
`src/models/vehicle/spacecraft/components.jl` into one file each beside them,
moves the six-axis thruster allocator out of `src/models/gnc/control/rpo_mpc/`
into the same folder, deletes a five-line re-export module, and adds a README
to the folder. It is the first step of the actuator-layer plan and changes no
behaviour.

Authorship disclosure: this record was drafted by the author of the PR and
committed by the principal investigator, because the independent reviewer was
unavailable. Readers should weigh the record accordingly.

## Findings

No P1 or P2 findings.

- The extracted record files were compared with the removed text: each is
  verbatim after its three-line comment, and the new `components.jl` equals
  the old one with the three blocks replaced by the includes.
- The four moved files are byte-identical to their sources.
- Inside `Components` the three records are now defined before `Facet`
  instead of after it. None of the four definitions refers to another, so the
  order has no effect.
- The deleted module had one user the first commit missed: the runtime
  benchmark `benchmarks/studies/performance_runtime_analysis/main.jl` bound
  `SimulationModel.DynamicEffectors.BaseThrusterModel`, which would have
  stopped that study at load (found by the automated review on the PR). The
  second commit binds it from the owner `ThrusterModels`. A resolver over every
  literal `SimulationModel.…` path in benchmarks, examples, scripts and tests
  then finds no other broken binding. No source module reached the type
  through `DynamicEffectors`; the callback registry was already required by
  the architecture gate to import from the owner. The removal shrinks
  `names(DynamicEffectors)` by one; the binding remains exported by
  `SimulationModel` and is the same object.
- Low, carried to the next step: `Thruster.direction` is described as the
  thrust direction by its field comment and by `add_thruster!`, while the
  Apollo descent controller and the viewer use it as the exhaust direction.
  This PR moves the text unchanged; the convention is settled in the
  actuator-contract step.

## P1 Assessment

No P1 findings. The PR changes file locations and include paths only; no
function body, type, field, module identity or exported name of the package
root changes.
