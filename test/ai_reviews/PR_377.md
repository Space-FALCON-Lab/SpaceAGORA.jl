## Findings

Author's notes for the reviewer (no P1 known to the author):

- **Design, medium: the run's length no longer follows the plan by itself.** The
  old builder set the simulated time to `max(mission_time, t_ref_end + hold)` from
  its pre-run plan. With planning in the run (D1 = b) that is unknown beforehand.
  The builder therefore sets `max_mission_time_s` (default 1800 s) as the cap and
  the plan's lifetime, and returns a stop callback that ends the run at the same
  time as before. A caller that runs `demo.args` without the callback simulates to
  the cap. A plan longer than the cap is refused and stops the run with an
  `RPOPlanningError`. Every caller in the repository passes the callback
  (`run_rpo_case` or `extra_callbacks`). The stop is the first step at or after that
  time; in the delta runs it matched the old end time exactly.
- **Design, medium: which limits the run validates.** Clearance always;
  `reference_max_speed_mps` only when given (the planner then keeps its 1% headroom
  below it, so the ISS demo's flown reference is 1% slower than HyPR's own retiming
  of its plan); the thrusters' per-axis acceleration only when the retimer limits
  acceleration. A retimer setting is not turned into a validated limit, so replaying
  a plan does not change its timing.
- **Behaviour change, medium: the reconstruction example no longer flies refused
  plans.** Before, every planner's plan was flown and its clearance violations were
  counted. Now a plan the run refuses is not flown: the evaluation records
  `refusal` and fails, with NaN flight metrics. Comparison statistics that counted
  violations of flown unsafe plans change meaning. This has not been run across the
  full planner campaign locally.
- **Behaviour change, low: Batch runtime columns.** `planner_runtime_s`,
  `simulation_runtime_s` and `pso_refinement_improved` are dropped. One
  `total_runtime_s` covers planning and simulation.
- **API, low: `RetainedPathRPOPlanner`.** Promises: copies at construction; end
  points within `endpoint_tolerance_m` (default 1e-6 m) are set to the request's,
  otherwise `:infeasible` with `:start_not_on_path` or `:goal_not_on_path`; the
  request mapping and HYPR retimer of `HYPRRPOPlanner`; no random draws; no retiming
  or restart; needs HYPR; and in a run the lifecycle validates the result. No
  exported function was added, so the extension hook registry (#361) needs no row;
  its gate passes on a merge with this branch.
- **Refactor, low: shared timing function.** `retime_rpo!` now calls
  `timed_candidate`, which holds its former body; the route is computed before
  rather than after the budget checks, with no side effects. The #365 parity
  fingerprints, including the HYPR retime, are bitwise unchanged.
- **D3 (a): the replanning study stays as the legacy reproduction.** It stays on
  the deprecated model through `legacy_guidance_demo`, which repeats the old
  builder's retiming, plan buffer and simulated time. Its header and the paper
  guide name `b165c0528b782316db65142f19def374c181b47f` (the merge of #307) as the
  commit to reproduce its results from after the removal: no release tag contains
  the study (the latest, `v2.0.0`, is from May 2026). Choosing a release instead, if
  one is cut before the removal, is Giusy's call. It stays in the examples smoke:
  smoke mode only checks the saved baseline and never configures the model, so it
  emits no deprecation warning under `--depwarn=error`; the routing test now checks
  that. The full study was not run here.
- **Example, low: the disturbance example's pins.** The request times at 0, 10,
  30.1 and 55 s are structural (tick multiples, the sphere's appearance and
  removal, a preset-time callback before guidance) and pinned exactly. The settled
  retry depends on the braking flight; it was recorded at 24.2 s and is pinned to
  one tick. The flight metrics are bounds (final distance and speed under 1 mm and
  1 mm/s, propellant between 4 and 8 g, recorded 5.84 g, clearance of at least
  0.2 m). The displacement uses `derivative_discontinuity!`, because
  `u_modified!` is deprecated and throws under `--depwarn=error`.
- **Note: the ISS demo was not run end to end** (it needs the visualizer
  environment and the NASA model). Its definitions load in the station tests'
  provenance testset.

## Update after review (eab14e799, c332e4f17)

- **Resolved: refused plans lost in the reconstruction campaign (r4302639945).**
  `refused_evaluation` returns a `NaN` duration; `main` then built the HYPR
  trace's time grid from it (`collect(0:.1:NaN)` throws `InexactError`), so the
  catch recorded `execution_error` and the refusal was lost. The other planners'
  refused plans were recorded as `executed`. `main` now records a refused
  evaluation with `refused_row` (`status="refused"`, `plant_executed=false`) and
  its plan file, and skips the command log, trace and deadband comparison. A
  refused HYPR plan keeps the measured allowance and warm start for the
  comparisons.
- **Resolved: references that outlast the mission cap (r4302639946).** The
  lifetime, `max_mission_time_s + (mpc_horizon + 1) * dt`, covers the controller's
  preview to the end of the run, and the planners check the reference end only
  against it. Replayed under a 35.1 s cap, the main example's 35.6 s reference was
  accepted and the run ended at the cap with `Success`. The example now plans
  through `RPOMissionCapPlanner`, which refuses a reference ending after the cap
  (`:reference_ends_after_mission_cap`); the same replay stops with an
  `RPOPlanningError`. The wrapper forwards `consumes_rng`, so the run's stream is
  unchanged.
- Tests: "The reconstruction records a refused plan without flying it" (a real
  refusal from `full_evaluate`, the refused row and its JSON) and the cap checks in
  the main example's testset (refused 0.5 s before the reference's end, accepted
  at its end).
- Evidence: Locally on `c332e4f17`: the examples planner-contract tests (65/65), the station, results, adapter and lifecycle unit files, the HYPR example routing test, the examples smoke for all seven RPO examples under `--depwarn=error`, 33/33 contract gates and the strict documentation build pass.
- Not run: `main` of the reconstruction example end to end (a full campaign); the
  refused branch is covered through `full_evaluate` and `refused_row`.
