# PR review: retire calcForceTorque from the package

## Scope

Review of PR 349 (branch `force-torque-hook-retirement`, head `bbdc5209f`) against
`main` at bc823fecc: `git diff main force-torque-hook-retirement`. Three commits:
929e898cb (the change), 5bbd4f79b (review fix: direct calls build their
environment from their own state) and bbdc5209f (a merge of `main` bc823fecc).

- The 12 built-in `calcForceTorque` methods (11 models plus the telemetry
  scaled-aero wrapper) and two helpers only they used are removed.
- `RobotArmReactionEffector` gets `wrench`. The harmonics legacy method becomes
  the internal `_harmonics_force_torque`.
- An untyped `calcForceTorque(model, x, p, i)` forwarder serves direct calls.
- The pre-run check warns about user models that implement `calcForceTorque`,
  through the new shared `_hook_deprecation`.
- The template and three examples move to `wrench`; tests are migrated.
- A new pull-request gate refuses methods of deprecated hooks in `src/`,
  `templates/` and `examples/`.

Authorship disclosure: the author of the PR drafted this record. It lists what the
author checked and what the independent reviewer must verify; it does not replace
that review.

## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- Fixed in 5bbd4f79b (review comment on #349, P2): in 929e898cb the forwarder
  sampled the environment through `sample_environment_with_reusable_buffers`.
  - With `rhs_planet_frame_prefilled[]` or `rhs_atmosphere_prefilled[]` set,
    that reads the buffered planet frame and atmosphere whatever `x` is; only
    the solar buffer checks `t`.
  - So a direct call for a state other than the one the right-hand side
    prefetched would have paired `x` with another state's environment.

  The forwarder now calls `sample_environment(...; write_buffers=false)` on
  `x`. A state-checked reuse was not possible, because the buffers do not
  record the state they came from.

  At the dynamics' own state a direct call still equals the dynamics'
  evaluation bit for bit, for all 14 built-in force models. That was checked
  with nothing prefilled, with buffers prefilled for that state, and under
  `SPACEAGORA_DENSITY_FREEZE_PER_STEP=on` (`h5_direct_vs_dynamics.jl`).
- Kept on purpose: a direct call evaluates `wrench_caching!`, so it writes the
  run's drag caches, as the removed methods did.
  - Wrapper effectors evaluated inside a right-hand side keep their saved drag
    diagnostics. These are the in-repository direct callers.
  - A diagnostic call with another state overwrites spacecraft `i`'s caches
    until the next right-hand-side evaluation. The docstring and the
    forwarder's comment say so.
- Low: direct calls of `calcForceTorque` on built-in models now return the
  `wrench` result, through the forwarder. Before, they ran the removed legacy
  methods.
  - The dynamics never made such calls, so no run's result changes.
  - Code that calls the hook by hand can see last-bit differences, or larger
    ones where the two implementations differed. The aero probe pins
    agreement to `rtol = 1e-12` for the aerodynamic model with attitude off.
  - In this repository the only such caller is
    `benchmarks/studies/cygnss_reconstruction/cygnss_constellation.jl`
    (`ScaledAero`). It is left unchanged and now also warns before its runs.
- Low: the forwarder evaluates at `p.shared_buffers.current_time[]`, as the
  removed methods did. Outside a run that is whatever the caller set.
- Low: the removed aerodynamic method wrote the density, temperature and wind
  stage buffers (`_stage_environment_state(...; write_buffers=true)`) on every
  call. The forwarder samples the atmosphere from `x` without writing them. Suite 04's heat-load test relied on that side effect and now
  fills the buffers through `sample_atmosphere(...; write_buffers=true)`.
- Low: index guards change. The removed gravity-gradient method returned zero
  for an out-of-range index; the forwarder raises a `BoundsError` from
  `p.args.dynamics_model.spacecraft[i]`. The tests that pinned the zero were
  removed.
- Low: `_own_force_torque_method` tells the forwarder apart by
  `which(f, tt) !== which(f, Tuple{Any, Any, Any, Any})`. A user method with the
  same fully untyped signature would replace the forwarder and count as the
  user's own. That is not a realistic signature for a model hook.
- Note: the pre-run check warns at most once per model type and hook in a
  process (`maxlog=1` keyed on `(T, :calcForceTorque)`). Under
  `--depwarn=error` it throws instead, and the run stops before integration.
  The probe drivers run with that flag. The repository's remaining legacy-hook
  test models run only in the main test process, which warns.
- Note: `NBodyScratchWorkspace` and the aero workspace helpers
  (`_nbody_workspace_for_sat!`, `_aero_workspace_for_sat!`) are no longer used
  by `src/`. Tests still check them, so they stay; removing them is a follow-up.
- Note: `docs/public_api_symbols.jl` still lists `calcForceTorque` under
  "Model Extension Hooks". A "Deprecated hooks" section comes with a later PR of
  the program, as the docs-phase plan expects.

Reviewer to verify:

- No built-in model's evaluation path changes.
  - Every type in `hp_package_types(AbstractForceTorqueModel)` has `wrench`.
  - `_wrench_method_available` is unchanged, so every built-in but harmonics
    goes through `wrench_caching!` as before.
  - Harmonics reaches `_harmonics_force_torque`, whose body is the removed
    method's.
- The forwarder builds its sample and environment from `x`:
  `build_state_sample` with the run's `orientation_sim` and the index,
  `sample_environment` (not the right-hand side's prefilled buffers), and
  `wrench_caching!`. Outside a right-hand side, where no buffer is prefilled,
  this equals `_evaluate_dynamic_effector`'s `wrench` branch.
- The gate's AST walk finds every method form in the package: long form,
  short form, qualified names, `@inline`, `where`, return-type annotations.
  The gate controls exercise three spellings and a typed forwarder.
- The `Earth_Navigation.jl` start epoch matches the engine's `et_start`: it
  calls `ephemerides_time_seconds(initial_time, SpiceEphemeridesModel())`, and
  the environment uses that same ephemerides model.
- `RobotArmReactionEffector`'s `wrench` returns zero in every case, as the
  removed method did. Selecting by `x.spacecraft_index` matches the old
  `sat_idx == model.spacecraft_idx` test inside a run.

## Residual Risk

- External code that calls `calcForceTorque` on built-in models gets the
  `wrench` results, which can differ from the removed methods in the last bits.
  For example, a wrapper around a built-in model that implements only
  `calcForceTorque`.
- External packages that extended a built-in model's `calcForceTorque` method
  get a method of their own type only. The engine never called the built-in
  ones, so runs are unaffected.
