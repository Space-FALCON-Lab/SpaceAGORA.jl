- renames `planet_frame_lpi(planet, et, model)`,
  `ephemerides_sun_direction_ii(planet, et, model)` and
  `ephemerides_time_seconds(initial_time, model)` to

- makes the five ephemerides hooks public, with registry rows and a section in
  the configuration guide;
- migrates the built-in models, the EDG services, the examples, the scripts and
  the tests.

## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- Low: the bridges query `hasmethod` with the exact argument types of the call.
  A new method typed narrower than the call (for example `et::Float32`) is not
  found, and the bridge then calls the old name, whose fallback raises a
  `MethodError` naming the new hook. The built-in methods take
  `et::Float64`, as before.
- Low: a method of an old name written for a built-in model and a planet type of
  the user's own (a test probe did this) is no longer reached: the built-in
  model's new method answers first. The pre-run check reports it ("never used;
  rename it ... or delete it"). The probe moves to the new name.
- Note: `_ephemerides_time_seconds_flexible` used
  `applicable(ephemerides_time_seconds, ...)`. The old name's untyped fallback
  makes that true for every type, so it now asks for the new hook or a method
  of the model's own of the old one; the name-based conversion for a model whose
  type has a built-in model's name is unchanged.
- Note: two companion files call old names directly and log one warning per
  name until their follow-ups: the MuJoCo companion's `test/common.jl` (two
  names, C-M2) and the EDG companion's
  `benchmarks/native_reference/observer_comparison_cases.jl` (one name, C-E2).
  Neither runs with `--depwarn=error`.
- Note, pre-existing and not changed here: `ephemerides_cache_key` on a model of
  your own must today return a tuple of at least three elements. For any key
  other than `(:spice,)` the engine's cache-reuse key
  (`_ephemerides_model_reuse_key` in `setup.jl`) reads elements 2 and 3 and
  drops the first, so a one-element key such as `(:mine,)` stops the run at
  setup with a `BoundsError`, and two models whose keys share elements 2 and 3
  share the ephemeris caches. Checked on 45eb6cbcd, before H6: a one-element key
  fails, a three-element key runs. H6 documents the key as a tuple, as the
  engine intends; the fix (a reuse key built from the whole tuple, with the
  built-in keys' strings unchanged) belongs in its own PR.

Reviewer to verify:

- **No warning is reachable from the engine.** A bridge's old branch runs only
  for a type without the new hook. A fallback warns only for a type with it, and
  both use the same query on the same argument types. A type's own old method
  is dispatched to directly. No engine call names an old hook outside the
  bridges.
- **The renamed methods' bodies are unchanged:** the diff of each built-in
  method is its signature line only.
- **The pre-run check** for each case: old only (warns once per name), new only
  (silent), both ("never used"), and the built-in models (silent).
- **The gate's sanctioned fallbacks:** three, three and two untyped arguments in
  `ephemerides_hooks.jl`.
- **The EDG facade** (`EDGServices`, `_edg_planet_frame_lpi(p, t)`) keeps its
  signatures.
- **Under `--depwarn=error`,** no test, probe or example calls an old name,
  other than the compatibility file's child process, which expects the error.
