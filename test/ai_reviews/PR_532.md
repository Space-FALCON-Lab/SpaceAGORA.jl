# Maneuver request stability review

## Scope

Prevent flight-scaled campaign guidance from requesting duplicate burns after
an earlier request is accepted. Remove extra solver-state saves at maneuver
planning ticks, retain the control schedule and exact burn edges, and document
the owner-confirmed once-per-explicit-request policy for configured delta-v.

## Changed Files

- `src/models/gnc/guidance/maneuvers/thruster_guidance_functions.jl`: reuse a
  campaign request already accepted for the same spacecraft and source orbit.
- `src/models/gnc/control/maneuvers/propulsive_maneuvers.jl`: expose existing
  consumed-request state through the private campaign lookup and clarify the
  refusal of old checkpoints even when no burn was configured.
- `src/models/gnc/control/hooks.jl`: import that dispatch and correct control-clock
  documentation.
- `src/models/gnc/guidance/hooks.jl`: describe scoped guidance on the run clock
  and the late maneuver-planning phase.
- `src/models/gnc/contracts/algorithm_lifecycle.jl`: correct the planning comment.
- `src/orchestration/simulation/callbacks/control_callbacks.jl`: disable saves
  only for the maneuver-planning callback.
- `src/orchestration/simulation/callbacks/periodic_tick_callbacks.jl`: retain the
  existing default save behavior while allowing that specific override.

Tests add campaign acceptance/resume coverage and strengthen burn-family
comparisons. The upgrading guide distinguishes the unpublished corrections from
v0.7.0 and explains request identity, repeat requests and legacy state limits.

## Findings

Independent source review found no new blocking implementation finding. Campaign
flight scaling updates before acceptance, then reuses the accepted tuple instead
of allowing changing osculating apoapsis to produce a second request. Bound scope
is retained. Generic custom guidance still uses delta-v, direction and source
orbit as request identity. The implementation uses existing scheduler state,
without adding model checkpoint fields or changing its version.

Only maneuver-planning ticks disable before/after saves. Solver stops remain on
the defined control clock; burn-edge callbacks and other periodic callback save
behavior are unchanged. Strict final-state and burn-window comparisons replace
unnecessary tolerance in the affected burn-family regression.

The configured delta-v decision is once per explicit request. Guidance must issue
repeat requests; no automatic recurrence at atmosphere exit is introduced.

## Residual Risk

A fixed reader cannot undo duplicate burns already flown or accepted by v0.7.0.
Old state may also contain an emitted request before its next guidance update;
the latch takes effect when guidance runs. Restart affected flight-scaled
campaigns to obtain a history without those earlier duplicate requests. Accepted
old plans are not canceled because their stored tuple lacks producer provenance.

The control clock still adds solver stopping times, so this change does not
promise bitwise equivalence to older scheduling policies or remove all planning
overhead. Configured requests, custom guidance requests and explicit burn-plan
installations retain their separate contracts. Published v0.7.0 and its tag remain
unchanged; patch release qualification and coordinator closure are still required.
