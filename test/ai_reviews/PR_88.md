# AI Review — PR #88: NaN-altitude guard in the tabulated-flight atmosphere interpolation

## Scope

A crash fix on the tabulated-flight density path, root-caused from the chronically red nightly-stress workflow on `main`. `_tab_flight_interp` guards its exponential tails with `h <= alts[1]` and `h >= alts[n]`; both comparisons are false for a NaN altitude while `searchsortedlast` orders NaN past every bin and returns `n`, so the interior branch indexes `alts[n+1]` and a `BoundsError` escapes as a `TaskFailedException` that kills the whole threaded telemetry study. A NaN altitude legitimately reaches the RHS from an adaptive solver's rejected trial states during long GRAM-deterministic regressions. The fix returns NaN density so the solver rejects the step and continues — the standard contract, and the same defense the elapsed-time lookup in `getDensity` already carries.

## Changed Files

- `src/environment/atmosphere/density_models.jl` — `_tab_flight_interp` early-returns `(NaN, NaN)` for `isnan(h)` with a comment stating the reachable path; downstream `getDensity` then yields NaN density and NaN temperature (`clamp` propagates NaN) with zero wind. Finite inputs, including ±Inf (already covered by the tail guards: +Inf extrapolates to vacuum, −Inf to the bottom tail), are bit-identical.

## Findings

- The failure signature was taken from the nightly-stress logs on `main` (scheduled run, pre-dating the frame-fix PR): `BoundsError: attempt to access 21-element Vector{Float64} at index [22]` at the interior interpolation line, i.e. `j = n` out of `searchsortedlast`. With sorted finite bins and finite `h` the interior branch cannot produce `j = n` (the `h >= alts[n]` guard catches it), and ±Inf hits a tail guard; NaN is the only input that reaches the indexing with `j = n`. Confirmed mechanically: `searchsortedlast([1.0, 2.0, 3.0], NaN) == 3` and both guards compare false.
- The author had already clamped the analogous elapsed-time `searchsortedlast` in `getDensity` a few lines below; the altitude lookup was the one missing the defense.
- Returning NaN (rather than clamping `j` to `n − 1`) is deliberate: clamping would fabricate a finite density for a non-finite state and mask the NaN, while NaN propagates to the wrench, the step-error estimate, and a solver step rejection.
- The 5-hour-timeout `cancelled` mode of nightly-stress is a separate symptom (workflow `timeout-minutes: 300` budget), possibly downstream of this crash's retry behavior; not addressed here and noted in the PR.

## P1 Assessment

The crash is P1-class for the nightly telemetry regression (it terminates the entire ensemble task mid-study and has kept nightly-stress red on `main`); this PR removes it. No behavior change for any finite input.

Unresolved P1: No

## Residual Risk

Profile vectors are trusted to be sorted, finite, and non-empty per leg (construction-time responsibility; the empty-leg case is already guarded in `getDensity`). A NaN produced by archive parsing inside `logs`/`sigs` would still propagate NaN density — which is the desired reject-the-step behavior, not a crash. The nightly-stress 5-hour timeout mode remains to be characterized once this crash fix is in.
