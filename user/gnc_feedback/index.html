Feedback Controllers and Estimators

Start here when each tick computes a command or estimate from the current state. For a separate package, follow the rate-damper package recipe. For a planner that proposes a checked product, use Planning Algorithms. Both profiles follow the shared house rules.

The examples are complete scripts in examples/gnc_algorithm_env/, a separate project that uses only the public API. CI runs them; the excerpt gate keeps the code blocks below identical to those scripts. From the SpaceAGORA checkout:

julia --startup-file=no --compiled-modules=existing --project=examples/gnc_algorithm_env examples/gnc_algorithm_env/setup.jl
julia --startup-file=no --compiled-modules=existing --depwarn=error --threads=2 --project=examples/gnc_algorithm_env examples/gnc_algorithm_env/feedback_controller.jl

Run a complete script, including its imports, before changing its snippets. For the rate-damper blocks in a fresh Julia session, first load:

using SpaceAGORA
using SpaceAGORA.Conformance: conformance_fixture, test_control_model
using StaticArrays
using Test

The feedback profile

A feedback controller has two halves:

  • The tick, update_control!(model, u, p, t, spacecraft_index), runs once per control period. It computes the command from the state u, limits it, and holds it in the model.
  • The output hooks, control_wrench(model, x, p, t), control_propellant_rate(model, x, p, t) and control_wheel_torque(model, x, p, t), run at every evaluation of the equations of motion. They return the held command and never run the law. The force is inertial, the torque in the body frame, and the propellant rate positive.

A controller that drives mounted hardware declares actuation_mode(model) = :mounted and returns the hardware levels from actuator_levels(model, spacecraft_index) instead of the output hooks; see Adding an Actuator. Estimators and guidance models tick the same way, with update_navigation!(model, u, p, t, spacecraft_index) and update_guidance!(model, u, p, t, spacecraft_index), and keep their result for the controller to read. When ticks coincide, sensors sample first, then navigation ticks, then control, then guidance; a planning binding's request comes before the control tick it feeds.

Declarations

A model declares what it acts on and what it assumes. Each declaration has a default equal to the engine's usual behaviour, so declare only what differs. The engine reads them before the run and at each tick.

DeclarationDefaultDeclare it when
spacecraft_scope(model)AllSpacecraft(): ticked for every spacecraftthe model acts on some spacecraft only: BoundSpacecraft(indices), or CoupledSpacecraft(primary, partners) for a model ticked for primary that also reads partners
gnc_period_s(model)nothingthe law assumes a tick period, such as the step it was discretized with. Before the run the engine refuses the run when the control rate differs
skip_inactive(model)true: a spacecraft that is no longer active, after an impact or a touchdown, is not ticked; each tick calls release_command!(model, t, spacecraft_index) instead. The model supplies its off command, such as zero thrust, by implementing release_command!: the fallback does nothing, so a model without its own method keeps the command it last heldthe model must keep ticking for an inactive spacecraft: return false. Before SpaceAGORA 0.4.0 the default was false
held_command(model, spacecraft_index), held_command_time(model, spacecraft_index)nothing, NaNthe model holds a command: return it, as an immutable value, and the time of the tick that produced it
gnc_links(model)nonethe model shares an object with a partner: see Pairing through a link

Output hooks are called for every spacecraft whatever the scope, so they check x.spacecraft_index themselves. A SpacecraftSelection scopes dynamic effectors only (see Effectors on part of a constellation); the scope check refuses it from a guidance, navigation or control model.

A control model that is not ticked periodically declares tick_schedule(model) = :event_driven and brings its own callbacks with gnc_callbacks(model, num_sats, args, period_s), as the burn scheduler does. The engine adds those callbacks to the run as they are, outside the wrapper that runs periodic ticks, so each callback does that wrapper's work itself:

  • scope: act only on the spacecraft spacecraft_scope names;
  • inactive spacecraft: follow the model's declared skip_inactive policy. With true, once p.is_active says a spacecraft is inactive, leave it alone and release its command as release_command! does; with false, keep acting as for an active spacecraft;
  • timing: keep its times on the run's clock. A checkpointed run is solved in segments and can resume from a file, so a callback timed from the start of a solve shifts;
  • saved state: keep any state it needs in the model, where checkpoint_state can save it. The engine does not save a callback's own state, and the checkpoint table leaves custom callbacks outside its guarantee.

A periodic model can add solver stops after each tick with register_tstops!(integrator, model, spacecraft_index), and record when its clock starts with gnc_clock_started!(model, period_s, origin_s). Most models need none of these.

Worked example A: a rate damper

RateDamper damps a spacecraft's body rate: its law is a torque proportional to the rate, limited on each axis. The script is examples/gnc_algorithm_env/feedback_controller.jl.

Base.@kwdef mutable struct RateDamper <: SpaceAGORA.AbstractControlEffectorModel
    spacecraft_index::Int = 1           # the spacecraft it acts on, its position in the run
    gain_n_m_s::Float64 = 2.0           # torque per unit body rate, N·m per rad/s
    max_torque_n_m::Float64 = 1.0       # torque limit on each body axis, N·m
    period_s::Float64 = 1.0             # the tick period the law assumes, s
    # Run state: the held command and the time of the tick that set it.
    torque_body::SVector{3, Float64} = zero(SVector{3, Float64})
    tick_s::Float64 = NaN
end

# Declarations: what the controller acts on and what it assumes.
SpaceAGORA.spacecraft_scope(c::RateDamper) = BoundSpacecraft((c.spacecraft_index,))
SpaceAGORA.gnc_period_s(c::RateDamper) = c.period_s
SpaceAGORA.held_command(c::RateDamper, spacecraft_index) = c.torque_body
SpaceAGORA.held_command_time(c::RateDamper, spacecraft_index) = c.tick_s
# While its spacecraft is inactive (after an impact or a touchdown), the engine calls
# this at each tick in place of the tick (`skip_inactive`): the off command.
function SpaceAGORA.release_command!(c::RateDamper, t, spacecraft_index)
    c.torque_body, c.tick_s = zero(SVector{3, Float64}), t
    return nothing
end

# At each run's start: fresh run state, so two runs of one configuration start equal.
function SpaceAGORA.initialize_control!(c::RateDamper, u, p, t)
    c.torque_body, c.tick_s = zero(SVector{3, Float64}), NaN
    return nothing
end

# The tick (shape T), once per control period: run the law, limit it, hold the command.
function SpaceAGORA.update_control!(c::RateDamper, u, p, t, spacecraft_index)
    ω_body = SVector{3, Float64}(u.sc[spacecraft_index].ω)
    c.torque_body = clamp.(-c.gain_n_m_s .* ω_body, -c.max_torque_n_m, c.max_torque_n_m)
    c.tick_s = t
    return nothing
end

# The output (shape R), at every evaluation of the equations of motion: the held
# command, never the law. Output hooks are called for every spacecraft.
function SpaceAGORA.control_wrench(c::RateDamper, x::StateSample, p, t)
    zero3 = zero(SVector{3, Float64})
    x.spacecraft_index == c.spacecraft_index || return zero3, zero3
    return zero3, c.torque_body             # force_ii (N), torque_body (N·m)
end

# A checkpoint must carry the held output between ticks, including its timestamp.
# These values are immutable; restoring them cannot share mutable buffers.
SpaceAGORA.checkpoint_state(c::RateDamper) =
    (torque_body=c.torque_body, tick_s=c.tick_s)
function SpaceAGORA.restore_checkpoint_state!(c::RateDamper, data)
    c.torque_body, c.tick_s = data.torque_body, data.tick_s
    return nothing
end

# Declared on a spacecraft: a copy for that spacecraft, with fresh run state.
SpaceAGORA.bind_spacecraft(c::RateDamper, spacecraft_index::Int) = RateDamper(;
    spacecraft_index, gain_n_m_s=c.gain_n_m_s, max_torque_n_m=c.max_torque_n_m, period_s=c.period_s)

Run it on a cube far from any planet, spinning about one axis, with nothing else acting on it:

# A 500 kg cube far from any planet, spinning about body z; only the controller acts.
root = Link(root=true, m=500.0, dims=MVector(1.0, 1.0, 1.0))
ω0 = 0.05                                    # initial rate, rad/s
ic = CartesianInitialCondition(SVector(4.0e9, 0.0, 0.0), SVector(0.0, 0.0, 0.0);
                               q=SVector(0.0, 0.0, 0.0, 1.0), ang_vel=SVector(0.0, 0.0, ω0))
spacecraft = SpacecraftModel(links=[root], root=root, prop_mass=0.0, inertia_tensor=root.inertia,
                             initial_condition=ic, id=1)
damper = RateDamper()
mission_s = 120.0
planet = make_no_gram_planet(:earth)
config = SimulationConfiguration(
    simulation_settings=SimulationSettings(
        results=false, verbose=false, generate_plots=false, normalize=false),
    mission_configuration=MissionConfiguration(
        mission_type=MissionTime, mission_time=mission_s, number_of_orbits=1,
        keplerian=false, orientation_sim=true, num_steps_to_save=120, data_rate=1.0),
    environment_model=EnvironmentModel(
        planet=planet, EI=120.0, density_model=NoAtmosphereModel(),
        ephemerides_model=SimpleEphemeridesModel(),
        thermal_model=MaxwellianHeat(thermal_accomodation_factor=1.0, planet=planet),
        topography=false, wind=false),
    dynamics_model=DynamicsModel([spacecraft], ()),
    guidance_model=GuidanceModel(guidance_effectors=(), guidance_rates=Float64[]),
    navigation_model=NavigationModel(navigation_effectors=(), navigation_rates=Float64[]),
    control_model=ControlModel(control_effectors=(damper,), control_rates=[damper.period_s]),
    initial_time=InitialTime(year=2024, month=1, day=1, hour=0, minute=0, second=0.0),
    integration_tolerances=IntegrationTolerances())

solution = run_simulation(config; return_solution=true)

The result can be checked by hand. A torque held for one control period on a body whose inertia is the same about every axis changes the rate by a fixed fraction:

# By hand: the first tick is one period after the start, and each held torque
# -k ω(t_n) acts for one period on a cube (no gyroscopic torque), so after the
# ticks at 1, 2, ..., N s the rate is ω0 (1 - k Δt / I)^N.
inertia = root.inertia[3, 3]
ticks = floor(Int, mission_s / damper.period_s) - 1        # ticks before the end
expected = ω0 * (1 - damper.gain_n_m_s * damper.period_s / inertia)^ticks
final = solution.u[end].sc[1].ω[3]
println("body rate after $(mission_s) s: $(final) rad/s, by hand $(expected) rad/s")
@test final ≈ expected rtol=1e-6

The important choices:

  • The law runs in the tick only. update_control! reads the rate from u.sc[spacecraft_index] (ω is the body rate in rad/s), limits the torque and stores it. control_wrench returns the stored torque at every evaluation, so the vehicle feels a zero-order hold of the command, as it would from flight software.
  • The command is held until the first tick. The first tick is one control period after the start; until then the initial held command acts, here zero.
  • The declarations state the assumptions. gnc_period_s lets the engine refuse a run whose control rate in ControlModel(control_rates=...) is not the period the gain was tuned for. held_command and held_command_time make the held command readable outside the model.
  • Fresh at every run. initialize_control! sets the held torque back to zero when a run starts. run_simulation runs a copy of the configuration, but with isolate_state=false the same model runs again, and it must start as it did the first time.
  • Registration. Add the model to ControlModel(control_effectors=(...), control_rates=[...]), or declare it on a spacecraft with SpacecraftModel(...; control=ControlModel(...)): the engine then calls bind_spacecraft(model, spacecraft_index), which returns a copy for that spacecraft with fresh run state.

The configurable fields are the spacecraft index, gain, torque limit and period. The held torque and tick time are owned run state: initialization clears them; change the gain or limit to configure the next run, not the previous output. The checkpoint hooks carry that output through a restart between ticks. For a model whose run also writes user-configurable data, follow the conditional reset rule.

The lifecycle hooks

Besides its tick, a guidance, navigation or control model can implement hooks the engine calls around the ticks. Each default does nothing.

HookWhen the engine calls itImplement it to
preflight_guidance(model, args; isolate_state), preflight_control(model, args; isolate_state)before the run, on the caller's configurationrefuse a configuration the model cannot run, with an ArgumentError; it must change nothing
initialize_navigation!(model, u, p, t), initialize_guidance!(model, u, p, t), initialize_control!(model, u, p, t)at the start of each run: after the links' link_initialize!, the navigation models, then guidance, then controlreset the model's run state, so that two runs of one configuration with isolate_state=false start equal, and keep a change a user made between the runs (see the house rules)
requires_atmosphere_events(model), atmosphere_transition!(model, u, p, t, spacecraft_index, inside)when a spacecraft enters or leaves the atmosphere, in runs where a model declares truereact to the entry or exit
before_reference_control!(producer, consumer, u, p, t)before each periodic tick of a control model, for each model that produces a link it consumesbring what the producer writes up to date, as the RPO planner checks its reference

What a run leaves in a model stays readable after the run; the reset happens when the next run starts. A custom sensor resets its own state in initialize_sensor! (Extensibility).

Worked example B: an estimator and a link

An estimator ticks and holds, like a controller, but its output is an estimate for other models to read. GyroRateEstimator reads a gyro and holds the measured rate; EstimatedRateDamper is example A's controller reading that estimate instead of the true state. The script is examples/gnc_algorithm_env/estimator.jl.

Pairing through a link

The two models share one object, a link. Each declares its part with gnc_links(model): Produces(link) for the model that writes it, Consumes(link) for a model that reads it. The engine groups the run's models by link, which survives the deep copy of the configuration, and before the run checks each link's counts against link_cardinality(link) and calls check_link(link, producers, consumers, args), where you can refuse settings that disagree. At the start of every run it calls link_initialize!(link, producers, consumers, u, p, t), before any model's own initializer, so the link starts empty in every run.

# The estimate the navigation model writes and the controller reads: one shared object.
mutable struct RateEstimate
    ω_body::SVector{3, Float64}     # estimated body rate, rad/s
    time_s::Float64                 # time of the measurement behind it, s into the run
end
RateEstimate() = RateEstimate(zero(SVector{3, Float64}), NaN)

# One estimator writes it; any number of controllers read it. Each run starts empty.
SpaceAGORA.link_cardinality(::RateEstimate) = (producers = 1:1, consumers = 0:typemax(Int))
function SpaceAGORA.link_initialize!(e::RateEstimate, producers, consumers, u, p, t)
    e.ω_body, e.time_s = zero(SVector{3, Float64}), NaN
    return nothing
end

The estimator reads the latest measurement of the gyro mounted on its spacecraft with sensor_measurement and sensor_measurement_time:

struct GyroRateEstimator <: SpaceAGORA.AbstractNavigationModel
    spacecraft_index::Int
    gyro::Int                       # the gyro's position among the spacecraft's sensors
    estimate::RateEstimate
end
SpaceAGORA.spacecraft_scope(n::GyroRateEstimator) = BoundSpacecraft((n.spacecraft_index,))
SpaceAGORA.gnc_links(n::GyroRateEstimator) = (Produces(n.estimate),)

# The tick: read the latest measurement and hold it as the estimate. Sensors
# sample before navigation ticks at the same time.
function SpaceAGORA.update_navigation!(n::GyroRateEstimator, u, p, t, spacecraft_index)
    spacecraft = p.args.dynamics_model.spacecraft[spacecraft_index]
    n.estimate.ω_body = SVector{3, Float64}(sensor_measurement(spacecraft, n.gyro))
    n.estimate.time_s = sensor_measurement_time(spacecraft, n.gyro)
    return nothing
end

# The producer saves the estimate. Restore its values into the existing link so
# every consumer still reads the same shared object.
SpaceAGORA.checkpoint_state(n::GyroRateEstimator) =
    (ω_body=n.estimate.ω_body, time_s=n.estimate.time_s)
function SpaceAGORA.restore_checkpoint_state!(n::GyroRateEstimator, data)
    n.estimate.ω_body, n.estimate.time_s = data.ω_body, data.time_s
    return nothing
end

The controller declares that it consumes the estimate:

With an exact gyro sampled at the control ticks, the pair gives example A's result: the gyro samples, then the estimator ticks, then the controller, all at the same time.

Test your algorithm

SpaceAGORA.Conformance runs the engine's own machinery on your model or algorithm: the pre-run hook check, short runs repeated sequentially, after a deepcopy, with the global random stream reseeded, on two threads and twice on one configuration with isolate_state=false (the reset at the run's start), and, for planners, the family's request driver. Each check_* function returns a report; with using Test, each test_* function records the same checks as tests. Each example script ends with them:

# The engine's own checks on the controller: hooks, reproducibility, copies, the
# reset at each run's start, output-hook purity and the copies `bind_spacecraft` makes.
@testset "RateDamper conformance" begin
    # Use the spinning case above: a zero-rate fixture would not expose a lost torque.
    report = test_control_model(damper;
        fixture=conformance_fixture(configuration=config))
    # Require the checkpoint check itself to pass on this nonzero-spin fixture.
    @test only(filter(check -> check.id === :checkpoint_round_trip,
                      report.checks)).status === :pass
end

Keep the estimator demonstration at 120 seconds. For conformance, build a separate 13-second configuration with the same spinning spacecraft, shared estimate and mounted gyro. Its checkpoint falls at 6.5 seconds, between ticks, so the check must preserve the estimate and held command until the next update:

@testset "Estimator and controller conformance" begin
    # Keep the student demonstration at 120 s. This separate short configuration
    # checkpoints at 6.5 s, between ticks, while retaining the same nonzero-spin pair.
    conformance_config = estimator_configuration(13.0)
    fixture = conformance_fixture(configuration=conformance_config)
    reports = (test_navigation_model(estimator; fixture=fixture),
               test_control_model(damper; fixture=fixture))
    for report in reports
        @test only(filter(check -> check.id === :checkpoint_round_trip,
                          report.checks)).status === :pass
    end
end

Run the checks with two or more threads, so that concurrent runs are compared with sequential ones. A pass certifies interface behaviour only: the method, its parameters and the claims made from it stay with you.

To keep your algorithm in a repository of your own, tested against a recorded SpaceAGORA commit, start from a contributor starter: see Building Your Own Research Repository.
