# Geodetic conversion results as static vectors: review record

## Scope

A two-line change in the geodetic converters of the reference-system helpers. No numerical change: the same values are returned, built from their elements instead of through a heap vector literal.

## Changed Files

- src/foundation/core/interfaces/reference_system.jl: `rtolatlong` and `rtolatlongrad` return `SVector{3, Float64}(a, b, c)` instead of `SVector{3, Float64}([a, b, c])`.

## Findings

A static vector converted from a vector literal is a heap allocation that the just-in-time compiler elides but the Linux package image keeps. The planet-frame sampler calls `rtolatlong` on every right-hand-side evaluation that needs the planet frame (J2 gravity, aerodynamics, anything with `planet_frame=true`), so a package image that precompiles such a run made those evaluations allocate once per call in CI while the same code stayed allocation-free when compiled locally. The allocation profiler on CI placed every allocation of the failing live-pose test at that return statement, three calls per evaluation; with the change applied, every one of the failing tests measured zero allocations on CI under that workload.

## P1 Assessment

No P1. The change removes an allocation; the returned values are identical, and the geodetic contract tests pass unchanged.

## Tests Added/Updated

None added. The geometry altitude contract tests and the reference-system probes cover the converters' values; the allocation-free right-hand-side tests (articulated_engine_tests.jl, compliant_attachment_tests.jl, live_pose_loads_tests.jl) cover the paths that call them and were run on CI against the workload of #581 to confirm the allocation is gone. The repository's own CI meets the package-image form of these converters only once a workload precompiles a run that samples the planet frame, which the workload change in #581 is the first to do.

## Residual Risk

Other static vectors built from vector literals remain in the reference-system helpers, on orbital-element and initial-attitude paths that run outside the right-hand side (setup, callbacks and guidance ticks). They would show the same behaviour only if a package image compiled them onto a hot path.
