# Concurrent process startup review

## Scope

Review of 5a9af086705463735d98e43895deaa98c8f96200 and the focused API documentation follow-up. This is a correctness and CI review, not acceptance of the draft performance study.

## Changed Files

- src/SpaceAGORA.jl: imports and exports the scoped warm-up override.
- src/parallel/process/parallel_process.jl: exposes the same override from the process module.
- src/parallel/process/worker_pool.jl: bootstraps independent workers concurrently, then warms them concurrently; pool registration follows both barriers. Documents concurrent side effects and best-effort warm-up failure handling.
- src/simulation/campaigns/adaptive_routing.jl: selects the default sample warm-up, a supplied callable, or no warm-up.
- src/simulation/campaigns/simulation_campaigns.jl: imports the override used by adaptive routing.
- docs/public_api_symbols.jl: registers the exported setting in the generated public reference.
- test/unit/parallel/process_warmup_tests.jl (new, registered in test/unit/runtests.jl): docstrings attached, scoped override and restoration, and a real two-worker concurrent bootstrap and warm-up.

## Findings

The missing public API registration caused the contract and nightly failures. The documentation build also requires top-level docstring forwarding, as with the other process APIs. The follow-up registers and forwards the existing documented symbol without changing scheduling or scientific calculations. Bootstrap completion is a barrier before warm-up; pool registration is a barrier after warm-up. Only newly spawned workers receive the warm-up. Per-worker warm-up exceptions remain warnings.

Concurrent warm-up changes side-effect ordering. Callers must use independent output destinations or a side-effect-free representative call. Documentation now states this constraint. The draft still needs actual multi-worker startup, failure and campaign evidence before final acceptance.

Follow-up review after merging `main` (PRs #189, #190, #201; no conflicts): the docstring move left a blank line between `ensure_process_workers!`'s docstring and its definition, which detached the docstring. The public reference still built because the top-level `@doc` forwarding in `src/SpaceAGORA.jl` republished Julia's "No documentation found" fallback, so neither the docs build nor `Docs.hasdoc` caught it. The blank line is removed, and the new test reads `ParallelProcess`'s own doc table so a detached docstring fails it (verified: the test fails without the fix). The PR also had no committed test for its behavior; the new file adds one.

## October 4 real-worker validation follow-up

Production source was pinned to `ba984ccddbbe0f2427be09c1c9e44f8c3e596856`. The proposed follow-up changes the regression test and this review record only. It retains two workers, requires both warm-ups to reach a barrier before either is released, matches one start and finish per worker, and records any unexpected rewarm before its error can be swallowed. The second-arrival deadline is shorter than the worker barrier timeout, so a serial warm-up implementation cannot pass by waiting for the first warm-up to fail. Cleanup releases barriers and reclaims processes spawned by this test, including unregistered processes after an error. An outer process timeout remains necessary for exceptional shutdown behavior.

Local Julia 1.12.3 validation passed:

- Strengthened real two-worker regression: 15 assertions.
- Existing process dispatch/cache tests: 49 assertions.
- Existing process-campaign probes: 24 assertions.
- Independent real-worker probe: 38 assertions plus 4 cleanup assertions. It verifies loaded source identity, overlapping custom warm-ups, exactly-once counts, growth to three workers with an intentionally failed default warm-up followed by successful dispatch, disabled warm-up during growth to four workers, reuse without rewarming, scoped-value restoration, ordered results and shutdown.

These are 130 assertions for the candidate; the original 9-assertion test also passed separately before the change. No test worker remained. An independent source review found no new blocking production defect, and a second reviewer found no blocking issue in the test diff. The regression barrier proves warm-up overlap, not bootstrap overlap.

The bounded local run used existing packages and compilation images only, four coordinator threads, one thread per worker, `--compile=min -O0`, and simple integer-valued campaign functions. Optional GRAM/SPICE bootstrap warnings were expected because the isolated checkout lacks those native inputs. Julia 1.12 also emitted Distributed world-age warnings. Neither native-library initialization nor numerical campaign correctness is certified by these results. No target-machine speedup is claimed.
