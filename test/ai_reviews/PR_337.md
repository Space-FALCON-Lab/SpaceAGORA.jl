# PR review: pre-run warning for unpaired Apollo descent guidance and control

## Scope

Review of PR 337 (branch `apollo-pairing-check`, head `6330af4af`) against `main` at `58b8dbc40`: `git diff main...apollo-pairing-check`. Two code commits (`6eed7b858`, and `6330af4af` after review) plus this record's commit. `ApolloDescentControlModel` gains a `SimulationLifecycle.preflight_control` method. When a configuration has both Apollo guidance and Apollo control, the method logs one warning (`maxlog=1`) if any spacecraft is controlled or guided without its counterpart on the same `ApolloDescentState`. A direction is not checked when the configuration also has a guidance (or control) model of another type. The docstring and the lunar landing page describe the check.

## Findings

Author's notes for the reviewer (no P1 known to the author; the one P2 raised in review is resolved):

- Resolved, P2 from a review comment on the PR: in a mixed configuration, one spacecraft with an Apollo pair and another whose Apollo control is fed by a guidance model of another type that writes the state, both sides are present, so the one-sided exemption did not apply, and the custom-guided spacecraft was reported as never receiving a command (the mirror case held for control). `6330af4af` skips the "controlled but not guided" report when the configuration has a guidance effector of another type, and the "guided but not controlled" report when it has a control effector of another type. A per-state exemption was not used, because it would silence V13 itself (guidance and control on two separate states). The PI chose this rule on 2026-10-16, until the GNC link declarations replace the check with exact pairing.

- Confirmed defect (V13): on `main`, `calcControlEffect!` returns with zero thrust while `state.phase_start_s[1, i]` is `NaN` (the "nothing to track until the guidance has issued its first command" branch), and only `ApolloDescentGuidanceModel` sets it. With the guidance on another state object, the control never thrusts and nothing reports it. The new closed-loop test reproduces this: after the run, the control's `phase_start_s` is all `NaN` and its thrust is zero.
- Low, scope choice: configurations with only Apollo guidance or only Apollo control are not checked, because a user's guidance could write the state, or guidance could run alone. The PI decided this scope on 2026-10-15.
- Low, coarse exemption (PI decision 2026-10-16): a direction is skipped when any non-Apollo model is on that side, including one unrelated to the descent, so a real mismatch can go unreported in that direction for such configurations. The GNC link declarations will replace the check with exact pairing.
- Low, `maxlog=1`: the warning is shown once per Julia session (the design's mechanics for checks that will become errors). A second mismatched configuration in the same session does not warn again.
- Note: `run_simulation` calls `preflight_control` for each control effector, before `isolate_state` copies the configuration (`execution.jl:546-551`), and again if the parallel flag re-enters `run_simulation`. The check is repeated in those cases; `maxlog=1` keeps it to one message.
- Note: configuration and terrain agreement, which the guidance docstring also asks for, are not checked.
- Note: `import ..GuidanceHooks` is already present in `ControlHooks` (from `control/energy_depletion_lifecycle.jl`); repeating it in this file keeps the file independent of include order.

Reviewer to verify:

- The grouping by `IdDict` on the state matches the run's actual pairing: guidance writes and control reads only `model.state` for indices in `spacecraft_indices` (both models, including copies made by `bind_spacecraft`, which keep `m.state`).
- No configuration in `examples/`, `scripts/`, `test/` or `docs/` that pairs Apollo models now warns (the author found the closed-loop tests, `scripts/dev/viewer_demos/apollo11_landing.jl` and the docs example all build both models from one state with the default or the same selection).
- The new tests fail on `main` (no `preflight_control` method for the type, so no warning is logged), and the mixed-case assertions fail on `b44191488`.
- The skip conditions use only effector types, so a configuration of Apollo models alone is checked exactly as before the second commit.
- The hook is not in `src/orchestration/simulation/engine/setup.jl`, which another branch changes.
