# PR review: warn about direct calls of deprecated hooks

## Scope

Review of PR 354, the `direct-call-deprecation-warnings` branch. It is stacked on #349
(`force-torque-hook-retirement`, e16f86888); review
`git diff e16f86888 direct-call-deprecation-warnings`. Two commits:

- 95f205434, the warning on direct `calcForceTorque` calls and the gate
  hardening;
- d2199fbf2, the warning on the five-argument plume `wrench`.

The PR changes:

- The untyped `calcForceTorque(model, x, p, i)` forwarder for direct calls now
  warns through `_hook_deprecation`, once per model type, and throws under
  `--depwarn=error`.
- The five-argument plume `wrench(model, x, env, t, i)` does the same. The
  four-argument form and `wrench_caching!` call a new internal `_plume_wrench`,
  so the engine path does not warn.
- The deprecated-hook gate recognises callable-method definitions and pins the
  forwarder's arity.

## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- Low: both warnings sit on the call path. A wrapper effector that calls either
  deprecated form inside a right-hand side pays a log lookup per call after the
  first warning. The pre-run check already warns about a wrapper that
  implements `calcForceTorque`; a wrapper that calls the five-argument plume
  form gets only this warning.
- Low: the key `(typeof(model), :calcForceTorque)` is the one the pre-run check
  uses. The two never apply to the same type: the forwarder serves only types
  without their own method, and the pre-run check warns only about types with
  one.
- Note: the plume key is `(PlumeSurfaceInteractionModel, :wrench_with_index)`,
  without type parameters, so the warning comes once for all plume models.

Reviewer to verify:

- The engine never reaches either warning:
  - `_evaluate_dynamic_effector` calls `wrench_caching!` for wrench-capable
    models, and the forwarder only for models with neither hook;
  - the plume's `wrench_caching!` and four-argument `wrench` call
    `_plume_wrench` directly.
- `_plume_wrench`'s body is the removed five-argument body, unchanged.
- Under `--depwarn=error`, both warnings throw before any sampling or
  evaluation. The child-process tests pass `nothing` for `x` and `p` (forwarder)
  or an empty environment (plume).
- No test or probe that runs with `--depwarn=error` makes a deprecated direct
  call other than the aerodynamic-torque probe's, which expects the error.
