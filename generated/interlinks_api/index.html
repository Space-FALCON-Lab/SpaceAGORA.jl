Interlinks API

This page documents the supported public interface available from SpaceAGORA.

Interlinks

SpaceAGORA.SimulationModel.InterLinkModels.AbstractInterlink — Type
AbstractInterlink

Supertype of the link kinds. One value describes one registered link between two terminals: register it with register_link!. A kind implements link_range_m, and the effects it has: link_force for a link that pushes its endpoints (the default exerts none). link_available decides when the link can close (by default, within link_range_m). The built-in kind is LaserMomentumLink.

source
SpaceAGORA.SimulationModel.InterLinkModels.LinkContext — Type
LinkContext(; time_s=NaN, planet=nothing)

What a link hook may read besides its two endpoints: the time (s into the run) and the run's planet. The engine passes the run's values; a call outside a run gets the defaults.

source
SpaceAGORA.SimulationModel.InterLinkModels.LaserMomentumLink — Type
LaserMomentumLink(; power_w=10_000.0, magnification=100.0, range_m=200e3)
LaserMomentumLink(terminal::LaserTerminal)

An open-cavity laser link that pushes its two spacecraft apart: an idealized central force of magnification * power_w / c on each endpoint, directed away from the other, equal and opposite, at any separation up to range_m. It models no pointing, occultation or beam losses. power_w (W) must be nonnegative, magnification and range_m (m) positive. The terminal form takes a link between two terminals of that design: its max_power_w, magnification and range_m.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_range_m — Function
link_range_m(link) -> Float64

The maximum separation in metres at which link can close. Every link kind implements it.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_available — Function
link_available(link, a::StateSample, b::StateSample, ctx::LinkContext) -> Bool

Whether link can close between its endpoints a and b, in the order of the link's key (the lower (spacecraft, terminal) pair first). The engine asks at the start of the run and after every accepted step, once the run's own rules (forbidden pairs, active spacecraft) allow the pair. Default: the endpoints are apart and within link_range_m(link).

source
SpaceAGORA.SimulationModel.InterLinkModels.link_force — Function
link_force(link, a::StateSample, b::StateSample, ctx::LinkContext) -> (force_a_ii, force_b_ii)

The inertial forces (N) an active link puts on its endpoints a and b, in the order of the link's key. The engine adds them to the endpoints' accelerations at every right-hand-side evaluation, and the scheduling policies score candidate links by them. Default: no force.

source
SpaceAGORA.SimulationModel.InterLinkModels.InterlinkModel — Type
InterlinkModel(; forbidden_pairs=(), record_available=nothing)

The interlinks of a run: the candidate links between spacecraft terminals, each with its own link kind (register_link!), spacecraft pairs that may never link, and the accepted-step history of the links the scheduler selected. Attach it with SimulationConfiguration(interlink_model=model, ...). Endpoints are (spacecraft vector index, terminal number) pairs: the position of the spacecraft in dynamics_model.spacecraft, not its id. Terminals 1:n_terminal are virtual; mounted terminal hardware (see link_terminal) follows.

record_available sets whether each history sample also records the links that were available, which contact_windows reads: nothing, the default, records them in a run with a DataLink; true always; false never. A large constellation over a long run keeps a list of available links per accepted step, so the default leaves them out of runs that carry no data.

source
SpaceAGORA.SimulationModel.InterLinkModels.InterLinkGraph — Type

Indexed terminal vertices, candidate edges, the link of each edge (edge_properties) and availability/selection flags. Register candidates with register_link!.

source
SpaceAGORA.SimulationModel.InterLinkModels.InterLinkKey — Type

Canonically ordered pair of (spacecraft array index, terminal number) endpoints.

source
SpaceAGORA.SimulationModel.InterLinkModels.InterLinkHistory — Type

One accepted-step schedule sample: time in seconds, the selected InterLinkKey values (active) and the available ones (available, recorded in a run with a data link or with InterlinkModel(; record_available=true), and empty for a sample built from a time and the selected keys). contact_windows reads a run's samples.

source
SpaceAGORA.SimulationModel.InterLinkModels.register_link! — Function
register_link!(model::InterlinkModel, spacecraft, first_endpoint, second_endpoint, link::AbstractInterlink) -> InterLinkKey

Register a candidate link of kind link between two terminals and return its key. Each endpoint is (spacecraft vector index, terminal), where the terminal is a terminal number or a terminal mounted on that SpacecraftModel. The terminals must be on different spacecraft, numbered within each spacecraft's terminal_count, and able to carry the link (terminal_supports); a link that reads the terminal hardware at both ends (a DataLink with a ShannonBudget) refuses a virtual terminal. A link registers once. Its key lists the lower (spacecraft, terminal) first, or, for a directed link (link_directed), the endpoints in the order given. The link is available only when link_available allows it, and active only when the scheduler selects it.

source
SpaceAGORA.SimulationModel.InterLinkModels.register_links! — Function
register_links!(model::InterlinkModel, spacecraft, pairs, link; terminals=nothing) -> Vector{InterLinkKey}

Register one candidate link per spacecraft pair (i, j) in pairs and return their keys in order. The pairs come from all_pairs(spacecraft), from a constellation's planes and slots (same_plane_pairs, ring_pairs, grid_pairs), or from any vector of index pairs. link is a link kind value, or a function (i, j) -> link that builds each pair's link.

Each spacecraft's links take the terminals that can carry them in turn, starting again from the first when they run out; links that share a terminal compete for it when the scheduler selects. Pass terminals=(i, j) -> (terminal_i, terminal_j) to choose them instead. For a directed link, i is the transmitter.

source
SpaceAGORA.SimulationModel.InterLinkModels.all_pairs — Function
all_pairs(spacecraft) -> Vector{Tuple{Int, Int}}

Every pair (i, j) of distinct spacecraft vector indices with i < j, in order: the candidate pairs of a fully connected interlink graph, for register_links!.

source
SpaceAGORA.SimulationModel.InterLinkModels.same_plane_pairs — Function
same_plane_pairs(spacecraft) -> Vector{Tuple{Int, Int}}

Every pair (i, j), i < j, of spacecraft in the same orbital plane, by their constellation_slot (set by build_constellation), for register_links!. Spacecraft without a slot take part in no pair; two spacecraft in one slot are refused.

source
SpaceAGORA.SimulationModel.InterLinkModels.ring_pairs — Function
ring_pairs(spacecraft) -> Vector{Tuple{Int, Int}}

Each spacecraft with the next slot in its plane, and the last slot with the first: the in-plane rings of a constellation, by constellation_slot. A plane of two gives one pair, a plane of one none. Pairs are (i, j) with i < j.

source
SpaceAGORA.SimulationModel.InterLinkModels.grid_pairs — Function
grid_pairs(spacecraft; wrap_planes=true) -> Vector{Tuple{Int, Int}}

The "+grid" of a constellation, by constellation_slot: the in-plane rings (ring_pairs) and each slot with the same slot of the next plane, planes taken in plane-number order. With wrap_planes, the last plane links to the first; pass false for a Walker star, whose first and last planes counter-rotate. A slot missing from the next plane links nothing across. Pairs are (i, j) with i < j.

source
SpaceAGORA.SimulationModel.InterLinkModels.PowerBeamLink — Type
PowerBeamLink(; power_w, wavelength_m=1.064e-6, waist_radius_m=0.05, range_m)

A power beam from a transmitter terminal (a LaserTerminal) to a PowerReceiver: a directed link that carries power and applies no force.

  • The beam. The transmitter runs at power_w optical watts while the link is active, and draws its own electrical power for it (power_w / efficiency for a LaserTerminal), as a tier-1 laser load. The beam is Gaussian, with its waist, of 1/e² radius waist_radius_m, at the transmitter, and wavelength wavelength_m. Its spot radius at range d is beam_spot_radius_m(link, d).
  • The receiver. It captures beam_capture_fraction(link, radius, d) of the beam through its aperture of radius radius. It delivers that times its efficiency, up to its max_power_w.
  • Availability. The link can close within range_m, while the segment between the two spacecraft clears the planet (a sphere of its equatorial radius).
  • Deferred. It does not model pointing, the receiver's incidence angle, the atmosphere, beam quality or the beam's radiation pressure.
source
SpaceAGORA.SimulationModel.InterLinkModels.link_received_power_w — Function
link_received_power_w(link, receiver, a::StateSample, b::StateSample, ctx::LinkContext) -> Float64

The electrical power (W) that receiver, the terminal hardware at link's receiving end b, delivers to its spacecraft's bus while link is active, with a the transmitting end. It is generation in that spacecraft's power budget. The engine asks for it at every right-hand-side evaluation, for each active directed link that ends on terminal hardware, and PowerDeliveryPolicy and EnergyBalancingPolicy score candidate links by it. Default: 0.

source
SpaceAGORA.SimulationModel.InterLinkModels.beam_spot_radius_m — Function
beam_spot_radius_m(link::PowerBeamLink, distance_m) -> Float64

The 1/e² radius (m) of link's beam at distance_m from its waist: w0 √(1 + (d / z_R)²), with the Rayleigh range z_R = π w0² / λ.

source
SpaceAGORA.SimulationModel.InterLinkModels.beam_capture_fraction — Function
beam_capture_fraction(link::PowerBeamLink, radius_m, distance_m) -> Float64

The fraction of link's beam power within radius_m of its axis at distance_m, the share a centred circular aperture of that radius captures: 1 − exp(−2 r² / w²), with w the spot radius there.

source
SpaceAGORA.SimulationModel.InterLinkModels.DataLink — Type
DataLink(; transmit_power_w, budget, range_m)

A one-way data link from a transmitter terminal to a receiver: a directed link that carries data and applies no force.

  • The rate. budget (a FixedRateBudget, a ShannonBudget, or a budget kind of your own) sets it at the current separation. It is capped at each end's max_rate_bps when that end is a RadioTerminal. While the link is active, the transmitter's spacecraft integrates it into data_sent_bits, and the receiver's into data_received_bits.
  • The transmitter. A RadioTerminal transmitter runs at transmit_power_w radio watts while the link is active and draws transmit_power_w / efficiency as a tier-1 load: when its battery sheds tier 1, the link closes. A virtual terminal draws nothing.
  • Availability. The link can close within range_m, while the segment between the two spacecraft clears the planet (a sphere of its equatorial radius).
  • Direction. Two-way traffic is two links, one each way. A radio carries one active link at a time.
source
SpaceAGORA.SimulationModel.InterLinkModels.AbstractDataBudget — Type
AbstractDataBudget

Supertype of the link budgets that set a DataLink's rate. A budget kind is an immutable struct that implements budget_rate_bps. The built-in kinds are FixedRateBudget and ShannonBudget.

source
SpaceAGORA.SimulationModel.InterLinkModels.FixedRateBudget — Type
FixedRateBudget(; rate_bps)

A link budget with a constant rate: rate_bps bits per second while the link is active, at any range up to the link's range_m. It works between virtual terminals as well as between radios.

source
SpaceAGORA.SimulationModel.InterLinkModels.ShannonBudget — Type
ShannonBudget(; bandwidth_hz, frequency_hz, implementation_efficiency=0.5, max_rate_bps=Inf)

A radio link budget: the Shannon capacity of the received signal over thermal noise, scaled by implementation_efficiency (the share of capacity the modem and coding reach, in (0, 1]) and capped at max_rate_bps. With the link's transmit_power_w as P_t, both radios' gains G_t and G_r (from their gain_dbi) and the receiver's noise_temperature_k as T:

  • received power (Friis): P_r = P_t G_t G_r (λ / 4πd)², with λ = c / frequency_hz;
  • noise: N = k_B T bandwidth_hz;
  • rate: implementation_efficiency × bandwidth_hz × log₂(1 + P_r / N).

Both ends must be RadioTerminals; register_link! refuses a virtual terminal. It does not model pointing, antenna patterns, atmospheric or polarization losses, Doppler or interference.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_data_rate_bps — Function
link_data_rate_bps(link, transmitter, receiver, a::StateSample, b::StateSample, ctx::LinkContext) -> Float64

The data rate (bits per second) that link carries from its transmitting end a to its receiving end b while it is active. transmitter and receiver are the terminal hardware at the two ends, nothing for a virtual terminal. The engine integrates it, at every right-hand-side evaluation, into the sending spacecraft's data_sent_bits and the receiving one's data_received_bits, and DataThroughputPolicy scores candidate links by it. Default: 0.

source
SpaceAGORA.SimulationModel.InterLinkModels.budget_rate_bps — Function
budget_rate_bps(budget, link, transmitter, receiver, distance_m) -> Float64

The data rate (bits per second) that budget gives link, a DataLink, at a separation of distance_m between its ends. transmitter and receiver are the terminal hardware at the two ends, nothing for a virtual terminal. The DataLink then caps it at each RadioTerminal's max_rate_bps. Every budget kind implements it.

source
SpaceAGORA.SimulationModel.InterLinkModels.contact_windows — Function
contact_windows(history; active=false) -> Vector{NamedTuple}

The contact windows of a run's links, from its interlink history (model.history): one entry (key, start_s, end_s, duration_s) for each span of consecutive accepted steps over which a link was available (could close), or, with active=true, selected. The history records the available links in a run with a DataLink, or with InterlinkModel(; record_available=true); without them, only active=true finds windows. A window starts at the first step that has the link and ends at the next step that does not, or at the last step of the history. Windows are sorted by start time, then key.

The resolution is the scheduler's: the run's accepted steps. A history resumed from a checkpoint covers the resumed interval only, so a window that spans the resume is split at it.

source
SpaceAGORA.SimulationModel.InterLinkModels.contact_time_s — Function
contact_time_s(history, key; active=false) -> Float64

The total time (s) that the link key was available, or with active=true selected, over a run's interlink history: the sum of its contact_windows.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_directed — Function
link_directed(link) -> Bool

Whether link runs one way, from its first endpoint (the transmitter) to its second (the receiver). A directed link is keyed in the order its endpoints were registered, so the hooks receive the transmitter as a. An undirected link is keyed with the lower (spacecraft, terminal) first. Default: undirected, as for LaserMomentumLink.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_terminal_levels — Function
link_terminal_levels(link) -> (level_a, level_b)

The levels at which the hardware terminals at link's two endpoints run while it is active, in key order and in their actuators' units (watts of transmitted optical power for a LaserTerminal). Each such terminal draws actuator_consumption(terminal, level, ctx).power_w from its spacecraft's power budget, and is at level 0 while its link is inactive. A virtual terminal draws nothing. Default: zero levels.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_terminal — Function
link_terminal(actuator) -> Bool

Whether a mounted actuator is interlink terminal hardware, which can be a link endpoint. True for LaserTerminal, PowerReceiver and RadioTerminal; a terminal kind of your own opts in with SpaceAGORA.link_terminal(::MyTerminal) = true. A spacecraft's terminals are its n_terminal virtual terminals, numbered 1:n_terminal, followed by its mounted terminals in mounting order. Default: false.

source
SpaceAGORA.SimulationModel.InterLinkModels.terminal_supports — Function
terminal_supports(terminal, link) -> Bool
terminal_supports(terminal, link, side) -> Bool

Whether the terminal hardware terminal (a mounted actuator with link_terminal) can carry link. register_link! refuses a link that either endpoint's terminal cannot carry. A virtual terminal carries every kind, except a DataLink whose ShannonBudget reads the radios at both ends.

  • side is the end the terminal would take: :transmitter or :receiver for a directed link, :either for an undirected one. A kind whose terminals work one way implements the three-argument form.
  • Default: the two-argument form, which is true. A LaserTerminal carries LaserMomentumLink and transmits a PowerBeamLink; a PowerReceiver receives a PowerBeamLink; a RadioTerminal transmits or receives a DataLink. Other kinds need a method of their own.
source
SpaceAGORA.SimulationModel.InterLinkModels.terminal_shed_tier — Function
terminal_shed_tier(actuator) -> Int

The battery shedding tier that closes the links of the terminal hardware actuator (a mounted actuator with link_terminal) while a link drives it: 1 sheds it with the laser terminals, 2 with the torque rods, 3 with the reaction wheels, 0 never. A shed terminal draws nothing, and its links are unavailable until the tier clears. Its demand counts in that tier of the power budget (0: with the kinds never shed). 1 for LaserTerminal and RadioTerminal. Default: 0.

source
SpaceAGORA.SimulationModel.InterLinkModels.terminal_count — Function
terminal_count(spacecraft) -> Int

The number of interlink terminals on spacecraft: its n_terminal virtual terminals and, on a SpacecraftModel, its mounted terminal hardware (see link_terminal).

source

mounted_link_terminals(spacecraft::SpacecraftModel) -> Vector

The terminal hardware mounted on spacecraft (actuators with link_terminal), in mounting order. Each entry gives:

  • link: the link it is mounted on;
  • terminal: the actuator.
source
SpaceAGORA.SimulationModel.InterlinkTerminals.terminal_number — Function
terminal_number(spacecraft::SpacecraftModel, terminal) -> Int

The terminal number of terminal, mounted on spacecraft, for a link endpoint (spacecraft index, terminal number). register_link! also takes the terminal itself. Two mounted terminals with equal fields cannot be told apart, so for those give the number.

SpaceAGORA.SimulationModel.InterLinkModels.update_availability! — Function
update_availability!(model::InterlinkModel, spacecraft, state; is_active=nothing, context=LinkContext(),

SpaceAGORA.SimulationModel.InterLinkModels.interlink_force_on_spacecraft — Function
interlink_force_on_spacecraft(model::InterlinkModel, state, satellite; is_active=nothing, spacecraft=nothing, context=LinkContext())

The sum of the inertial forces (N) the selected links put on spacecraft satellite (its vector index), each from its link's link_force. Optional is_active flags mask links with an inactive endpoint.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.SchedulingPolicyModel — Type
SchedulingPolicyModel(policy::AbstractSchedulingPolicy)

The run's interlink scheduler: the scheduling policy whose total score it maximizes (objective) and the matching workspace it reuses between scheduling calls (matching). Pass it, or the policy alone, as SimulationConfiguration(scheduling_policy_model=...); the default is SchedulingPolicyModel(SemimajorAxisRatePolicy()).

The policies chosen by a symbol, SchedulingPolicyModel(:gve_sma) and the others, were removed in SpaceAGORA 0.6.0, with their target_index and target_indices keywords and properties and the older target_idx and target_idxs. A call with a symbol throws an ArgumentError that names its typed replacement, such as SemimajorAxisRatePolicy(targets=[31, 32]) for SchedulingPolicyModel(:gve_sma; target_indices=[31, 32]), and so does a read or write of a removed property, naming .objective or .objective.targets.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.AbstractSchedulingPolicy — Type
AbstractSchedulingPolicy

Supertype of the interlink scheduling policies. A policy is an immutable value whose fields say what it scores, and it holds no run state. A policy type implements candidate_score. The built-in policies are SemimajorAxisRatePolicy, EccentricityRatePolicy, PowerDeliveryPolicy, DataThroughputPolicy, EnergyBalancingPolicy and WeightedPolicy, a weighted mix of policies. Give a run its policy with SimulationConfiguration(scheduling_policy_model=policy).

source
SpaceAGORA.SimulationModel.SchedulingPolicies.SemimajorAxisRatePolicy — Type
SemimajorAxisRatePolicy(; targets=1)

Score each available link by the rate (m/s) at which its force raises the osculating semimajor axis of its target spacecraft: da/dt = 2a² (v · F) / (μ m) at each target end, summed. The force is the link's link_force. targets picks the ends:

  • a spacecraft vector index: that spacecraft's end only;
  • a vector or range of indices: every end in the set, stored sorted;
  • :both: both ends of every link;
  • :lower_index: the lower spacecraft index of each pair.

A link that lowers the semimajor axis scores negative, and links that apply no force (power beams, data links) score 0, so this policy never selects them.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.EccentricityRatePolicy — Type
EccentricityRatePolicy(; targets=1)

Score each available link by the rate (1/s) at which its force raises the eccentricity of its target spacecraft, de/dt = ê · ė, at each target end, summed. targets is a spacecraft vector index, or :both for both ends of every link. The force is the link's link_force.

At an eccentricity no greater than sqrt(eps(Float64)) the score is the norm of the eccentricity-vector rate, ‖ė‖. Such norms are not additive, so a candidate set that could put two positive-score links on one such target, through different terminals, is refused. A link that lowers the eccentricity scores negative, and links that apply no force score 0.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.PowerDeliveryPolicy — Type
PowerDeliveryPolicy()

Score each available directed link whose receiving end is terminal hardware by the electrical power (W) it would deliver to the receiver's bus, link_received_power_w at the current state. It selects power beams, which apply no force. Other links score 0, and so does every link when the run's spacecraft models are not given.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.DataThroughputPolicy — Type
DataThroughputPolicy()

Score each available directed link by the data rate (bit/s) it would carry, link_data_rate_bps at the current state, with the terminal hardware at its two ends (nothing for a virtual terminal). It selects data links. Undirected links score 0, and so does every link when the run's spacecraft models are not given.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.EnergyBalancingPolicy — Type
EnergyBalancingPolicy()

Charge the lowest state of charge. Score each available directed link whose receiving end is terminal hardware, between two spacecraft with a battery, by P × (s_tx − s_rx) (W): P is the electrical power it would deliver to the receiver's bus (link_received_power_w, as PowerDeliveryPolicy scores it), and s_tx and s_rx are the two batteries' states of charge (state_of_charge). Power flows only from a fuller battery to an emptier one, and a beam into a full battery never scores: a battery the power system counts as full (its stored energy within 1e-9 of its capacity) counts as 1, so two full batteries tie at 0. Of receivers competing for one sender's terminal, the emptier wins at equal delivered power. The score is signed: a beam from an emptier battery to a fuller one scores negative. Links with no battery at either end, a link that would deliver no power (or, for a link kind of your own, a negative power), and every link without the run's spacecraft models score 0.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.WeightedPolicy — Type
WeightedPolicy(terms::PolicyTerm...)

A weighted mix of policies: each available link scores Σ weight × (score / scale) over the terms, summed in term order from 0.0. Each term's policy applies its own rules (an orbital term scores power beams 0, a power term scores momentum links 0), so one run can weigh link kinds against each other. Each term's checks run, and an eccentricity term keeps its near-circular refusal over the mix's own candidates. A nonfinite term is refused. Mixes nest. A term with weight=1 and scale=1 alone schedules as its policy does.

WeightedPolicy(PolicyTerm(SemimajorAxisRatePolicy(targets=1); scale=1.0),   # 1 m/s counts as one
               PolicyTerm(EnergyBalancingPolicy(); scale=100.0))            # and so do 100 W
source
SpaceAGORA.SimulationModel.SchedulingPolicies.PolicyTerm — Type
PolicyTerm(policy::AbstractSchedulingPolicy; scale::Real, weight::Real=1.0)

One term of a WeightedPolicy: policy's score divided by scale and times weight. scale is in the policy's own unit (m/s, W, bit/s, ...), the amount of its score that counts as one, so it makes the term dimensionless; it must be finite and positive. weight must be finite; a negative weight penalizes the term.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.state_of_charge — Function
state_of_charge(ctx::SchedulingContext, spacecraft_index::Integer) -> Float64

The state of charge (a fraction of its capacity) of spacecraft spacecraft_index's battery at the scheduling state: its battery_wh over its capacity_wh, the battery_soc column's value. NaN without a battery, without the run's spacecraft models, or for a state without battery_wh.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.candidate_score — Function
candidate_score(policy, candidate::LinkCandidate, ctx::SchedulingContext, t::Float64) -> Float64

The score policy gives candidate, an available candidate link, at t s into the run (ctx.link_context.time_s; NaN outside a run). The scheduler activates the terminal matching with the largest total score, and only links with a positive score can be selected. The engine calls it at the start of the run and after every accepted step, once for each available candidate; an unavailable candidate scores 0 without a call. A nonfinite score is refused. Every policy type implements it: a run refuses at setup a policy without a method.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.LinkCandidate — Type
LinkCandidate

One available candidate link, as a scheduling policy scores it.

  • key: its endpoints, (spacecraft vector index, terminal number) each, in key order: the transmitter first for a directed link, the lower endpoint first otherwise.
  • link: its link kind value.

SpaceAGORA.SimulationModel.SchedulingPolicies.select_interlinks! — Function
select_interlinks!(model::InterlinkModel, policy::SchedulingPolicyModel)

Activate a maximum-total-score matching of available, positive-score links, with at most one link per terminal. Of parallel links (directed links both ways between the same two terminals), only the highest-scoring is a candidate, the first in endpoint order on a tie. Topology belongs to model.graph; policy.matching contains raw per-edge score values and reusable solver scratch arrays. Pass the same policy used by score_candidates!; selection uses its stored scores, not its scoring objective. A fresh workspace starts with zero scores. Appending links preserves existing scores and initializes new scores to zero when the workspace is refreshed. Switching graphs or discarding the workspace resets scores; rescore before selecting again. Use separate policies for independent scheduling runs. Deep-copy the model and policy together to preserve their workspace binding. Edge order is sorted locally on each selection, not stored in either structure. Registered topology and iterative DFS identify tree components, solved with linear-time dynamic programming. Cyclic components use NetworkX's weighted Blossom algorithm through PythonCall, with O(N^3) arithmetic operations for N cyclic endpoints. Both solvers use exact BigInt weights scaled from Float64 scores; no floating-point score sums are compared. Ties are deterministic for a given backend version, but tree ties may choose a different optimum than Blossom alone. Register topology through register_allowed_link!. For manual scores, refresh with matching_workspace!(model, policy) before editing its score vector. Graph availability and workspace scores are reread on every call. Tree components work without Python. Cyclic components require the optional PythonCall package loaded with using PythonCall, and NetworkX installed in the Python environment used by PythonCall. Core loading does not install either backend.
