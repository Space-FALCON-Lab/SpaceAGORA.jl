## Findings

The independent review of `5c8728f4` found two P2 correctness regressions and one P3 documentation defect. All three are corrected in this follow-up.

The implicit default repeats the first campaign sample on every new worker. Those calls may share result/checkpoint files, so the router now passes `warmup_concurrent=false` for that default. Explicit custom warm-ups remain concurrent and must isolate their side effects. `false` still skips warm-up. Generic bootstrap remains concurrent.

Mandatory bootstrap now uses an `@sync` barrier. A failed bootstrap waits for all started siblings before removing only the newly spawned workers and releasing the pool lock. Existing pool workers remain registered. If removal itself fails, its warning preserves the original bootstrap error. This closes the introduced in-flight-task ownership gap and adds cleanup for the failed addition.

The public example now passes seeds positionally. Docstrings remain attached and describe the concurrency choice.

Independent static review found no further blocking defect. The new tests invoke actual parsed or included production methods with local worker effects injected, without replacing SpaceAGORA or Distributed methods. Separate existing tests and the retained external probe cover real Distributed workers.

## October 4 real-worker validation follow-up

Production source was pinned to `ba984ccddbbe0f2427be09c1c9e44f8c3e596856`. The proposed follow-up changes the regression test and this review record only. It retains two workers, requires both warm-ups to reach a barrier before either is released, matches one start and finish per worker, and records any unexpected rewarm before its error can be swallowed. The second-arrival deadline is shorter than the worker barrier timeout, so a serial warm-up implementation cannot pass by waiting for the first warm-up to fail. Cleanup releases barriers and reclaims processes spawned by this test, including unregistered processes after an error. An outer process timeout remains necessary for exceptional shutdown behavior.
