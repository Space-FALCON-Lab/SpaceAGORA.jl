Extension Hooks API

This page documents the supported public interface available from SpaceAGORA.

Model Extension Hooks

SpaceAGORA.SimulationModel.EffectorSampling.wrench — Function
wrench(model, x::StateSample, env::EnvironmentSample, t::Float64) -> (force_ii, torque_body)

Preferred additive extension hook for custom AbstractForceTorqueModel implementations. The engine owns stage-consistent sampling and caching, then passes a typed state/environment bundle into wrench.

Return inertial-frame force and body-frame torque in SI units. Implementations should behave as pure functions of (model, x, env, t). A model that acts on one spacecraft of a multi-spacecraft run selects it with x.spacecraft_index.

source
SpaceAGORA.SimulationModel.EffectorSampling.environment_requirements — Function
environment_requirements(model) -> EffectorEnvironmentRequirements

Preferred additive declaration hook for the sampled environment capabilities a wrench implementation requires. The default requests no sampled environment fields.

source
SpaceAGORA.SimulationModel.DynamicEffectors.is_gravitational — Function
is_gravitational(effector) -> Bool

Whether a dynamic effector models gravity: the central body's field and its harmonics, third bodies, and the gravity-gradient torque. An accelerometer does not feel these effectors' forces (see Accelerometer). A user-defined gravity model should add a method returning true.

source
SpaceAGORA.SimulationModel.EffectorSampling.solver_partition — Function
solver_partition(model) -> Symbol

Optional additive declaration hook for split_imex solver partitioning of dynamic effectors.

Return :implicit to place the effector on the atmosphere-implicit IMEX side, or :explicit to keep it on the non-stiff explicit side. The default is :explicit.

source
SpaceAGORA.trial_rhs_safe — Function
trial_rhs_safe(model) -> Bool

Declare that a model's RHS evaluation is repeatable for perturbed trial states and times without advancing physical, random or controller history. This is an interface contract, not scientific validation. Unknown models default to false. Accepted-step callbacks may still update discrete commands normally.

source
SpaceAGORA.SimulationModel.EffectorSampling.gravity_backbone_structure — Function
gravity_backbone_structure(model) -> Symbol

Optional additive declaration hook for the gravity_backbone_split solver mode.

Return :position_only_static_gravity for effectors that can participate in the gravity-only translational backbone, or :unsupported otherwise. The default is :unsupported.

source
SpaceAGORA.SimulationModel.EffectorSampling.gravity_backbone_acceleration_ii — Function
gravity_backbone_acceleration_ii(model, x::StateSample, env::EnvironmentSample, t::Float64) -> accel_ii

Optional additive acceleration hook for gravity_backbone_split.

Implementations must return inertial-frame translational acceleration in SI units for effectors that declare gravity_backbone_structure == :position_only_static_gravity.

source
SpaceAGORA.SimulationModel.EffectorSampling.gravity_backbone_kick_structure — Function
gravity_backbone_kick_structure(model) -> Symbol

Optional additive declaration hook for explicit translational perturbation kicks in gravity_backbone_split.

Return :velocity_kick_explicit for effectors that should be applied as explicit velocity kicks around the gravity core, or :unsupported otherwise. The default is :unsupported.

source
SpaceAGORA.SimulationModel.EffectorSampling.gravity_backbone_kick_acceleration_ii — Function
gravity_backbone_kick_acceleration_ii(model, x::StateSample, env::EnvironmentSample, t::Float64) -> accel_ii

Optional additive acceleration hook for explicit velocity kicks in gravity_backbone_split.

Implementations must return inertial-frame translational acceleration in SI units for effectors that declare gravity_backbone_kick_structure == :velocity_kick_explicit.

source
SpaceAGORA.SimulationModel.EnvironmentModels.getDensity — Function
getDensity(model, h, lat, lon, el_time, wind[, p]) -> (rho, temperature, wind_vec)

Stable extension hook for custom AbstractDensityModel implementations. The scalar form returns density, temperature, and wind for a single atmosphere query.

The arguments, as the simulation engine passes them:

  • h: geodetic altitude above the planet's reference ellipsoid, in m.
  • lat: geodetic latitude, in rad.
  • lon: east longitude in the planet-fixed frame, in rad.
  • el_time: elapsed seconds since the scenario epoch.
  • wind: whether the caller needs the wind vector. A model may return a zero wind_vec when it is false.
  • p: the run's parameters, in the 7-argument form.

The engine computes h, lat and lon from the planet-fixed position with Bowring's method (rtolatlong). On a planet with zero flattening, geodetic and planetocentric latitude coincide.

The result is rho in kg/m³, temperature in K, and wind_vec, the air's velocity relative to the rotating planet as east, north and up components in m/s.

Calendar-dependent models require the 7-argument form: el_time is elapsed seconds from the scenario epoch, which only p.args.initial_time can resolve to an absolute date. NRLMSISE00AtmosphereModel therefore throws on the 6-argument form instead of silently evaluating at a fixed reference epoch.

source
SpaceAGORA.SimulationModel.EnvironmentModels.density_altitude_derivative — Function
density_altitude_derivative(model, altitude_m) -> Float64

Derivative of the model's density with respect to altitude (kg/m⁴), for the altitude-only models (no atmosphere, constant, exponential, piecewise exponential and polynomial fit). The aerobraking MPC uses it for the analytic density gradient of its drag linearisation. Custom altitude-only models may implement this optional query; use applicable to check support (there is no generic fallback). Polynomial fits return zero outside altitude/exponent clamps and for a zero-width altitude domain. At nondegenerate clamp endpoints they return the interior derivative. Piecewise exponentials select the right-hand layer at a breakpoint; a discontinuous join has no two-sided derivative. Exponential validity bounds are advisory: their derivatives extrapolate with the density model.

source
SpaceAGORA.SimulationModel.EnvironmentModels.getDensityBatch! — Function
getDensityBatch!(rhos, Ts, winds, model, hs, lats, lons, el_time, wind, p)

Optional batch extension hook for AbstractDensityModel implementations that can answer many atmosphere queries more efficiently than repeated scalar getDensity dispatch.

For query k it writes rhos[k], Ts[k] and winds[k], the scalar form's results for hs[k], lats[k] and lons[k], in the same units and conventions as getDensity. el_time is either one elapsed time for every query or one per query. The method for any AbstractDensityModel calls the scalar form query by query.

source
SpaceAGORA.SimulationModel.EnvironmentModels.with_density_model_epoch — Function
with_density_model_epoch(model::AbstractDensityModel, initial_time)

Return a density model whose native elapsed-time origin matches initial_time. The default implementation returns model unchanged; custom epoch-dependent models may extend this hook. run_simulation calls it before state isolation.

For a keyword-built GRAMAtmosphereModel, an unchanged epoch returns the same object. A changed epoch reconstructs a fresh native model from its owned construction recipe, preserving the other recorded options. Equality uses the stored integer calendar fields and Float32 seconds, without a time tolerance. A raw-core wrapper with an unknown recipe cannot be realigned safely and throws.

A GRAMAtmosphereModelSurrogate backed by GRAM rejects a changed epoch: rebuilding its native fallback cannot validate or re-epoch its fixed table. Construct and validate a table/model for the requested epoch explicitly. An unchanged epoch preserves the surrogate object, file and fallback setting. Surrogates with a non-GRAM base retain the default no-op behavior.

This hook changes the construction epoch only. It does not convert time systems, validate atmospheric coordinate/datum conventions, certify cached or surrogate data, or preserve a previously advanced native random stream or manual handle mutations. Existing native cache and environment policies still apply.

source
SpaceAGORA.SimulationModel.EphemeridesModels.ephemerides_frame_lpi — Function
ephemerides_frame_lpi(model, planet, et) -> SMatrix{3, 3, Float64}

The rotation from the inertial (J2000) frame to planet's planet-fixed frame at ephemeris time et, so that r_pf = L * r_ii. The engine calls it wherever it needs the planet-fixed frame, for example for the atmosphere, gravity-harmonics and magnetic-field samples, guidance and the scene export. It returns the rotation only; a caller that needs planet-relative velocity adds the transport term with the planet's spin vector.

et is in seconds past the J2000 epoch on the model's own timeline: the run's start, ephemerides_epoch_seconds, plus the elapsed time. SpiceEphemeridesModel asks SPICE for the transform; SimpleEphemeridesModel turns the planet about its spin axis, by default Earth by its Greenwich mean sidereal time.

source
SpaceAGORA.SimulationModel.EphemeridesModels.ephemerides_sun_ii — Function
ephemerides_sun_ii(model, planet, et) -> Union{Nothing, SVector{3, Float64}}

Unit vector from the planet's center to the Sun, in the inertial (J2000) frame the integrated state uses, or nothing when this ephemeris backend cannot resolve the Sun for this body. et is as for ephemerides_frame_lpi. The power callbacks and the saved Sun direction call it.

SpiceEphemeridesModel asks SPICE for the Sun's position relative to the planet, so it works for every body whose SPK is furnished. SimpleEphemeridesModel carries no planetary ephemeris, so it answers only for Earth, from a low-precision analytic Sun; it returns nothing for any other body rather than inventing a direction.

source
SpaceAGORA.SimulationModel.EphemeridesModels.ephemerides_epoch_seconds — Function
ephemerides_epoch_seconds(model, initial_time) -> Float64

The run's start epoch, initial_time (an InitialTime, UTC), in seconds past the J2000 epoch on the model's own timeline. The engine calls it before the run and adds the elapsed time to it for each ephemeris time et it passes to ephemerides_frame_lpi and ephemerides_sun_ii.

SpiceEphemeridesModel returns SPICE's ephemeris time (TDB); SimpleEphemeridesModel returns leap-second-free UTC seconds past J2000 plus its reference_epoch_seconds.

source
SpaceAGORA.SimulationModel.EphemeridesModels.ephemerides_requires_spice — Function
ephemerides_requires_spice(model) -> Bool

Whether the model reads SPICE kernels. When it does, the planet-fixed position and velocity transforms ask SPICE for the full state transform rather than ephemerides_frame_lpi, and the run counts the model's SPICE frame calls.

source
SpaceAGORA.SimulationModel.EphemeridesModels.ephemerides_cache_key — Function
ephemerides_cache_key(model) -> Tuple

A key for the model's timeline and frames: the engine may reuse an ephemeris cache built for one run in a later run whose model has an equal key. Two models with equal keys must give the same frames and times.

source
SpaceAGORA.SimulationModel.ControlHooks.update_control! — Function
update_control!(model, u, p, t, spacecraft_index) -> nothing

The control tick, which every effector in a ControlModel implements for its own type. The effector computes its command (a thrust, a torque, actuator levels, panel angles) and keeps it in its own state; the engine ignores the return value and applies the held command until the next tick:

  • in :ideal actuation, the default actuation_mode, through the effector's control_wrench, control_propellant_rate and control_wheel_torque, which the dynamics evaluate at every step;
  • in :mounted actuation, through the levels actuator_levels returns for the actuators mounted on the spacecraft; control_wrench and control_propellant_rate are not called.

The arguments:

  • model: the control effector.
  • u: the full integrated state. u.sc[spacecraft_index] is the spacecraft, with pos (m) and vel (m/s) relative to the planet's centre in the inertial frame and mass (kg); with attitude propagation also q = (x, y, z, w), scalar last, with v_body = rot(q) * v_inertial (body means bus axes), and ω, the bus angular velocity in rad/s.
  • p: the run's parameters; p.args is the SimulationConfiguration.
  • t: elapsed time since the run's start epoch, in seconds (Float64).
  • spacecraft_index: the spacecraft's position in the run (Int, from 1), not its ID.

Effector k runs on the simulation's control clock every control_rates[k] seconds, once for each spacecraft in its declared scope. Checkpoint segments and resume retain that clock rather than starting a new period. The calls for different spacecraft run one after another unless the effector's type is declared thread-safe (SimulationModel.SimulationCallbacks.control_model_threadsafe(::MyEffector) = true) or the run sets SPACEAGORA_CONTROL_CALLBACK_ASSUME_THREADSAFE=1; then they may run at the same time on different threads, and state that several spacecraft share needs a lock. BaseThrusterModel considers new maneuver requests on its control ticks, after guidance due at the same time. Startup and atmosphere-exit bookkeeping do not force an extra request-processing tick; a control tick pending at resume is still taken once. Accepted burn windows and explicitly installed plans retain their ignition and stop times, including boundaries between control ticks.

Before integration starts, run_simulation checks that every control effector has a method of this function and, unless its actuation is :mounted, of control_wrench, and stops with an ArgumentError naming the effector otherwise.

source
SpaceAGORA.SimulationModel.ControlHooks.control_wrench — Function
control_wrench(model, x::StateSample, p, t::Float64) -> (force_ii, torque_body)

The force and torque a control effector applies to its spacecraft, which the dynamics evaluate at every right-hand-side evaluation in :ideal actuation, the default actuation_mode. Every control effector whose actuation is not :mounted needs a method for its own type. There is no fallback: run_simulation checks for the method before integration starts, as it does for update_control!.

Return a tuple of two 3-vectors:

  • force_ii: in the inertial frame, in N;
  • torque_body: in the bus frame, about the root body's centre of mass, in N·m. The dynamics apply it only when the run propagates attitude.

An effector that applies neither returns two zero vectors. The arguments:

  • model: the control effector.
  • x: the StateSample of that spacecraft. x.pos_ii (m) and x.vel_ii (m/s) are relative to the planet's centre in the inertial frame and x.mass_kg is its mass. With attitude propagation, x.q_ib is the quaternion q = (x, y, z, w), scalar last, with v_body = rot(q) * v_inertial (body means bus axes), and x.ω_body the bus angular velocity in rad/s; both are nothing otherwise. x.spacecraft_index is the spacecraft's position in the run (Int, from 1), not its ID.
  • p: the run's parameters.
  • t: elapsed time since the run's start epoch, in seconds (Float64).

Return the command held since the last update_control! tick rather than recomputing the control law here. A method typed x::StateSample, or with x untyped, is the one the dynamics call. The dynamics call it, and the other output hooks, only for the spacecraft the model's spacecraft_scope names (SpaceAGORA 0.6 and earlier called them for every spacecraft); return zeros for any other, which direct callers may still ask about.

source
SpaceAGORA.SimulationModel.ControlHooks.control_propellant_rate — Function
control_propellant_rate(model, x::StateSample, p, t::Float64) -> Float64

The propellant a control effector uses, in kg/s: positive while propellant is used, and 0.0 when none is. The engine subtracts it from the spacecraft's mass derivative. A nonfinite rate is ignored.

The dynamics call it at every right-hand-side evaluation in :ideal actuation, so return the rate held since the last update_control! tick. An effector that uses no propellant needs no method: the fallback, for any model, returns 0.0. The arguments are those of control_wrench; the spacecraft's index in the run is x.spacecraft_index. The BaseThrusterModel method returns norm(force) / (Isp * g0) during an active valid burn and 0.0 otherwise.

source
SpaceAGORA.SimulationModel.ControlHooks.control_wheel_torque — Function
control_wheel_torque(model, x::StateSample, p, t::Float64) -> Union{Nothing, AbstractVector}

Optional hook for a control effector that drives reaction wheels: the part of its commanded torque on the spacecraft that the wheels produce, a 3-vector in the bus frame in N·m. An effector that drives no wheel needs no method: the fallback, for any model, returns nothing.

The momentum stored in the wheels (the h_wheels state) changes at the opposite rate, mapped onto the wheel axes. In :ideal actuation the engine applies this torque only to the wheels: the effector includes it in the torque its control_wrench returns. In :mounted actuation the engine adds it to the torque of the mounted actuators.

The dynamics call it at every right-hand-side evaluation, so return the torque held since the last update_control! tick. The arguments are those of control_wrench; the spacecraft's index in the run is x.spacecraft_index.

source
SpaceAGORA.SimulationModel.ControlHooks.control_thruster_levels — Function
control_thruster_levels(effector, spacecraft_index::Int) -> Union{Nothing, AbstractVector{<:Real}}

Optional hook: the firing level (0 to 1) of every thruster of the spacecraft at spacecraft_index (its position in the run, from 1), in the order the visualization scene lists them (the spacecraft's links in order, each link's thrusters in order). Effectors that drive no named thruster return nothing, the default for any effector type that does not override this method; an effector that drives only some of them may return a shorter vector, and the remaining thrusters are idle.

The engine reads this at save time, so an effector must compute the levels in update_control! and keep them in its own actuator state rather than recomputing them here. During the run it asks only for the spacecraft the effector's spacecraft_scope names (for every spacecraft in SpaceAGORA 0.6 and earlier). Before the run, when the result columns are sized, it asks every effector about every spacecraft with thrusters, so keep returning nothing for a spacecraft outside the scope.

source
SpaceAGORA.SimulationModel.ControlHooks.touchdown_spec — Function
touchdown_spec(effector, spacecraft_index::Int) -> Union{Nothing, NamedTuple}

Optional terrain-contact event for a selected spacecraft's index in the run (not its user-defined ID). Return nothing for unselected spacecraft, or (terrain, reference_radius_m, height_m, on_touchdown): an AbstractTerrainModel, its explicit positive reference-sphere radius in metres, a finite nonnegative clearance in metres, and a callable accepting (t, r_p, v_p, spacecraft_index). The callback receives planet-fixed position and ground-relative velocity in metres and metres per second. It may record contact and turn off actuators.

The first downward crossing deactivates only this spacecraft; the solve ends once all spacecraft are inactive. Initial contact/below-ground states and multiple specifications for one index are rejected. The usual 50 km impact stop remains active for every spacecraft with no touchdown specification.

source
SpaceAGORA.SimulationModel.GuidanceHooks.update_guidance! — Function
update_guidance!(model, u, p, t, spacecraft_index) -> nothing

The guidance tick, which every effector in a GuidanceModel implements for its own type. The effector updates its own state (a plan, a target, a mode) for control effectors to read; the engine ignores the return value.

  • model: the guidance effector.
  • u: the full integrated state. u.sc[spacecraft_index] is the spacecraft, with pos (m) and vel (m/s) relative to the planet's centre in the inertial frame and mass (kg); with attitude propagation also q = (x, y, z, w), scalar last, with v_body = rot(q) * v_inertial (body means bus axes), and ω, the bus angular velocity in rad/s.
  • p: the run's parameters; p.args is the SimulationConfiguration.
  • t: elapsed time since the run's start epoch, in seconds (Float64).
  • spacecraft_index: the spacecraft's position in the run (Int, from 1), not its ID.

Effector k runs every guidance_rates[k] seconds of simulated time for the spacecraft in its declared scope, starting one period after the run starts. Checkpoint segments and resume retain that run clock. When ticks coincide, navigation runs first, followed by control and guidance; energy depletion guidance with targeting runs before control instead. Maneuver planning runs after all guidance due at that time. Startup and atmosphere exits do not force extra guidance ticks; a tick pending at resume is taken once on the retained clock.

Before integration starts, run_simulation checks that every guidance effector has a method of this function for these arguments and stops with an ArgumentError naming the effector otherwise.

source
SpaceAGORA.SimulationModel.NavigationHooks.update_navigation! — Function
update_navigation!(model, u, p, t, spacecraft_index) -> nothing

The navigation tick, which every effector in a NavigationModel (a sensor or a state estimator, usually an AbstractNavigationModel) implements for its own type. The effector takes its measurements or updates its estimate and keeps them in its own state for guidance and control effectors to read; the engine ignores the return value. SpaceAGORA has no built-in navigation effector, so this function has no methods until one is added.

  • model: the navigation effector.
  • u: the full integrated state. u.sc[spacecraft_index] is the spacecraft, with pos (m) and vel (m/s) relative to the planet's centre in the inertial frame and mass (kg); with attitude propagation also q = (x, y, z, w), scalar last, with v_body = rot(q) * v_inertial (body means bus axes), and ω, the bus angular velocity in rad/s. These are the true values; any sensor noise is the effector's own. Sensors mounted with add_sensor! are sampled before navigation ticks at the same time; read them with sensor_measurement(p.args.dynamics_model.spacecraft[spacecraft_index], k).
  • p: the run's parameters; p.args is the SimulationConfiguration.
  • t: elapsed time since the run's start epoch, in seconds (Float64).
  • spacecraft_index: the spacecraft's position in the run (Int, from 1), not its ID.

Effector k runs every navigation_rates[k] seconds of simulated time, once for each spacecraft in index order, starting one period after the solve starts. When ticks coincide, navigation effectors run before guidance and control effectors.

Before integration starts, run_simulation checks that every navigation effector has a method of this function for these arguments and stops with an ArgumentError naming the effector otherwise.

source
SpaceAGORA.SimulationModel.VehicleThermalModels.getHeatRate — Function
getHeatRate(model, S, T, ρ, v, α) -> Float64

The heat rate of one thermal link, which every AbstractThermalModel implements for its own type. The built-in models return W/cm², the unit of the saved heat_rate columns, and the engine integrates the rate into each link's heat_loads state without converting it.

  • S: molecular speed ratio, sqrt(γ / 2) times the Mach number (no unit).
  • T: free-stream temperature, K.
  • ρ: free-stream density, kg/m³.
  • v: speed relative to the atmosphere (planet rotation and wind removed), m/s.
  • α: incidence angle of the link to the flow, rad.

Whenever the engine samples heating where the density is positive, it calls this for each link of each spacecraft, with all arguments Float64, and stores a non-finite or negative result as zero. Before integration starts, run_simulation checks that the configured thermal model has this method and stops with an ArgumentError otherwise.

source
SpaceAGORA.SimulationLifecycle.bind_spacecraft — Function
bind_spacecraft(effector, sat_idx::Int)

Extension point for per-spacecraft GNC: return effector bound to spacecraft sat_idx (a run index, 1-based). A SpacecraftModel can declare guidance, navigation and control effectors; at the start of run_simulation each one is passed through this function with the position of its spacecraft, and the result joins the configuration-level GNC tuples.

Implement it for an effector that selects its vehicle by an index field: return a shallow copy (sharing mutable members with the original) with that field set, or effector itself when it already targets sat_idx. A member that holds one spacecraft's run state (a held command, a controller's warm start) needs its own copy, so spacecraft bound from one template do not share it; members indexed by spacecraft, such as an ApolloDescentState, stay shared. The fallback throws an ArgumentError that names the effector's spacecraft_scope: an effector that acts on every spacecraft (AllSpacecraft) or couples several vehicles (CoupledSpacecraft, for example the RPO chaser and target types) cannot belong to one; declare it at configuration level instead.
