Migrating Extension Hooks

SpaceAGORA's extension hooks follow one set of conventions: time before the spacecraft index, a state sample for right-hand-side hooks, and positive consumption. Ten hook names, and one form of the plume model's wrench, did not. SpaceAGORA 0.3.0 deprecated them and 0.5.0 removed them. In 0.3.0 and 0.4.0, the pre-run check warned about a model's method of an old name once per process for each model type and name, a direct call of an old name warned too, and the five-argument plume form warned only when called directly. This page lists each name with its replacement.

A method of a removed name no longer runs. One that names the package, such as SpaceAGORA.calcForceTorque(...) = ..., fails when its file loads, because the name is gone. The pre-run check refuses a model left without a method of a required replacement, a tick, control_wrench (unless the effector's actuation is :mounted) or wrench, and names the hook it needs. control_propellant_rate and control_wheel_torque are optional: without a method of its own, an effector gets 0.0 and nothing, and the check does not refuse it. An ephemerides model without the model-first hooks stops with a MethodError naming the hook when the run first asks it for its epoch or frame. To find the old names in your code:

grep -rnE "calcForceTorque|calcControl(ForceTorque|MassFlowRate|Effect!)|calcReactionWheelTorque|calc(Guidance|Navigation)Effect!|planet_frame_lpi|ephemerides_(sun_direction_ii|time_seconds)" src test

The sign changes

calcControlMassFlowRate returned the spacecraft's mass derivative, negative while propellant is used. control_propellant_rate returns the propellant used, positive. Flip the sign when you rename the method: a method renamed without it makes the vehicle gain mass.

The frames, units and values are otherwise unchanged. An effector that uses no propellant, or drives no wheel, needs no control_propellant_rate or control_wheel_torque: their defaults return 0.0 and nothing. A force or torque model declares what it reads from the environment with environment_requirements(model). Adding a Force or Torque of Your Own and Extending SpaceAGORA show complete methods of the replacements.

Schedule

  • 0.3.0. The new names, with warnings for the old ones. ExternalPropagationServices, HYPRServices and EDGServices are at contract 2.0.0, with SpaceAGORAMuJoCo 0.2.0, HYPR 0.2.0 and SpaceAGORAEDG 0.2.0.
  • 0.3.1. RobotArmReactionEffector.spacecraft_idx becomes spacecraft_index, with a warning for the old name.
  • 0.4.0. The companion packages use the new names. skip_inactive defaults to true: a guidance, navigation or control model stops ticking for a spacecraft once it is inactive, unless it returns false. The pre-run configuration checks that warned in 0.3 refuse the run with an ArgumentError, whether or not Julia runs with --depwarn=error: a control period (gnc_period_s) that differs from its control rate or from its controller's discretization step, a spacecraft scope that names a position outside the run, and Apollo descent guidance and control that do not share their state and spacecraft.
  • 0.5.0, or 1.0 if that comes first. The deprecated names are removed, and control_propellant_rate and control_wheel_torque gain defaults, 0.0 and nothing. The removal waits until a tagged release has carried the warnings and the companion packages have moved.

Release numbers follow version in Project.toml. The older v1.0.0 and v2.0.0 git tags predate it.

Checklist

  1. Find each method of an old name with the command above. On 0.4.0, a test run with julia --depwarn=error also stops at each one. Search for RPOGuidanceModel too: its warning on 0.3 and 0.4 was an ordinary warning, which --depwarn=error does not turn into an error.
  2. Rename each tick.
  3. Move each output hook to its state-sample form, and flip the sign of the propellant rate.
  4. Move each calcForceTorque method to wrench, with an environment_requirements method if it reads the atmosphere, the Sun or the planet-fixed frame.
  5. Type the sample argument x::StateSample, or leave it untyped (see the conventions).
  6. Run the tests again: the pre-run check accepts every model.

Names that cannot warn

The interlink names deprecated in 0.5.0 are listed under Interlinks. Two of them, ConstellationInterLinkModel (now InterlinkModel) and InterLinkParameters (now LaserMomentumLink), are aliases of the new types and cannot warn: code that uses them runs silently, also under julia --depwarn=error. Search your code for them before SpaceAGORA 1.0 removes them:

grep -rnE "ConstellationInterLinkModel|InterLinkParameters" src test
