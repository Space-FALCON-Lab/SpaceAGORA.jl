## Findings

No findings. Three points for review:

- **Both plot flags are checked.** The failed-path figures need PlotlyJS too, so the refusal covers `write_failed_path_outputs` as well as `write_plotly_outputs`. ## Residual Risk

- **A breaking change for plotting scripts.** Scripts and projects that plot must add and load PlotlyJS. SpaceAGORA 0.5.1 announced it, and the Upgrading page and the error message give the steps.
- **Configurations with only `write_plotly_outputs=false`** now refuse without PlotlyJS. They need `write_failed_path_outputs=false` too.
- **The PlotlyJS stack floats** in the examples and test environments, as the rest of the plotting stack does by decision; only Roots is pinned.
- **The renderer registry is process-global.** Sandboxed source loads (suites 01 and 03) keep their own registry, and only the package's extension registers. A sandbox copy therefore has no renderer unless PlotlyJS's extension is loaded for it, and its figure functions refuse.
- **The full sysimage** no longer bakes in PlotlyJS, so plotting sessions with that image compile PlotlyJS and the extension at first use.
