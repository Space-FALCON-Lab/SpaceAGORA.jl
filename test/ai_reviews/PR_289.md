## Findings

- The current-main union preserved all 43 PR-only and 28 main-only files, with
  reviewed composition in two callback/engine files. No runtime repair was
  needed for integration with operational mission segments.
- The companion receives immutable physical observations and geometry plus
  synchronous, call-scoped query capabilities. Public config/state/model/command
  identities remain in core. Core retains physical integration, heat, callbacks
  and panel actuation. There is one active implementation of the eight kernels.
- Review found ordinary property access could expose the borrowed query closure.
  Properties are now opaque and expiry is checked inside that closure. Core
  revokes leases on success and exception. Reflection into Julia private storage
  is outside this ownership contract, which is not a security sandbox.
- Numerical file comparison accepts only explicit service/projection substitutions
  and relocation of the single core-owned decision type. Passage-heat code is
  byte-identical; no constants, comparison policy or arithmetic were retuned.
- The CLI previously restarted examples under core's project and would lose the
  installed provider. The bounded routing for the two EDG examples preserves an
  explicit validated environment through the actual child and common.jl switch.
- Moving numerical files would have removed them from core's coverage denominator.
  CI now collects their measurements and includes the pinned companion sources
  in the existing authoritative gate at unchanged thresholds. Missing source or
  measurement is a failure. Tests still execute the original EDG suites.
- The old source-completeness classification called the compatibility dispatcher
  a pure include aggregator. Its specific classification now enforces the exact
  forwarding/inventory contract; generic silent-stub guards and negative controls
  remain active. Include-boundary fixtures were updated narrowly for the actual
  reviewed facade include; no runtime code changed to satisfy these gates.

- The public example originally reached into an internal module for its aerodynamic
  constructor. Core now exports the existing `AerodynamicCoefficientfM` type
  directly, with inherited documentation and seven API assertions. No methods,
  defaults or equations changed. The example uses only public names.
