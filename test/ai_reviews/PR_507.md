What it does:
- **The maneuver guidance models bind.** `ApoapsisTargetPeriapsisRaiseGuidanceModel`
  and `AerobrakingCampaignPropulsiveManeuverGuidanceModel` gain
  `spacecraft_index` (0, every spacecraft, by default), a `spacecraft_scope` that
  follows it, and `bind_spacecraft`. A bound periapsis-raise copy has its own
  command states and checkpoints only its own entry. The fallback's refusal of
  a model for every spacecraft, such as `BaseThrusterModel`, points to one
  shared model with one entry per spacecraft.
- **The warning.** A bound copy whose scope is still `AllSpacecraft()` warns once
  per type in each run, naming the spacecraft's run position and id.
- **The ensemble refusal.** `run_constellation_ensemble(args;
  allow_gnc_effectors=true)` refuses a configuration-level model whose scope is
  a `BoundSpacecraft`, a `CoupledSpacecraft` or a `SpacecraftSelection`, unless
  the ensemble has one member and the scope names position 1 alone.

Rule: every existing run is bitwise unchanged. A configuration that relied on a
configuration-level model bound to run positions in an ensemble is refused, by
decision (D-C3-9).

## Findings

- **F1 (the periapsis-raise copies' run state, against the design).** The design
  had bound copies share the template's `command_state`, which is indexed by
  spacecraft. The conformance kit's `bind_fresh_state` check refuses a mutable
  object that two copies bound from one template share and that the run changes,
  and the design's test plan asks that check to pass. So each copy gets its own
  copy of the vector at binding. A copy writes only its own spacecraft's entry,
  so the bits are those of the shared vector.
- **F2 (the oracle's saved points).** Each periodic guidance callback saves at its
  ticks (D-C3-10, not changed here), so N bound copies save N times at a tick
  time where one shared model saves once. The tests compare the state at every
  saved time, the last saved at each, and the final state: bit for bit the same.
- **F3 (when the burn scheduler plans).** The scheduler plans when the run starts
  and at each atmosphere exit, after running the guidance for that spacecraft. A
  periapsis-raise command is issued only in the window before apoapsis, and a
  campaign maneuver at a scheduling pass. So the tests start the raise
  spacecraft inside its window and give the campaign runs an interface above
  their periapsis (no atmosphere model, so no drag), and they check that every
  spacecraft's semimajor axis moved by kilometres. The GNC fingerprint probe kept
  outside the repository has a maneuver case that plans no burn, so these tests
  are the ones that exercise the bound copies' burns.
- **F4 (historical finding; fixed by the current #509 integration).** On main 92f2974a9, a run with
  `ApoapsisTargetPeriapsisRaiseGuidanceModel` at configuration level and the burn
  scheduler, checkpointed at 7000 s and resumed there, does not end where the
  run without the break ends; without the guidance it does. Bound copies give the
  bits of the shared model under the same break, so this PR neither causes nor
  changes it. The in-house review's lead held: the burn scheduler's commands and
  plans (`SharedBuffers.maneuver_commands`, `maneuver_burn_plans`) are not in the
  checkpoint, so a command or plan waiting at the checkpoint is lost on resume.
  The campaign case has a second cause: the orbit counter (`p.orbit_counter`) is
  not in the checkpoint either, so a resumed run starts again on orbit 1 and plans
  orbit 1's maneuver a second time. The same counter ends a `MissionOrbits` run,
  which resumed therefore ends an orbit late. The fix for both on main is a PR of
  its own (branch `resume-maneuver-buffers`); this PR's campaign late-resume
  check was a broken test until that fix was integrated. The current integration
  changes it to `@test`; it now passes without changing its fixture or comparison.
- **F5 (where the warning looks).** The warning checks a copy's scope right after
  `bind_spacecraft`, before the run-start initializers. A model whose copy's
  scope an initializer narrows would warn. No built-in does this: every built-in
  binder sets its index in `bind_spacecraft`.
- **F6 (selections in ensembles, from #492's review).** A configuration-level
  model with `SpacecraftSelection(ids=[k])` failed in every member without id k,
  and one with `SpacecraftSelection(positions=[1])` acted on every member. Both
  are refused now, with `BoundSpacecraft` and `CoupledSpacecraft` scopes, before
  any member runs. The RPO pair, coupled, was already failing in members; it is
  refused up front too.
- **F7 (the burn scheduler's refusal, found by the conformance tests).** The first
  version gave `BaseThrusterModel` a `bind_spacecraft` method that only refused.
  The kit's `bind_fresh_state` check takes any type with its own method for a
  model that binds, so it bound the scheduler and failed. 9a5f2848e removes the
  method and puts the pointer in the fallback's message, which is where the
  design asked for it.
- **F8 (the in-house review, 2026-10-23).** Clear, with no P1 or P2: bound copies
  act only on their spacecraft, index 0 gives main's bits, and the refusal comes
  before any member runs. Nine P3s:
  - 507-P3-1: a model that picks its spacecraft by an index field without
    declaring its scope is not detected by the ensemble check. Documented on the
    constellations page and in the ensemble's docstring (b01250872);
  - 507-P3-2: an ensemble of one refused `BoundSpacecraft((1,))`, which #450's
    check keeps for dynamic effectors. It keeps a scope that names position 1
    alone now (b01250872);
  - 507-P3-3: a selection-scoped model without `bind_spacecraft` was told it acts
    on every spacecraft and pointed to the burn scheduler. The fallback names the
    selection now (b01250872);
  - 507-P3-4: the warning repeats in each ensemble member's run, and its
    "spacecraft k" was the run position. It names the run position and id, and
    the docs say once per type in each run (b01250872);
  - 507-P3-5: neither model's `update_guidance!` checked its index, so a direct
    caller could make a copy act on another spacecraft. Both check it now,
    bitwise for index 0 and for every engine call (b01250872);
  - 507-P3-6: the opt-in wording asked models "for a single satellite" to opt in,
    which the refusal now refuses. It asks for models that act on each satellite
    on its own (b01250872);
  - 507-P3-7: the late-resume check compared with a resumed run that main gets
    wrong (F4). The raise runs, which burn at their start, are compared with the
    run without the break at both breaks, and the campaign case is a broken test
    until the fix for main lands (b01250872);
  - 507-P3-8: stale heads in this record and the body;
  - 507-P3-9: the refusal printed the scope with its type parameters. It writes
    it as users do (b6d865d6f).
- No P1 or P2 finding.
