# PR 301 review: optional CSV output

## Scope

Adapt the original `fix/save-csv-conditional` guard to the current output and
mission-history contracts. Review performed against main
`ab545b85c99cd795c61a29dc0ae928d8b6195770`; independent review covered the source,
regression tests and user documentation. Scientific equations, model choices,
integration settings and tolerances are unchanged.

## Changed Files

- `src/orchestration/simulation/engine/execution.jl`: honor `save_csv` when
  writing the primary CSV, retaining `nothing` for the absent output path.
- `src/interfaces/io/outputs/io_outputs.jl`: invalidate an earlier owned
  mission-history association before a bundle write, including Feather-only
  writes and partial failures.
- `src/orchestration/simulation/engine/persistence.jl`: invalidate the same
  association before the engine replaces a scene without CSV or bundle output.
- `test/unit/simulation/output_policy_tests.jl`: public output-switch matrix,
  table parity, file inventories, old-file preservation and partial-write tests.
- `test/unit/runtests.jl`: include the new regression suite.
- `docs/src/user/outputs.md`: explain disabled outputs and surviving old files.

## Findings

The unmodified base wrote an unwanted CSV with `results=true, save_csv=false`;
the new regression reproduced four failed assertions. Guarding only the CSV
call would also skip mission-history invalidation before Feather replacement.
The bundle writer now invalidates that association itself. Existing CSV files
are neither removed nor reported as output of a run that disables CSV saving.
No blocking findings remain after independent review. A suggested exact
returned-file assertion for a reused directory was added.
The final overwrite review also found that a scene-only run could retain the
old association. Its regression reproduced the failure; scene writes now
invalidate ownership after their enable checks. Runs writing no outputs retain
the previous saved association.

## P1 Assessment

No unresolved P1 finding. The partial-write regression verifies that a new
Feather file cannot retain an old owned mission-history association if manifest
serialization fails. Historical mission-record bytes and unrelated old manifest
fields are preserved for recovery.

## Tests Added/Updated

- Final output-policy suite: 74 assertions passed across all eight combinations
  of results, CSV and bundle switches, with exact returned-table parity, plus
  scene-only replacement and no-output ownership preservation.
- Existing mission workflow and operational-segment suites: 499 assertions passed.
- Existing result-thinning/storage and SimulationResults suites: 81 assertions
  passed. The separate SPICE-dependent RPO command-log case was explicitly
  skipped because the small source checkout omits native data.
- Architecture, source-completeness and documentation contract gates passed.
- `git diff --check` passed.

## Residual Risk

Hosted CI remains required, including native and optional-package integration.
These local checks do not qualify unrelated native-GRAM behavior or performance.
Existing files are intentionally retained when their output format is disabled;
the manifest and returned file list describe this run's writes only.
