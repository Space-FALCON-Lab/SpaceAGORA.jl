\begin{abstract}
This document describes the implementation currently present in
\code{SpaceAGORA_RL.jl}.  The package implements a Mars Odyssey aerobraking
Markov decision process (MDP), paper-compatible PR-DRL/DDQN training, an
advantage actor--critic (A2C) alternative, threaded rollout orchestration,
CPU and optional CUDA learning, a fast paper surrogate, and continuous
high-fidelity SpaceAGORA propagation.  It also provides protected campaign
initialization, reusable full-physics templates, shared ephemeris caches,
checkpoints, manifests, baseline policies, and evaluation/reporting tools.

The emphasis is operational: the document traces data from TOML
configuration through scenario reset, pass propagation, transition
construction, learning, checkpointing, and evaluation.  Parameter tables
distinguish TOML-resolved defaults from lower-level Julia constructor
defaults where they intentionally differ.
\end{abstract}

\section{Scope and implementation status}

The package is a Julia 1.12 project with package version \code{0.1.0}.  It is
located beneath the parent SpaceAGORA repository and uses the parent package
for live dynamics.  Its principal implemented capabilities are:

\begin{itemize}
  \item a nine-feature, thirteen-action aerobraking MDP;
  \item the four Mars Odyssey phases \emph{Walkout}, \emph{Endgame},
        \emph{Campaign}, and \emph{Main};
  \item three accepted training algorithms: \code{pr_drl}, \code{ddqn}, and
        \code{a2c};
  \item a deterministic/stochastic \code{paper_surrogate} backend;
  \item live backend modes \code{spaceagora_physics},
        \code{spaceagora_full_physics}, and \code{spaceagora_marsgram};
  \item GRAM/Mars-GRAM or tabulated Odyssey flight-density atmospheres;
  \item threaded rollout workers with a central learner and a specialized
        pass-streaming path for PR-DRL with live physics;
  \item CPU learning and an optional CUDA extension;
  \item run manifests, serialized checkpoints, disk-backed training history,
        baselines, frozen-checkpoint evaluation, and generalization suites.
\end{itemize}

The Python files beneath \code{Reference Code (ABTS)} are research reference
material.  They are not imported by the Julia module and are not on the
runtime path.

\subsection{Decision state}

\code{AerobrakingDecisionState} is the backend-independent state carried
between apoapsis decisions.  It contains pass index, apoapsis radius,
periapsis altitude, inclination, RAAN, argument of periapsis, true anomaly,
absolute epoch, elapsed mission time, accumulated maneuver magnitude,
maneuver count, the preceding pass's maximum density and heat rate, drag
passage time, a GRAM seed, and multiplicative $C_D$/$C_L$ scales.

The decision point is apoapsis.  An action commands an apoapsis burn, the
backend propagates through the subsequent atmospheric passage and orbit, and
the next transition is recorded at the following high-altitude apoapsis.

\subsection{Observation space and normalization}

The raw \code{PaperObservation} is a nine-element vector.  Normalization is
componentwise affine,
\[
  \hat{x}_i = \frac{x_i-\ell_i}{u_i-\ell_i}.
\]
The implementation deliberately does not clamp: an out-of-range physical
value produces a normalized value outside $[0,1]$.

\subsection{Action space and maneuver convention}

The executable action table is
\[
[-1.0,-0.5,-0.3,-0.2,-0.1,-0.05,0.0,
  0.05,0.1,0.2,0.3,0.5,1.0]\ \unit{m\,s^{-1}}.
\]
Index 7 is no maneuver.  Negative values lower periapsis and positive values
raise periapsis.  \code{AerobrakingAction} stores signed delta-V, magnitude,
paper angle $\phi$ ($0^\circ$ for non-positive and $180^\circ$ for positive
actions), and Boolean direction flags.  The live thruster's low-level
direction convention is the opposite numerical angle: negative delta-V uses
$\pi$ and positive delta-V uses $0$.

The two-body maneuver conversion changes apoapsis speed and recovers the new
periapsis from specific orbital energy:
\[
 v_a=\sqrt{\mu\left(\frac{2}{r_a}-\frac{1}{a}\right)},\quad
 \mathcal{E}=\frac{v_a'^2}{2}-\frac{\mu}{r_a},\quad
 a'=-\frac{\mu}{2\mathcal{E}},\quad
 h_p'=2a'-r_a-R_M.
\]
Both backends clamp the commanded periapsis used for propagation to
$50$--$180$ km.

\subsection{Reset and domain randomization}

For a nominal reset, apoapsis, periapsis, and all three orientation angles
receive symmetric uniform jitter about phase constants; the epoch remains
nominal.  For a nonnominal reset, apoapsis and periapsis retain symmetric
jitter, while inclination, RAAN, and argument of periapsis are sampled
uniformly from configured intervals.  The epoch is sampled from the
configured date window (or nominal epoch plus 0--27 days), optionally with a
uniform time of day.  True anomaly is jittered about $\pi$.

Each episode also receives a deterministic-from-RNG GRAM seed.  If
aerodynamic dispersion is enabled, independent scales
$1+U(-s_D,s_D)$ and $1+U(-s_L,s_L)$ multiply drag and lift coefficients.
Surrogate process noise multiplies the modeled apoapsis drop by
$1+\sigma_p N(0,1)$; the final drop is floored at zero.

\subsection{Reward model}

Thermal classes are ordered by the following logic:

\begin{enumerate}
  \item above \code{heat_hard_w_cm2}: hard;
  \item else above \code{heat_medium_w_cm2}: medium;
  \item else above \code{heat_high_w_cm2}: high;
  \item else below \code{heat_low_w_cm2} while more than
        \code{near_target_band_m} from the target: low;
  \item otherwise nominal.
\end{enumerate}

Terminal contributions are $-6$ for impact, $-6$ for leaving the drag
passage, $-4$ for target undershoot, and for success
\[
  10 - 0.4\,
  \operatorname{round}\!\left(\frac{|r_a-r_{a,\mathrm{target}}|}{1000}\right).
\]
The implementation uses Julia's \code{round(Int,...)} rather than a floor.
Hard, medium, and other nonnominal thermal classes add $-6$, $-5$, and $-4$
respectively.

For nominal thermal status and nonnegative normalized target distance, the
running term is
\[
\begin{split}
d &= \frac{r_a-r_{a,\mathrm{target}}}
          {r_{\mathrm{norm}}-r_{a,\mathrm{target}}},\\
c_q &= \frac{\dot q-q_{\mathrm{low}}}
            {q_{\mathrm{high}}-q_{\mathrm{low}}},\\
r_{\mathrm{run}} &=
(1-d^{0.4})
\frac{g}{\sigma_q\sqrt{2\pi}}
\exp\!\left[-\frac{1}{2}
\left(\frac{c_q-c_0}{\sigma_q}\right)^2\right]
+r_{\mathrm{step}}-\lambda_{\Delta v}c_{\Delta v},
\end{split}
\]
where defaults are $g=0.025$, $\sigma_q=0.1$, $c_0=0.5$,
$r_{\mathrm{step}}=-0.1$, and $\lambda_{\Delta v}=0.1$.  Normally
$c_{\Delta v}=|\Delta v|$.  Below the low heat threshold, $c_q$ is set to
zero and $c_{\Delta v}=||\Delta v|-1.0|$, favoring the strongest available
periapsis-lowering action.

\subsection{Termination and truncation}

\code{classify_termination} computes independent flags, then combines them:

\begin{itemize}
  \item success if $|r_a-r_{a,\mathrm{target}}|\leq10$ km;
  \item target undershoot if $r_a-r_{a,\mathrm{target}}<-10$ km;
  \item impact if $h_p$ is below the lower threshold;
  \item out of drag passage if $h_p$ is above the upper threshold;
  \item optionally terminal on any nonnominal thermal class;
  \item truncated when pass count reaches \code{max_passes}.
\end{itemize}

\code{terminated} and \code{truncated} remain separate in replay.  By default
DDQN bootstraps across truncation but never across true termination.

\subsection{Protected initialization}

Protected initialization can precede learned control:

\begin{enumerate}
  \item propagate one forced zero-action pass;
  \item optionally suppress a terminal condition caused \emph{only} by the
        thermal flag during protected passes;
  \item optionally command action 13 ($+1$ m/s) above the protected high
        corridor or action 1 ($-1$ m/s) below the protected low corridor;
  \item mark these passes in \code{EpisodeSummary.protected_trace}.
\end{enumerate}

Protected transitions are excluded from learned step accounting in the live
streaming path.  The ordinary worker initializer also executes them before
the learned rollout begins.  A bare \code{ProtectedInitializationConfig()}
defaults to enabled initialization, enabled corridor correction, thermal-only
terminal suppression, and a 0.025--0.40 W/cm$^2$ protected corridor; this is
the default used by evaluation APIs.  Training instead maps the
\code{training.protected_*} keys, whose resolver defaults disable the
protected first pass and corridor action.

\subsection{Paper surrogate}

The surrogate executes one complete pass per call:

\begin{enumerate}
  \item convert the apoapsis action to a post-burn periapsis;
  \item compute periapsis speed from vis-viva;
  \item evaluate exponential density and the paper heat-rate approximation;
  \item estimate drag-passage duration;
  \item compute heat-scaled apoapsis decay, optionally with process noise;
  \item advance by the larger of orbital period and drag-passage duration;
  \item update RAAN and argument of periapsis using J2 secular rates;
  \item accumulate delta-V, maneuver count, epoch, and pass metrics.
\end{enumerate}

The Mars density model is
\[
  \rho(h)=\rho_{\mathrm{ref}}
  \exp\!\left[-(h-h_{\mathrm{ref}})/H\right],
\]
and the heat approximation scales nominal heat by square-root density and
cubic velocity ratio.  Surrogate defaults include a $20$ km base apoapsis
decay, $130$ km heat gain, nominal altitude $92$ km, nominal speed
$3450$ m/s, and nominal heat $0.15$ W/cm$^2$.

\subsection{Live SpaceAGORA physics model}

The live template contains a Mars planet, three-body spacecraft, finite-burn
thruster, solar third-body gravity, Mars gravitational harmonics, solar
radiation pressure, aerodynamic coefficients, and a solver policy.  The
current spacecraft fixture uses:

\begin{itemize}
  \item bus dimensions $(2.2,2.6,1.7)$ m and bus mass 391 kg;
  \item two 10 kg panels, each $1.9\times1.91$ m (the paper's combined
        $3.8\times1.91$ m solar-array planform), 50 kg propellant, and
        reflection coefficient 0.9;
  \item one 4 N apoapsis-maneuver thruster with infinite $I_{sp}$ so the
        paper's constant-mass burn does not deplete propellant;
  \item burn duration $t_b=m|\Delta v|/4$;
  \item Sun N-body gravity, normalized Mars harmonics with J2 from file
        coefficient $C_{20}$, SRP, and aerodynamic force;
  \item atmospheric entry interface at 160 km and state data rate 10 s;
  \item orbital tolerances $10^{-8}$ with maximum step 30 s, atmospheric
        tolerances $10^{-8}$ with maximum step 5 s;
  \item split-IMEX mode with \code{kencarp4}.
\end{itemize}

For \code{tabulated_flight}, the backend constructs an Odyssey flight-density
truth model from the configured Feather file and sigma.  For \code{gram} or
\code{marsgram}, it initializes \code{GRAMAtmosphereModel} from the parent
repository's GRAM Suite and SPICE directories, using the episode seed and
configured perturbation scale.

Pass statistics are sampled by callback.  The implementation records maximum
density, maximum stage heat rate in W/cm$^2$, minimum altitude, and atmospheric
entry/exit times.  At each high-altitude radial-velocity root (apoapsis),
SpaceAGORA Cartesian state is converted to orbital elements and a transition
is produced.  The low-altitude periapsis root is ignored as a decision point.

\subsection{Continuous campaign and reusable templates}

Live PR-DRL does not rebuild and solve an independent problem for every pass.
Each worker runs a continuous campaign integrator.  At an apoapsis callback
it emits the completed transition, waits for the master's next action, updates
the finite burn and solver stops, and resumes the same integration.  The
worker's \code{SpaceAGORAPhysicsSimulationTemplate} is reused for subsequent
episodes, with initial conditions, atmosphere, aerodynamic scales, and burn
schedule updated per campaign.

Campaign horizon is
\[
  \max\!\left(2T,\;1.25(N_{\mathrm{pass}}+1)T\right),
\]
where $T$ is the initial orbital period.  The pass cap is the minimum of the
training cap and termination cap.

\subsection{Shared ephemeris cache}

Before live PR-DRL training, the master can precompute one thread-safe cache
covering all possible randomized campaign start dates and the maximum
campaign duration.  The cache holds Sun N-body positions, SRP Sun positions,
and Mars planet-frame quaternions.  It is installed into each integrator at
initialization, after coverage validation.  When this cache is active, the
three corresponding SpaceAGORA core caches are disabled to avoid redundant
per-worker construction.

\section{Learning algorithms}

\subsection{PR-DRL and DDQN}

\code{pr_drl} and \code{ddqn} construct the same \code{DDQNLearner}.  The
algorithm label controls reporting and selects the specialized streaming
architecture only when \code{pr_drl} is paired with a live backend.

The network is a hand-coded fully connected model:
\[
  9 \longrightarrow H \longrightarrow H \longrightarrow 13,
\]
with $H=1024$ by default, ReLU after both hidden layers, orthogonal weights
with gain $\sqrt{2}$, zero biases, and a linear Q output.  The implementation
uses explicit matrix operations and hand-coded backpropagation, not an
automatic differentiation package.

For sample $i$, Double-DQN selects the bootstrap action with the online
network and values it with the target network:
\[
  a_i^\star=\arg\max_a Q_\theta(s'_i,a),\qquad
  y_i=r_i+\gamma\,m_i Q_{\bar\theta}(s'_i,a_i^\star),
\]
where $m_i=0$ for termination and, by default, $m_i=1$ for truncation.
Selected-action mean squared error is optimized with Adam.  Gradients are
clipped by global norm.  The target network is copied after the configured
number of \emph{learner update steps}, not environment steps.

The replay buffer is a preallocated circular structure of column-major
\code{Float32} observations and next observations plus typed vectors for
actions, rewards, flags, and information indices.  Uniform sampling is with
replacement from the populated prefix.

Exploration is piecewise linear:
\[
\epsilon(t)=
\begin{cases}
\epsilon_{\mathrm{start}}, & t\leq t_0,\\
\max\left(\epsilon_{\mathrm{stop}},
\epsilon_{\mathrm{start}}+
(\epsilon_{\mathrm{stop}}-\epsilon_{\mathrm{start}})
\dfrac{t-t_0}{T_\epsilon}\right), & t>t_0.
\end{cases}
\]

\subsection{A2C}

A2C uses separate actor and critic instances of the same two-hidden-layer
network.  The actor output dimension is 13 and the critic output dimension is
1.  Each active worker advances one pass at a time; pass propagations at a
segment time index are threaded.  After up to \code{segment_length} steps,
the learner computes bootstrapped discounted returns backward through valid
worker slots and flattens them into one batch.

Actor actions are sampled from a numerically stabilized softmax; greedy
evaluation uses the largest logit.  Let $R$ be the return and $V$ the critic
prediction.  The implementation scales advantages as
\[
  A = \frac{R-V}{1+\operatorname{std}(R-V)}
\]
and optimizes policy loss minus entropy bonus plus weighted value loss.
Actor and critic have separate Adam states and separately clipped gradient
norms.  A2C uses ordinary in-memory histories and the threaded segment
collector; it does not use DDQN replay or the live PR-DRL channel protocol.

\subsection{Device model}

\code{device="cpu"} keeps parameters and batches in standard Julia arrays.
\code{device="cuda"} requires the CUDA extension to load and
\code{CUDA.functional()} to be true; otherwise device resolution throws an
error.  The extension transfers network parameters and batches to
\code{CuArray}, while replay storage and checkpoint serialization remain
CPU-compatible.  Checkpoints explicitly convert networks and Adam states back
to CPU arrays.

\section{Parallel execution architecture}

\subsection{Ordinary DDQN snapshot rollouts}

For surrogate DDQN-family training, the master limits active workers to
\code{min(n_workers, Threads.nthreads())}.  It snapshots the current online
network to CPU, launches a batch of episode tasks, and gives every task a
deterministic seed
\[
  s_{\mathrm{worker}}=s_{\mathrm{base}}+10000\,i_{\mathrm{worker}}
  +i_{\mathrm{episode}}.
\]
Workers choose actions from the frozen snapshot and return an episode summary
and transitions.  The master ingests transitions in task order, increments
the authoritative global step, updates replay and learner, writes checkpoints,
and then launches the next snapshot batch.  Consequently, workers within a
batch do not observe parameter updates made during that batch.

\subsection{Live PR-DRL pass streaming}

For \code{pr_drl} with a live backend, each worker task owns a long-running
SpaceAGORA campaign and an action channel.  All workers publish
\code{SpaceAGORAPhysicsPassEvent} records to a shared event channel.  The
central master:

\begin{enumerate}
  \item receives a pass transition and optional completed summary;
  \item excludes protected passes from learning;
  \item increments the global step and performs replay/training;
  \item writes any crossed checkpoint thresholds;
  \item selects the next epsilon-greedy action with the latest online network;
  \item sends that action back to the blocked worker;
  \item recycles completed workers into new episodes using the reusable
        template until the step or episode budget is reached.
\end{enumerate}

This preserves online master action selection while allowing expensive
propagation to proceed concurrently.  With more than one worker, the wrapper
sets \code{SPACEAGORA_OUTER_PARALLEL_ACTIVE=1}; if no inner budget is supplied
it selects
\code{max(1, fld(Threads.nthreads(), active_workers))}.

\subsection{A2C segmented workers}

A2C maintains mutable worker campaigns rather than complete episode tasks.
For each segment position, it snapshots the actor, chooses all actions, and
spawns one pass propagation per available worker.  Completed campaigns are
finalized and immediately reset while budgets remain.  After segment
collection, the central learner computes returns and applies one actor/critic
update.

\subsection{Stop budgets and cadence}

A positive \code{training.global_steps} makes global learned transitions the
primary stop budget.  If it is zero, training is episode/campaign-capped by
\code{training.episodes}.  An explicit \code{episodes} keyword can add an
episode cap.  Checkpoint and progress frequencies are compared to global
steps in step-limited mode and progress switches to episode cadence in
episode-limited mode.  A final checkpoint is always written.

\section{Runtime artifacts and reproducibility}

\subsection{Run directory}

\code{build_training_session} creates
\[
  \code{training.output_dir}/
  \code{yyyymmddTHHMMSS_config-algorithm}.
\]
The manifest records run ID, UTC time, phase, seed, source config path and
SHA-256, backend, algorithm, device, action table, normalization field names,
the four heat thresholds, and selected DDQN/A2C settings.

Typical training artifacts are:

\begin{itemize}
  \item \code{manifest.toml};
  \item \code{terminal_output.txt} when using \code{scripts/train.jl};
  \item \code{checkpoint_<step>.jls} at crossed thresholds;
  \item \code{checkpoint_final.jls};
  \item for live PR-DRL streaming,
        \code{training_episode_summaries.jls} and
        \code{training_transitions.jls} as disk-backed serialized histories.
\end{itemize}

DDQN checkpoints contain CPU online/target networks, replay, epsilon schedule,
configuration, optimizer state, global/train steps, last loss, device name,
and optional manifest.  A2C checkpoints contain actor/critic networks,
configuration, both optimizer states, counters, losses, device name, and
optional manifest.

\subsection{History memory behavior}

Ordinary DDQN and A2C return in-memory vectors.  Live streaming uses
\code{DiskBackedHistory}, an indexed serialization stream with byte offsets,
so long campaigns do not retain every summary and transition object in RAM.
\code{MappedHistory} lazily derives episode metrics from stored summaries.
The caller should close writable histories after manual use; the trainer does
so before returning.

\subsection{Evaluation protocols}

The standard IID count is 40 episodes and the generalization count is 100.
Evaluation converts the scenario to \code{training=false} while preserving
the physical backend and most configuration.  Two thermal modes are
available:

\begin{itemize}
  \item \code{conservative}: thermal violations remain terminal;
  \item \code{tolerant}: thermal violations are recorded but not terminal.
\end{itemize}

solver failures.  Pass logs include orbital elements, heat, density, reward,
and action traces.

\section{Extension points and implementation cautions}

\begin{itemize}
  \item A new task implements the small MDP/backend/policy contracts, but the
        current trainers and typed records are aerobraking-specific.
  \item A new propagation backend extends \code{SpaceAGORACoreAdapter} and
        should return a complete \code{AerobrakingDecisionState}.
  \item A new atmosphere for live physics extends the density-model builder
        and should update accepted configuration validation.
  \item \code{pr_drl} is not a distinct neural learner class; it is the DDQN
        learner plus PR-DRL naming and, for live physics, central pass-streaming
        execution.
  \item The AADS predictor is the paper surrogate heat model even when the
        evaluation backend is live physics.
  \item TOML resolution validates table types, algorithm names, atmosphere
        names, and date syntax, but most numeric ranges are not globally
        validated.  Physically nonsensical values may fail later or produce
        invalid simulations.
  \item The normalization bounds are fixed paper ranges and are not learned
        from data.
  \item Checkpoints use Julia \code{Serialization}; they are intended for
        compatible Julia/package environments, not as a language-neutral
        interchange format.
  \item Live SpaceAGORA loading and SPICE setup are protected by locks.
        Shared templates and caches reduce repeated setup but do not remove
        the need to size thread and memory budgets carefully.
\end{itemize}

\section{Summary}

\code{SpaceAGORA_RL.jl} is organized around a stable aerobraking MDP and two
interchangeable propagation fidelity levels.  A typed configuration resolves
paper parameters, reset distributions, algorithm settings, and runtime
budgets.  DDQN-family and A2C learners consume the same normalized
observations and discrete actions.  The key architectural specialization is
live PR-DRL: long-running SpaceAGORA campaign workers stream pass transitions
to one authoritative learner, which updates the network and returns the next
action without restarting propagation.  Reusable simulation templates,
shared ephemerides, protected initialization, CUDA transfer boundaries,
manifests, and disk-backed histories make that architecture practical and
reproducible for long aerobraking campaigns.
