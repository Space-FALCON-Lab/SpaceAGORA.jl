## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- **Design deviation, low: the EDG control-clock scan stays.**
  `_edg_targeting_control_clock(config, p)` is an EDG service the companion calls
  by configuration. Removing its scan changes that contract, which F-E does.
- **Design deviation, low: no Apollo link; EDG's single-instance checks stay
  configuration-wide.** The main failure, guidance and control on two different
  state objects, gives two one-sided links, which no per-link check sees.
- **Low, timing:** `before_reference_control!` now runs once per control tick,
  before the per-spacecraft loop, instead of inside the RPO controller's chaser
  tick. The RPO controller's other-spacecraft ticks return at once. The parity
  probe confirms identical runs.
- **Low, refusal order:** link checks run after every model's own preflight, so
  with two errors a later model's own error can now come first. The messages are
  unchanged.
- **Note:** `RPOGuidanceModel` buffers get no check, as the design says (the model
  is deprecated).

Reviewer to verify:

- `check_link(::RPOPlanBuffer)` reproduces the removed preflight checks and their
  messages, and acts only when a planner produces the buffer.
- `link_initialize!(::RPOPlanBuffer)` binds and resets the controller before the
  planner's initializer issues its first request, as before.
- The EDG state is initialized exactly once per run, with guidance, control, or
  both.
- The linked producers are captured from the same configuration object the
  integrator's parameters hold (built from the post-copy `args`).
- No run changes: the parity evidence.

## Update after review (670f1ecd7)

- **Resolved (P2): link checks ran twice under `SolverConfig(parallel=true)`.** The
  automated review (discussion_r4302788153) found that `check_gnc_links` ran before
  the parallel branch of `run_simulation`, which re-enters `run_simulation` under the
  flag's environment. The check then ran again in the inner call, so each link's
  `check_link` ran twice, against the once-per-link contract in its docstring. A
  contributor's stateful `check_link` could have failed, or mutated twice, only in
  parallel runs. Reproduced with the test below.
- **Fix:** `src/orchestration/simulation/engine/execution.jl` calls `check_gnc_links`
  right after the parallel branch instead of before it. It runs once, in the call
  that goes on to the run: still after the per-model preflights, before the state is
  isolated and before any output is created. `check_control_periods` keeps its place:
  #373's record accepted its second call, since its warning shows once.
- **Test:** `test/unit/gnc/gnc_runtime_declarations_tests.jl`, in the links testset:
  the shared-slot configuration runs with `SolverConfig(parallel=true)`, with the
  flag's persisted state (cost constants, policy state, calibration and route files)
  in a scratch folder, and must call `check_link` once and `link_initialize!` once.
- **Evidence on `670f1ecd7`:** the runtime testset passes 55 of 55 on four threads;
  with the old placement of the call it fails exactly that check (54 of 55). The
  parallel-flag unit tests (`test/unit/parallel/parallel_flag_tests.jl`) and the 33
  pull-request gates pass.
- **Residual:** the per-model preflights (`preflight_guidance`, `preflight_control`)
  run before the parallel branch, so under the flag they still run twice. That is
  main's behavior before this PR, unchanged here.
