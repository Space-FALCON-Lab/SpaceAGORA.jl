# PR 168: make the Odyssey surrogate walkthrough followable without guessing

## Scope

Fix the points where a newcomer following the README and `docs/src/tutorials/odyssey_surrogate.md` had to guess. Pkg's `Failure artifact` lines appeared during a successful first install. Named presets rejected `above_grid` with a `MethodError`. The docs did not say where results go, what frame the state columns use, or how to compare another cap with the baseline. Several smaller documentation gaps remained. Reviewed: the whole diff against `main`, the Pkg 1.12 `ensure_artifact_installed` keywords, the SPICE ephemerides frame used by the example, and a default run compared with main's version of the example on the same checkout.

## Changed Files

- `src/environment/atmosphere/surrogate_presets.jl`:
  - `_preset_artifact` sends Pkg's status output to a buffer and logs one line before and one after installation;
  - failures append Pkg's captured output to the `ArgumentError`;
  - `_PRESET_RESOLUTION_KEYWORDS` lists the keywords `surrogate_preset_model` accepts, and other keywords raise an `ArgumentError` naming the generic `GRAMGridAtmosphereModel`;
  - without `GRAMSuite` loaded, `surrogate_preset_model` raises an `ArgumentError` saying to `import GRAMSuite`, before resolving anything.
- `src/assets/odyssey_surrogate_assets.jl`: the same install logging and failure detail for the scenario assets.
- Also changed:
  - `examples/odyssey_surrogate.jl`: printed results location, `--cap`/`--baseline-cap`/`--help`, `compare_panel_caps` cap keywords, `state_frame`, existing-directory message;
  - `test/surrogate_presets_tests.jl` and `test/surrogate_workflow_tests.jl`;
  - `.gitignore`;
  - `README.md`, `docs/src/tutorials/odyssey_surrogate.md`, `docs/src/user/atmosphere_models.md`, `docs/src/user/examples_catalog.md`, `docs/src/user/installation_environment.md`, `docs/src/user/outputs.md`.

## Findings

- P2 (fixed in this PR, found by the agent pre-flight on this branch): the new direct-query paragraph omitted `using SpaceAGORA` and `import GRAMSuite`. Without GRAMSuite, `surrogate_preset_model` resolved the preset and then failed with a `MethodError` naming keywords the user never passed. The paragraph now shows the imports. The function checks for the GRAMSuite constructor first and raises a clear `ArgumentError` before any resolution.
- Checked, no finding: during a real first-use download, Pkg's status lines no longer reach the terminal, while its download progress bar still does. The two new log lines frame the install.
- P3 (accepted): the test that keeps `_PRESET_RESOLUTION_KEYWORDS` in step with `resolve_surrogate_preset` uses `Base.kwarg_decl`, an internal function. A future Julia release could change it; the test would then fail loudly rather than pass silently.
- P3 (out of scope, tracked): a query below the grid floor still raises GRAMSuite's DomainError, which mentions the above-grid vacuum policy. The text is fixed in Space-FALCON-Lab/GRAMSuite.jl#8 and reaches SpaceAGORA only with a pin update. The Atmosphere Models page and the walkthrough now state that below-floor queries always fail.
- Checked, no finding: the state columns and `common_state_m_m_s` come from the propagated state. That state starts from `spkezr(..., "J2000", ..., "499")`, and the SPICE ephemerides model rotates J2000 to the body-fixed frame, so `state_frame` (Mars-centred J2000 inertial) is correct.
- Checked, no finding: with the default caps, the trajectory tables are byte-identical to main's. `summary.toml` differs only by `state_frame` and the recorded wall time, and `comparison.toml` only by `baseline_cap_deg` and `variant_cap_deg`.
