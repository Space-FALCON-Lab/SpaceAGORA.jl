# Review record: PR 411: the 0.4.0 flips (skip_inactive defaults to true; pre-run configuration warnings become refusals)

## Scope

Review of the SpaceAGORA `gnc-040-flips` branch against main (`c7db8b6fb`, v0.3.1):
GNC PR 20 of the runtime and algorithm contract design (sections 3.3, 3.5, 3.6, 6.1,
6.2 and 7.3; decisions G-4 = b and G-5 = a), the first of the four 0.4.0 PRs. Four
commits:

- `ecfebfbef`, a characterization test that passes on main: an RPO chaser on the
  planner path touches down mid-run while its planner and controller keep ticking.
- `b9f2564a9`, `skip_inactive(model)` defaults to `true`, the engine's
  `before_reference_control!` call for a control model's linked producers is gated
  like its tick, and the characterization test moves to the new logs and records.
- `04f90fa14`, the four pre-run configuration warnings of 0.3 become `ArgumentError`
  refusals at the same pre-run point: a declared control period (`gnc_period_s`)
  that differs from the control rate, an MPC controller discretized with another
  step, a spacecraft scope that names a position outside the run, and Apollo descent
  guidance and control that do not share their state and spacecraft.
- `2edc40757`, a test-fixture comment that still said the scope check warns.

Model by model, for the new default (none overrides it):

- RPO MPC controller (`CoupledSpacecraft(chaser, (target,))`), robot arm controller
  and momentum manager (`BoundSpacecraft`), burn scheduler and EDG control
  (`AllSpacecraft`), `SolarPanelAngleOfAttackControlModel`: keep `true`. Each tick
  writes only that spacecraft's command and run state; the right-hand side zeroes an
  inactive spacecraft's whole derivative block (`_assemble_flat_satellite!`,
  `_assign_rhs_direct_satellite!`), so nothing the tick writes moves a trajectory.
- `PlannerGuidance`, the deprecated `RPOGuidanceModel`, `AlgorithmGuidance` (the
  burn-plan, joint-reference and EDG families), EDG guidance and the two thruster
  guidance models: keep `true`; a planner no longer requests a plan from a frozen
  state.
- Apollo descent guidance and control: already declared `true`, and keep the
  declaration, because the controller's `release_command!` turns the engine off.
- Navigation: no built-in navigation model.
- EDG companion: the EDG guidance and control model types are core types without a
  `skip_inactive` method, so the core fallback (`true`) reaches them. SpaceAGORAEDG
  (pinned `442efb3`) supplies only the decision kernels through `EDGServices`
  (`guidance_decision!`, `control_decision!`), which write only the ticked
  spacecraft's slots of the shared state; its source has no `GNCRuntime`,
  `skip_inactive`, `release_command!` or `is_active` reference. The companion needs
  no change.

The design's "unshared Apollo state" check (3.3, V13) is not a separate warning: the
pairing check groups the Apollo models by state identity, so guidance and control on
different states fail it in both directions at once. Apollo declares no `gnc_links`.
It is now refused with the other three.

Independent review: the coordinator reviewed the change under Giusy's delegation on

## Findings

No P1 or P2 findings. Points a reviewer should check:

- Behaviour change, by design (G-4 = b): after a deactivation the RPO controller's
  command log and the planner's records stop. In the characterization flight
  (touchdown at about 1.31 s of a 2 s run, 0.1 s ticks):
  - command log: 19 entries to 1.9 s, 6 of them after the touchdown and computed from
    the frozen chaser, become 13 entries to 1.3 s;
  - planner records: the `:control` and `:guidance` records after the touchdown
    (6 of each) are gone, and so are the replan of the event at 1.6 s (`:request`
    from the frozen chaser, about 2.2 km behind the target; `:rejected` with
    `:insufficient_reference_lifetime`; `:fallback_installed`); `request_id` stays 1
    instead of 2, and the event is never delivered;
  - held command: the command of the 1.3 s tick instead of the 1.9 s one;
  - with `on_rejection=:fail`: main stops the run with `RPOPlanningError` (request 2,
    `:infeasible`) at 1.6 s; the branch completes it, identical to the fallback run;
  - trajectory and touchdown time: bitwise identical on main and the branch.
- Behaviour change for user models: a model that relied on ticks after its
  spacecraft became inactive must now declare `skip_inactive(model) = false`.
  The migration page's 0.4.0 entry and the declarations table say so.
- Low: `release_command!` keeps its no-op default, so the built-in models other than
  the Apollo controller hold their last pre-deactivation command
  (`held_command`) rather than an off command. The right-hand side does not read
  it; reports that read `held_command` see the last real command.
- Low: the gate on `before_reference_control!` uses the consumer's scope and
  `skip_inactive` at each tick. For a model with `skip_inactive = false` the call is
  unchanged; for an `AllSpacecraft` consumer it stops only when every spacecraft is
  inactive.
- Low: the refusals no longer go through `_preflight_warning`, so a configuration
  that only warned on 0.3 (once per session, an `ErrorException` under
  `--depwarn=error`) now fails every run with an `ArgumentError`. No built-in
  configuration, example or test configuration other than the refusal tests trips
  them (evidence below). `_preflight_warning` keeps its default `:preflight` group;
  no configuration check uses it any more.

## P1 Assessment

No P1 findings. The default flip changes which ticks run for an inactive spacecraft
only; the right-hand side already ignores that spacecraft, and the trajectories of
the characterization flights and of the base fingerprints are bitwise identical. The
refusals reject exactly the configurations that warned before, at the same point.

Review fix (`4aa50450d`, P2 from review): a burn scheduler in `:mounted` actuation kept its own periodic tick for an inactive spacecraft; that tick now runs through `_gnc_tick!`, the scheduler's `release_command!` turns the spacecraft's mounted engine and wheels off, and the mounted actuators apply the release at each tick, as after any release. Its new test passes and fails with the gate or the release removed; an active mounted burn's final state is bit-for-bit that of `723a65bdc`; the 33 PR gates pass.

Unresolved P1: No

## Residual Risk

- Users who read `held_command` after a deactivation see the last command before it;
  a model that needs an off command there defines `release_command!`, as the Apollo
  controller and the feedback example do.
- External code that still configures one of the four mismatches stops at the
  pre-run check instead of warning; the message names the model and the values.
- The companion migration (0.4.0 PR 2) and the checkpoint follow-ups (PR 3) also
  touch the periodic tick callbacks; whichever merges second merges main in.
