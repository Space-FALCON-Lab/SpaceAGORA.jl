## Findings

No P1 or P2 findings. Points a reviewer should check:

- Low, modelling: the solar flux uses the central body's mean distance from
  the Sun (a table by planet name), not the instantaneous distance; for Earth
  the flux is off by up to about 3.4 % over the year.
- Low, modelling: without SPICE the Sun's direction is known only for Earth
  (`SimpleEphemeridesModel`); elsewhere the arrays then generate nothing.
- Low, by design: the shedding tier changes at step ends, so the instant a
  load is shed or restored depends on the step size (the empty and full
  states themselves switch at events).
- Low, by design: when the battery is empty, every sheddable tier is shed
  if the constant loads alone exceed the generation, including the wheels'
  motors, which leaves the attitude uncontrolled by the wheels until the
  generation covers the loads again.
- Low, by design: shedding applies only to mounted actuators; effectors in
  `:ideal` actuation are not limited by the battery.
- Low: the power snapshot runs once per right-hand-side evaluation for each
  spacecraft with a battery (the Sun's direction and two passes over the
  mounted actuators).
- Fixed after the first push: the power callbacks called
  `derivative_discontinuity!(integrator, false)` after switching the battery's
  state, which declares that nothing changed (a discrete or event callback
  counts as a discontinuity unless it clears the flag). They now declare it
  when a flag or the tier changed and clear it otherwise, so the step-end
  update costs no re-evaluation when nothing switched. The same correction
  went into #325's window-edge callback (535078b41), merged here. After the
  fix the power tests (56 of 56) and the contract tests pass.
- Fixed after the automated review of 54e901a8d (8db863a0c), two P1 findings:
  - Checkpoint segments: each segment's solve initializes the callbacks
    again, and the initialization rebuilt the battery's flags from the
    stored energy alone, so an empty battery recharging below `recovery_soc`
    stopped shedding at a segment boundary. The flags are now set only at the
    run's first initialization and carried over after that, as the plume
    callback does with its mass. A checkpoint file holds the stored energy but
    not the flags, so a run with a battery refuses `resume_from_checkpoint`,
    as the GRAM density perturbation and external propagation refuse it for
    state the file lacks.
  - Several `:mounted` control effectors: the dynamics apply the actuators of
    each one that holds levels, but the power snapshot counted only the first
    one's draw. It now sums the draw of every one (the constant loads once),
    so the battery, the shedding tier and the load and shed columns see the
    whole load. The `actuator_level` and `actuator_power` columns keep
    following the first effector, as documented since #322.
