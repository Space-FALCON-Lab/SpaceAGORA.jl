# AI Review — PR #581: Precompile an Earth/J2/NoAtmosphere workload

## Scope

The precompile workload ran only the Mars default (exponential atmosphere, inverse-square gravity), so the first `run_simulation` of an Earth case, including the `AGORA_Basic_Quickstart` configuration, paid a long compilation in every fresh process. The workload now also runs Earth with J2 and no atmosphere, once with `results=false` and once with `results=true`. The Mars default is unchanged. No runtime code path changes; only what is compiled at precompile time.

## Changed Files

- `src/precompile_workload.jl` — `_spaceagora_precompile_args` takes `planet`, `dynamic_effectors`, `density_model`, `results` and `results_directory` as keywords (defaults reproduce the old Mars configuration). `_run_spaceagora_precompile_workload` runs three configurations in order (Mars default, Earth/J2/NoAtmosphere without results, the same with results written to the workload's tempdir).

## Findings

- P3 — Earth results are not bit-identical to the previous main, because Earth-typed methods now run from the package image instead of just-in-time code. Measured on one process per arm and duration, Earth/J2/NoAtmosphere: the final-state position differs at the sub-millimetre to millimetre level over 30 to 365 days (relative differences in the eleventh to tenth significant digit, growing roughly linearly). Running with `--pkgimages=no` reproduces the previous results exactly. Mars is bit-identical. Specific energy and angular momentum drift identically in both arms.
- P3 — Cold precompilation of SpaceAGORA takes somewhat longer; `using SpaceAGORA` time is unchanged.
- P3 — Warm Earth runs were slightly slower in all three process pairs, which is consistent with package-image code differing from just-in-time code here. Warm run times are bimodal in both arms, so this rests on the lower mode.
- Resolved before merge — The package image built by this workload made the allocation-free right-hand-side tests fail in CI (J2 attachment, articulated and live-pose cases) while they passed locally: `rtolatlong`, which the planet-frame sampler calls on every evaluation that needs the planet frame, built its static vector through a heap vector literal that the just-in-time compiler elides and the Linux package image keeps. #583 builds that vector from its elements; with it, the same tests measured zero allocations on CI under this workload.
- No P1 or P2 issues found. `Earth()` (the keyword constructor) furnishes no SPICE kernel and fills no planet cache, so `_reset_furnished_kernels!` and `_reset_process_local_state!` have nothing extra to undo; the planet-frame reuse cache the Earth runs fill is cleared by the existing reset.

## P1 Assessment

No P1. The change adds compile-time coverage only, does not alter any simulation algorithm, and does not touch the modules the contract gates guard. The one observable difference is the last-digit change in Earth results described above.

## Tests Added/Updated

No new tests. The workload itself is exercised by every precompile. The Precompilation Contract in the integration suite passed on the earlier base `9fc7e8791`; the A/B measurements above were taken on `3ef2ed2e2`: the first Earth `run_simulation` no longer pays the compilation, the quickstart's wall time drops accordingly, and the first Mars call is unchanged. The allocation-free right-hand-side tests pass on CI with #583 in main.

## Residual Risk

- Users who compare Earth results against numbers produced before this change will see last-digit differences of the size listed above.
- The warm slowdown is not isolated further; the cause (package-image versus just-in-time code generation for Earth-typed methods) is the likely explanation but is not tested beyond the `--pkgimages=no` reproduction.
- The longer cold precompile applies once per source change and is paid by CI and fresh worktrees.
- Any other static array built from a heap literal on a path this workload precompiles would allocate the same way from the package image; the remaining such sites in the reference-system helpers lie outside the right-hand side.
