# AI Review Artifact — PR #121

## Scope
Post-hoc interactive 3D visualization of runs. A run flagged with `simulation_settings.save_visualization_scene` (or `run_simulation(args; visualization=true)`, `SPACEAGORA_VISUALIZATION=1`, `spaceagora run --visualize`) writes a scene sidecar beside its results and three new save fields (link poses, arm poses, density); `export_visualization` then bundles the sidecar, the decimated trajectory, a planet texture, optional 3D models (STL/OBJ/glTF), planned-path overlays and reference "ghost" trajectories into one self-contained HTML page driven by a vendored three.js viewer under top-level `viewer/`. Monte Carlo ensembles get their own manifest and page. The last commits add NASA models for Magellan, Cassini-Huygens and the Apollo lunar module, the ghost feature, and mission-recreation drivers (Magellan aerobraking at Venus, Cassini's TA and T5 Titan flybys with the reconstructed SPICE trajectory drawn as a ghost, Apollo 11 in lunar orbit). Reviewed: every changed `src/**/*.jl` against the default no-visualization path, the viewer modules, the bundler's data contract, the CDN page builder used for artifact pages, and the new unit tests. Rendering was verified in headless Chromium (Playwright, SwiftShader) on this machine for the ISS, Magellan, Cassini and Apollo pages, both the local `data:`-URL variant and the CDN variant.

## Findings
- **P2 (found and fixed during review): the selected-spacecraft panel reported a wrong latitude, longitude and altitude (altitude equal to minus the polar radius) on every page.** `globe.rotationAt(t, out)` wrote the quaternion with `out.set(x, y, z, w)`, which is correct for a `THREE.Quaternion` but a no-op for the `Float32Array` that `selectionInfo` passes, so the body-frame position was rotated by a zero quaternion. Planet-fixed playback was unaffected because it passes a `THREE.Quaternion`. Fixed in `viewer/src/globe.js` by branching on `isQuaternion`; verified in headless Chromium that the readout now carries the geodetic values.
- **P2: the "ISS is back to a box" report could not be reproduced.** The ISS orbit page and its CDN variant both load the glTF (`glb (36 meshes, ×2.4)` in the model-status row) and draw the station in follow mode under headless Chromium. Boxes stay visible only when the parse fails or never returns; the status row now names the failure, and the ghost feature reuses the same loader so a failure shows in both places. Left open pending a report of the status row's text from the affected browser.
- **P3: `render_viewer_html` escapes `<`, `>` before `&`**, so a title containing `<` becomes `&amp;lt;`. Cosmetic (titles are set by the caller); should be reordered in a follow-up.
- **P3: `_gltf_accessor` reads buffer slices under `@inbounds`**, so a truncated or malformed GLB with a bad `byteOffset` or `count` can read out of bounds instead of raising. Only reachable through a caller-supplied model file; the STL reader validates lengths first.
- **P3: `_density_sample` swallows every exception** (bare `catch`) and returns `nothing`, so a broken density model yields an empty profile with no diagnostic. Only reached with the flag on.
- **P3: `_save_density` reads `shared_buffers.densities`**, written by the density callbacks and the flat-RHS prefill; a route that samples with `write_buffers=false` would leave a stale column. The three mission drivers (serial, GRAM) show the expected profiles; a non-flat multi-satellite run with the flag on is untested.
- Design notes recorded rather than flagged: `with_visualization_scene` and `with_results_directory` rebuild `SimulationSettings`/`SimulationConfiguration` field by field (a future field is silently dropped on the visualization path, the same pattern `_ensemble_member_settings` already used); `export_visualization` runs inside `run_simulation` when `visualization=true`, so a missing `viewer/` tree fails the run after the results are on disk; the CDN page builder concatenates the viewer modules into one scope, so top-level names must stay unique across modules (checked with `node --check` on the concatenation).

## Residual Risk
Moderate, concentrated in the viewer rather than the runtime. The Julia side is additive and gated, and the unit tests cover the data contract end to end, so the default simulation path carries no new risk. The browser side is verified only in headless Chromium here and in the user's Firefox earlier; a rendering difference in another browser (the box report) has no automated catch beyond the status row. The mission drivers depend on external assets (NAIF kernels downloaded on first run, Venus/Titan GRAM) and are dev tooling, not CI. The reference ghosts assume the run's inertial frame is J2000 centred on the primary, which holds for the SPICE ephemerides path used by the drivers; a run on the simple ephemerides would need its own sampling. Separation between the simulated Magellan and its kernel reaches about 14 km after two aerobraking orbits and about 5 km for Cassini over five hours, consistent with the simplified drag geometry and mass, and is reported on the page rather than hidden.
