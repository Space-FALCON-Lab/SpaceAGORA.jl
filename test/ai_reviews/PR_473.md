## Findings

No open findings. Local verification found four issues, each fixed before the push:

- **P2, `examples/common.jl`.** The environment switch loaded Pkg and called it in one top-level block. From the root project this failed with a world-age `MethodError`. It now calls `Pkg.activate` through `Base.invokelatest`; both projects run the quickstart, with identical results.
- **P2, root-project children.** Two probe children (`scenario_matrix_debug_probes.jl` and `xval_provenance_probes.jl`) and the full-arc runner's documented command loaded the scenario matrix, which imports Plots, in the root project. The children now run in the environment the tests run in, and the runner's usage and error text name `--project=examples`.
- **P3, GRAM loading contract.** The GRAMSuite retry's fallback is now the examples environment, so the test's expectation changed with it.
- **P3, root manifest.** The hand edit left a trailing blank line. The manifest is now byte-identical to Pkg's own rewrite of it.

Found by an outside review of `779b9d083` and fixed in `817479b4153c0c51c41a295d46082446ebdc7438`:
- **P2, HYPR research-example setup.** The planner environment's README gave the research-example command after only the planner setup; those examples continue in the examples environment, so a fresh checkout stopped at the guard. The README, the comments of `Earth_RPO_CubeSat_MPC.jl`, the robot-arm demo and the FinalISpaRo example, the Batch example's usage text, the examples catalog (its commands and table), recipes and the planner pilot page now add `julia --startup-file=no examples/setup.jl`. The asset-free planner smoke still needs only the planner setup.
- **P3, the environment switch.** `upgrading.md` and `installation_environment.md` promised the switch for every example started with `--project=.`. Only examples that include `examples/common.jl` switch; the pages now say so and send the cloth-panel and solar-panel demos to `--project=examples`. Those two demos keep loading PlotlyJS directly, without the `common.jl` bootstrap: they need nothing else from it, and their documented commands already use `--project=examples`.
- **P3, the version claims.** `examples/setup.jl` and README said setup keeps every seeded version. It starts from them: the records of the libraries bundled with Julia (CompilerSupportLibraries_jll, MozillaCACerts_jll, OpenSSL_jll) follow the installed Julia. The README, `examples/setup.jl` and `installation_environment.md` now say so; `test/setup.jl` and `docs/setup.jl` carried the same sentence and now match.
- **Optional, taken.** `build/build_sysimage.jl` notes that its default trace example needs the examples environment, and stops early, with the setup command, when it is missing.

Found by an outside recheck of `f4fe97c8a` and fixed in `82b94fae2efb10bb3f7e9a93946e1b20d01d9917` (all P3):
