# Atmospheric solver phase lifecycle repair

## Scope

Apply the configured atmospheric timestep cap and component tolerances whenever any active spacecraft is inside the atmosphere, including startup, crossings, deactivation, cached-integrator reuse and checkpoint segments or resume. The base is main `3287f0fc145d779ce3bd0ac608eb3352d671b85e`; the accepted runtime is `b2f83f960b450fbf5e89b97f22424f45552bd56f` and its documentation/test follow-up is `44f41ea687fbfd9a580a4f9dde447ebb0e9ca77a`.

No dependency or nonlinear-solver policy changes are included. Explicit multirate subsolve overrides are restored at every reused subsolve, including their supplied tolerances. Installed crossing callbacks can still update phase settings within that subsolve. This changes physical multirate behavior that previously inherited crossing settings across subsolves. Fixed-step drivers are exempt from adaptive phase updates; atmospheric gravity-backbone operation is not established by these checks.

## Changed Files

- `src/simulation/callbacks/density_callbacks/assembly.jl`: aggregate active phase and derive/apply its cap and component tolerances.
- `src/simulation/callbacks/event_callbacks.jl`: update settings after crossings, impact and touchdown; reconcile simultaneous flags from crossing geometry and radial direction, preserving vacuum-cache invalidation on exit.
- `src/simulation/engine/solver_policy.jl`: select startup settings and restore reused-integrator options; initialize current callbacks before estimating the initial step, matching fresh initialization.
- `src/simulation/engine/setup.jl` and `src/simulation/engine/execution.jl`: initialize flags from actual checkpoint state, including partitioned gravity-backbone states.
- `test/unit/simulation/atmospheric_phase_tests.jl` and `test/unit/runtests.jl`: register lifecycle regressions.
- `test/unit/dynamics/mesh_aero_tests.jl`: explicitly set the intended 0.05-second atmospheric cap in the existing force/work fixture, retaining its 5% acceptance limit.
- `docs/src/user/solver_configuration.md`: describe aggregate phase and override behavior.

## Findings

The original phase selection was incomplete. Initial atmospheric flags existed, but the solver still started with the orbital cap. Cached options and crossing effects could also disagree with the aggregate active state. The repair consistently derives adaptive settings from that state.

During implementation, the existing solver libraries delivered only one callback for identical simultaneous spacecraft crossings. The new reconciliation handles both flags from the event state. An initial reuse attempt restored options but estimated its first step before housekeeping callbacks initialized the new run; callback refresh and initialization order now make the tested fresh and reused trajectories bit-identical. Both failed attempts are retained in the internal evidence.

## Residual Risk

These bounded exponential-atmosphere fixtures do not establish full-duration native GRAM mission accuracy. The independently reviewed PR170 nonlinear-policy change remains a separate merge decision. Reinitializing callbacks intentionally repeats their initialization at reused physical-run and checkpoint boundaries; existing checkpoint regressions pass, but user-supplied callback side effects should be considered in independent review. Large-constellation runtime cost has not been measured. The existing solver stack can stall on identical simultaneous spacecraft at large elapsed epochs; independent base-versus-repair probes establish that this predates the repair. PR170's libraries remove that old-stack stall. Checkpoint files also do not preserve spacecraft deactivation flags, and omitted old-stack exit callbacks can miss per-member thruster scheduling; these are pre-existing limits outside this repair.
