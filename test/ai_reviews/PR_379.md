## Scope

Review of the `tick-hooks` branch, one commit (45eb6cbcd) on `main` d19535201;
review `git diff d19535201 tick-hooks`. It is H4 of the hook-signature program (design
v1.2.1, section 5 row 8 and the H4 row of 5.1).

The PR:

- renames the GNC ticks `calcControlEffect!`, `calcGuidanceEffect!` and
  `calcNavigationEffect!` to `update_control!`, `update_guidance!` and
  `update_navigation!`, with the same arguments;
- routes each tick through a callback bridge that calls the new name when the
  effector's type has it, and the type's old method otherwise;
- deprecates the old names, with warnings before the run and on direct calls;
- migrates the built-in effectors, the templates, the examples, the docs and
  the tests.

## Findings

Author's notes for the reviewer (no P1 or P2 known to the author):

- Low: the bridges query `hasmethod` with the exact argument types the
  callback passes, as the pre-run check does.
  - A new tick typed narrower than the run's state (for example
    `u::Vector{Float64}`) is not found.
  - The pre-run check then stops the run and names the new tick. It also says
    that the effector has methods of that function but none accepts the run's
    arguments.
- Low: as in #349 and #364, a direct call of an old name warns on the call
  path. A wrapper effector that calls an old tick inside its own tick pays a
  log lookup per tick after the first warning.
- Note: `_has_methods_for` now skips a method whose signature is fully untyped.
  It is used only for the "none accepts" hint, and a deprecated hook's fallback
  for direct calls accepts every type, so without the skip the hint would
  always fire for the old names.
- Note: the MuJoCo companion's test (`test/engine_tests.jl`, `ShadowProbe`)
  implements `calcNavigationEffect!`. It logs one deprecation warning per run
  until C-M2 renames it. Neither its CI nor core's
  `optional-mujoco-installation` job runs with `--depwarn=error`.

Reviewer to verify:

- **No warning is reachable from a callback.** A bridge's old branch runs only
  for a type without the new tick. A fallback warns only for a type with it,
  and both use the same query on the same argument types. A type's own old
  method is dispatched to directly.
- **The renamed methods' bodies are unchanged:** the diff of each built-in tick
  method is its name line only (and docstring headers).
- **The pre-run check** for each case: neither name (refused, the message names
  the new tick), old only (accepted, warns), an old method for another state
  type (refused, with the hint), new only (accepted, silent), both (accepted,
  "never used").
- **The gate's sanctioned fallbacks:** five untyped arguments for each old tick
  in `tick_hook_bridges.jl`.
- **The EDG ownership pattern** refuses a tick call in the owner files under
  each of the four names.
- **Under `--depwarn=error`,** no test, probe or example ticks an effector
  through an old name, other than the compatibility file's child process,
  which expects the error.
