# AI Review Artifact - PR #132

## Scope
Adds an opt-in preallocated fixed-cadence trajectory recorder for large constellation output. The new recorder preserves the existing `SaveField` payload shape, records built-in default fields into typed preallocated arrays during the solve, fuses the default-field sampling pass, and materializes the old `Vector{SaveData}` shape only at the output boundary. The existing `SavingCallback`/`SavedValues` path remains available and unchanged.

## Changed Files
- src/simulation/callbacks/event_callbacks.jl - adds `TrajectoryRecorder`, capacity/growth/reset helpers, a `SavingCallback` adapter, typed accessors for recorded fields, a fused default-save-field sampler, and `trajectory_save_data` materialization back to the legacy snapshot shape. Custom/non-default save fields fall back to generic storage.
- src/simulation/callbacks/registry.jl - exports the recorder type and helper functions from the callbacks registry.

## Findings
- P2: output parity could drift because the optimized path bypasses `_save_snapshot` for default fields. Covered by `test/unit/simulation/trajectory_recorder_tests.jl`, which compares sample times and every saved field against the existing `get_data_saving_callback` path field-by-field on the same solve.
- P2: direct typed storage is valid only for the built-in default field shapes. The implementation gates typed storage on the known built-in field names and component counts; custom fields are stored through the fallback vector and are not forced through the fused path.
- P3: the optimization intentionally moves allocation to the output boundary rather than removing it entirely. `trajectory_save_data(rec)` still allocates the legacy `SaveData` dictionaries when a caller asks for them, while the solve itself avoids retaining one dictionary per sample.
- P3: the fused default sampler recomputes the default field payload in one pass and depends on the same state/environment helpers used by the existing save fields. The regression test exercises the supported SPICE-free inverse-square case; native GRAM/full telemetry coverage is supplied by CI rather than a new unit test here.

## P1 Assessment
No P1 findings. Unresolved P1: No. The branch introduces a new opt-in recorder surface and does not alter the existing fixed-cadence saver or default callback behavior unless a caller explicitly constructs and attaches a `TrajectoryRecorder`.

## Residual Risk
Low to medium. Functional risk is limited because the recorder is opt-in, the legacy saver remains the default, and the test compares the new materialized payload against the existing path. The main residual risk is performance-shape risk: the fused default-field pass reduces fixed-output overhead for the measured constellation case but does not address the solver/RHS allocation floor, so the benefit depends on cadence, field set, and constellation size. Custom save fields use the generic fallback and do not get the fused/default-field speedup.
