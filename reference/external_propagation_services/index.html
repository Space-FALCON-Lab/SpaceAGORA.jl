External propagation service contract

SpaceAGORA.ExternalPropagationServices is the supported facade for optional external spacecraft integrators.

This facade follows the optional adapter standard. This page describes contract 2.0.0, which applies SpaceAGORA's hook conventions to the external-owner protocol: time before index, an owner-local position named slot, and one definition of the attitude quaternion. It has no global provider registry: independently configured owners may coexist, provided they do not claim the same spacecraft.

Use with_external_propagators to attach owners to a configuration, external_initial_state in preparation, and external_runtimes in telemetry callbacks. These helpers keep adapter code independent of configuration-copy and engine-storage implementation details. Borrowed runtimes must not be stepped or mutated from telemetry callbacks.

Configuration preflight checks ownership and solver compatibility. Execution still checks routing, the flat-RHS guard and other runtime restrictions. This facade does not add checkpoint/resume, ensemble/process-pool support, actuator coupling or a higher-order native step.

Conventions

  • Argument order. external_state(rt, t, slot) and external_acceleration(rt, t, slot) take the elapsed engine time t [s] before slot. slot is the 1-based position in the owner's external_spacecraft(ep) list, not a run index. external_initial_state(u0, spacecraft_index) takes a run index: the position in the configuration's spacecraft list.
  • Frames and units. Positions, velocities and accelerations are inertial, in m, m/s and m/s². Angular velocity is in body axes, in rad/s.
  • Attitude quaternion. q = (x, y, z, w) is scalar last and gives v_body = rot(q) * v_inertial, with rot(q) = (w^2 - e⋅e) I + 2 e eᵀ - 2 w [e×] for e = (x, y, z) and [e×] the cross-product matrix of e. The engine's state, StateSample.q_ib and the saved sc<i>_q_* columns use the same convention.

Changes from contract 1.0.0

Contract 2.0.0 changes signatures and wording only; the engine's numerical behavior is unchanged.

  • external_state(rt, k, t) became external_state(rt, t, slot), and external_acceleration(rt, k, t) became external_acceleration(rt, t, slot). An adapter swaps the last two arguments of both methods and requires v"2.0.0". The exact version check refuses an adapter built for 1.0.0 before it defines any method. Update the methods and the required version together: a method typed (rt, k::Int, t::Float64) matches no 2.0.0 call, but an untyped one would receive the arguments swapped.
  • The quaternion is defined by the formula above. The 1.0.0 text called it a scalar-last body-to-inertial quaternion; the numbers are the same.
  • StateSample, which sample_planet_frame_with_lpi accepts, gained a spacecraft_index field while the contract was 1.0.0. Contract 2.0.0 records this additive change.

The SpaceAGORAMuJoCo companion implements contract 2.0.0 from its version 0.2.0.

Adapter implementation hooks

SpaceAGORA.SimulationModel.ExternalPropagation.AbstractExternalPropagator — Type
AbstractExternalPropagator

Supertype for a template that owns selected spacecraft throughout a simulation. Use the versioned SpaceAGORA.ExternalPropagationServices facade to implement the eight external_* hooks. The engine keeps owned spacecraft as shadow entries for ordinary output and guidance, with owner-supplied translational acceleration and attitude kinematics between synchronization points.

Templates may be shared by concurrent runs. external_prepare must construct a separate mutable runtime from the supplied initial state; neither preparation nor stepping may mutate the template or another run's runtime. After every accepted solver step, external_sync! advances whole owner steps without passing the solver time, before other discrete callbacks run. external_state supplies the state at solver time, including any remainder shorter than one owner step, using a model consistent with external_acceleration and attitude kinematics.

Ownership, solver, callback-rate and event limits are checked by the facade's validate_external_propagators and by run setup. No optional engine is loaded merely by loading SpaceAGORA or this interface.

SpaceAGORA.SimulationModel.ExternalPropagation.external_state — Function
external_state(rt, t, slot) -> (pos, vel, q, ω)

Return the absolute state, at elapsed engine time t [s], of the owned spacecraft at position slot (1-based) of the owner's external_spacecraft list; slot is local to the owner, not a run index. The fields are inertial position pos [m], inertial velocity vel [m/s], attitude quaternion q and body angular velocity ω [rad/s]. Account for any lag after the last whole owner step with the model used by the shadow acceleration and attitude kinematics.

q = (x, y, z, w) is scalar last and gives v_body = rot(q) * v_inertial, with rot(q) = (w^2 - e⋅e) I + 2 e eᵀ - 2 w [e×], e = (x, y, z) and [e×] the cross-product matrix of e. This is the engine's convention for the state q, StateSample.q_ib and the saved sc<i>_q_* columns.

Contract 2.0.0 order: time before the position. Contract 1.0.0 was external_state(rt, k, t).

source

external_acceleration(rt, t, slot) -> SVector{3,Float64}

Inertial translational acceleration [m/s^2] that the shadow entry of the owned spacecraft at position slot follows at elapsed engine time t [s]. Contract 2.0.0 order: time before the position; contract 1.0.0 was external_acceleration(rt, k, t).

Core services

sample_planet_frame_with_lpi accepts either a StateSample or a named tuple (pos_ii=..., vel_ii=...) with SVector{3,Float64} values: inertial position in metres and inertial velocity in metres per second. The named-tuple form is part of this service contract and requires no mass or attitude fields. In both forms, the supplied l_pi maps inertial components to planet-fixed components, and the returned velocity includes the planet-rotation transport term.

SpaceAGORA.ExternalPropagationServices.with_external_propagators — Function
with_external_propagators(config::SimulationConfiguration, owners::Tuple)

Return a configuration with exactly owners as its external propagators; () removes all owners. Every other field and reference is preserved. This is a shallow update: owner templates may be shared across runs, while external_prepare must create a separate mutable runtime for each run. The input configuration is unchanged. Ownership and solver compatibility are checked by validate_external_propagators and again during run setup.

source
SpaceAGORA.ExternalPropagationServices.validate_external_propagators — Function
validate_external_propagators(config::SimulationConfiguration, solver_mode::Symbol)

Check external ownership against the requested solver mode; return nothing or throw ArgumentError. This calls each owner's external_preflight, but does not prepare a runtime or advance a simulation. Run setup still performs these checks using its resolved solver mode.

Supported modes are :tsit5, :auto_stiff, :rodas5p and :dp8. Checkpointing, resume, continuous events on owned spacecraft, engine articulation or control of owned spacecraft, and callback rates incompatible with an owner's fixed step are refused. An empty owner tuple requires no external-propagation checks. Ensemble/process-pool routing and the flat-RHS environment guard are checked elsewhere during run setup. Owner-defined preflight may perform its own checks; this function is not a guarantee of complete run readiness or side-effect freedom.

source
SpaceAGORA.ExternalPropagationServices.external_runtimes — Function
external_runtimes(integrator)

Return an iterable of the current run's external runtimes, in configuration owner order, for use inside a SaveField getter or simulation callback. It is empty when the run has no external owners. The iterable and runtime objects are borrowed: callers must not change their contents, step them, or retain them for another run. Their concrete storage type is not part of this interface.

After an accepted solver step, external synchronization precedes other discrete callbacks. An owner may lag the solver time by less than one fixed owner step; use external_state to obtain its spacecraft state at the callback time.

source
SpaceAGORA.ExternalPropagationServices.external_initial_state — Function
external_initial_state(u0, spacecraft_index::Integer) -> (pos, vel, q, ω)

Read one spacecraft's initial state from the u0 passed to external_prepare. The index is 1-based in the configuration's spacecraft list, not local to the owner. Returns immutable copies: inertial position pos [m], inertial velocity vel [m/s], attitude quaternion q (scalar last, v_body = rot(q) * v_inertial, the convention of external_state), and body angular velocity ω [rad/s]. If orientation simulation is disabled, q is the identity (0, 0, 0, 1) and ω is zero.

SpaceAGORA.SimulationEngine.sample_planet_frame_with_lpi — Function
sample_planet_frame_with_lpi(x::StateSample, planet, l_pi::SMatrix{3,3,Float64,9}) -> PlanetFrameSample

Sample planet-fixed position, velocity, altitude [m], latitude [rad], and longitude [rad] from inertial state x and an inertial-to-planet rotation l_pi. Velocity includes the rotating-frame transport term from planet.ω. The caller supplies the rotation at the desired epoch; this function performs no ephemeris lookup and does not mutate the state, planet, or rotation.

SpaceAGORA.SimulationModel.EffectorSampling.gravity_backbone_relative_acceleration_ii — Function
gravity_backbone_relative_acceleration_ii(model, x_base, ρ, x_far, env_base, env_far, t) -> Δg_ii

Acceleration difference g(x_base + ρ) - g(x_base) of one position-only gravity effector, where x_far and env_far are the samples at x_base.pos_ii + ρ. The fallback subtracts two evaluations of gravity_backbone_acceleration_ii; models override it to difference their point-mass part analytically (Encke), so a small ρ does not lose the difference to cancellation.
