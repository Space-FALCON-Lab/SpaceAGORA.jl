## Findings
- P2: the batched harmonics kernel existed for SIMD across satellites; deleting it changes the flat route's cost profile for large constellations. Checked: the pre-pass still splits satellites across workers with the same allotment; each satellite pays the scalar kernel the serial route already pays. The cost-model weights keep their per-satellite phase counts.
- P2: `use_buffered_density=false` adds one atmosphere sample per satellite per stage in the flat route. Checked: this is exactly what the serial route does; the buffered value differed from a fresh sample at the parts-per-million level and reached the integrated heat load.
- P2: a `@noinline` dispatch and non-inlined force bodies add a call per effector per satellite per stage. Checked: microseconds against kernel work; the mechanism they remove was demonstrated directly (identical inputs, one-ULP difference in `mass * L' * g` between two functions).
- P3: partition mode (split solvers) sums only the selected effectors' slots, mirroring the serial partition loop; unselected slots stay zero and are skipped.
- P2: the first CI run of the route-parity probe still showed the two flat variants drifting on the runner (identical on Apple silicon, with or without coverage instrumentation). The kernels were already single bodies, which leaves the shared environment helpers inlined into different callers; they are now `@noinline` too. Checked locally that nothing regresses; the runner is the decisive check.
- P2: the merge met two fixes for the tabulated-flight NaN-altitude defect; the branch's vacuum short-circuit preempted main's NaN interpolation and the certification-mode probe failed in CI. Checked: the guard now returns NaN and keeps the branch's non-finite elapsed-time check; the probe's testset passes in isolation.
- P2 (Codex round 2): `_release_oversized_flat_scratch!` compared the slots' third dimension, now the satellite count, against the worker allotment, so a calibrated constellation with more satellites than workers dropped a correctly sized buffer and re-allocated it on the first RHS call. Resolved by deleting the helper, its two call sites and its knob; the slot shape is independent of the plan.
- P2 (Codex round 2): `predict_plan_ns` still charged flat plans one coefficient walk per worker and priced their lanes at batch width, assumptions of the deleted `@turbo` kernel, so the analytic planner under-priced flat harmonics plans by about the satellites-per-worker factor. Resolved by pricing the flat branch per satellite at width one, the same as `satellite_batch`; the work counts (per-satellite flops, per-satellite touches) already described the scalar kernel and are unchanged. The rate constants were calibrated on the synthetic kernel and still apply; the router branch's flat-route calibration data should be re-measured after merge, as already noted under Residual Risk.
- P3: the router branch's fifteen unit-test files under test/unit/parallel/ were never run by any CI job (test/runtests.jl only includes the integration harness), which is why its cost-model files showed near-zero coverage. Seventeen now run as coverage-aware subprocesses in suite 10; `machine_topology_tests.jl` (assumes physical cores <= Sys.CPU_THREADS, false on Apple Silicon), `mc_route_tie_tests.jl` and `policy_v2_tests.jl` (assume the host's full thread and process budget) stay with the standalone driver.
