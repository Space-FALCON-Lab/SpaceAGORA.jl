Contributor Conformance API

This page documents the supported public interface available from SpaceAGORA.

Contributor conformance

SpaceAGORA.Conformance — Module
SpaceAGORA.Conformance

Checks that code built around SpaceAGORA (a force/torque model, a service facade) behaves as the engine's contracts require. Each check_* function runs the engine's own machinery (its pre-run hook check and run_simulation) on the object and returns a ConformanceReport; it needs no test framework. With the Test standard library loaded, each test_* function records the same checks as tests:

using Test, SpaceAGORA
using SpaceAGORA.Conformance

@testset "MyModels" begin
    test_force_torque_model(MyDisturbanceTorque(gain=1e-6))
end

A conformance pass certifies interface behaviour only. Scientific validation of a model, its parameters and the claims made from it stay with its author.

source
SpaceAGORA.Conformance.ConformanceCheck — Type
ConformanceCheck(id, status, since, detail)

One check of a ConformanceReport.

  • id::Symbol: the check, for example :repeatable_run.
  • status::Symbol: :pass, :fail, :skip (the check could not apply, detail says why) or :advisory_fail (a check added in the current minor release that did not pass; it becomes required in the next one).
  • since::VersionNumber: the SpaceAGORA release that added the check.
  • detail::String: what differed, or why the check was skipped; empty on a pass.

A passing check certifies interface behaviour only. Scientific validation of the model stays with its author.

source
SpaceAGORA.Conformance.ConformanceReport — Type
ConformanceReport(target, kind, checks)

The result of one check_* call: target names the object checked, kind the contract it was checked against (for example :force_torque_model), and checks holds one ConformanceCheck per check id, in a fixed order. passed tells whether every required check passed; show prints one line per check.

source
SpaceAGORA.Conformance.passed — Function
passed(report::ConformanceReport) -> Bool

true when no check of report has status :fail. Skipped checks and advisory failures do not fail a report.

source
passed(check::ConformanceCheck) -> Bool

true unless the check's status is :fail.

source
SpaceAGORA.Conformance.ConformanceFixture — Type
ConformanceFixture

A configuration the checks run, with the concrete argument types its run passes to the hooks. Build it with conformance_fixture.

  • configuration: the SimulationConfiguration every check runs. Checks run it with isolate_state=true, except deepcopy_equivalent, which runs it once with isolate_state=false after the other runs.
  • arguments: the configuration the engine's pre-run hook check reads, after the same per-spacecraft GNC flattening and density epoch alignment run_simulation applies first.
  • call: the run's state and parameter types, as the pre-run check derives them from build_initial_conditions and ODEParams.
  • solver_mode: the solver mode of the run.
source
SpaceAGORA.Conformance.conformance_fixture — Function
conformance_fixture(; configuration=nothing, spacecraft_count=1, mission_time_s=60.0,
    guidance=(), navigation=(), control=(), effectors=(), sensors=(), guidance_rate_s=10.0,
    navigation_rate_s=10.0, control_rate_s=1.0, orientation=true) -> ConformanceFixture

The run the checks use. Without configuration it is a short Earth orbit that needs no native GRAM, SPICE kernels or private data: make_no_gram_planet(:earth), NoAtmosphereModel(), SimpleEphemeridesModel(), spacecraft_count single-link spacecraft (100 kg, 2 m², on a 650 km by 700 km orbit at 45°, spaced 5° apart in true anomaly), a MissionTime of mission_time_s seconds, attitude propagation when orientation is true, InverseSquaredJ2GravityModel() followed by effectors as the force/torque models, sensors mounted on the first spacecraft's root link with add_sensor!, and the given guidance, navigation and control models at their rates in seconds.

A model that needs more (an atmosphere for drag, a second spacecraft with a particular orbit, articulated links) is checked on a configuration the author builds, which must already contain the models under test; the component keywords are then refused.

SpaceAGORA.Conformance.check_force_torque_model — Function
check_force_torque_model(model; fixture=conformance_fixture(effectors=(model,)), samples=nothing)
    -> ConformanceReport

Check a force/torque model against the engine's contract for it. fixture must contain model itself (found by identity) among its dynamic_effectors. The checks, in report order:

  • hooks_present: the engine's own pre-run hook check, on the fixture's concrete argument types, reports nothing for the fixture.
  • supported_sample_signature: no method of wrench, wrench_caching! or a gravity backbone hook that applies to the model types a sample argument narrower than StateSample or EnvironmentSample (such as x::StateSample{MySpacecraft}); the supported forms are x::StateSample and an untyped x.
  • repeatable_run: two runs with isolate_state=true save equal times and states, bit for bit.
  • deepcopy_equivalent: a run of the model itself (isolate_state=false) equals the run of its deep copy (isolate_state=true).
  • global_rng_independent: runs with the global random number generator seeded two ways are equal (it is restored afterwards); a model draws only from the streams the engine supplies.
  • concurrent_equals_sequential: two runs on separate threads, kept in step after every solver step so that they overlap, equal the two sequential runs. When Julia counts line executions (--code-coverage or --track-allocation), the runs take turns instead, one solver step each, and never step at the same time: two threads running the same counted lines share each line's counter, which makes them several times slower than two sequential runs. Taking turns still interleaves the runs step by step, so a state they share is caught either way; a race that needs both runs inside a step at the same moment can only show without counting. It fails when a run waits more than 60 s for the other at a step, since the runs then did not overlap. Skipped when Julia runs with one thread.
  • output_hook_pure: two calls of wrench with the same arguments return equal values, leave a deep copy of the model unchanged, and log nothing at Info level or above.
  • environment_declared: wrench returns a finite force and torque (two three-vectors) when only the EnvironmentSample fields its environment_requirements declares are set and the rest are nothing. A model that declares third bodies needs a fixture with SPICE ephemerides, which the built-in one does not load.

The last two call wrench on samples the engine builds (build_state_sample and sample_environment) at the start, quarters and end of a fixture run, or on samples: a collection of (x, env, t) tuples. A model with no wrench method skips them.

Every run deep-copies the fixture except the deepcopy_equivalent run, which runs model itself after all the others, so a model with run state holds that run's state afterwards. A check that cannot run its comparison because a run failed fails with the run's error. A pass certifies interface behaviour, not the model's physics.

source
SpaceAGORA.Conformance.check_service_facade — Function
check_service_facade(facade::Module; version::VersionNumber) -> ConformanceReport

Check a versioned service facade against the optional adapter standard. One check, facade_shape, verifies that:

  • the facade defines CONTRACT_VERSION, CompatibilityError, require_version, IMPLEMENTED_FUNCTIONS and CONSUMED_SERVICES;
  • CONTRACT_VERSION equals version, the contract version the caller reviewed;
  • require_version(version) returns nothing, and every neighbouring version (one patch, minor or major release up or down, and v"0.0.0") throws the facade's CompatibilityError: the check is exact;
  • the two inventories are collections of names or name paths (tuples of names), each listed once, none in both; every implemented name resolves to a function and every consumed one to a value.

A facade that breaks any of these gets a failing facade_shape with the problems in its detail; the check does not throw on a malformed facade.

SpaceAGORA.Conformance.check_sensor — Function
check_sensor(sensor; fixture=conformance_fixture(sensors=(sensor,)), seeds=(7, 8))
    -> ConformanceReport

Check a sensor kind against the engine's sensor contract. fixture must have sensor itself (found by identity) mounted on one of its spacecraft. The checks, in report order:

  • run_state_fields: the sensor is a mutable struct with the fields the engine fills (period_s, seed, rng, latest, latest_time_s), a finite positive period, a positive sensor_dimension and a latest with that many components.
  • requirements_supported: the engine's add_sensor! accepts a copy of the sensor; it refuses the environment requests (sensor_requirements) the engine does not sample for sensors, and any record it cannot mount.
  • measurement_shape: sensor_measure returns sensor_dimension finite components (a number or a vector for one component, a vector otherwise), in the fixture run and when called on the truths the engine builds at the start, quarters and end of it.
  • repeatable_run, deepcopy_equivalent, global_rng_independent and concurrent_equals_sequential: as for force/torque models, comparing the sensor's measurements and their times, bit for bit, instead of the state.
  • seed_repeatable: two runs with the first of seeds give the same measurements, and a sensor whose measurement depends on its random stream (two streams give different measurements of the same truth) measures differently in a run with the second seed.
  • custom_state_reset: two runs with isolate_state=false on one configuration give the same measurements, so any state the sensor keeps beyond the engine's fields is reset by initialize_sensor!.
  • checkpoint_round_trip (added in 0.4.0, advisory in 0.4): the fixture run with a checkpoint halfway, interrupted after it and resumed from the file, gives the measurements of an uninterrupted run with the same checkpoints from halfway on, so any state the sensor keeps beyond the engine's fields is in checkpoint_state. Skipped when the fixture refuses checkpointed runs at setup.

When the fixture cannot be built (add_sensor! refuses the sensor), the checks that need a run fail with its error. Every run deep-copies the fixture except the deepcopy_equivalent run, which runs sensor itself after all the others. A pass certifies interface behaviour, not the sensor's model of the instrument.

source
SpaceAGORA.Conformance.check_guidance_model — Function
check_guidance_model(model; fixture=conformance_fixture(guidance=(model,)), spacecraft_index=1)
    -> ConformanceReport

Check a guidance model. fixture must hold model itself (found by identity) among its configuration's guidance effectors. The checks, in report order:

  • hooks_present: the engine's pre-run hook check, on the fixture's concrete argument types, reports nothing.
  • repeatable_run, deepcopy_equivalent, global_rng_independent, concurrent_equals_sequential: as for force/torque models, comparing the saved states and the model's own state at the end of each run, bit for bit.
  • initialize_resets: two runs with isolate_state=false on one configuration end with equal states and an equal model, so initialize_guidance! resets the model's run state.
  • bind_fresh_state: for a model with a bind_spacecraft method, no mutable object reachable from the copies bound to spacecraft 1 and 2 changes during a run of the fixture with the model declared on its first two spacecraft instead of in the shared container (a fixture with one spacecraft gets a copy of it as the second, its mounted sensors included). Skipped without a method.
  • checkpoint_round_trip (added in 0.4.0, advisory in 0.4): the fixture run with a checkpoint halfway, interrupted after it and resumed from the file, ends its second half with the states and the model's own state of an uninterrupted run with the same checkpoints, bit for bit: checkpoint_state and restore_checkpoint_state! carry the run state the model keeps from the checkpoint into the fresh copy the resumed run starts from. Skipped when the fixture refuses checkpointed runs at setup.

A pass certifies interface behaviour, not the guidance law.

SpaceAGORA.Conformance.check_navigation_model — Function
check_navigation_model(model; sensors=(), fixture=conformance_fixture(navigation=(model,), sensors=sensors),

SpaceAGORA.Conformance.check_control_model — Function
check_control_model(model; fixture=conformance_fixture(control=(model,)), spacecraft_index=1)
    -> ConformanceReport

Check a control model. The checks, in report order: hooks_present; supported_sample_signature (no method of control_wrench, control_propellant_rate or control_wheel_torque that applies to the model types its sample argument narrower than StateSample); the four run-level checks of check_guidance_model; initialize_resets (initialize_control! resets the model's run state, as for guidance); output_hook_pure (each output hook the model has, called twice on the same arguments, returns equal values, leaves the model unchanged and logs nothing at Info level or above); positive_consumption (control_propellant_rate is finite and not negative); bind_fresh_state; checkpoint_round_trip, as for guidance; outputs_in_scope (added in 0.7.0, advisory in 0.7): after the model's ticks, its output hooks and levels (actuator_levels, control_thruster_levels) return zeros or nothing for a fixture spacecraft outside the spacecraft_scope the run took, once the model's run-start initializers ran. From 0.7.0 the engine calls them only inside the scope, but direct callers may ask about any spacecraft. A fixture with one spacecraft is checked with a copy of it as the second; skipped when the scope names every spacecraft of the fixture.

The output hooks are called on the states, parameters and copies of the model the engine holds at the start, quarters and end of a fixture run, on spacecraft spacecraft_index. A model with no output hook skips those checks.

SpaceAGORA.Conformance.check_algorithm — Function
check_algorithm(algorithm, requests; trusted=NamedTuple(), run_context=(seed=1,), simulation=nothing)
    -> ConformanceReport

Check a planning algorithm of the general GNC algorithm contract against its declared family, on requests, the family's representative requests (for RPO, rpo_conformance_requests), proposed in order from a fresh state. trusted holds the queries the family's validation needs (for RPO, rpo_trusted_queries); run_context is passed to initialize_algorithm with the stream's seed words added. A request the family's is_revision_request marks is sent to propose_revision! with the product of the latest accepted proposal. The checks, in report order:

  • family_resolves: algorithm_family returns an AbstractAlgorithmFamily.
  • family_trusted: the family is defined in core (a family module or a service facade), not in the algorithm's own package.
  • result_contract: every proposal has the family's algorithm_result_type, a known status, the request's request_id, and a product (proposed_product) exactly when its status is :candidate.
  • stream_untouched_if_declared: an algorithm that declares consumes_rng = false leaves the stream unchanged. Skipped for one that declares true.
  • deterministic_given_stream: two walks through the requests from fresh states and equal streams, with the global random number generator seeded 1 and 2, give equal results.
  • request_not_mutated: the copy of each request handed to the algorithm is unchanged after its proposal.
  • initialize_independent: two states from initialize_algorithm share no mutable object.
  • refuses_explicitly: a revision request the family's capability check refuses gets an :unsupported result from propose_revision!, never a product. Skipped when no request is such a revision.
  • driver_round_trip: the requests run in order through run_algorithm_request! with the kit's test binding end as the family decides on proposals made from copies of the same state and stream: an accepted proposal is installed (the link changes, the installed product equals the proposal and is current at the request's time), a refusal follows the family's on_rejection. No request may end as :invalid_result_type or :algorithm_exception. Skipped for a family without a conformance link.
  • simulation_run: simulation(algorithm), a short simulation that returns the binding's run records (for RPO, rpo_conformance_simulation), completes with a product installed and no failure record. Skipped when simulation is nothing.

A pass certifies interface behaviour, not the algorithm's method.

source
SpaceAGORA.Conformance.check_algorithm_family — Function
check_algorithm_family(family, algorithm, requests; link, trusted=NamedTuple(), run_context=(seed=1,))
    -> ConformanceReport

Check a family of the general GNC algorithm contract (a new family's core half, or a family a service facade serves), with an algorithm of the family and its representative requests, which should include one the family refuses. link is a fresh object of the kind products are installed into; each run uses a copy. The checks, in report order:

  • family_resolves: algorithm_family(algorithm) has the type of family, as the request driver requires.
  • family_obligations: validate_proposal, install! and is_current have methods for the family's requests and products; fallback_product has one when on_rejection(family) is :install_fallback; on_rejection is a known policy; validation leaves the request, the result, the trusted queries and the global random number generator unchanged; install! changes none of its arguments but the link; is_current returns a Bool; algorithm_result_type is a subtype of AbstractAlgorithmResult; and a family a service facade serves (its module defines CONTRACT_VERSION) states family_contract_version.
  • driver_round_trip: as for check_algorithm, with family as the bound family, so its rejection policy is the one exercised.

SpaceAGORA.Conformance.rpo_conformance_requests — Function
rpo_conformance_requests(; goal_rtn_m=(5.0, 0.0, 0.0)) -> Vector{RPOPlanningRequest}

Representative requests of the RPO reference family for check_algorithm: an initial request at 0 s from 3 m along the target's radial axis, a forced request at 1 s from another state, and a retiming request at 2 s, with the pilot's chaser and station geometry (the station 50 m off the path) and constraints. goal_rtn_m=nothing makes each request's goal its own start position, for a planner valid only for an unchanged goal.

rpo_trusted_queries() -> NamedTuple

The queries the RPO family's validation needs, as the RPO binding supplies them: clearance_at, the distance from a point to the station in a request's geometry.

SpaceAGORA.Conformance.rpo_conformance_simulation — Function
rpo_conformance_simulation(; mission_time_s=0.2, kwargs...) -> Function

A simulation for check_algorithm: a function of a planner that runs make_rpo_configuration(; planner, mission_time_s, kwargs...) twice in sequence and, with two or more threads, twice concurrently, and returns the planner binding's run records of the first run. It throws when a run fails or the runs differ, so simulation_run fails for a planner whose runs do not repeat.

SpaceAGORA.Conformance.burn_plan_conformance_requests — Function
burn_plan_conformance_requests() -> Vector{BurnPlanRequest}

Representative requests of the burn-plan family for check_algorithm, for one 150 kg spacecraft at perigee of a 400 by 2000 km Earth orbit with 50 kg of propellant, a 50 N thruster and a 300 s specific impulse: an initial request at 0 s; a forced request at 100 s while an installed burn is in progress, which the family refuses (:burn_in_progress) and, by its :keep_previous policy, keeps the installed plan for; and a replanning request at 300 s, after that burn has ended. The family's validation needs no trusted queries.

SpaceAGORA.Conformance.burn_plan_conformance_simulation — Function
burn_plan_conformance_simulation(; mission_time_s=10.0) -> Function

A simulation for check_algorithm: a function of a burn planner that runs it through AlgorithmGuidance, with one request at the run's start, on one spacecraft in a 400 by 2000 km Earth orbit whose burn scheduler (a BaseThrusterModel) plans no burn of its own. The run is made twice in sequence and, with two or more threads, twice concurrently, and the binding's run records of the first run are returned. It throws when a run fails or the runs differ.

SpaceAGORA.Conformance.joint_reference_conformance_requests — Function
joint_reference_conformance_requests() -> Vector{JointReferenceRequest}

Representative requests of the joint-reference family for check_algorithm, for the default robot arm (default_robot_arm_model()) with its base at the origin, from rest at zero joint angles to a reachable target over 4 s sampled every 0.5 s: an initial request at 0 s; a forced request at 5 s with a 2 cm sphere on the straight joint-space path, which a planner that does not avoid it proposes through and the family refuses (:insufficient_clearance) and, by its :fail policy, fails the request for; and a replanning request at 10 s with the sphere moved clear of the path. The family's validation needs no trusted queries.

SpaceAGORA.Conformance.joint_reference_conformance_simulation — Function
joint_reference_conformance_simulation(; mission_time_s=1.0) -> Function

A simulation for check_algorithm: a function of a joint-reference planner that runs it through AlgorithmGuidance, with one request at the run's start, on one spacecraft in a 400 by 2000 km Earth orbit whose RobotArmControlEffector tracks the default arm's plans from its plan buffer at a 0.5 s control step, the buffer starting with a hold at zero joint angles. The run is made twice in sequence and, with two or more threads, twice concurrently, and the binding's run records of the first run are returned. It throws when a run fails or the runs differ. The arm's coupled compliant state needs short solver steps, so the default run is short: it covers the request and install at the start and the controller's ticks at 0, 0.5 and 1 s.

SpaceAGORA.Conformance.test_report — Function
test_report(report::ConformanceReport)

Record report in the current Test testset: a testset named after the target, with one testset per check. A failed check fails its test and prints its detail; a skipped check is recorded as skipped and an advisory failure as broken. Returns report.

When the environment variable SPACEAGORA_CONFORMANCE_REPORT_DIR names a directory, the report is also written there as a TOML file (target, kind, and one [[checks]] table per check with id, status, since and detail), which the contributor CI workflow summarizes.

Needs the Test standard library: using Test loads the method.
