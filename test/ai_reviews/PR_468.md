What it does:
- **Scoped entries.** An entry `scoped(effector, scope)` in a `DynamicsModel`'s
  effector tuple acts only on the spacecraft its scope names. The scope is
  `BoundSpacecraft(positions)`, `AllSpacecraft()` (no scope), or the new
  `SpacecraftSelection(; positions, ids, planes, slots, where)`. An effector type
  may also declare its own `spacecraft_scope`.
- **Resolution.** `run_simulation` resolves the scopes once, after the GNC
  flattening, into bare effectors plus an `EffectorScopes` table of run
  positions.
- **The right-hand side** skips out-of-scope effectors on every route.
- **Consumers** that read effectors per spacecraft follow the scope: the
  accelerometer, the cost count and probe, the flat atmosphere pre-sample, and
  the ensemble's members.
- **Refusals** at the start of the run for scopes the run cannot honour (design
  §6, D-C2-4, D-C2-5, D-C2-7).
- **Checkpoints** record the scopes, and a resume refuses different ones (D-C2-8).

Rule: every run without a scoped effector is bitwise unchanged. A scoped run has
the bits of the same run with a model that returns zero outside its spacecraft.

## Findings

No P1 or P2 findings.

Points a reviewer should check:

- **Found by hosted CI and fixed (b8fd0a8b3).**
  - The failure: suite 01's "Include-Order + Name Ambiguity Smoke" failed. The
    engine's `effector_scopes.jl` imported `AlgorithmLifecycle`,
    `GNCAlgorithms` and `EDGGuidanceFamilies` for the EDG refusal. In the
    standalone composition the first and last of these load after the engine
    ("undeclared at import time").
  - The fix follows #461: a private GNCRuntime predicate with a `false`
    fallback, and its `true` methods added where the types are defined. The
    engine imports only GNCRuntime, which loads before it.
  - Checks:
    - suite 01 fails before the fix (the two warnings) and passes after it, plain and with code coverage;
    - the package loads with no warning;
    - the fingerprints are unchanged;
    - the mutants that drop either `true` method are caught.

- **Bitwise identity of unscoped runs.**
  - `_resolve_effector_scopes` returns the configuration itself when no entry is a `ScopedEffector` and no effector declares a scope, so there is no table (tested).
  - Each summer branches on the table first. With `nothing` it runs its existing statements; the item lists' added test is a constant `true`; the batch flags are `p.is_active` itself.
  - The fingerprints below confirm it.
- **Skipping equals adding a zero.** Every route's sums start at +0.0, and
  +0.0 + (−0.0) = +0.0, so a running sum is never −0.0 and `x + 0.0 == x`.
  - A scoped run reproduces the gated workaround (a model returning zero outside
    its spacecraft) bit for bit, on every route and solver mode.
  - Mutants that replace a skip with adding the zero result are equivalent, and
    are not counted as gaps.
- **Fused single-effector routes** (single harmonics, single inverse-square,
  budget-1 pre-pass). They need the only effector, or every effector, to be
  gravity or a pre-pass model. With a non-trivial scope that one gravity effector
  would leave spacecraft without gravity, which R9 refuses. So no plan rule was
  added, and the harmonics and aero item lists honour scopes anyway.
- **Outputs of out-of-scope spacecraft.**
  - Aerodynamic diagnostics stay at their setup zero (tested).
  - Density and temperature columns come from the density callback, which runs
    before the saving callback at each accepted step (`density_callbacks/assembly.jl:232` before `:289`). The RHS heat rates sample their own atmosphere.
  - The flat route skips the per-spacecraft atmosphere pre-sample for
    spacecraft no atmosphere consumer acts on. The uniform-batch and density-service paths still sample every spacecraft; they are stateless or serve the batch.
- **Low: the robot-arm refusal widens D-C2-7(b).** The design named
  articulated and compliant spacecraft. A run with a robot arm is refused too,
  because its link gravity (`_ArmLinkGravity` through `_ArticulatedGravity`)
  sums every effector per body.
- **Low: `where` is a Julia keyword in type expressions but works as a keyword
  argument and field name** (checked on 1.12), so the accepted name is kept.
- **Found by the chain and fixed before handover.** The checkpoint entry first
  read `args.dynamics_model.effector_scopes` directly. The interlink checkpoint
  test writes a checkpoint with a stand-in `dynamics_model` (a `NamedTuple`),
  and it failed. The entry now reads the table through the guarded accessor the
  RHS uses (`_effector_scopes_of`). Every test that writes checkpoints with
  stand-in arguments passes at the final head.
- **Coordination: the index-bound ensemble refusal (#450).** Its check runs
  inside `_validate_ensemble_uncoupled`. C-2 resolves the scopes first
  (369400b0f), so the check sees the bare effectors. A custom effector with a
  `spacecraft_index` field inside `scoped(...)` would otherwise pass it and
  then never act in its one-spacecraft member (tested in 6f3bf9986; mutant M16).
- **Low: #450's message.** It says that "each member gets the whole dynamic
  effector tuple". That still holds for unscoped entries. A scoped entry goes
  only to the members in its scope, but it is never refused with that message
  unless it is also bound by its own field.
- **Open branches.** `git merge-tree` of the head with every open PR (#457 to
  #465; #458 `hardware-run-start-reset` f2d031aa4, #465 `solve-bookkeeping`
  949a00d26) gives no conflicts. #451 merged into main and is in the head. C5's planned edits to `execution.jl`
  (about lines 1034 to 1151) do not overlap C-2's lines there (the flattening
  rebuild, the resolution call and the scope check in `_resume_engine_state!`).
- **The scope resolution call** in `run_simulation` sits next to
  `_flatten_spacecraft_gnc`, ahead of the run-start phases C2b named. Only the
  checkpoint check is in the resume phase, `_resume_engine_state!`.

## Residual Risk

- **Atmosphere pre-sample.**
  - On the flat route, the per-spacecraft path skips out-of-scope spacecraft
    (tested since d38e12efc). The constellation-batch and density-service paths
    still sample them.
  - The batch path serves only stateless analytic models, so it changes nothing
    a later sample sees. The density service serves native GRAM; with it, an
    out-of-scope spacecraft's density column could depend on the route.
  - Its state cannot, since no in-scope effector reads that sample.
- **The cost counts are approximate.** The cost model's per-satellite terms
  (`simd_terms`, `scalar_items`) still count every spacecraft. Only
  `queue_nodes` follows the scope. This affects route choice for scoped runs,
  never bits.
- **Scope-unaware consumers.** Two consumers read the tuple without scopes, and
  are refused (EDG) or unchanged in meaning:
  - the EDG prediction, refused for scoped J2 and N-body (R11);
  - the thermal incidence mode.
  A custom consumer that reads `dynamic_effectors` per spacecraft would need
  `effector_scopes`.
- **Ensembles with index-bound effectors.** These are a separate defect fix in
  progress, and C-2 does not change them.
- **Shard weights.** `.github/ci-shards.toml` carries estimated weights for the
  two new files until `ci_shard_weights.py` measures them.
- **Not run:** `builtin_conformance_tests` with the EDG companion, and the
  examples smoke. `ScopedEffector` is not an `AbstractForceTorqueModel`, so the
  built-in enumeration is unchanged.
- **One crash in an untouched test.** After the first merge, `parallel_flag_tests` crashed once with a bus
  error in the machine-calibration kernel (`calibration_kernels.jl:62`), code this PR does not touch, while
  the machine was heavily loaded. It passed 133 of 133 on rerun at the same head.
- **Process-worker campaigns.** A `where` function travels to a process worker
  with its configuration, as any closure in a configuration does.
