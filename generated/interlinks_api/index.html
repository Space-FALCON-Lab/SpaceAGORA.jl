Interlinks API

This page documents the supported public interface available from SpaceAGORA.

Interlinks

SpaceAGORA.SimulationModel.InterLinkModels.AbstractInterlink — Type
AbstractInterlink

Supertype of the link kinds. One value describes one registered link between two terminals: register it with register_link!. A kind implements link_range_m, and the effects it has: link_force for a link that pushes its endpoints (the default exerts none). link_available decides when the link can close (by default, within link_range_m). The built-in kind is LaserMomentumLink.

source
SpaceAGORA.SimulationModel.InterLinkModels.LinkContext — Type
LinkContext(; time_s=NaN, planet=nothing)

What a link hook may read besides its two endpoints: the time (s into the run) and the run's planet. The engine passes the run's values; a call outside a run gets the defaults.

source
SpaceAGORA.SimulationModel.InterLinkModels.LaserMomentumLink — Type
LaserMomentumLink(; power_w=10_000.0, magnification=100.0, range_m=200e3)
LaserMomentumLink(terminal::LaserTerminal)

An open-cavity laser link that pushes its two spacecraft apart: an idealized central force of magnification * power_w / c on each endpoint, directed away from the other, equal and opposite, at any separation up to range_m. It models no pointing, occultation or beam losses. power_w (W) must be nonnegative, magnification and range_m (m) positive. The terminal form takes a link between two terminals of that design: its max_power_w, magnification and range_m.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_range_m — Function
link_range_m(link) -> Float64

The maximum separation in metres at which link can close. Every link kind implements it.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_available — Function
link_available(link, a::StateSample, b::StateSample, ctx::LinkContext) -> Bool

Whether link can close between its endpoints a and b, in the order of the link's key (the lower (spacecraft, terminal) pair first). The engine asks at the start of the run and after every accepted step, once the run's own rules (forbidden pairs, active spacecraft) allow the pair. Default: the endpoints are apart and within link_range_m(link).

source
SpaceAGORA.SimulationModel.InterLinkModels.link_force — Function
link_force(link, a::StateSample, b::StateSample, ctx::LinkContext) -> (force_a_ii, force_b_ii)

The inertial forces (N) an active link puts on its endpoints a and b, in the order of the link's key. The engine adds them to the endpoints' accelerations at every right-hand-side evaluation, and the scheduling policies score candidate links by them. Default: no force.

source
SpaceAGORA.SimulationModel.InterLinkModels.InterlinkModel — Type
InterlinkModel(; forbidden_pairs=())

The interlinks of a run: the candidate links between spacecraft terminals, each with its own link kind (register_link!), spacecraft pairs that may never link, and the accepted-step history of the links the scheduler selected. Attach it with SimulationConfiguration(interlink_model=model, ...). Endpoints are (spacecraft vector index, terminal number) pairs: the position of the spacecraft in dynamics_model.spacecraft, not its id. Terminals 1:n_terminal are virtual; mounted terminal hardware (see link_terminal) follows.

source
SpaceAGORA.SimulationModel.InterLinkModels.InterLinkGraph — Type

Indexed terminal vertices, candidate edges, the link of each edge (edge_properties) and availability/selection flags. Register candidates with register_link!.

source
SpaceAGORA.SimulationModel.InterLinkModels.InterLinkKey — Type

Canonically ordered pair of (spacecraft array index, terminal number) endpoints.

source
SpaceAGORA.SimulationModel.InterLinkModels.InterLinkHistory — Type

One accepted-step schedule sample: time in seconds and selected InterLinkKey values.

source
SpaceAGORA.SimulationModel.InterLinkModels.register_link! — Function
register_link!(model::InterlinkModel, spacecraft, first_endpoint, second_endpoint, link::AbstractInterlink) -> InterLinkKey

Register a candidate link of kind link between two terminals and return its key. Each endpoint is (spacecraft vector index, terminal), where the terminal is a terminal number or a terminal mounted on that SpacecraftModel. The terminals must be on different spacecraft, numbered within each spacecraft's terminal_count, and able to carry the link (terminal_supports). A link registers once. Its key lists the lower (spacecraft, terminal) first, or, for a directed link (link_directed), the endpoints in the order given. The link is available only when link_available allows it, and active only when the scheduler selects it.

source
SpaceAGORA.SimulationModel.InterLinkModels.register_links! — Function
register_links!(model::InterlinkModel, spacecraft, pairs, link; terminals=nothing) -> Vector{InterLinkKey}

Register one candidate link per spacecraft pair (i, j) in pairs and return their keys in order. The pairs come from all_pairs(spacecraft), from a constellation's planes and slots (same_plane_pairs, ring_pairs, grid_pairs), or from any vector of index pairs. link is a link kind value, or a function (i, j) -> link that builds each pair's link.

Each spacecraft's links take the terminals that can carry them in turn, starting again from the first when they run out; links that share a terminal compete for it when the scheduler selects. Pass terminals=(i, j) -> (terminal_i, terminal_j) to choose them instead. For a directed link, i is the transmitter.

source
SpaceAGORA.SimulationModel.InterLinkModels.all_pairs — Function
all_pairs(spacecraft) -> Vector{Tuple{Int, Int}}

Every pair (i, j) of distinct spacecraft vector indices with i < j, in order: the candidate pairs of a fully connected interlink graph, for register_links!.

source
SpaceAGORA.SimulationModel.InterLinkModels.same_plane_pairs — Function
same_plane_pairs(spacecraft) -> Vector{Tuple{Int, Int}}

Every pair (i, j), i < j, of spacecraft in the same orbital plane, by their constellation_slot (set by build_constellation), for register_links!. Spacecraft without a slot take part in no pair; two spacecraft in one slot are refused.

source
SpaceAGORA.SimulationModel.InterLinkModels.ring_pairs — Function
ring_pairs(spacecraft) -> Vector{Tuple{Int, Int}}

Each spacecraft with the next slot in its plane, and the last slot with the first: the in-plane rings of a constellation, by constellation_slot. A plane of two gives one pair, a plane of one none. Pairs are (i, j) with i < j.

source
SpaceAGORA.SimulationModel.InterLinkModels.grid_pairs — Function
grid_pairs(spacecraft; wrap_planes=true) -> Vector{Tuple{Int, Int}}

The "+grid" of a constellation, by constellation_slot: the in-plane rings (ring_pairs) and each slot with the same slot of the next plane, planes taken in plane-number order. With wrap_planes, the last plane links to the first; pass false for a Walker star, whose first and last planes counter-rotate. A slot missing from the next plane links nothing across. Pairs are (i, j) with i < j.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_directed — Function
link_directed(link) -> Bool

Whether link runs one way, from its first endpoint (the transmitter) to its second (the receiver). A directed link is keyed in the order its endpoints were registered, so the hooks receive the transmitter as a. An undirected link is keyed with the lower (spacecraft, terminal) first. Default: undirected, as for LaserMomentumLink.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_terminal_levels — Function
link_terminal_levels(link) -> (level_a, level_b)

The levels at which the hardware terminals at link's two endpoints run while it is active, in key order and in their actuators' units (watts of transmitted optical power for a LaserTerminal). Each such terminal draws actuator_consumption(terminal, level, ctx).power_w from its spacecraft's power budget, and is at level 0 while its link is inactive. A virtual terminal draws nothing. Default: zero levels.

source
SpaceAGORA.SimulationModel.InterLinkModels.link_terminal — Function
link_terminal(actuator) -> Bool

Whether a mounted actuator is interlink terminal hardware, which can be a link endpoint. True for LaserTerminal; a terminal kind of your own opts in with SpaceAGORA.link_terminal(::MyTerminal) = true. A spacecraft's terminals are its n_terminal virtual terminals, numbered 1:n_terminal, followed by its mounted terminals in mounting order. Default: false.

source
SpaceAGORA.SimulationModel.InterLinkModels.terminal_supports — Function
terminal_supports(terminal, link) -> Bool

Whether the terminal hardware terminal (a mounted actuator with link_terminal) can carry link; register_link! refuses a link that either endpoint's terminal cannot carry. A virtual terminal carries every kind. Default: true; a LaserTerminal carries LaserMomentumLink, and other kinds only when they add a method.

source
SpaceAGORA.SimulationModel.InterLinkModels.terminal_count — Function
terminal_count(spacecraft) -> Int

The number of interlink terminals on spacecraft: its n_terminal virtual terminals and, on a SpacecraftModel, its mounted terminal hardware (see link_terminal).

source
SpaceAGORA.SimulationModel.InterlinkTerminals.mounted_link_terminals — Function
mounted_link_terminals(spacecraft::SpacecraftModel) -> Vector

The terminal hardware mounted on spacecraft (actuators with link_terminal), in mounting order. Each entry gives:

  • number: its terminal number, after the n_terminal virtual terminals;
  • position: its position among the mounted actuators, the index of its level;
  • link: the link it is mounted on;
  • terminal: the actuator.
source
SpaceAGORA.SimulationModel.InterlinkTerminals.terminal_number — Function
terminal_number(spacecraft::SpacecraftModel, terminal) -> Int

The terminal number of terminal, mounted on spacecraft, for a link endpoint (spacecraft index, terminal number). register_link! also takes the terminal itself. Two mounted terminals with equal fields cannot be told apart, so for those give the number.

source
SpaceAGORA.SimulationModel.InterLinkModels.update_availability! — Function
update_availability!(model::InterlinkModel, spacecraft, state; is_active=nothing, context=LinkContext(),
                     terminal_available=nothing)

Mark each candidate link available when its spacecraft pair is not forbidden, both spacecraft are active (when activity flags are supplied), both terminals are available (when terminal_available gives a flag per graph vertex: in a run, terminal hardware the power budget sheds is not), and its link's link_available allows it (by default, the endpoints are apart and within link_range_m). Return a fresh Vector{Bool} in registration order.

source
SpaceAGORA.SimulationModel.InterLinkModels.interlink_force_on_spacecraft — Function
interlink_force_on_spacecraft(model::InterlinkModel, state, satellite; is_active=nothing, spacecraft=nothing, context=LinkContext())

The sum of the inertial forces (N) the selected links put on spacecraft satellite (its vector index), each from its link's link_force. Optional is_active flags mask links with an inactive endpoint.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.SchedulingPolicyModel — Type
SchedulingPolicyModel(policy; target_index=1, target_indices=nothing)

Create a scheduling policy. For :gve_sma and :gve_eccentricity, target_index selects one target and target_index=nothing scores both link endpoints. For :gve_sma, target_indices optionally selects a set of targets and takes precedence over target_index; all selected indices must exist in the simulation state.

target_idx and target_idxs, the old names of target_index and target_indices, still work as keywords and properties with a deprecation warning until SpaceAGORA 1.0.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.score_candidates! — Function

Score available links using a SchedulingPolicyModel, the current spacecraft state and the gravitational parameter, from each link's link_force (or a caller's candidate_force(target, partner, link)).

source
SpaceAGORA.SimulationModel.SchedulingPolicies.select_interlinks! — Function
select_interlinks!(model::InterlinkModel, policy::SchedulingPolicyModel)

Activate a maximum-total-score matching of available, positive-score links, with at most one link per terminal. Topology belongs to model.graph; policy.matching contains raw per-edge score values and reusable solver scratch arrays. Pass the same policy used by score_candidates!; selection uses its stored scores, not its scoring objective. A fresh workspace starts with zero scores. Appending links preserves existing scores and initializes new scores to zero when the workspace is refreshed. Switching graphs or discarding the workspace resets scores; rescore before selecting again. Use separate policies for independent scheduling runs. Deep-copy the model and policy together to preserve their workspace binding. Edge order is sorted locally on each selection, not stored in either structure. Registered topology and iterative DFS identify tree components, solved with linear-time dynamic programming. Cyclic components use NetworkX's weighted Blossom algorithm through PythonCall, with O(N^3) arithmetic operations for N cyclic endpoints. Both solvers use exact BigInt weights scaled from Float64 scores; no floating-point score sums are compared. Ties are deterministic for a given backend version, but tree ties may choose a different optimum than Blossom alone. Register topology through register_allowed_link!. For manual scores, refresh with matching_workspace!(model, policy) before editing its score vector. Graph availability and workspace scores are reread on every call. Tree components work without Python. Cyclic components require the optional PythonCall package loaded with using PythonCall, and NetworkX installed in the Python environment used by PythonCall. Core loading does not install either backend.

source
SpaceAGORA.SimulationModel.SchedulingPolicies.schedule_interlinks! — Function

Refresh link availability, score candidates, and select the maximum-total-score terminal matching.

ConstellationInterLinkModel

Deprecated, use InterlinkModel: the same type under its old name, which will be removed in SpaceAGORA 1.0. The name is an alias and cannot warn on its own: ConstellationInterLinkModel(; forbidden_pairs) runs silently. Its constellation_link_type keyword and property warn: each registered link has its own kind.

InterLinkParameters
