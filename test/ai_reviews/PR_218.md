# AI Review Artifact — PR #218

## Scope
`SpacecraftModel` can declare its own guidance, navigation and control effectors. They are bound to the spacecraft's run index through a new `bind_spacecraft` extension point and flattened into the configuration-level GNC tuples at the start of `run_simulation`. The engine, RHS and callbacks are unchanged.

## Changed Files
- src/vehicle/spacecraft/model.jl — `guidance`/`navigation`/`control` fields on `SpacecraftModel`. An 11-argument positional constructor fills them with empty models, and the keyword constructor accepts them. The GNC model structs move above `SpacecraftModel` so the field types resolve.
- src/gnc/interfaces/simulation_lifecycle.jl — `bind_spacecraft(effector, sat_idx)` with a throwing fallback that names chaser/target coupling or the absence of an index, plus `_shallow_copy`.
- src/gnc/control/control_hooks.jl — binding methods for `MagneticMomentumManagerModel`, `RobotArmControlEffector`, `ApolloDescentControlModel`.
- src/gnc/guidance/guidance_hooks.jl — binding method for `ApolloDescentGuidanceModel`.
- src/simulation/engine/execution.jl — `_flatten_spacecraft_gnc`, called first in `run_simulation`, and the `isolate_state=false` docstring caveat.
- src/simulation/campaigns/constellation_ensemble.jl — docstring: per-spacecraft GNC needs no flag; configuration-level indices are not remapped.
- src/SpaceAGORA.jl — root export of `bind_spacecraft`.

## Findings
- P2 (reported, not changed): `run_constellation_ensemble` with `allow_gnc_effectors=true` passes configuration-level effectors to every member unchanged, so indexed effectors are not remapped. Measured on a 5-satellite ensemble: `sat_idx=3` never fires in any member (differences of about 1e-5 m, solver noise), and `sat_idx=1` acts on every member (differences around 2.3 km). This is existing behavior and is now documented; per-spacecraft declaration is the way to get per-member GNC.
- P3 (fixed during review): the built-in binding methods were first tested only through a custom test effector. Tests now build real instances of all four binding types and check the new index, that the original is unchanged, identity when already bound, and carried-over fields and shared state.
- P3 (documented): with `isolate_state=false` and per-spacecraft GNC, the configuration that runs is a flattened copy, so bound effector copies and stripped spacecraft copies are not the caller's objects.
- P3: flattening returns `args` itself when no spacecraft declares GNC, so default runs are unchanged. The flattened tuples are concrete; the test asserts the tuple type.
- P3 (out of scope, noted): `templates/control_hook_template.jl` defines `calcControlMassFlowRate(model, u::AbstractVector, p, ...)`, which is ambiguous with the built-in default typed on `p::ODEParams`.

## Residual Risk
Low to moderate. Default runs take an early return and are unchanged. The main exposure is code that copies `SpacecraftModel` by field position with 11 fields; it would now need 14. No such code was found in `src/`, and the integration suites, which build spacecraft through many paths, pass.
