## Findings

No P1 or P2 findings. Points a reviewer should check:

- Low, by design: faults act only on mounted actuators; an effector in
  `:ideal` actuation is not affected.
- Low, by design: a failed hinge holds its angle rather than driving to angle
  zero, its level; for every other kind `:failed` is level zero, which for a
  user-defined kind whose range excludes zero means its lower limit after
  saturation.
- Low: a `:degraded` fault scales the actuator's limits from
  `actuator_limits`; a kind with asymmetric limits keeps their ratio.
- Low: the switching callback's discontinuity declaration cannot be told
  apart by a run (removing it passes the tests), because the solver
  re-evaluates after other callbacks in the same steps; removing the solver
  stops at the fault times does fail the exact-timing test.
- Low: a stuck fault captures the command of the first `:mounted` effector
  that holds levels; with several such effectors, each applies the same
  held level.
- Fixed after the automated review of b5e0264f5 (5520b2105), one P1 and two P2
  findings:
  - Firing dynamics (P1): a thruster with firing dynamics delivers the average
    thrust its last control tick scheduled, so a fault that began between
    ticks acted only from the next tick (a failed jet kept firing for up to a
    control period). Faults on such a thruster now act on the thrust it
    delivers, and the tick schedules from the command, so they switch at
    their own times. Running the trigger again at the fault's start was not
    used: it advances the ramp state by a whole period.
  - Thruster-level columns and plumes (P2): they took the controller's raw
    levels. A `:mounted` effector on a spacecraft with faults now gives the
    mounted thrusters' fractions through the faults and the shedding; runs
    without faults keep the reported levels.
  - Power shedding after a switch (P2): the fault callback ran after the
    power budget's step-end update, so the step after a fault's start or end
    used the shedding tier of the old load. The fault callbacks now run
    first.
- Fixed before publishing (b5e0264f5): each checkpoint segment initializes
  the callbacks again, and the fault callback reset every fault there, so a
  stuck actuator captured a new level at each segment start (the same class
  of defect as the battery's flags in #327's review). The faults are now
  reset at the run's first initialization only; a `:stuck` fault without a
  value refuses `resume_from_checkpoint`. Found while writing its test: a
  checkpointed run appears to skip the control tick at each segment
  boundary (a periodic controller holds its previous command one period
  longer); the control callbacks are not part of this PR, and the point is
  raised separately.
