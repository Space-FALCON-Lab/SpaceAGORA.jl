# PR322 review: actuator environment requests, thruster firing dynamics, actuator level and power columns, and a mounted-actuator example

## Scope

Review of the SpaceAGORA `actuator-gaps` branch against its base,
`actuator-kinds` (PR #319). The PR closes the gaps the PI asked to fix on
2026-10-15 after the actuator-layer plan: environment requests for actuator
kinds, firing dynamics for mounted thrusters, result columns for every
mounted actuator's applied level and the actuators' power, and a
mounted-actuator example. Two commits: the engine work with its tests, then
the example and the docs.

Authorship disclosure: this record was drafted by the author of the PR. The
plan assigns behaviour PRs of the actuator layer an independent reviewer (the
PI, or the second reviewer when available); this record does not replace that
review.

## Findings

No P1 or P2 findings. Points a reviewer should check:

- Low, by design: a row saved before the mounted effector's first control
  tick reports the levels the effector held then (zeros for the example's
  controller), as the `thruster_level` columns do.
- Low, pre-existing behaviour reused: the Schmitt trigger of the firing
  dynamics compares the requested on-time, in seconds, with `level_on` and
  `level_off`, as `thrust_calculation_schmitt_trigger!` always has; a request
  under the minimum on-time fires for the minimum on-time only above
  `level_on`. The new path calls the existing function unchanged.
- Low, by design: `mounted_power` evaluates each kind's consumption without
  the sampled environment, so a kind whose power depends on its environment
  reports its environment-free value; the docstring says so. Among the
  built-in kinds only the laser terminal draws power.
- Low, by design: the columns follow the first control effector in `:mounted`
  actuation that holds levels for the spacecraft, the same rule as the
  `thruster_level` columns; the wrench still sums every mounted effector.
- Low, cost: `mounted_requirements` walks the user-defined kinds at every
  evaluation of a mounted run (built-in kinds cost a count).

## P1 Assessment

No P1 findings. Effectors in the default `:ideal` actuation take the same code
path as before; mounted runs change only when a thruster sets
`firing_dynamics=true` or a kind asks for environment; the period keyword
defaults to the old value. The comparison below shows the Apollo fingerprint,
the momentum-manager example and the walkthrough unchanged against #319.
