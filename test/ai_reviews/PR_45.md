# AI Review — PR #45: earth_gmat epoch correction, speed-channel tolerance tables, surrogate fail-loud

## Scope

Single-commit follow-up to PR #42. Corrects the `earth_gmat` scenario epoch from a VEX-inherited timestamp to the epoch the GMAT truth file itself records in its `DefaultSC.A1ModJulian` column (2014-05-27T05:00:00 UTC), recalibrates the scenario's tolerances at the corrected epoch, adds explicit tolerance tables for the derived speed channels, and makes the Earth offline-surrogate fallback fail loudly. Quantitative before/after results are recorded in the lab notes (lab members only).

## Changed Files

- `src/analysis/verification/telemetry_verification/manifest_parsing.jl` — `_parse_tolerances` previously read only the scenario's `events` list, so an explicit `peri_speed`/`apo_speed` tolerance table in a manifest was silently ignored and the derived speed rows always inherited the base event's limits (the existing fallback in `_evaluate_thresholds`). Explicit `<event>_speed` tables are now parsed when present, via a small extracted helper (`_parse_event_tolerance`); limits for speed rows are in km/s. Absent tables preserve the inheritance behavior exactly; a malformed explicit table still errors loudly through the same `_require_*` validators.
- `test/telemetry_benchmark_manifest.toml` — `earth_gmat` epoch corrected to the truth file's recorded start (provenance comment inline); periapsis full-run tolerances tightened to match the corrected-epoch tracking; apoapsis nmae tightened within the existing envelope; explicit `peri_speed`/`apo_speed` tables added (km/s); `gram_offline_surrogate` `"auto"` → `"off"` (the shipped Earth surrogate is a frozen-epoch grid capped at 300 km that returns zero density above it — a missing native library must fail, not silently degrade); `assumption_id` bumped to `earth_gmat_gram_deterministic_v2`. VEX audited in the same pass: no change needed (epoch matches the ESA flight-dynamics elements source; epoch is the only physically meaningful atmosphere knob Venus-GRAM exposes).
- `test/coverage_parallel_telemetry_probes.jl` — regression testset for the speed-table parsing: explicit table honored, absent table falls back, malformed table throws.

## Review

- The parser change is additive and backward-compatible: manifests without `*_speed` tables parse to an identical tolerance map, and `_evaluate_thresholds`' fallback path is unchanged. The only scenario using the new tables is `earth_gmat`.
- The epoch value is auditable against the committed truth file (first `A1ModJulian` row, 26804.708739 → 2014-05-27T05:00:00 UTC); the previous value matches the VEX example timestamp, consistent with an inheritance mistake at scenario creation.
- Threshold direction is strictly tightening or neutral for every gate (periapsis, apoapsis nmae, speed channels vs their previously-inherited limits at the old epoch); no limit was loosened.
- Verified locally: full-profile telemetry study passes `--enforce=true` end to end for all three scenarios at the new thresholds; the new testset and the full probes file pass.
