## Findings

Resolved in `75d65ce96`: one P1 from the automated review of `0e8b9afad`.

- **P1, stop registration ran inside the possibly threaded tick.**
  `register_tstops!` was called in each spacecraft's tick. A control model declared
  thread-safe, in a constellation at the thread threshold, ticks on several threads.
  A contributor's `register_tstops!` would then add stops to the shared integrator
  concurrently. The ticks still run as before, threaded when allowed. The
  registrations now follow them, one spacecraft at a time on the callback's thread.
  The built-in path was never affected: the burn scheduler registers its stops in
  its own serial callbacks, and it never ticks periodically.

Author's notes for the reviewer (no open P1 or P2 known to the author):

- **Design deviation, low: no `requires_initial_derivative_reset`.** The EDG
  periodic callback's derivative-flag reset equals `PeriodicCallback`'s default
  initialization (`derivative_discontinuity!(integrator, initial_affect)` with
  `initial_affect = false`, DiffEqCallbacks 4.19.4). Only the clock origin is
  specific to EDG, so `gnc_clock_started!` covers it.
- **Design deviation, low: `gnc_callbacks` takes `period_s`.** The burn scheduler's
  `:mounted` tick needs its configured control rate.
- **Low, semantics:** every periodic control callback now passes an `initialize`
  closure. For models other than EDG it calls the no-op `gnc_clock_started!`, then
  the same flag reset as the default.
- **Low, scope:** the four declarations are read for control models only.
  Atmosphere-exit rescheduling stays internal; it calls the integrator-level
  scheduler.
- **Note:** the `isa` at the old length check is dropped, because the burn
  scheduler's own callback builder throws the same error.

Reviewer to verify:

- **Each built-in path is reached as before:**
  - the burn scheduler gets the same callbacks in the same order: schedule
    callback, burn edge, then the mounted tick in `:mounted` actuation;
  - its periodic `register_tstops!` path was unreachable before and still is;
  - the EDG clock origin is set at each solve's start.
- **The initialization order:** navigation, then guidance, then control. Navigation
  had no initializer before.
- **The sensor reset:** `initialize_sensor!` runs once per run, after
  `reset_sensors!`, with the first sample's truth and context. It does not run on
  later checkpoint segments.
- **No numeric change:** see the parity evidence.
