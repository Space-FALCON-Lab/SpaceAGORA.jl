# PR review: declare the GNC hooks, make them public and check model hooks before a run

## Scope

Review of PR 332 (SpaceAGORA branch `gnc-hook-declarations`, head
`994f5040e`) against main (`a946f6c36`). The PR declares the guidance, navigation and control tick hooks,
`calcReactionWheelTorque` and `getHeatRate` as generic functions with
docstrings, adds `AbstractNavigationModel`, exports six names, and adds a check
in `run_simulation`, before integration, that every guidance, navigation and
control effector, force/torque model and the density model has a method of
each hook the engine calls on it. No hook's signature or argument order
changes.

Authorship disclosure: this record was drafted by the author of the PR. It
does not replace an independent review.

## Findings

No P1 or P2 findings.

What the check does, for a reviewer to confirm: `_hook_method_may_apply(f,
argtypes)` is true when some method's signature intersects
`Tuple{typeof(f), argtypes...}`. The argument types are those every call site
guarantees: `AbstractVector` for the state (the full state at the GNC ticks in
`navigation_guidance_callbacks.jl` and `control_callbacks.jl`, one
spacecraft's view in `dynamics_rhs.jl`), `ODEParams`, `Float64` time and `Int`
index. Force/torque models reuse the engine's own `_wrench_method_available`
before falling back to `calcForceTorque`, so the check and the dispatch in
`_evaluate_dynamic_effector` agree. The control check skips
`calcControlForceTorque` exactly when `_accumulate_control_effectors_from_tuple!`
takes the mounted branch (`actuation_mode(e) === :mounted`). The density check
uses the seven-argument form, the only one the run's density paths
(`density_callbacks/runtime.jl`, `vacuum_predicted_gram.jl`,
`gram_track_cache/refresh.jl`, `aerodynamic_wrench_models.jl`) call.

Points a reviewer should check:
- Low, by design: the check can miss a method typed more narrowly than what
  the engine passes (for example `u::Vector{Float64}`), a model that opts into
  `link_wrench` but lacks `wrench` in a run without live-pose loads, and the
  components of a wrapping density model (`CombinedAtmosphereModel`,
  `PassKeyedExponentialAtmosphereModel`), which are not checked recursively.
  Each of these still fails during the run, as before. The intersection rule
  was chosen over `hasmethod` on abstract types because the latter refuses
  working built-in methods (for example `u::ComponentVector`); the mutation
  check shows that.
- Low, behaviour change: a configuration that ran only because a missing
  method was never reached (a tick after the mission end, a six-argument-only
  density model never sampled) is now refused. `SolarPanelAngleOfAttackControlModel`
  on its own is refused for want of `calcControlEffect!`; on main such a run
  fails at the first control tick.
- Low, documentation: the `calcControlEffect!` docstring points to
  `SimulationModel.SimulationCallbacks.control_model_threadsafe`, the existing
  but unexported opt-in for threaded control ticks. The root docstring of
  `calcControlForceTorque` is still the `BaseThrusterModel` method's text;
  both belong to the documentation pass that follows.
- Low, not checked: a `:mounted` effector without an `actuator_levels` method
  drives nothing; the default returns `nothing`, so no `MethodError` arises
  and the check does not flag it.

## P1 Assessment

No P1 findings. No hook signature, dispatch target or numerical path changes:
the new code runs once per `run_simulation` call before integration, reads
method tables only, and either returns or throws. The only removed method is
the `calcNavigationEffect!` catch-all that threw a `MethodError`; calling the
function for a type without a method still throws a `MethodError`.

Unresolved P1: No

  found no model placed in a run without its hooks.
- GRAMSuite was not installed locally, so GRAM-backed density models were
  checked only as "refused without the extension"; with it loaded, the
  extension's seven-argument methods make them pass.
- Follow-ups outside this PR: the `calcControlForceTorque` root docstring and
  the `docs/src/extensibility.md` guide (documentation pass); whether a
  `:mounted` effector without `actuator_levels` should be flagged.
