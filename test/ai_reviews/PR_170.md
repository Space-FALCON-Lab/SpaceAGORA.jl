# PR 170: coordinated LinearSolve 5 migration

## Scope

Resolve the actual LinearSolve 5.18.1 dependency graph and adapt SpaceAGORA's
existing solver interfaces. The previous Project change still instantiated
LinearSolve 3 from the committed Manifest. The migration requires OrdinaryDiffEq
7, DiffEqBase 7, SciMLBase 3 and RecursiveArrayTools 4. Compatible
SatelliteToolbox packages move to their Base-2 generation. Unrelated root
packages retain their baseline versions.

The development tools and EDL study environments are resolved against the same
shared package versions. The study's independent NetCDF dependency versions are
preserved. Current-repository CI checkout uses the job token without persisting
credentials, as in PR166; native GRAM retrieval credentials and exact pins are
unchanged.

## Changed Files

- `src/simulation/callbacks/event_callbacks.jl`: adapt the signed simultaneous-event mask to the existing directional per-spacecraft effects, including all events at one root, and avoid invalidating derivative caches when every triggered direction is ignored.
- `src/simulation/callbacks/state_anchor_callbacks.jl`: use the renamed derivative-discontinuity notification after a state anchor.
- `src/simulation/engine/setup.jl`: explicitly import the existing IMEX, DP8 and symplectic algorithms from their owning packages, and the solver interface modules.
- `src/simulation/engine/execution.jl`: preserve full specialization on the explicit sparse ODEFunction wrappers, whose library default changed. Bare ODEProblem construction remains unchanged.
- `src/simulation/engine/solver_policy.jl`: adapt componentwise tolerances only at linear-solver initialization; keep the ODE tolerance arrays and the existing dense/default versus sparse/KLU selection; bound inference at the solver-selection call without changing integrator specialization.
- `src/dynamics/coupled/perturbations.jl`: use the magnetic library's Val-based warning switch, preserving the existing once-per-model warning policy.

Project/Manifest files, the two renamed SGP4 constants in development tools,
regression tests and workflow checkout configuration complete the migration.

## Findings

Implementation self-review, not an independent Claude review. The original
migration exposed a reproducible Rodas5P initialization failure: OrdinaryDiffEq
passes componentwise relative tolerances into LinearSolve 5, which attempts a
scalar conversion. An owned adapter now delegates initialization to the same
library backend with the minimum component tolerance, returning its ordinary
cache. The integrator's per-component relative and absolute tolerances are not
changed. Scalar tolerances pass through unchanged. No methods on entirely
foreign argument types are overridden.

The callback mask sign was verified against the installed DiffEqBase 7.21.2
implementation and real root-finding runs: positive is upcrossing, negative is
downcrossing. The compatibility floor records that contract. The new library
locates both directions before the adapter filters effects. Ignored crossings
therefore can still add root-location/save points compared with the old API;
the adapter explicitly clears the derivative-discontinuity flag when it ran
no effect. Cross-version internal timestep or row-count identity is not a
contract of this major migration.

## Residual Risk

This is a coordinated major solver-stack upgrade. Small upstream atmosphere
changes are measured and disclosed, not hidden by a weakened assertion. No
existing numerical tolerance or physical reference is changed. The first candidate spent more than 25 minutes compiling its first simulation.
A runtime-only experiment isolated inference through the solver-policy call;
the final source uses a no-inline, non-specializing dispatch boundary there.
At normal optimization the final four-case run took about 51 seconds inside
the four simulation calls. Actual library integrators still specialize on their
problem and algorithm. This measures startup for this fixture, not throughput.
No optimization flag was changed in production or CI. No performance improvement,
native GRAM campaign equivalence or full-suite pass is claimed here.
