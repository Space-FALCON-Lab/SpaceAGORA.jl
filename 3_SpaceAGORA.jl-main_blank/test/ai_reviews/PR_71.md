# AI Review — PR #71: Closed-loop magnetic momentum manager (discrete ZOH control effector)

## Scope

Adds `MagneticMomentumManagerModel`, a stateful zero-order-hold control
effector on the existing `ControlModel` discrete-rate (PeriodicCallback)
path. At each rate tick it advances an internal wheel-momentum accumulator
from the re-evaluated attitude-control command (`dH_w/dt = -tau_cmd`) and
refreshes a held rod torque from the cross-product unloading law
`m = mu (H_w x B)/|B|^2` with a dipole-capability cap. Purely additive; no
engine changes; decoupled from controllers/field models via two callables.

## Changed Files

- `src/gnc/control/momentum_manager.jl` (new): model + `calcControlEffect!`
  + `calcControlForceTorque`.
- `src/gnc/control/control_hooks.jl`: include + export registration only.
- `test/probes/coverage_parallel_telemetry_probes.jl`: 16-assert testset.
- `examples/Earth_Momentum_Manager_Test.jl` (new): full-solve regression,
  runs under the CI examples smoke.

## Findings

- The accumulator MUST live on the discrete callback path: continuous-effector
  wrenches cannot hold integration state under adaptive stepping (documented
  engine constraint). The example pins step-size invariance of the
  accumulator at machine precision (~1e-15 N m s loose-vs-tight tolerances).
- Found while testing, now documented in the model docstring:
  `run_simulation`'s default `isolate_state=true` deep-copies the
  configuration, so the simulation advances a COPY of any stateful control
  effector; reading held state back requires `isolate_state=false`. This
  equally affects post-run state reads of the existing RPO MPC and robot-arm
  held-actuation models (their in-sim behavior is unaffected).
- Defining `calcControlMassFlowRate` with untyped `u`/`p` arguments is
  method-ambiguous against the `AbstractControlEffectorModel` fallback;
  the model defines none (rods consume no propellant; fallback returns 0.0).

## P1 Assessment

No P1. The change is additive: with no `MagneticMomentumManagerModel`
configured, no new code executes (include/export registration only), so
existing scenarios are structurally bit-identical. The new discrete callback
follows the exact pattern of the shipped RPO MPC/robot-arm effectors.

## Tests Added/Updated

- Probe testset "Magnetic momentum manager (discrete ZOH control effector)"
  (16 asserts): accumulator init/advance semantics, ZOH hold between ticks,
  dipole cap engagement, unloading direction (dH·H < 0 on the perp-B
  component), field-parallel unreachability (tau = 0 for H parallel to B),
  body-frame consistency under attitude rotation, off-spacecraft and
  degenerate-field guards.
- `examples/Earth_Momentum_Manager_Test.jl`: >1-orbit full solve with the
  LVLH cascade holding an off-nadir setpoint; asserts managed momentum well
  below the mu=0 accounting run (order-10x separation), and the solver
  invariance pin above. Runs in the CI examples smoke/regression jobs.

## Residual Risk

- The `solver_cache` integrator-reuse path re-inits with
  `reinit_callbacks=false`, which resets tstops without re-running callback
  initialize; time-based callbacks (this one included) are not supported
  under solver-cache reuse. Documented; the standard `run_simulation` path
  is unaffected.
- First tick fires at t = rate (PeriodicCallback has no initial_affect), so
  the held torque is zero over the first period — negligible by
  construction and covered by the boundedness regression.
- Single-spacecraft state per model instance (`sat_idx`); multi-sat use
  requires one instance per spacecraft, matching the existing held-state
  effector convention.
