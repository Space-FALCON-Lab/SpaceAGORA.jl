# Review record: PR 460: RPO comparison report data apart from the Plotly figures

## Scope

C4-4a of the post-0.5.0 cleanup. It separates the RPO comparison reports' data, CSV and metrics preparation from their PlotlyJS figures within `RPOComparisonReports`, without changing behaviour. The reviewed head is `0e1c2eed1ee182c65eecab39a4ec42e53c074b28`, one commit on main `d3288ce8d594a6e7ab5325706d1edf498ff72e7f`, which contains #448.

The historical report functions keep their GuidanceHooks identities and their sole methods in `RPOComparisonReports`. Unchanged:
- PlotlyJS, a direct dependency that loads eagerly;
- the qualified `GuidanceHooks.PlotlyJS` binding;
- `rpo_path_plot` and `rpo_tracking_plot`;
- public exports, dependencies, manifests and provider pins.

Independent review: the coordinator reviewed PR 460 at `0e1c2eed1` under Giusy's
delegation on 2026-10-21. It was a read-only review of the diff, without rerunning
the tests.

- **Line comparison.** Comparing the old file's non-comment lines with the two new
  files', as multisets, leaves 74 old and 123 new lines. Every styling line is
  unchanged: trace kinds, colours, widths, opacities, titles, layout and axis
  domains. The lines that differ are the data sources (prepared series, paths,

- **Preparation.** `_rpo_comparison_cost_series` keeps the same finiteness filter

## Findings

No findings.

The builders consume the prepared data in the original evaluation order:
- `_rpo_comparison_case_path` records whether a plan has a `raw_path` property and keeps the value unconverted. A raw path is therefore converted only where it is drawn, as before, and a plan whose `raw_path` is `nothing` still fails the same way.
- The cost plot still checks the planner before it prepares any series.

The writer's return value keeps its fields, their order and their value types, and it writes the same files in the same order.

## Residual Risk

- The fingerprint uses a synthetic fixture; it does not use real HYPR comparison batches. The batch example and `rpo_port_tests.jl` exercise real batches and pass, but their outputs were not compared byte for byte with main.
- Plotly's HTML embeds random div ids, so HTML equality is checked after normalizing them.
- The figure builders still live in core and PlotlyJS still loads with SpaceAGORA. Moving the figures file into an extension, with errors that name `using PlotlyJS` when it is not loaded, is C4-4c (0.6.0). C4-4b (0.5.1) adds the one-time notice first.
