GNC Runtime API

This page documents the supported public interface available from SpaceAGORA.

GNC runtime

SpaceAGORA.GNCRuntime.tick_schedule — Function
tick_schedule(model) -> Symbol

How the engine runs control model.

  • :periodic, the default: a periodic callback at the model's control rate calls its tick (update_control!) for every spacecraft.
  • :event_driven: no periodic tick. The model brings its own callbacks (gnc_callbacks). BaseThrusterModel, the burn scheduler, is event-driven.
source
SpaceAGORA.GNCRuntime.gnc_callbacks — Function
gnc_callbacks(model, num_sats, args, period_s) -> Tuple

The callbacks an :event_driven control model adds to a run of num_sats spacecraft with configuration args. period_s is the model's configured control rate, for a model that also ticks periodically. The engine reads it only for :event_driven models. Default: none.

source
SpaceAGORA.GNCRuntime.register_tstops! — Function
register_tstops!(integrator, model, spacecraft_index) -> nothing

Called after each periodic tick of control model, once for each spacecraft its spacecraft_scope names, in ascending order (SpaceAGORA 0.5.1 and earlier called it for every spacecraft index). Use it to add the solver stops that the new command needs; the burn scheduler adds the ends of its burn window. The ticks of several spacecraft may run on different threads, but these calls do not: they run one spacecraft at a time, after all of that tick's spacecraft have ticked, because the stop list belongs to the integrator they share. Default: none.

source
SpaceAGORA.GNCRuntime.gnc_clock_started! — Function
gnc_clock_started!(model, period_s, origin_s) -> nothing

Called with the period of control model's periodic callback and the time its clock starts from (s into the run): when the run starts, after the links are initialized and before the models' own initializers, and again when the callback starts, at every solve's start, so a checkpointed run calls it again at each segment. The clock starts from the solve's start, or from the run's start (0) in a checkpointed or resumed run, whose ticks keep one grid across segments. A model that keeps a clock of its own ticks records it here. Default: nothing.

source
SpaceAGORA.GNCRuntime.gnc_period_s — Function
gnc_period_s(model) -> Union{Nothing, Float64}

The tick period (s) that control model's law assumes, such as the step its controller was discretized with. Before the run the engine compares it with the rate of the model's periodic callback and refuses the run when they differ. Default: nothing, no declared period, as for a law that measures the elapsed time itself.

source
SpaceAGORA.GNCRuntime.Produces — Type
Produces(link)

Wraps a shared object that a model writes for others to read, in gnc_links.

source
SpaceAGORA.GNCRuntime.Consumes — Type
Consumes(link)

Wraps a shared object that a model reads, in gnc_links. Before a periodic control model's tick, the engine calls before_reference_control! for each model that produces a link it consumes, unless the tick releases or skips every spacecraft.

source
SpaceAGORA.GNCRuntime.gnc_links — Function
gnc_links(model) -> Tuple

The links a guidance, navigation or control model takes part in, as Produces and Consumes wrappers around the shared objects. Default: none.

source
SpaceAGORA.GNCRuntime.link_cardinality — Function
link_cardinality(link) -> NamedTuple

How many models may produce and consume link, as ranges: (producers = 0:1, consumers = 0:1). Before the run the engine refuses a link whose counts fall outside them. Default: any number of each.

source
SpaceAGORA.GNCRuntime.check_link — Function
check_link(link, producers, consumers, args) -> nothing

Before the run, once per link: check that the models sharing link agree, such as matching settings. Throw an ArgumentError to refuse the run. producers and consumers are the configured models in configuration order. Default: nothing.

source
SpaceAGORA.GNCRuntime.link_initialize! — Function
link_initialize!(link, producers, consumers, u, p, t) -> nothing

At the start of the run, once per link and before any model's own initializer: reset the run state the link owns. Default: nothing.

source
SpaceAGORA.GNCRuntime.SpacecraftScope — Type
SpacecraftScope

The spacecraft a guidance, navigation or control model acts on, as its spacecraft_scope declares: AllSpacecraft(), BoundSpacecraft(indices) or CoupledSpacecraft(primary, partners).

source
SpaceAGORA.GNCRuntime.AllSpacecraft — Type
AllSpacecraft()

Scope of a model ticked for every spacecraft of the run, the default. Such a model keeps one slot of run state per spacecraft.

source
SpaceAGORA.GNCRuntime.BoundSpacecraft — Type
BoundSpacecraft(indices)

Scope of a model that acts only on the spacecraft at the run positions in the tuple indices: the engine ticks it for those spacecraft only.

source
SpaceAGORA.GNCRuntime.CoupledSpacecraft — Type
CoupledSpacecraft(primary, partners)

Scope of a model that couples several spacecraft: the engine ticks it for primary only, and the tick also reads the spacecraft at the run positions in the tuple partners, as the RPO controller ticks for the chaser and reads the target.

source
SpaceAGORA.GNCRuntime.spacecraft_scope — Function
spacecraft_scope(model) -> SpacecraftScope

The spacecraft guidance, navigation or control model acts on. The engine ticks the model only for the spacecraft its scope names (every one, the BoundSpacecraft indices, or the CoupledSpacecraft primary), reading the scope at each tick. Before the run it refuses a scope that names a run position the run does not have. The output hooks are still called for every spacecraft, so they keep their own index checks. A dynamic effector's scope, read once when the run starts, decides which spacecraft it acts on (see scoped); a dynamic effector also takes a SpacecraftSelection. Default: AllSpacecraft().

source
SpaceAGORA.GNCRuntime.skip_inactive — Function
skip_inactive(model) -> Bool

Whether the engine stops ticking model for a spacecraft that is no longer active (after an impact, a touchdown or another event that deactivates it). For a model that returns true, while spacecraft spacecraft_index is inactive, each tick time calls release_command!(model, t, spacecraft_index) instead of the tick. For a CoupledSpacecraft model the primary decides; a model that must react to an inactive partner checks p.is_active itself. Default: true (since SpaceAGORA 0.4.0; false before). Return false for a model that must keep ticking, as for an active spacecraft.

source
SpaceAGORA.GNCRuntime.release_command! — Function
release_command!(model, t, spacecraft_index) -> nothing

Called at tick time t (s into the run) in place of the tick of a model whose skip_inactive is true, while spacecraft spacecraft_index is inactive: set the held command to the model's off command, such as zero thrust. Default: nothing.

source
SpaceAGORA.GNCRuntime.held_command — Function
held_command(model, spacecraft_index) -> Any

The command control model holds for spacecraft spacecraft_index between its ticks, which its output hooks read, as an immutable value or named tuple; the model's own state is not shared with it. In :mounted actuation the levels the mounted actuators apply, derived from it, are actuator_levels(model, spacecraft_index). Default: nothing, no held command, as for a spacecraft the model does not act on.

source
SpaceAGORA.GNCRuntime.held_command_time — Function
held_command_time(model, spacecraft_index) -> Float64

The time (s into the run) of the tick that produced held_command(model, spacecraft_index). Default: NaN, before the first tick or for a model that does not record it.

source
SpaceAGORA.SimulationLifecycle.preflight_guidance — Function
preflight_guidance(model, args; isolate_state) -> nothing

Before a run starts, for each guidance model of the configuration args: check that the configuration can run it and throw an ArgumentError naming the problem otherwise. isolate_state is the run's setting. The check reads the caller's objects, before the run copies them, so it must change nothing. Default: no check.

source
SpaceAGORA.SimulationLifecycle.preflight_control — Function
preflight_control(model, args; isolate_state) -> nothing

As preflight_guidance, for each control model. Default: no check.

source
SpaceAGORA.SimulationLifecycle.initialize_navigation! — Function
initialize_navigation!(model, u, p, t) -> nothing

At the start of each run, for each navigation model: reset its run state, so that two runs of one configuration with isolate_state=false start equal. u is the initial state, p the run's parameters and t the start time (s into the run). The engine calls the links' link_initialize! first, then this hook for every navigation model, then initialize_guidance! and initialize_control!, so each stage may read what the previous one set up. What a run leaves in the model stays readable after the run: the reset happens when the next run starts. Run state of a custom sensor is reset in its initialize_sensor!. Default: nothing.

source
SpaceAGORA.SimulationLifecycle.initialize_guidance! — Function
initialize_guidance!(model, u, p, t) -> nothing

As initialize_navigation!, for each guidance model, after the navigation models: reset its run state, so that two runs of one configuration with isolate_state=false start equal. Every built-in guidance model's run state is reset when a run starts, here or by the link it shares (link_initialize!), and a value a user may configure is kept when the user changed it, as for initialize_control!. Default: nothing.

source
SpaceAGORA.SimulationLifecycle.initialize_control! — Function
initialize_control!(model, u, p, t) -> nothing

As initialize_navigation!, for each control model, after the guidance models: reset its run state, so that two runs of one configuration with isolate_state=false start equal. Every built-in control model's run state is reset when a run starts, here or by the link it shares. A value a user may configure that the run also writes, such as a held command, returns to its value at the previous run's start while it still equals the model's last write in that run; a value the user changed since is kept, and later runs start from it. Default: nothing.

source
SpaceAGORA.SimulationLifecycle.checkpoint_state — Function
checkpoint_state(model) -> data

The run state model keeps itself, for a checkpoint file: plain data (numbers, arrays, named tuples, random streams), or nothing when it keeps none. The engine calls it at every checkpoint for each guidance, navigation and control model and each mounted sensor, and stores a copy of the data with the engine's own run state; a resumed run hands it to restore_checkpoint_state!. Return nothing for the whole run or data for the whole run. A model that returns data implements restore_checkpoint_state!: a checkpointed run refuses at setup a model that has the first and not the second. Default: nothing.

source
SpaceAGORA.SimulationLifecycle.restore_checkpoint_state! — Function
restore_checkpoint_state!(model, data) -> nothing

On a run resumed from a checkpoint file, put back the run state data that checkpoint_state(model) returned when the file was written (read from the file, so the model may keep it). For a guidance, navigation or control model the engine calls it after the run-start initializers, so the restored state replaces their reset; for a sensor before its sampling resumes (a resumed run does not call initialize_sensor!). The resumed run refuses a checkpoint whose models differ in kind or position from its own, or that holds no run state for a model that keeps some. No default: a model whose checkpoint_state returns data implements it.

source
SpaceAGORA.SimulationLifecycle.requires_atmosphere_events — Function
requires_atmosphere_events(model) -> Bool

Whether guidance or control model needs atmosphere_transition! calls. When any model of the run declares true, the engine tracks atmosphere entries and exits even where its tolerances would not need them. Default: false.

source
SpaceAGORA.SimulationLifecycle.atmosphere_transition! — Function
atmosphere_transition!(model, u, p, t, spacecraft_index, inside) -> nothing

Called for each guidance and control model when the spacecraft at spacecraft_index (its position in the run, from 1) enters (inside is true) or leaves the atmosphere at time t (s into the run), after the engine has reconciled every spacecraft's crossing at that time. u is the state and p the run's parameters. The model's run state is its own. Default: nothing.

source
SpaceAGORA.SimulationLifecycle.before_reference_control! — Function
before_reference_control!(producer, consumer, u, p, t) -> nothing

Before each periodic tick of control model consumer, once per tick and on the callback's thread, for each model that produces a link consumer consumes (gnc_links): let producer bring what it writes up to date for time t (s into the run), as the RPO planner checks its reference. u is the state and p the run's parameters. Not called at a tick that runs consumer for no spacecraft, as when every spacecraft in its scope is inactive and it declares skip_inactive.

The producers are called link by link, in the order the run's models first declare those links, and within a link in configuration order. A producer of several of consumer's links is called once, for the first of them. This is not configuration order: with A producing links X and Y, B producing Y and C producing X, a consumer of X and Y gets A, C, B. A producer must not rely on another having been called first. Default: nothing.
