# AI Review Artifact — PR #217

## Scope
Opt-in `run_simulation(args; return_results=true)` returns a new exported `SimulationResults`: the results table in memory, the configuration that ran, the files written, and optionally the solution. The default path is unchanged.

## Changed Files
- src/simulation/engine/results.jl — new `SimulationResults{C,S}` struct with docstring.
- src/simulation/engine/simulation_engine.jl — includes results.jl before execution.jl and exports the struct.
- src/simulation/engine/execution.jl — the `return_results` keyword. It is rejected together with `return_solver_metadata` and forwarded through the parallel-flag re-entry. `_save_simulation_results_if_enabled!` gains `return_table`: the same `_build_results_dataframe` call builds the table, and files are written only when `simulation_settings.results` is set. The `files` list is assembled from paths this run wrote.
- src/simulation/callbacks/density_callbacks/assembly.jl — `get_callbacks(...; record_saved_values=false)` attaches the data-saving callback when results are on or the table is requested.
- src/SpaceAGORA.jl — root export and docstring of `SimulationResults`.

## Findings
- P2 (found and fixed during review): `files` first listed the `.feather` and `.manifest.toml` paths whenever they existed on disk. A `results=false` run in a directory holding an earlier run's bundle therefore reported files it never wrote. The bundle paths are now added only when this run wrote a bundle (`results && SPACEAGORA_SAVE_BUNDLE`), and a test reproduces the earlier-run case.
- P3: with `results=false` the saved-values buffer was never filled, because the saving callback was attached only when results were on. The new `record_saved_values` keyword attaches it on request and is off by default, so default runs build the same callback set.
- P3: the checkpointed solve copies from the same buffer per segment. It was reviewed and covered by a three-segment test.
- P3: `return_results` with `return_solver_metadata` is rejected rather than merged, since the two return shapes conflict.

- P2 (found and fixed during final integration review): resuming an already completed checkpoint listed the existing checkpoint files despite writing none. A focused runtime probe reproduced this with unchanged file bytes and modification times. The engine now records whether this call successfully wrote a checkpoint before adding those paths. A regression covers the completed-resume case and confirms the old files remain unchanged.
- P3: clarified that `results=false` suppresses result files; explicitly enabled checkpoint output is independent.
