# AI Review — PR 57: digital-twin productization 2/2 — IC offsets, differential-correction fit, illumination truth mask

## Scope
Second of the two twin-productization PRs (see PR #56). Three coupled capabilities that complete the public machinery behind the CYGNSS campaign's 46 m nightside result: (1) manifest-level Cartesian IC offset knobs, (2) a public differential-correction fit of the initial state built on those knobs, and (3) an illumination screen for single-frequency GNSS truth.

## Findings
- P2 (documented, by design): fitted IC components trade against un-modeled forces (an SMA offset absorbs along-track drag drift — the campaign's central degeneracy). The module header directs users to interpret the fitted IC jointly with a decay-consistent drag scale (PR #56's utility). The fit is a tool, not a truth oracle.
- P3 (accepted): the solar direction is the low-precision analytic formula (~0.01°), ample for an illumination screen; validated in the probes against the campaign's ephemeris values for the CYGNSS epoch (RA 75.6°, dec 22.8°).
- P3 (accepted): the mask drops screened samples from comparison, calibration, and fitting alike (single semantics). The telemetry's first-row IC and the time rebase are computed before masking, so the scenario epoch does not shift when early samples are screened.
- P3 (accepted): `fit_initial_state` runs 7–8 full verification runs sequentially; for the CYGNSS-class quick profile that is minutes. Parallelizing the perturbation runs is a possible follow-up.
- No P1 findings.

## Codex review findings (addressed in-branch)

- **P1 — masked runs truncated the propagation** (`telemetry_loading.jl`/`runner.jl`): with a `truth_mask` screening out the earliest samples, `time_s[1] > 0` but the mission duration was computed as `time_s[end] − time_s[1]` while the IC stays anchored at t=0 — late retained samples were silently clamped to the final propagated state. Fixed: duration now runs through `time_s[end]` (identical behavior for unmasked scenarios, whose `time_s[1] == 0`). Regression probe: a nightside-masked synthetic scenario whose first samples are dropped must compare tightly at the latest retained timestamps.
- **P1 — Keplerian IC shifted by the mask** (`telemetry_loading.jl`): the returned first-row orbital elements came from the first *retained* sample instead of the original epoch. Fixed: pre-mask first-row elements are captured (exactly as the Cartesian IC already read `perm[1]`). Regression probe: a masked load of per-row-varying element columns returns the row-1 values.
- **P2 — `tabulated_time_file` was cwd-relative** (`manifest_parsing.jl`, from #56): now normalized with `_resolve_repo_path` like every other manifest file field (`tabulated_flight_file` normalized too, same reasoning; absolute paths unaffected).
- **P2 — `flight_density_table` window guard ignored drifting-amplitude columns** (`decay_diagnostics.jl`, from #56): `drifting_amplitudes` is now an explicit keyword and the minimum-sample guard counts its extra columns, so undersampled windows are skipped as documented instead of throwing.
- **P2 — Mars matrix constant vs locked references** (`test/gmat_scenario_matrix.jl`, from #55): the locked reference generator (`gmat_matrix_parity_locked.py`) built the Mars trajectories with Mars-50c; the constant now points at `Mars50c.csv` (GMM2B.csv remains available as an asset). The two merged-PR P2s ride along here because their files overlap this branch's diff.
