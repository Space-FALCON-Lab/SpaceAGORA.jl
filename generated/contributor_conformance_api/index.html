Contributor Conformance API

This page documents the supported public interface available from SpaceAGORA.

Contributor conformance

SpaceAGORA.Conformance — Module
SpaceAGORA.Conformance

Checks that code built around SpaceAGORA (a force/torque model, a service facade) behaves as the engine's contracts require. Each check_* function runs the engine's own machinery (its pre-run hook check and run_simulation) on the object and returns a ConformanceReport; it needs no test framework. With the Test standard library loaded, each test_* function records the same checks as tests:

using Test, SpaceAGORA
using SpaceAGORA.Conformance

@testset "MyModels" begin
    test_force_torque_model(MyDisturbanceTorque(gain=1e-6))
end

A conformance pass certifies interface behaviour only. Scientific validation of a model, its parameters and the claims made from it stay with its author.

source
SpaceAGORA.Conformance.ConformanceCheck — Type
ConformanceCheck(id, status, since, detail)

One check of a ConformanceReport.

  • id::Symbol: the check, for example :repeatable_run.
  • status::Symbol: :pass, :fail, :skip (the check could not apply, detail says why) or :advisory_fail (a check added in the current minor release that did not pass; it becomes required in the next one).
  • since::VersionNumber: the SpaceAGORA release that added the check.
  • detail::String: what differed, or why the check was skipped; empty on a pass.

A passing check certifies interface behaviour only. Scientific validation of the model stays with its author.

source
SpaceAGORA.Conformance.ConformanceReport — Type
ConformanceReport(target, kind, checks)

The result of one check_* call: target names the object checked, kind the contract it was checked against (for example :force_torque_model), and checks holds one ConformanceCheck per check id, in a fixed order. passed tells whether every required check passed; show prints one line per check.

source
SpaceAGORA.Conformance.passed — Function
passed(report::ConformanceReport) -> Bool

true when no check of report has status :fail. Skipped checks and advisory failures do not fail a report.

source
passed(check::ConformanceCheck) -> Bool

true unless the check's status is :fail.

source
SpaceAGORA.Conformance.ConformanceFixture — Type
ConformanceFixture

A configuration the checks run, with the concrete argument types its run passes to the hooks. Build it with conformance_fixture.

  • configuration: the SimulationConfiguration every check runs. Checks run it with isolate_state=true, except deepcopy_equivalent, which runs it once with isolate_state=false after the other runs.
  • arguments: the configuration the engine's pre-run hook check reads, after the same per-spacecraft GNC flattening and density epoch alignment run_simulation applies first.
  • call: the run's state, spacecraft-view and parameter types, as the pre-run check derives them from build_initial_conditions and ODEParams.
  • solver_mode: the solver mode of the run.
source
SpaceAGORA.Conformance.conformance_fixture — Function
conformance_fixture(; configuration=nothing, spacecraft_count=1, mission_time_s=60.0,
    guidance=(), navigation=(), control=(), effectors=(), guidance_rate_s=10.0,
    navigation_rate_s=10.0, control_rate_s=1.0, orientation=true) -> ConformanceFixture

The run the checks use. Without configuration it is a short Earth orbit that needs no native GRAM, SPICE kernels or private data: make_no_gram_planet(:earth), NoAtmosphereModel(), SimpleEphemeridesModel(), spacecraft_count single-link spacecraft (100 kg, 2 m², on a 650 km by 700 km orbit at 45°, spaced 5° apart in true anomaly), a MissionTime of mission_time_s seconds, attitude propagation when orientation is true, InverseSquaredJ2GravityModel() followed by effectors as the force/torque models, and the given guidance, navigation and control models at their rates in seconds.

A model that needs more (an atmosphere for drag, a second spacecraft with a particular orbit, articulated links) is checked on a configuration the author builds, which must already contain the models under test; the component keywords are then refused.

SpaceAGORA.Conformance.check_force_torque_model — Function
check_force_torque_model(model; fixture=conformance_fixture(effectors=(model,)), samples=nothing)
    -> ConformanceReport

Check a force/torque model against the engine's contract for it. fixture must contain model itself (found by identity) among its dynamic_effectors. The checks, in report order:

  • hooks_present: the engine's own pre-run hook check, on the fixture's concrete argument types, reports nothing for the fixture.
  • supported_sample_signature: no method of wrench, wrench_caching! or a gravity backbone hook that applies to the model types a sample argument narrower than StateSample or EnvironmentSample (such as x::StateSample{MySpacecraft}); the supported forms are x::StateSample and an untyped x.
  • repeatable_run: two runs with isolate_state=true save equal times and states, bit for bit.
  • deepcopy_equivalent: a run of the model itself (isolate_state=false) equals the run of its deep copy (isolate_state=true).
  • global_rng_independent: runs with the global random number generator seeded two ways are equal (it is restored afterwards); a model draws only from the streams the engine supplies.
  • concurrent_equals_sequential: two runs on separate threads, kept in step after every solver step so that they overlap, equal the two sequential runs. It fails when a run waits more than 60 s for the other at a step, since the runs then did not overlap. Skipped when Julia runs with one thread.
  • output_hook_pure: two calls of wrench with the same arguments return equal values, leave a deep copy of the model unchanged, and log nothing at Info level or above.
  • environment_declared: wrench returns a finite force and torque (two three-vectors) when only the EnvironmentSample fields its environment_requirements declares are set and the rest are nothing. A model that declares third bodies needs a fixture with SPICE ephemerides, which the built-in one does not load.

The last two call wrench on samples the engine builds (build_state_sample and sample_environment) at the start, quarters and end of a fixture run, or on samples: a collection of (x, env, t) tuples. A model with no wrench method skips them.

Every run deep-copies the fixture except the deepcopy_equivalent run, which runs model itself after all the others, so a model with run state holds that run's state afterwards. A check that cannot run its comparison because a run failed fails with the run's error. A pass certifies interface behaviour, not the model's physics.

source
SpaceAGORA.Conformance.check_service_facade — Function
check_service_facade(facade::Module; version::VersionNumber) -> ConformanceReport

Check a versioned service facade against the optional adapter standard. One check, facade_shape, verifies that:

  • the facade defines CONTRACT_VERSION, CompatibilityError, require_version, IMPLEMENTED_FUNCTIONS and CONSUMED_SERVICES;
  • CONTRACT_VERSION equals version, the contract version the caller reviewed;
  • require_version(version) returns nothing, and every neighbouring version (one patch, minor or major release up or down, and v"0.0.0") throws the facade's CompatibilityError: the check is exact;
  • the two inventories are collections of names or name paths (tuples of names), each listed once, none in both; every implemented name resolves to a function and every consumed one to a value.

A facade that breaks any of these gets a failing facade_shape with the problems in its detail; the check does not throw on a malformed facade.

source
SpaceAGORA.Conformance.test_report — Function
test_report(report::ConformanceReport)

Record report in the current Test testset: a testset named after the target, with one testset per check. A failed check fails its test and prints its detail; a skipped check is recorded as skipped and an advisory failure as broken. Returns report.

When the environment variable SPACEAGORA_CONFORMANCE_REPORT_DIR names a directory, the report is also written there as a TOML file (target, kind, and one [[checks]] table per check with id, status, since and detail), which the contributor CI workflow summarizes.

Needs the Test standard library: using Test loads the method.
