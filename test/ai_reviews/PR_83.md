# AI Review — PR #83: expose fixed-attitude incidence modes through the scenario manifest

## Scope

Manifest-surface completion of PR #79. The telemetry-verification scenario layer constructed `AerodynamicCoefficientfM()` with defaults, so the incidence modes were unreachable from manifests. Adds the `aero_fixed_attitude_incidence` scenario key (string `max_drag` | `attitude` | `tumbling_average`), parse-time validation with the scenario context in the error, the field on both scenario-config structs (default `:max_drag`), and forwarding into the constructed effector.

## Changed Files

- `src/analysis/verification/telemetry_verification/types.jl` — `aero_fixed_attitude_incidence::Symbol = :max_drag` on both scenario-config structs, with a comment naming the three modes and the bit-compat default.
- `src/analysis/verification/telemetry_verification/manifest_parsing.jl` — key parsed once with an explicit allowlist; invalid values error before any simulation with the scenario name in the message; passed at both config construction sites.
- `src/analysis/verification/telemetry_verification/scenario_builders.jl` — `_scenario_dynamic_effectors` constructs `AerodynamicCoefficientfM(fixed_attitude_incidence=cfg.aero_fixed_attitude_incidence)`; the `ScaledAerodynamicCoefficientfM` wrapping path inherits the mode unchanged since it wraps the same instance.
- `test/probes/coverage_parallel_telemetry_probes.jl` — testset mirroring the existing manifest-key patterns.

## Findings

- Absent-key behavior is bit-identical: the default field value produces `AerodynamicCoefficientfM(fixed_attitude_incidence=:max_drag)`, which PR #79 pinned as bit-identical to the pre-#79 construction; no existing manifest changes behavior.
- The parse-time allowlist duplicates the model-level `_validate_fm_incidence` deliberately: the manifest layer fails at load time with scenario context, while the model-level validator remains the backstop for programmatic construction. The two lists must stay in sync; both are three-symbol literals adjacent to their docstrings.
- Validation happens before config construction, so a bad value can never reach the effector builder or the RHS.
- Field placement after `drag_enabled` in both structs keeps the kwdef positional order stable for any positional constructors (none found in-repo; kwdef callers unaffected regardless).

## P1 Assessment

No P1s. Additive key with a bit-compat default; error paths fail at parse time.

## Tests Added/Updated

- `coverage_parallel_telemetry_probes.jl` gains "manifest aero_fixed_attitude_incidence key": absent-key default (`:max_drag`), key round-trip through `_load_scenarios_from_manifest` → `_scenario_initial_condition` → `_make_spacecraft` → `_scenario_dynamic_effectors` into the built fM effector's field, and the invalid-value parse error naming the key. The chain was additionally smoke-run standalone against the working tree (parse, build, and error branches all exercised).

## Residual Risk

The two mode allowlists (manifest parser, model validator) are maintained independently; a future fourth mode added to the model without the parser update would be invisible from manifests (fail-safe direction — it cannot produce wrong physics, only a parse error). The scenario key only affects `drag_enabled` scenarios; drag-free scenarios carry the field inertly.
