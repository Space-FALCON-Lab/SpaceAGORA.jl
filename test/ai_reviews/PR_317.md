# PR317 review: add the actuator contract and drive mounted thrusters through it

## Scope

Review of the SpaceAGORA `actuator-contract` branch against its base,
`actuator-layout` (PR #316). The PR adds the actuator contract
(`src/models/vehicle/actuators/actuators.jl`), mounting and the evaluation of
a mounted set (`mounting.jl`), makes the thruster the first actuator kind
(`thruster.jl`), adds an opt-in `:mounted` actuation for control effectors in
the right-hand side and the thruster-level save field, gives the RPO MPC and
Apollo descent controllers an `actuation` option, settles the thruster
direction as the thrust direction, and fixes `add_thruster!`. It is the second
step of the actuator-layer plan; decisions D-8 to D-11 were taken by the PI on
2026-10-15.

Authorship disclosure: this record was drafted by the author of the PR. The
plan assigns behaviour PRs of the actuator layer an independent reviewer (the
PI, or the second reviewer when available); this record does not replace that
review.

## Findings

No P1 findings. Three P2 findings from the automated review of the first
commit, all fixed in the second commit (d66fd0c21), each with a test that
fails without its fix:

- P2, fixed: `descent_thruster_layout` built its torque arms from each jet's
  link-local location and direction, while `mounted_wrench` applies the link
  pose, so in `:mounted` actuation jets on a translated or rotated non-root
  link would not produce the allocated torque. The layout now takes each jet
  through its link's configured pose; a root link at the body origin skips the
  arithmetic, which keeps every existing layout bit-identical. Test: on a
  rotated, offset link the layout's torque arms equal the mounted jets'
  full-thrust torques.
- P2, fixed: mounted RPO returned six levels, so a chaser carrying any other
  mounted actuator failed on every evaluation. It now fills one level per
  mounted actuator at each control tick, the six allocated forces on the first
  six mounted thrusters and every other actuator idle; a chaser with fewer
  than six thrusters is refused with a message. Test: a chaser with an extra
  actuator evaluates, and the extra stays at zero.
- P2, fixed: `allocate_actuators(...; method=:axis_clamp)` accepted lower
  bounds and discarded them. Every level is now clamped to both bounds; with
  the RPO allocator's zero lower bounds this changes nothing, and the exact
  agreement with it on 2000 random cases still holds. Test: a positive lower
  bound holds for every jet, idle ones included.

Low, by design: a `:mounted` RPO chaser's six-axis jets must be the first six
mounted thrusters; the count is checked, their geometry is not.

Found and fixed while building: `add_thruster!` had never worked; it stored a
3-vector in the link's thruster Jacobian matrix and threw on its first call.

## Residual Risk

- The companion-backed suites, the RPO example (HYPR) and the Apollo demo's
  viewer run were not run locally; CI runs the suites.
- `:mounted` RPO assumes the chaser carries `six_axis_thrusters(model.thrusters)`;
  the count is checked, the geometry is not.
- `:mounted` Apollo realizes a clipped least-norm allocation of the attitude
  torque, so its attitude response differs from `:ideal`; the test bounds it.
- A user-defined kind on `Link.custom_actuators` is dispatched dynamically at
  every right-hand-side evaluation; the cost is documented, not measured here.
