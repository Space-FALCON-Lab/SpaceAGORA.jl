# AI Review — PR #86: aero wrench attitude tracking + center-of-pressure torque

## Scope

One latent-defect fix and one capability on the live aerodynamic wrench path. The fix: under `orientation_sim=true`, aero link attitudes came from the static `Link.q` on the spacecraft model via `rotate_to_inertial` — nothing syncs the integrated attitude back into that quaternion, so aero geometry (incidence, force direction, per-link sampling positions) was frozen at the initial attitude for the whole simulation while the attitude ODE spun the body. The capability: `Link.cop_offset_b`, a link-frame center-of-pressure offset (default zeros), with the lever-arm torque rebuilt frame-consistently in the root body frame — previously the torque crossed a root-frame offset with a link-frame force, and root-only spacecraft could never carry aero torque (the only lever was the always-zero root `body.r`).

## Changed Files

- `src/dynamics/coupled/aerodynamic_wrench_models.jl` — `_aero_link_angles` takes the propagated `q_root_ib` (throws when the orientation branch is entered without it) and composes `R = rot(q_root_ib)'` for the root, `rot(q_root_ib)' · rot(body.q)'` for children (stored root-relative child q preserved for articulated panels); the lever-arm block computes `force_root = rot(x.q_ib) · force_ii` and `lever_root = body.root ? cop : body.r + rot(body.q)' · cop`, accumulating `cross(lever_root, force_root)`; per-link atmosphere sampling rotates `body.r` by the propagated root attitude; the stale function-level comment claiming an all-inertial return contract is corrected (torque is the root-body frame, matching every other torque-returning effector and the `wrench` interface docstring).
- `src/vehicle/spacecraft/model.jl` — `cop_offset_b::MVector{3, Float64}` on `Link`, kwarg default zeros, appended to the inner constructor; all existing constructions value-identical.
- `test/probes/aero_torque_probes.jl` — new probe (31 assertions, see below).
- `test/suites/09_probe_drivers.jl` — probe registered.

## Findings

- The frozen-attitude defect was found by a three-lens capability audit (whether aero torque was expressible at all) and confirmed by direct reading: the engine routes all three aero effectors through the wrench path, `build_state_sample` populates `q_ib` from the integrated state, but `_aero_link_angles` read `spacecraft.root.q` — the configured initial value. No campaign or CI configuration ever hit it: every attitude example and suite pairs attitude with `NoAtmosphereModel` (zero density short-circuits the wrench), and the fM incidence probes run `orientation_sim=false`. Blast radius of the fix is therefore empty for existing tests and examples, and the `orientation_sim=false` paths regress bit-identically (fM incidence 20/20, eddy 196/196 after the change).
- The torque frame contract (root body frame) matches `_assign_orientation_rhs!`, which feeds accumulated effector torque as `tau_body` into the body-frame Euler equation, and matches the magnetic effectors' returns.
- Frame consistency for canted panels: the old `cross(body.r, R_body_to_inertial' · force)` mixed a root-frame lever with a link-frame force; the rewrite works entirely in the root frame with the CoP offset composed through the child attitude.

## Adversarial review (pre-push)

Three-lens review (frames / compatibility / test adequacy) with per-finding adversarial verification. Refuted: an end-to-end coverage claim, a tolerance-fragility claim (measured 51× margin), and a cd-scaled-model bypass claim (that model has no wrench method). Confirmed and addressed before push:

- **P1 (test gap)**: the torque frame at non-identity `q_ib` was unpinned — a verifier empirically applied the `rot → rot'` transpose mutant and all 20 first-draft assertions passed. Fixed with a rotated-attitude pin whose rotation axis is perpendicular to both the flow and the lever, so the two frame conventions give opposite-sign torques; the transpose is asserted wrong explicitly. (A first attempt rotated about the flow-lever plane's normal complement and was degenerate — both conventions gave zero; documented in the probe.)
- **P2**: child composition order `R_root · rot(body.q)'` only exercised where unobservable — fixed with a composed-attitude equivalence test using different rotation axes (canted child on rotated root ≡ root-only body at the quaternion-product attitude, helper self-validated against the rotation matrices).
- **P2**: per-link atmosphere position fix had zero test executions — fixed with a recording sampler asserting the propagated-rotated position and rejecting the unrotated one.
- **P3**: missing-`q_ib` guard untested — `@test_throws` added. **P3**: stale contract comment — corrected. A vacuous assertion (structurally-zero dot product) flagged by the review was removed.

## P1 Assessment

The latent frozen-attitude behavior was itself P1-class for any future attitude+atmosphere simulation; this PR removes it before any user could rely on it. No new P1s: the capability is additive (zero-default CoP), the orientation-off paths are bit-identical, and the guard converts a silent misuse into a construction-time error.

## Tests Added/Updated

`test/probes/aero_torque_probes.jl` (31 assertions, registered): attitude-tracking pin (rotating `q_ib` changes the fM wrench; static `Link.q` untouched), root CoP lever arm at identity and rotated attitude (mutant-killing sign pin), mirrored-panel exact cancellation, child composition-order equivalence, per-link atmosphere position pin, missing-attitude guard throw, `orientation_sim=false` force-only/CoP-blind invariants, and an end-to-end pair showing the CoP torque drives the attitude while the 600 s trajectory stays within meters.

## Residual Risk

The Hart closed-form moment coefficients present in the file remain unwired (dead code): per-face intrinsic aero moments are a strictly larger follow-on; the CoP lever arm is the smallest physically-sound torque. The legacy aero `calcForceTorque` methods (unreachable behind the wrench methods, two internally broken) are untouched — tracked separately. `cop_offset_b` is not yet plumbed through the scenario-manifest layer; direct `SpacecraftModel` construction carries it.
