# AI Review — PR #84: plumb per-link attitude quaternions through the scenario spacecraft config

## Scope

Completes the reachability of the PR #79 `:attitude` incidence mode for manifest-driven, held-attitude multi-panel vehicles. Before this PR every link built by the scenario layer carried the identity quaternion — the configuration where `:attitude` ≡ `:max_drag` exactly (the equivalence theorem pinned in `fm_incidence_probes.jl`), so the mode was a no-op end-to-end for such spacecraft. Adds optional `bus_attitude_q` / `panel_attitude_q_left` / `panel_attitude_q_right` keys (x, y, z, w scalar-last) to the spacecraft block, parse-time validated and normalized, carried on `SpacecraftConfig`, and forwarded through `make_three_body_spacecraft` onto the constructed `Link`s.

## Changed Files

- `src/analysis/verification/telemetry_verification/types.jl` — three `Union{Nothing, NTuple{4, Float64}} = nothing` fields on `SpacecraftConfig`, with the frame conventions documented (bus q in the flow-aligned reference frame; panel q relative to the bus frame per the kinematics contract; consumed only by fM `:attitude` with `orientation_sim=false`).
- `src/analysis/verification/telemetry_verification/manifest_parsing.jl` — `_parse_attitude_q`: absent → `nothing`; else 4-element finite array with norm > 1e-8, returned normalized; errors name the key and scenario context. Wired into `_parse_spacecraft_config`.
- `src/analysis/verification/telemetry_verification/example_support.jl` — `make_three_body_spacecraft` gains the three kwargs; `_link_q` maps `nothing` to the explicit identity `MVector` (the Link constructor's own default value, so existing callers are bit-identical) and otherwise splats the normalized tuple.
- `src/analysis/verification/telemetry_verification/scenario_builders.jl` — `_make_spacecraft` forwards the three fields.
- `test/probes/coverage_parallel_telemetry_probes.jl` — new testset (see below), appended after the coverage-paydown testsets from PR #83 (rebase resolved by keeping both groups).

## Findings

- Bit-compat is by construction: absent keys produce the same `q = (0, 0, 0, 1)` `MVector` the `Link` kwdef default supplies, so the built spacecraft is value-identical to the pre-capability one; no manifest or caller changes behavior.
- Normalization at parse time (rather than at use) keeps a single canonical value on the config and makes the round-trip test exact; the 1e-8 norm floor rejects degenerate input while accepting any reasonable unnormalized quaternion.
- The panel-relative-to-bus convention matches `rotate_to_inertial` (child q composed with root q) and therefore the `_attitude_link_alpha` composition added in PR #79 — the testset's mirrored-cant pin (α_left + α_right = π) would fail under any frame-convention mismatch.
- The quaternion component order (x, y, z, w scalar-last) matches the `Link` field convention (identity = (0,0,0,1)); stated in the key documentation and the parse error text.
- `bus_attitude_q` on the root link is consumed as attitude-relative-to-flow (PR #79 docstring); for the standard held-attitude translational scenarios it should normally stay absent, which the docs note by describing the panels as the primary use.
- **Defect found in review (Codex, PR #84 comment) and fixed before merge**: the historical `:max_drag` branch reads non-root link quaternions via `_quaternion_link_alpha`, so a manifest supplying panel quaternions while leaving the incidence mode at its default would have silently changed default-mode physics, contradicting the documented attitude-only contract. Fix: parse-time rejection — any attitude key with `aero_fixed_attitude_incidence != "attitude"` errors with the scenario context; the engine paths are untouched and `:max_drag` remains bit-identical for all previously expressible manifests (which could not set link quaternions at all).

## P1 Assessment

No P1s. Additive keys with a bit-compat default; validation fails at parse time before any simulation; only the fM `:attitude` path reads link quaternions when attitude is not simulated.

## Tests Added/Updated

- `coverage_parallel_telemetry_probes.jl` "manifest link attitude quaternions" (13 assertions, including the mode-coupling rejection: attitude keys under the default mode error naming the requirement): absent-key identity default across all links; normalized round-trip of deliberately unnormalized ±22.5° panel cants; wrong-length and zero-norm parse errors naming the key; and the incidence pin — canted panels under `:attitude` land exactly π/8 off flow-normal, mirrored pair summing to π, bus staying flow-normal — the complement of the PR #79 identity-equivalence pin.
- Full probe file green locally under the driver flags (74 assertions across the three testset groups).

## Residual Risk

The three keys only affect vehicles built by `make_three_body_spacecraft`; direct `SpacecraftModel` constructors bypass them (they already accept `Link` quaternions natively). A cant expressed on a panel also rotates that panel's dims-derived Hart side-face terms — physically intended, but users porting areas fitted under flow-normal assumptions should re-derive reference areas rather than combine fitted areas with newly canted attitudes.
